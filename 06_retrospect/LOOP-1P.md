# 메타 루프 ⑤ — 시스템 회고 루프 (1P)

> **한 줄 목적**: 세션이 끝날 때마다 stock-os 자체를 최소 한 뼘 개선·축적하고, 그 결과를 다음 세션에
> 되먹여 OS를 복리로 키운다. (투자 성과 회고가 아니라 **OS·워크플로우** 개선 루프)

## 흐름

```
        ┌──────────────── 다음 세션에 되먹임 ◀────────────────┐
        │                                                    │
[SessionStart 훅]──주입──▶  세션 작업 (①②③④)  ──세션 끝──▶  /retrospect (⑤)
  열린 이슈 + 최근 lessons                                     ① 안전한 1건 즉시 개선
  (읽기측)                                                     ② 이슈 기록/해결
                                                              ③ lesson 누적 (쓰기측)
```

읽기(되먹임)와 쓰기(축적)가 짝을 이룬 **닫힌 고리**다. 열린 이슈가 매 세션 다시 눈에 밟혀 하나씩
닫히므로, 회고가 write-only 무덤이 되지 않고 부채가 **수렴**한다.

## 구성요소

| 파트 | 파일 | 역할 |
|------|------|------|
| 읽기측(되먹임) | `.claude/hooks/session-start-context.py` | 세션 시작에 **열린 이슈 전부 + 최근 lessons(≤5)**를 컨텍스트로 주입. compact엔 미주입, 빈 상태엔 조용히 `{}`. |
| 쓰기측(축적) | `.claude/skills/retrospect/SKILL.md` | 세션 끝 `/retrospect`. **메인 컨텍스트 스킬**(세션 맥락은 메인만 앎 → subagent 아님). |
| 상태 | `06_retrospect/issues.md` | 미해결 개선 부채(열림/해결). 최신순 상단 append, 닫을 땐 그 자리 상태 갱신. |
| 상태 | `06_retrospect/lessons.md` | 일반화된 배움 누적. `[시스템]`/`[투자]` 태그. |
| 양식 | `06_retrospect/_template.md` | 회고 작업 양식(저장 불필요, 결과만 반영). |

## 한 사이클 (6단계)

1. **스캔** — 이번 세션에 한 일·마찰·정정을 훑고, 주입됐던 열린 이슈를 건드렸는지 먼저 확인.
2. **분류** — (a) 작고 안전 = 즉시 개선 / (b) 크거나 판단 필요 = 이슈.
3. **즉시 개선** — (a) 중 가장 값진 1건을 실제로 수정(큰 리팩터는 몰래 시작 금지 → (b)로).
4. **이슈** — 신규 (b)는 `열림`으로 append, 이번에 해결된 건 그 자리 `해결(날짜)`로 갱신.
5. **lesson** — 일반화 가능한 배움 ≥1건 append("다음에 어떻게 적용"까지).
6. **3줄 요약** — 고친 것 / 기록한 것 / 다음 세션이 이어받을 열린 이슈.

## 가드레일

- **최소 1개 변화 보장** — 즉시 개선 또는 신규 lesson 중 최소 하나. 0건이면 회고 실패.
- **append 보존** — lessons·issues는 지우지 않고 위로 쌓는다. 해결은 그 자리 상태 갱신.
- **추정 금지** — 원인·데이터 없으면 "미상"/빈칸. 지어내지 않는다.
- **작게** — 회고 중 개선은 안전·소규모 1건까지. 큰 건은 이슈로.

## 왜 "실행할수록 개선"인가

매 세션이 (개선 1건 + 배움 ≥1) 씩 남기고, 남긴 것이 SessionStart로 **다음 세션에 자동 재노출**된다.
열린 이슈 수는 (새로 열림 − 닫힘)으로 관리되며 닫는 압력이 계속 걸려 **부채가 줄고 배움이 두꺼워진다** —
이것이 복리다.

## 현재 한계 & 확장안 (로드맵)

정직하게 남기는 미해결 부분 — issues.md로 추적한다.

- **복리 단절(`issues #001`)** — lessons/issues가 **메인 컨텍스트에만** 되먹여진다. 데일리 조언을
  만드는 subagent(`portfolio-analyst` 등)는 lessons를 안 읽어, `[투자]` 교훈이 조언 품질엔 복리로
  안 붙는다. → 확장 루프 **A**로 정면 해결 예정.
- **수동 트리거 의존(`issues #002`)** — `/retrospect`를 사람이 세션 끝에 불러야만 돈다. → Stop 훅
  넛지 검토.

확장 루프 후보(다음 단계, 아직 미구현):

- **A. 데일리 조언 적중 피드백** — 데일리의 시나리오·목표가 vs ④ 실제 결과를 대조·축적해 조언 품질을
  복리 개선. (한계 #001을 정면으로 메움)
- **B. 소스 신뢰도** — `data-reviewer`의 WARN/FAIL을 축적해 `data-sources.md` 신뢰도를 점진 갱신.
- **C. watchlist 재정렬** — 데일리 언급 빈도로 관심종목 자동 승격/강등.

## 이번 문서화 중 개선한 것 (dogfood)

이 1P를 쓰면서 회고 루프를 자기 자신에 돌렸다:
- 훅 `source` 게이팅 추가(compact 재주입 노이즈 차단).
- SKILL.md에 로그 아카이빙 기준 명시(비대화 방지).
- 위 두 한계를 `issues #001·#002`로, 되먹임 설계 교훈을 `lessons`로 축적.
