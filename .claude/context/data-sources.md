# 데이터 소스 규약 (data-sources)

> 어디서 데이터를 얻고, 무엇은 쓰지 않으며, 출처를 어떻게 표기하는가. 출처: docs/OS.md 데이터 소스 결정.

## 채택 소스

| 용도 | 소스 | 왜 |
|------|------|----|
| 시세·시총·PER·ROE (스크리닝) | 네이버 금융 시총 표 (EUC-KR) | 키 불필요, 일괄 컬럼 제공 — `screen_kospi.py` |
| 개별 재무 (부채비율·영업이익·배당) | 네이버 금융 종목 페이지 '기업실적분석'(FnGuide, UTF-8) | 요약 재무를 한 곳에서 — `score_stocks.py`·`fundamentals.py` |
| 현재가·52주 고저 | 네이버 금융 — `quote.py` | 진입/손절 앵커. **현재가 진실원천은 quote.py 한 곳** (회고 evaluate_records.py도 재사용) |
| 일별 OHLCV (지지/저항·변동성) | 네이버 일별 시세 (sise_day, EUC-KR) — `ohlcv.py` | 정밀 수치는 웹검색이 아니라 스크립트 파싱 |
| 뉴스·주가 흐름·거시 (정성) | 서브에이전트 웹검색 (company-news·stock-trend·kr-macro researcher) | 내러티브·해석 전용 — 정밀 수치로 쓰지 않음 |

## 기각·보류 소스 (다시 검토하지 말 것)

- **pykrx — 탈락.** 시장 전체 일괄 조회 함수가 모두 `data.krx.co.kr`(403/`LOGOUT`)에 막혀 빈 데이터로 크래시(2026-06-30 직접 테스트). 1차 필터에 필요한 바로 그 기능이 막혀 부적합.
- **DART — 도입 보류.** 필터는 네이버로 충분. 강점(공시 사건·수치 공신력)은 한 종목 심층 분석에서 유효하므로, 필요해지면 `analyze-company`에 서브에이전트로 후행 도입.

## 출처 표기 규칙

- 리포트·기록의 모든 수치에는 산출 주체를 밝힌다: 스크립트 값은 스크립트명(예: `ohlcv.py`), 웹검색 값은 "웹검색(정성)"으로.
- 웹검색 수치와 스크립트 수치가 충돌하면 **스크립트가 이긴다** (정밀 수치=스크립트 원칙).
- 못 구한 값은 "확인 불가"로 표기하고 빈 자리를 추정치로 채우지 않는다.
