# 팀 역량 — 개발 수행 단위로서 우리 팀

> **성격**: 정책 입력 (사실). 판단 규칙은 [`classification-policy.md`](./classification-policy.md) 에 있다.
> **변경 주기**: 사람이 들어오고 나가거나, 새 스택을 익히면 갱신. 분기 1회 점검 권장.
> **읽는 쪽**: `classifier`(내부/외주 판단), `intake-interview`(질문 범위 조절)
> **현재 대상 시스템**: `sandbox/board` (연습용 게시판 API)

## 주력 스택 — 자신 있게 내부 개발

| 영역 | 스택 |
| --- | --- |
| 웹 백엔드 API | Python / Flask |
| 자동화 테스트 | pytest |
| 데이터 조회·추출 | SQL |
| 배치·연동 스크립트 | Python (표준 라이브러리 + `requests` 수준) |

## 부분 대응 — 소규모만, 신규 기능은 부담

| 영역 | 가능한 것 | 안 하는 것 |
| --- | --- | --- |
| 프론트 화면 | 서버 템플릿, 바닐라 JS 소규모 화면 | SPA(React/Vue 등) 신규 구축, 복잡한 상태관리 |
| 레거시 사내 배치 | 스크립트 수정, 쿼리 튜닝 | 구조 변경, 런타임·프레임워크 업그레이드 |
| 패키지 솔루션 | 설정 변경, 플러그인 | 소스 커스터마이징 |

## 범위 밖 — 기본 외주

- 모바일 네이티브 앱 (iOS / Android)
- 벤더 패키지(ERP 등) 내부 로직 수정
- 디자인 산출물, 번역, 규제 인증

> **주의** — "인프라·보안"은 범위 밖이 아니라 **사내 IT팀이 직접 수행**한다.
> `classification-policy.md` §0 선판정 참고.

## 인력 구성 (집계)

> 개인 식별 정보(이름 등)는 담지 않는다 — `OS.md` §5 원칙 2, 이 파일은 팀 전체 집계만 유지.

| 역할 | 인원 | 숙련도 분포 |
| --- | --- | --- |
| 백엔드 (Python/Flask) | 2명 | 시니어 1 · 주니어 1 |
| 프론트 (서버 템플릿·바닐라 JS) | 1명 | 주니어 1 (겸임) |
| DB/쿼리 (SQL) | 2명 | 백엔드 인력과 겸임 |

## 동시 처리 여력

- 내부 개발 동시 진행 **상한 2건** (백엔드 시니어 1 + 주니어 1 기준 — 위 인력 구성표와 연동).
- 이번 달 실제 잔여 공수는 여기가 아니라 [`maintenance/capacity.md`](../../maintenance/capacity.md) 에 있다
  (변동성이 커서 분리했다).

## 시스템별 사실은 여기 쓰지 않는다

"정산시스템 A는 회사 A가 관리" 같은 **특정 시스템의 사실**은 `.claude/knowledge/systems/` 에 둔다.
이 파일은 **팀 전체 집계**만 담는다.
