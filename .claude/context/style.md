## 코드 (`sandbox/board` = Python)

- PEP 8, 4-스페이스 들여쓰기. 함수·변수 `snake_case`.
- **주변 코드의 관례를 먼저 따른다** — 주석 밀도, 네이밍, 에러 응답 형식.
  새 스타일·새 라이브러리를 이유 없이 들여오지 않는다.
- 에러 응답은 기존 컨벤션 재사용: `jsonify({"error": <메시지>}), <상태코드>`.
- 방어 순서: **타입 검사 → 값 검사.**
  (`isinstance(x, str)` 를 먼저 봐서 `None`·숫자에 `.strip()` 호출로 500 내지 않기 — REQ-001)
- 부작용(저장·id 발번)은 **모든 가드를 통과한 뒤에만** 실행한다.
- 주석은 "왜" 를 쓴다. "무엇" 은 코드가 말하게 둔다.

## 테스트 (TDD)

- **버그 수정은 실패하는 테스트(Red)를 먼저 추가**하고 나서 고친다. Red 없이 수정만 커밋하지 않는다.
- **기존 테스트 함수는 수정하지 않는다** — 회귀 탐지용. 새 케이스는 추가만 (파일 diff 가 추가-only).
- 새 테스트는 기존 픽스처·네이밍·스타일 그대로. 여러 입력은 `@pytest.mark.parametrize` 로 나열.
- 커밋·핸드오프 전 `cd sandbox/board && python3 -m pytest` **전체 통과** 확인 후 결과 숫자를 로그에 남긴다.

## 문서 (케이스 파일 · 스펙 · 노트)

- 한글 본문 + 영문 기술용어는 번역하지 않고 그대로 (`endpoint`, `commit`, `rollback`).
- 내부 문서(케이스 파일·스펙·구현 로그) = **지시형 평서체.** 담당자 통보문 = **존댓말.**
- 표를 우선한다. 나열은 불릿 3~5개. 완료 기준은 **번호 매김** + 각각 검증 가능하게
  ([`dod-patterns.md`](./dod-patterns.md)).
- 코드 인용은 `파일:라인` (예: `app.py:23-33`).
- 판단에 지침을 적용했으면 **출처(파일명 + 절)를 인용** (`CLAUDE.md` 규칙 5, `classification-policy.md` §5).

## 커밋 메시지

- Conventional Commits + 한글 본문. `feat:` · `fix:` · `refactor:` · `docs:` · `chore:`.
- 제목은 "무엇을 왜". 본문은 배경·판단. 세부는 `git-commit` 스킬 규칙을 따른다.
