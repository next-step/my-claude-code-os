# 검증할 것은 코드로, 보여줄 것은 지시문으로

마크다운 지시문은 자동 테스트가 불가능하다. AI에게 시킬 일을 검증 가능하게 만들려면 **먼저 검증 가능한 표면을 만들어야 한다.**

- 새 기능은 **(로직 = `.claude/lib/*.js`) + (지시문 = `SKILL.md`)** 로 나눈다. 판정·집계·파싱은 전부 `lib`으로 뺀다.
- `lib` 함수는 **순수 함수**로 쓰고 `fs` 접근은 옵션으로 주입받게 한다 — 실제 파일시스템 없이 테스트하기 위해서다 (`stats.js`·`context-map.js`·`session-board.js`의 공통 관례).
- `lib` 파일 하나에 `.claude/tests/<이름>.test.js` 하나를 짝지어 만들고, 테스트 제목에 AC 번호를 단다.
- 테스트는 **파일을 직접 지정**해 돌린다. `node --test .claude/tests/`는 Node가 `.`으로 시작하는 숨김 디렉터리를 자동 탐색에서 제외해 실패한다.
- **검증기가 보지 못하는 것을 코드 주석과 스킬 본문 양쪽에 적는다.** 형식 검사를 품질 보증으로 착각하는 것이 더 위험하다.

근거: `OS.md` 2026-08-27(마크다운은 테스트할 수 없다는 벽), 2026-09-02.
