# 코드 리뷰 루브릭 (review-rubric)

> `/verify` full 이 `reviewer`에게 넘기는 **코드 리뷰 채점 틀의 단일 출처**다.
> reviewer는 격리 컨텍스트라 이게 자동 주입되지 않으니, `/verify`가 이 카드를 **`Read`로 열어 프롬프트에 실어** 넘긴다.
> 목적: 매 리뷰가 **같은 축을 근거와 함께** 보게 해(재현성), `/impl`의 "점수 미달 → 부족한 축 채우기" 수렴 루프를 굴린다.

## 핵심 원칙 (안 게이밍)

- **점수는 찍는 게 아니라 결함에서 계산된다.** 각 축의 레벨(0·1·2)은 **인용된 구체 근거(코드 줄·테스트 출력)** 가 있어야 한다. 근거 없이 점수를 올리거나 내리지 않는다.
- **min-gate: 한 축이라도 0이면 블로킹.** 평균이 아무리 높아도 0축이 있으면 통과가 아니다(숫자가 결함을 숨기지 못하게).
- **루브릭 밖도 계속 의심하라.** 5축에 안 맞아도 이상하면 지적한다 — 루브릭은 "반드시 볼 축을 **추가**"하는 것이지 열린 적대적 탐색을 **대체**하지 않는다.

## 5축 · 앵커 (각 0·1·2)

| 축 | 2 (통과) | 1 (경미) | 0 (결함·블로킹) |
|----|----------|----------|------------------|
| **정확성/버그** | 로직·엣지·경계·동시성 결함 없음 | 미검증 의심 경로 있음 | 실제 버그·경계 오류 |
| **테스트 품질** | 추가/변경 동작을 어서션으로 실검증(엣지 포함) | 엣지 1~2 누락 | 무어서션·항상참·핵심 경로 미검증(게이밍) |
| **재활용성** | 기존 코드/유틸/스킬 재사용, 중복 없음 | 사소한 중복 | 기존 구현을 재구현/중복 (원칙 3.2 위반) |
| **단순성/과설계** | 필요한 만큼만, 죽은 코드 없음 | 약간 장황 | 명백한 과설계·불필요 복잡·데드코드 |
| **컨벤션/규격** | backend-conventions 준수(레이어·`errorCode`·docstring 등) | 경미한 일탈 | 규격 위반(에러 형식·레이어 경계 등) |

## 점수 · 판정

- **점수 = (축 레벨 합 / 10) × 100** (5축 × 2 = 만점 10 → 0~100).
  - 예: 정확성2·테스트0·재활용1·단순2·컨벤션2 = 7/10 → **70** (그리고 테스트 0 = 블로킹).
- **판정 매핑** (`/verify`의 3갈래로):
  - **점수 ≥ 90 AND 0축 없음** → **통과** (남은 1축은 "개선 제안"으로 첨부).
  - **0축 있음** → **구현결함** — 그 축의 인용 결함을 고친다. (단, 재활용성/접근이 0이고 **설계를 바꿔야** 풀리면 → **설계문제**.)
  - **점수 < 90 (0 없이 1이 여럿)** → **구현결함** — 미달 축을 채워 점수를 90 이상으로.

## 출력 형식 (reviewer가 이걸로 답한다)

```
## 리뷰 점수: NN/100 · 판정: 통과 | 구현결함 | 설계문제
## 축별 (레벨 · 근거 필수)
- 정확성/버그   [2] 없음
- 테스트 품질   [0] <파일:줄> 무어서션 — 무엇이 왜 / 어떻게 고칠지
- 재활용성      [1] <근거> — 중복 경미
- 단순성/과설계 [2] 없음
- 컨벤션/규격   [2] 없음
- (루브릭 밖)   없음 | <축 밖 결함>
## 근거 / 신호
- 테스트: 통과 N/M (실행했다면) · 그 외 객관 근거
```

> 이 루브릭은 커버리지 건강도(§/coverage)와 **같은 채점 규칙**(0·1·2 앵커 · min-gate · 근거필수)을 쓴다 — OS 공통 채점 컨벤션.
