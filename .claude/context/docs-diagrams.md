# 문서·다이어그램 규칙

아래 규칙은 전부 한 번씩 깨지고 고친 것들이다. 다시 겪지 않기 위해 적어 둔다.

- **`.mmd`가 원본, `.svg`는 생성물.** 고칠 때는 항상 `.mmd`를 고치고 다시 생성한다. 생성 명령은 `docs/diagrams/README.md`에 있다.
- 생성 옵션 세 가지는 선택이 아니라 필수다 — `mermaid-config.json`의 **`htmlLabels: false`**(없으면 GitHub에서 라벨이 통째로 사라진다), **`-b white`**(없으면 다크모드에서 안 보인다), **한글 폰트 명시**(없으면 headless Chromium에서 글자가 깨진다).
- 생성 후 `grep -c foreignObject *.svg` 가 **전부 0**인지 확인한다.
- **색 언어를 공유한다** — 노랑=사람 개입, 초록=스킬, 파랑=서브에이전트, 빨강=훅, 회색=데이터·시작·종료.
- 문서에 "지금 이 순간의 수치"를 박아 넣지 않는다. 수치는 스킬이 실행 시점에 집계하고, 문서는 변하지 않는 구조만 담는다.
  - **예외: 한 장짜리 개요 다이어그램**(`docs/diagrams/08-context-overview`). 규모 없이 구조만 보면 무엇이 비싼지 알 수 없어 개요의 목적이 사라진다. 대신 (1) 다이어그램 제목에 기준 시점을 밝히지 않는 대신 재생성이 한 줄이고, (2) 같은 수치를 `context-map` 스킬이 실행 시점에 다시 낸다. 즉 수치가 낡으면 스킬이 바로 드러낸다 — 예외를 두되 낡음을 감지할 경로를 함께 둔다.
- (권장) 한 장이 세로로 너무 길어지면 **성격이 다른 구간에서 나누는 것을 검토**한다. 규칙은 아니다 — 2026-08-27에 파이프라인을 승인 게이트 기준으로 둘로 나눠 좋았던 1회 사례다.
