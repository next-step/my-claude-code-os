# 작업 규약 (conventions) — 이 레포에서 커밋·브랜치·소통을 하는 방식

시각검증과 **무관한** 범용 컨텍스트다. 커밋·인터뷰처럼 도메인 밖 스킬이 공유한다.
(이 파일의 존재 자체가 증명이다 — 주입 시스템은 시각검증 전용이 아니라 **도메인 불문 범용**이다.)

## 커밋

- **Conventional Commits + 한글.** `<type>: <제목(한글·명령형·50자 이내)>`. type = `feat`·`fix`·`docs`·`style`·`refactor`·`test`·`chore`.
- 제목은 "무엇을 했다"가 아니라 **"무엇을 한다"** 명령형. 본문은 *무엇을 왜* 바꿨는지(선택).
- 논리적으로 별개인 변경은 **쪼개서** 여러 번 커밋한다. 한 커밋 = 한 의도.
- `git push`·기본 브랜치 직접 커밋·`--no-verify` 우회는 **하지 않는다**(사용자가 명시적으로 요청할 때만).

## 브랜치

- **PR 흐름:** `step*` 작업 브랜치 → `mintmin0320`(아이디 브랜치)로 올린다.
- **새 step 은 직전 step 브랜치에서 딴다.** 형제로 분기하면 `CLAUDE.md` add/add 충돌이 난다. (경험칙)

## 소통·PR

- 대화·커밋·문서·PR 은 **한글**로 쓴다.
- PR 본문엔 **접근 방식 · 설계 의도 · 궁금한 점**을 함께 적는다 — 그래야 양질의 리뷰가 돌아온다.
- **억지로 채운 부분은 정직하게 표시**한다. 흠을 숨기지 말고 "여기가 약하다"를 먼저 말한다.

## 아쉬움 → 원칙 승격 (gotcha)

- 스킬·에이전트를 쓰다 아쉬운 점이 나오면 `.claude/gotcha-log.md`에 기록한다.
- 같은 증상이 **3회 이상**이면 대상 md 하단 `## Gotcha`로 승격해 재발을 막는다. 3진 아웃 = 우연이 아니라 구조 문제.

## 일하는 결 (작업 우선순위)

- **우선순위를 먼저 제시**하고 움직인다. 나열이 아니라 추천.
- **엣지·가정(사각지대)을 선제적으로** 짚는다. 안 물어본 것까지 사냥한다.
- 확정된 판단은 **원칙으로 굳혀** 이후가 그걸 준수하게 한다(방어적 완결성).
