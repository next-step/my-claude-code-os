# 문서 작성 규칙 (docs/)

> 이 파일은 `docs/` 아래 문서를 만지는 순간 **자동 주입**되는 규칙 카드다(경로 매칭 = 결정적 주입).
> 스킬을 안 돌리고 맨손으로 문서를 고칠 때도, 격리된 서브에이전트가 문서를 쓸 때도 이 규칙이 따라온다.
> 규칙은 여기 한 곳에만 둔다(단일 출처). 실제 예시는 `docs/`의 기존 문서가 원본.

## docs/ 지도 (어떤 문서가 어디에)

```
docs/prd/<slug>.md            ① "무엇" — /prd 가 수집(러프 초안·/interview 씨앗)부터 정제·확정까지 (문제·목표·시나리오·범위밖·제약)
docs/plan/<slug>.md           ② "어떻게" — 구현 Plan (재활용 지도 → 직접 구현 → 테스트 전략)
docs/domain/<slug>.md         서비스 도메인의 정체·경계·관계 (/domain 이 유지)
docs/diagrams/<name>.{html,png}  도식 소스(HTML)와 검증된 산출물(PNG)
```

- **파일명 = 기능 slug** (kebab-case, 한 기능은 단계별로 같은 slug). 예: `signup-login-api.md`.
- 한 기능이 흐름을 따라 `prd → plan` 두 폴더에 **같은 이름**으로 쌓인다. (요구사항은 별도 폴더 없이 `/prd`가 `docs/prd/`에서 수집→정제한다.)

## 문서별 틀 (있는 걸 따르고, 새 틀을 만들지 않는다)

- **PRD**: `## 문제 / 목표 / 사용자 시나리오 / 범위 밖 / 제약·조건 / 열린 질문`. 실패는 **상태코드 + `errorCode`**까지 명시. (요구사항 수집 재료를 `/prd`가 이 형식으로 정제 — 별도 requirements 파일 없음. `/interview` 수집 씨앗은 정제 전 임시 원재료다.)
- **Plan**: `## 재활용할 기존 코드` → `## 직접 구현이 필요한 부분` → 테스트 전략. **재활용 조사 결과를 먼저** 적는다(새로 짜기 전 기존부터).
- **domain**: 정체·경계·관계만. 소스 구조(=/init 몫)는 다루지 않는다.

## 최신화 정책 — PRD·Plan은 스냅샷, domain·코드가 현재 진실

- **PRD·Plan은 "그 시점의 결정·설계 기록(스냅샷)"이다. 코드가 바뀌어도 최신화하지 않는다.**
  진실의 출처를 둘로 만들면 반드시 어긋난다(drift). 어긋난 문서는 없느니만 못하다.
- 각 PRD/Plan **첫머리에 상태 필드**를 둔다(읽는 이가 스냅샷임을 즉시 알게):
  `> 상태: 초안 | 확정 | 구현됨 | 폐기 · YYYY-MM (스냅샷 — 최신화 안 함)`
- **재작업은 옛 문서를 고치지 말고** 새 사이클(새 slug의 PRD) 또는 짧은 "변경 이력" 델타로 남긴다.
- **'현재 진실'은 코드+테스트(동작)·`docs/domain/`(구조)에 둔다** — 최신화 노력은 전부 거기로(`/domain`·`/retro`가 유지).
- **가치 차등**: PRD는 코드가 못 담는 **'왜'(문제·범위 밖)**라 얼려두면 가끔 참조 가치가 있다. Plan은 구현되면 비계 — 거의 안 보며, 억지로 보존·최신화하지 않는다(지워도 된다).

## 관례 (반드시 지킬 것)

- **한국어 서술.** 제목·본문·표를 한국어로. 첫머리에 "무엇을/왜"를 한 줄로.
- **[[링크]]로 도메인 지도를 잇는다.** 관련 문서는 `[[slug]]`로 연결하고, 새 도메인 문서를 추가하면 `docs/domain/README.md` 색인에 **한 줄 요약 + 링크**만 더한다(본문은 각 문서가 단일 출처).
- **단일 출처.** 같은 규칙을 여러 문서에 복붙하지 않는다 — 한 곳에 두고 나머지는 가리킨다(drift 방지).
- **상대 날짜 금지.** "다음 주" 같은 표현 대신 절대 날짜(YYYY-MM-DD).
- **모든 산출물은 저장소 안에.** 문서를 `/tmp`나 저장소 밖에 두지 않는다.
