# 개발 흐름 공통 규칙 (flow-rules)

> 여러 스킬·서브에이전트가 **공유**하는 개발 규칙의 **단일 출처**다.
> 전에는 이 규칙들이 `OS.md`·여러 `SKILL.md`에 흩어져 중복됐다 → drift(옛 기준 잔존)의 원인.
> 이제 규칙 상세는 **여기 한 곳**에만 두고, `OS.md`는 이 카드를 가리키는 얇은 청사진으로 둔다.
> (배경·"왜"의 내러티브는 `OS.md`, "지금 지킬 것"은 이 카드.)

## 지킬 것

1. **검토 후 구현 (게이트).** PRD(①)·Plan(②)을 사람이 **승인하기 전에는 구현을 시작하지 않는다.**
   게이트를 임의로 넘지 않는다 — 가장 중요한 안전장치.
2. **테스트는 구현의 일부.** 단위/통합 테스트 없이 "구현 완료"라고 하지 않는다. 구현과 **나란히** 작성한다.
3. **재활용 우선.** 새로 짜기 전에 **기존 코드·스킬·유틸을 먼저 조사**한다. 비슷한 게 있으면 재사용/확장한다.
4. **모든 산출물은 저장소 안에.** PRD·Plan·문서·스킬·훅·컨텍스트는 전부 이 저장소 안에 둔다.
5. **로컬은 가볍게, 외부는 무겁게.** 커밋은 진행하되 **푸시·머지처럼 되돌리기 어려운 일은 사람 확인 후.**

> 코드(app/) 고유 컨벤션은 [backend-conventions.md](./backend-conventions.md).
