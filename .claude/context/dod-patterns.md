# 완료 기준 패턴 — 검증 가능하게 쓰는 법

> **성격**: 판단 룰 (작성·검토 기준). DoD = Definition of Done.
> **변경 주기**: 반기. 새로 유용한 패턴이 나오면 사람이 추가한다.
> **읽는 쪽**: `/spec` (완료 기준 작성), `spec-reviewer` (검증가능성 판정 — 체크리스트 #1)

완료 기준 한 줄의 합격선은 딱 하나다:
**`/verify` 가 그 문장만 보고 "무엇을 / 어떻게 확인할지" 를 알 수 있는가.**
확인 주체와 방법이 안 떠오르면 그 문장은 아직 완료 기준이 아니다.

## 패턴 카탈로그

| 상황 | 템플릿 | 예시 (REQ-001) |
| --- | --- | --- |
| API 응답 | `«입력» → «상태코드» + 응답 바디 «정확한 JSON»` | `POST {"title": ""}` → `400` + `{"error": "title is required"}` |
| 부수효과 없음 | `«거부되는 입력» 직후 «관측» 이 «기대 상태»` | 거부 직후 `GET /posts` 결과가 `[]` |
| 회귀 없음 | `기존 테스트 «N»건이 코드 수정 없이 통과` | 기존 4개 테스트 함수 diff 는 추가만, 전부 통과 |
| 명령 결과 | `«명령» 실행 시 «관측 가능한 출력»` | `cd sandbox/board && python3 -m pytest` → `12 passed` |
| 문서 반영 | `grep «패턴» «파일» 결과가 «수»` | `grep -c "빈 제목" README.md` → `0` |
| 값 보존 | `«입력» → 저장·응답이 «바이트 단위로 동일»` | `"  가  "` → `201`, title 이 `"  가  "` 원본 그대로 |
| 5xx 방지 | `«비정상 입력» 이 «4xx» 이고 500 아님` | `{"title": 123}` → `400`, 500 아님 |

## 안티패턴 — 이렇게 쓰면 반려

- "잘 동작한다", "안정적으로 처리된다", "성능이 개선된다" — 측정 기준 없음
- "적절히 검증한다", "예외를 처리한다" — 무엇을? 어디까지?
- "사용자 경험이 좋아진다" — `/verify` 가 실행 불가

→ 고치는 법: **입력·명령·관측 지점**을 넣어 구체화한다.
"예외를 처리한다" → "`null` 입력 시 `400` + `{"error": "title is required"}`, 저장 안 됨".
