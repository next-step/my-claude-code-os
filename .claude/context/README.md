# 개인 컨텍스트 계층 (`.claude/context/`)

ATDD OS는 "이 프로젝트를 어떻게 만들지"에 대한 지침이고, 이 디렉터리는 그와 별개로 **"나(사용자)는 평소 어떻게 일하고 싶은지"**에 대한 지침을 담는다. 예: 코드 리뷰 시 우선순위, 커밋 메시지 톤, 설명을 받을 때 선호하는 깊이 등 — 특정 기능이 아니라 세션마다 반복해서 알려주고 싶은 것들.

## 왜 이런 계층이 필요한가

Claude Code는 세션을 열 때 루트 `CLAUDE.md`를 항상 읽는다. `CLAUDE.md`에 `@경로`를 적으면 그 파일도 재귀적으로(최대 5단계) 함께 불러온다. 지침이 한두 줄이면 `CLAUDE.md`에 바로 적어도 되지만, 여러 주제로 늘어나면:

- `CLAUDE.md`가 계속 길어지고, 주제가 섞여 찾기 어려워진다.
- 지침을 추가/수정할 때마다 프로젝트의 "얼굴"인 루트 파일을 매번 건드리게 된다.

그래서 `.claude/context/index.md`를 중간에 하나 둔다. 루트 `CLAUDE.md`는 `index.md` 하나만 가리키고, `index.md`가 실제 지침 파일들을 하나씩 가리킨다. `atdd-status` 스킬이 `failure-ledger`의 데이터를 직접 나열하지 않고 "가서 보라"고만 안내하는 것과 같은 습관이다 — **얇은 인터페이스, 자라나는 상세**.

## 새 지침 파일 추가 방법

1. `.claude/context/`에 새 `.md` 파일을 만든다 (예: `communication-style.md`).
2. `.claude/context/index.md`에 `@communication-style.md` 한 줄을 추가한다. **경로는 `index.md` 기준 상대 경로**이므로 같은 디렉터리에 있는 파일은 이름만 적는다 — 루트 기준으로 `@.claude/context/…`라고 쓰면 이중 중첩돼 경고 없이 조용히 로드되지 않는다.
3. **새 세션을 열어야 반영이 확인된다** — `@import`는 세션 시작 시에만 해석되므로, 진행 중인 세션에서는 새 파일이 로드되지 않는다.
4. 실제로 로드됐는지는 `.claude/skills/context-map` 스킬로 확인할 수 있다.

## 지켜야 할 것

- **내용을 지어내지 않는다.** 이 디렉터리는 사용자 본인의 실제 선호·규칙만 담는다. AI가 "이럴 것 같다"고 추측한 내용을 미리 채워 넣지 않는다.
- **5단계 재귀 제한**을 유념한다. 현재 깊이는 `CLAUDE.md`(1) → `index.md`(2) → 지침 파일(3)이라 여유가 있지만, 지침 파일이 또 다른 파일을 `@import`하는 중첩은 되도록 피한다.
- **존재하지 않는 파일을 가리키는 `@import`를 만들지 않는다.** `index.md`에 줄을 추가하는 시점과 실제 파일을 만드는 시점을 같이 가져간다.

## 커밋 여부

이 디렉터리의 파일들은 **커밋한다** (사용자 확정, 2026-09-02). 이 저장소는 클로드 OS 만들기 실습을 투명하게 기록하는 것이 목적이라, 다른 모든 것(스킬, 훅, `OS.md`의 설계 이력)과 마찬가지로 개인 지침도 기록에 남긴다. 대신 회사 내부 프로세스명, 민감한 용어처럼 공개하기 어려운 내용은 애초에 이 파일에 적지 않고, 필요하면 더 일반적인 표현으로 바꿔 적는다.

## 이 계층이 하지 않는 것

- **ATDD 파이프라인 지침이 아니다.** 그건 `OS.md`와 `.claude/skills/atdd-orchestrator/` 쪽 몫이다.
- **세션 간 상태 저장소가 아니다.** "지금 몇 단계까지 진행했는지" 같은 휘발성 상태는 여기 담지 않는다 (`OS.md` §7의 별도 열린 질문).
- **외부 문서(Confluence 등)의 캐시가 아니다.** 이번 범위에서 다루지 않는다.
