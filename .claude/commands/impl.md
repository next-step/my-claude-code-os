`$ARGUMENTS`는 작업 폴더(`$DIR`)다. `<프로젝트>/tasks/NNN-작업명` 형태라는 전제에서 프로젝트 루트(`$PROJECT`)를 도출한다.

## 원칙

- **spec.md가 유일한 요구사항 소스다.** `request.md`나 대화 기록이 spec과 다르면 spec을 따른다. spec 내부에서 모순을 발견하면 멈추고 보고한다.
- **진행 상태는 테스트 실행 결과다.** 어떤 정책이 남았는지를 장부나 기억이 아니라 테스트를 실제로 돌려서 판단한다.
- **테스트 파일은 수정하지 않는다.** 테스트가 잘못됐다고 판단되면 구현을 멈추고 보고한다 — 테스트를 고치고 싶다는 것은 스펙 변경 신호다.
- **정책 밖의 개선은 하지 않는다.** spec에 없는 추가 기능이나 이번 작업과 무관한 파일 정리를 임의로 하지 않는다. 유일한 예외는 3단계의 Refactor다 — 이번 작업에서 만진 코드를, 테스트 초록을 유지하는 조건으로, 닫힌 체크리스트 항목만 정리한다.

## 실행 순서

### 1단계: 게이트

1. `$DIR/spec.md`를 읽는다. 없으면 "해당 폴더에 spec.md가 없습니다. 먼저 /spec으로 작성하세요."라고 출력하고 종료한다.
2. **승인 게이트:** `status: approved`가 아니면(필드가 없거나 `draft`인 경우 포함) "spec.md가 아직 승인되지 않았습니다 (status: {값})."라고 출력하고 종료한다. 본문에 `결정 필요(미결정)` 항목이 남아 있으면 status와 무관하게 멈추고, 어떤 결정이 필요한지 나열한 뒤 종료한다.
3. **테스트 게이트:** `$DIR/test-plan.md`가 없으면 "테스트가 없습니다. /test를 먼저 실행하세요."라고 출력하고 종료한다.
4. **실패 원장 확인:** `$PROJECT/docs/failures.md`가 있으면 이 작업의 정책 ID가 등장하는 항목을 읽고, 거기 기록된 접근·원인을 이번 구현에서 반복하지 않는다.

### 2단계: 측정

test-plan.md에 매핑된 테스트 전체를 실행한다. **실패 테스트 목록이 곧 남은 작업이다.**

- 전부 통과하면 "모든 정책이 이미 충족되어 있습니다"를 5단계 체크리스트와 함께 보고하고 종료한다.

### 3단계: TDD 루프 (Green → Refactor)

실패 테스트를 정책 단위로 묶어 하나씩 처리한다:

1. **Green** — 한 정책의 실패 테스트들을 통과시키는 **최소한의 구현**을 한다.
2. 전체 테스트를 다시 실행한다. 새로 깨진 테스트(회귀)가 있으면 다음으로 넘어가기 전에 즉시 복구한다.
3. **Refactor** — 초록 상태에서, **이번 작업에서 생성·수정한 코드만** 대상으로 아래 닫힌 체크리스트 5항목만 점검·정리한다. 체크리스트 밖의 정리, 이번 작업 diff 밖의 파일은 건드리지 않는다 — 작성자가 못 보는 사각지대를 찾는 것은 impl-review의 몫이다.
   1. 중복 — 같은 로직이 2회 이상 나타나면 합친다
   2. 이름-도메인 정합 — spec 정책의 용어가 함수·변수 이름에 그대로 보이는가
   3. 죽은 코드 — 어떤 테스트도 거치지 않는 코드는 지운다
   4. 매직 넘버 — 정책에서 온 수치는 명명된 상수로
   5. 크기 — 함수 하나가 정책 하나에 대응하는 크기를 넘지 않는가
4. Refactor 후 전체 테스트를 다시 실행한다. 깨지면 그 정리를 되돌린다.
5. 남은 실패가 없을 때까지 1~4를 반복한다.

### 4단계: 막힘 처리 — 실패 원장 기록

다음 상황이면 구현을 멈추고, `$PROJECT/docs/failures.md`에 원장 항목(파일 머리의 양식·원인 분류를 따른다)을 추가한 뒤 보고하고 종료한다:

- spec 내부의 모순, 또는 정책과 테스트의 불일치를 발견했다 (테스트를 고쳐야만 통과 가능한 상태)
- 정책이 미구현 상태의 다른 정책이나 외부 요인에 의존해 단독으로 충족될 수 없다
- 같은 테스트가 3회 시도에도 통과하지 못한다

원장 파일이 없으면 양식 머리(항목 양식, 원인 분류, 소비자 설명)와 함께 생성한다.

### 5단계: 정책 체크리스트 보고

구현을 마치면 정책 각 항목을 ID별 체크리스트로 보고한다.

**출력 형식:**

```
정책 검증
──────────────────────────────
[x] P-002-1 <규칙 문장>
      → 테스트: test_P002_1_priority_saved 외 2개 통과
[x] P-002-2 <규칙 문장>
      → 테스트: test_P002_2_... 통과
...
──────────────────────────────
충족: N/M · 테스트: {통과}/{전체}
```

충족하지 못한 항목은 `[ ]`로 표시하고 원장에 기록한 사유를 한 줄로 요약한다.
