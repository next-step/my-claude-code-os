# ralph-loop

같은 작업을 **매번 새 서브 에이전트**에게 시켜, 측정 지표가 목표에 닿을 때까지 반복한다. (Geoffrey Huntley의 "Ralph" 기법)

세 가지 원칙:
- **무상태 반복** — 각 반복은 독립 컨텍스트에서 시작한다. 진행 상태는 오직 코드베이스의 실제 상태와 지표 측정값으로만 판단한다.
- **파일이 메모리** — 지식은 대화가 아니라 파일에 쌓는다. 두 층이다: **실행 내 노트**(`notes.md`, 반복끼리 주고받는 스크래치패드)와 **실행 간 교훈**(`LESSONS.md`, 모든 랄프 실행이 공유). 서브 에이전트는 둘 다 읽고, 실행이 끝나면 회고가 `LESSONS.md`에 교훈을 남긴다.
- **지표가 종료를 결정** — 사람의 감이 아니라 실행 가능한 측정 명령이 루프를 멈춘다.

## 실행 방법

```
/ralph-loop --goal "<완료 상태>" --metric "<진척도를 정수 하나로 출력하는 셸 명령>"
```

예시 (Jest → Vitest):
```
/ralph-loop --goal "All tests migrated to Vitest" \
  --metric "grep -rl \"from 'jest'\\|jest.mock\\|@jest/globals\" src test 2>/dev/null | wc -l"
```

| 파라미터 | 기본값 | 설명 |
|----------|--------|------|
| `--goal` | (필수) | 완료 상태를 한 문장으로. 서브 에이전트에 매번 그대로 주입된다. |
| `--metric` | (필수) | 진척도를 **정수 하나만** 표준출력하는 셸 명령. |
| `--target` | `0` | 목표 지표값. 초기값이 target보다 크면 감소형(값이 내려가면 진척), 작으면 증가형. |
| `--max-iterations` | `30` | 최대 반복. 무한 루프 하드 스톱. |
| `--stall-limit` | `3` | 지표가 개선 안 되는 연속 반복 허용 횟수. 초과 시 사람에게 넘긴다. |

인수가 없으면 `AskUserQuestion`으로 `--goal`, `--metric`을 채운다.

## 준비

1. 파라미터를 확정한다. `$GOAL`, `$METRIC`, `$TARGET`, `$MAX`, `$STALL`.
2. 실행 노트 경로를 정한다: `.claude/workspace/ralph/<goal-slug>/notes.md`. 없으면 아래 골격으로 생성한다.
   ```markdown
   # Ralph Loop 노트 — {GOAL}
   ## 규칙/패턴 (효과 있던 접근)
   ## 막다른 길 (피할 것)
   ## 남은 작업 후보
   ```
   교훈 파일 `.claude/workspace/ralph/LESSONS.md`(모든 랄프 실행이 공유)도 확인하고 없으면 빈 파일로 만든다. 여기 담긴 과거 실행들의 기술 교훈을 이번 실행 내내 서브 에이전트가 참고한다.
3. `git status --short`로 시작 상태를 확인한다. 작업트리가 지저분하면 커밋 후 시작을 권한다(랄프는 매 반복 코드를 고친다).
4. `$METRIC`을 실행해 베이스라인을 얻는다. 명령이 실패하거나 숫자가 아니면 중단하고 원본 출력을 보여준다.
5. 시작 요약 출력: `🔁 목표 / 지표 / 베이스라인 → target ({감소형|증가형}) / 안전장치 max·stall`.

## 루프

`정체=0`, `직전값=베이스라인`으로 시작해 반복한다.

**A. 완료 판정** — 현재값이 target 조건을 만족하면 → 완료. `반복 > $MAX`이면 → 한계 도달.

**B. 한 단위 작업** — 아래 격리 규칙을 지켜 서브 에이전트를 실행한다:
- **매번 새 `Agent` 호출** (`subagent_type: general-purpose`, `run_in_background: false`). 이전 반복 에이전트를 `SendMessage`로 잇지 않는다.
- 프롬프트에 **대화 이력이나 이전 보고서를 넣지 않는다.** 유일한 가변 정보는 `{현재값}`뿐. 나머지는 글자 그대로 고정한다. (반복 간 지식은 서브 에이전트가 노트 파일을 직접 읽어 얻는다.)

  ```
  당신은 큰 목표를 향해 점진적으로 일하는 작업자다. 이번 턴엔 딱 한 단위만 처리한다.

  ## 목표
  {GOAL}

  ## 진척 측정
  아래 출력이 {TARGET}이 되면 완료. 현재는 {현재값}.
      {METRIC}

  ## 절차
  1. 교훈 파일 `.claude/workspace/ralph/LESSONS.md`와 이번 실행 노트 `{노트경로}`를 먼저 읽어,
     과거 실행들의 기술 교훈과 이번 실행에서 밝혀진 규칙·막다른 길을 파악한다.
  2. 코드베이스를 조사해, 목표까지 남은 작업 중 가장 작고 독립적인 단위 하나를 고른다.
     (노트의 "막다른 길"에 있는 접근은 반복하지 마라.)
  3. 그 단위 하나만 완결적으로 처리하고, 관련 테스트/타입체크/린트를 실제로 실행해 검증한다.
     반쯤 고친 상태로 두지 마라.
  4. 노트 파일에 이번에 배운 것을 append한다: 효과 있던 패턴은 "규칙/패턴"에,
     안 되는 접근은 "막다른 길"에, 발견한 남은 작업은 "남은 작업 후보"에.

  ## 제약
  목표와 무관한 리팩터링·포맷팅·파일 수정 금지. 확신 없는 큰 결정은 하지 말고
  처리한 것과 남은 것을 보고하며 끝내라.
  ```

**C. 재측정 및 판정** — `$METRIC`을 다시 실행해 `현재값`을 얻는다.
- 진척 있음 → `정체=0`.
- 진척 없음/후퇴 → `정체+=1`. 후퇴면 `git diff`로 확인하고 명백히 잘못됐으면 되돌린다. `정체 >= $STALL`이면 → 정체 중단.
- 한 줄 로그: `[#n] {직전값} → {현재값} ({▼진척|─정체 정체/$STALL}) · {처리 요약}`.
- `직전값=현재값`, `반복+=1` 후 A로.

## 종료

- **완료** — `$METRIC`을 마지막으로 재확인한 값과 함께 `✅ {baseline}→{target} ({n}회)` 출력. `/git-commit` 제안(자동 커밋 안 함).
- **한계 도달** — 현재값·남은 양과 노트의 "남은 작업 후보"를 보여주고, `--max-iterations`를 늘려 재실행할지 묻는다.
- **정체 중단** — `⚠️ {현재값}에 고착`. 노트의 "막다른 길"과 마지막 diff를 근거로 사람이 개입할 지점을 짚어준다.

**회고 (종료 사유와 무관하게 항상 실행)** — 결과 요약을 낸 뒤, 마지막으로 **새 독립 서브 에이전트**(`general-purpose`, `run_in_background: false`)를 띄워 이번 실행을 회고시킨다. 프롬프트:
```
이번 랄프 루프의 행위를 검토해 다음 실행에 쓸 기술 교훈을 뽑아라.
- 맥락: 목표 "{GOAL}" / 결과 {완료|한계|정체}, 지표 {baseline}→{현재값}
- 근거: 실행 노트 `{노트경로}`와 `git diff`(또는 커밋 로그)를 읽어라.
- 판단: 이 코드베이스에만 국한되지 않고 "다음 랄프 루프에 도움이 될" 교훈만 골라,
  기술적으로 한두 문장으로 압축해 `.claude/workspace/ralph/LESSONS.md`에 append하라.
  기존 교훈과 중복되면 새로 쓰지 말고 넘어가라. 없으면 아무것도 쓰지 마라.
```

## 노트

- **왜 두 층의 파일인가**: 서브 에이전트는 무상태라 매번 백지에서 시작하지만, 같은 실수를 반복하면 낭비다. `notes.md`는 한 실행 안에서, `LESSONS.md`는 실행을 거듭하며 교훈을 대화 오염 없이 전달한다 — 컨텍스트는 깨끗하게, 지식은 누적되게. 랄프 루프를 돌릴수록 `LESSONS.md`가 두꺼워져 다음 실행이 더 빨라진다.
- **지표가 성패를 가른다**: 실행 가능하고, 진척에 단조롭게 반응하며, 위조 불가능한 값을 골라야 한다.
