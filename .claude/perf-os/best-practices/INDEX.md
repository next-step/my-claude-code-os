## 이 파일을 읽는 법

**이 디렉터리는 `perf-bp-curator` 에이전트가 단독으로 관리한다.**

| 규칙 | 이유 |
|---|---|
| 스킬은 이 경로를 모른다 | 경로가 두 곳에 적히는 순간 캡슐화가 무너진다 (OS.md §5 R3) |
| 사례는 **파일 추가가 아니라 병합** | 케이스마다 파일을 늘리면 1년 뒤 50개가 되고, 그러면 아무도 안 읽는다 |
| 틀린 항목은 **수정하거나 삭제**한다 | 축적은 추가만이 아니다. 모순된 조언이 공존하면 저장소 신뢰가 0이 된다 |
| 게이트 ④ 승인 전에는 쓰지 않는다 | 틀린 교훈이 영구 축적되면 다음 사이클을 오염시킨다 |

읽는 쪽(Stage 2 Lane B)과 쓰는 쪽(Stage 6)이 서로 다른 스킬에 있으므로, 이 디렉터리는 **어느 스킬의 소유물도 아니다.**

## 2단 로딩

전량은 큐레이터 안에서 소멸한다. 메인 컨텍스트에는 **발췌만** 올라온다.

```
INDEX.md (여기)  →  관련 패턴 파일만 펼침  →  발췌  →  Lane B
       └─────────── perf-bp-curator 내부 ───────────┘
```

파일이 50개가 되어도 메인은 영향받지 않는다. 이것이 "쌓이기만 하는 지식은 소음이다"를 막는 장치다.

## 발췌는 Lane B에만 간다

Lane A(일반 원리)와 Lane C(실측)에는 주지 않는다. 셋 모두에게 주면 축적된 지식이 세 레인에 동시에 확증 편향을 걸어, "서로 다른 출발점 3개"라는 3-lane의 존재 이유가 사라진다.

**무엇을 공유하지 않을지도 공유 설계의 일부다.**
