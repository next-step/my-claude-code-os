## 1. 결론

V502는 여러 개선을 한 번에 넣지 않는다. 후보 하나마다 `V501 + 후보 1개`를 만들어 같은 입력으로
비교한다. 후보가 맞힌 상품보다 새로 틀린 상품이 많거나, `MALE↔FEMALE` 직접 오류를 늘리면
버린다.

우선 검증 순서는 다음과 같다.

1. GT의 `UNISEX`와 `UNDETERMINED` 의미를 고정한다.
2. 최신 원문 입력으로 V501 기준선을 다시 만든다.
3. 상세 텍스트의 공통·브랜드 문맥 오염을 제거한다.
4. 썸네일과 상세 착장 모델을 이미지 단위 관찰값으로 합친다.
5. 의류 옵션·사이즈표는 판정하지 않는 shadow 신호부터 검증한다.
6. 카테고리, 브랜드 포지셔닝, 디자인·스타일은 별도 실험으로 남긴다.

## 2. 공통 실험 계약

### 2.1 데이터 세트의 역할

| 세트 | 역할 | 사용 방법 |
| --- | --- | --- |
| 현재 의류 260개 | 이미 여러 번 본 회귀·challenge 세트 | 알려진 오류가 다시 생기는지 확인한다. 최종 일반화 점수로 사용하지 않는다. |
| 과거 CORE AI 오답 | legacy recovery 세트 | 과거 오답을 몇 개 고쳤는지 측정한다. |
| 신규 시점 의류 표본 | 봉인 holdout | 정책을 고정한 뒤 한 번만 열어 실제 일반화 성능을 확인한다. |

현재 260개는 결과와 개별 사례를 이미 살펴봤기 때문에 시험 전에 답을 본 문제집과 같다. 최종
승격에는 이후 시점에서 무작위로 뽑고 독립 검수한 의류 표본이 필요하다.

### 2.2 모든 후보가 통과해야 하는 기준

1. **독립 효과**: 한 실험에는 정책 변화 하나만 넣는다.
2. **회귀 방지**: 현재 260개에서 이전 정답을 새로 깨는 회귀가 0건이어야 한다.
3. **고위험 오류 방지**: `MALE↔FEMALE` 직접 오류가 V501보다 늘면 탈락한다.
4. **라벨별 안전성**: 자동 적용하는 각 라벨 precision이 95% 미만이면 shadow로만 남긴다.
5. **UNISEX 과분류 방지**: `MALE/FEMALE → UNISEX` 회귀가 늘면 탈락한다.
6. **미판정 은폐 금지**: 정확도를 높이기 위해 전부 `UNDETERMINED`로 보내지 않았는지 보류율을
   함께 비교한다.
7. **새 holdout 확인**: 새 표본의 paired 결과가 개선 방향이어야 한다. 우연인지 판단하기 어려운
   1건 차이면 승격하지 않고 표본을 더 모은다.
8. **재현 가능성**: GT, 상품 입력, 이미지 집합, 프롬프트, 모델, reducer의 버전과 해시를 남긴다.
9. **기권→오답 확정 방지**: `UNDETERMINED`를 바꾼 건은 기존 정답 회귀로 잡히지 않으므로, 새로
   확정한 값 자체의 precision을 별도로 계산한다. 95% 미만이면 strict accuracy가 올라도 탈락한다.

결과 표에는 최소한 다음 숫자를 함께 싣는다.

- strict accuracy와 macro F1
- 라벨별 precision/recall
- `MALE↔FEMALE` 직접 오류 수
- `MALE/FEMALE → UNISEX` 오류 수
- `UNDETERMINED` 비율
- V501 대비 개선 상품과 회귀 상품 ID
- 결정 출처별 precision과 적용 건수

## 3. E1 — 상세 텍스트 문맥 오염 제거

### 가설

명시적인 대상 성별 문구는 유효하지만, 브랜드 소개·공통 변환표·정책 설명 문구를 같은 강도로
사용하면 `UNISEX`가 과도하게 늘어난다.

현재 확인된 반례는 다음과 같다.

- `6624759`: `DiiFF UNISEX BRAND`는 상품 대상 문구가 아니라 브랜드 설명이다.
- `6005556`: 남녀 공통 변환표는 해당 상품이 공용이라는 뜻이 아닐 수 있다.
- 저장 근거의 `남녀 사이즈가 별도로 안내되면 UNISEX 근거로 볼 수 있습니다.`는 상품 문구가
  아니라 설명·정책 문장이다.

### 후보 변경

HTML 전체를 한 문자열로 합쳐 키워드만 찾지 않는다. 먼저 DOM 블록 또는 문장 단위로 다음 관찰값을
만든다.

```text
matchedText: "남녀공용"
context: "본 상품은 남녀공용으로 출시되었습니다"
contextType: PRODUCT_TARGET | PRODUCT_SIZE | MODEL_PROFILE |
             BRAND_DESCRIPTION | GENERIC_GUIDE | POLICY_TEXT | UNKNOWN
productLinked: true | false
```

판정에 사용하는 것은 다음 두 종류로 제한한다.

- `PRODUCT_TARGET`: 본 상품·제품·스타일을 직접 수식하는 `남녀공용/여성용/남성용`
- `PRODUCT_SIZE`: 대상 상품의 실제 선택 옵션 또는 상품 전용 사이즈표

다음은 기권시킨다.

- `UNISEX BRAND`, 브랜드 소개, 캠페인 슬로건
- 사이트 공통 사이즈 변환표
- 남성/여성 모델의 키·몸무게·착용 사이즈
- 정책 설명, 배송, 리뷰, 고객센터, 추천 상품 문구
- 문맥을 판별할 수 없는 고립된 키워드

남성과 여성 단어가 각각 존재한다는 이유만으로 `UNISEX`로 만들지 않는다. 같은 상품 대상 문장이나
같은 상품 전용 사이즈표 안에서 둘이 연결된 경우에만 공용 근거로 인정한다.

### 넣지 않을 것

- 공용 키워드 사전을 무작정 확장하지 않는다.
- `오버핏`, `루즈핏`, `여성스러운` 같은 스타일 문구를 명시 성별로 승격하지 않는다.
- 브랜드 설명 문구를 상품 성별 근거로 사용하지 않는다.

### 실험과 통과 기준

1. 현재 의류 260개 중 Verbatim이 있는 132개를 전부 추출한다.
2. 키워드가 검출된 모든 문장을 사람이 `상품 대상/공통 문구/모델 정보/판단 불가`로 검수한다.
3. 기존 추출기와 문맥 추출기의 source precision과 coverage를 비교한다.
4. 알려진 참인 문구(`엘라모의 모든 제품은 남녀공용`, 상품 전용 남녀 사이즈)는 유지해야 한다.
5. `UNISEX BRAND`와 공통 변환표를 이유로 발생한 단성→공용 회귀는 0건이어야 한다.
6. validation에서 `DETAIL_TEXT` precision 95% 미만이면 자동 판정에 사용하지 않는다.

## 4. E2 — 썸네일과 상세 착장 모델 결합

### 가설

상세 이미지의 최종 라벨이 썸네일을 덮어쓰는 방식보다, 두 출처의 **대상 상품 착장 모델 관찰값**을
합치는 방식이 쓰레드의 검수 기준에 가깝다.

### 후보 변경

상세 모델에게 최종 `productGender` 하나만 받지 않고 다음 관찰값을 받는다.

```text
imageId
role: WORN_TARGET | MANNEQUIN_TARGET | PRODUCT_ONLY | IRRELEVANT | UNCLEAR
observedModelGender: MALE | FEMALE | PERSON_UNCLEAR | NONE
productLinked: true | false
confidence: HIGH | MEDIUM | LOW | NONE
```

그 뒤 reducer가 썸네일과 상세의 `WORN_TARGET && productLinked`만 합친다.

| 합쳐진 착장 모델 | 이미지 신호 |
| --- | --- |
| 남성만 있음 | `MALE` 후보 |
| 여성만 있음 | `FEMALE` 후보 |
| 남성과 여성 모두 있음 | `UNISEX` 후보 |
| 불명확 모델만 있음 | 기권 |
| 상품 컷만 있음 | 기권 |

이미지 신호는 상품명, 상품 대상 명시 문구, 확정적인 상품 구조보다 뒤에 둔다. `PRODUCT_ONLY`는
“공용”이 아니라 “모델 근거 없음”이다.

### 넣지 않을 것

- 기존 상세 최종 라벨과 썸네일 최종 라벨을 그대로 합치지 않는다.
- 코디 예시, 브랜드 캠페인 모델, 리뷰 작성자를 착장 모델에 포함하지 않는다.
- 저신뢰 남성 1장과 저신뢰 여성 1장이 있다는 이유만으로 공용을 확정하지 않는다.

### 실험과 통과 기준

1. 공통 브랜드 이미지 오류로 확인된 상품과 V500↔V501 변경 20개를 진단 세트로 사용한다.
2. 여기에 무작위 정답 상품을 추가해 특정 오류에만 맞춘 규칙이 되지 않게 한다.
3. 사람이 이미지별 `role/productLinked/modelGender`를 검수한 작은 정답지를 먼저 만든다.
4. 이미지 역할 분류 precision이 95% 미만이면 상품 reducer 실험으로 넘어가지 않는다.
5. V501 대비 개선 건수가 회귀보다 많고 `MALE↔FEMALE` 오류가 늘지 않아야 한다.
6. 상세 결과가 있는 상품뿐 아니라 상세 결과가 없는 상품의 판정이 그대로인지 확인한다.

## 5. E3 — UNISEX와 UNDETERMINED 계약 고정

### 문제

쓰레드에는 “애매하면 UNISEX”라는 표현이 있지만, 현재 도메인은 다음처럼 구분한다.

- `UNISEX`: 남녀공용이라는 적극적인 근거가 있음
- `UNDETERMINED`: 근거가 없거나 충돌해서 판단할 수 없음

두 의미를 섞으면 근거 없는 상품이 공용으로 부풀 수 있다.

### 후보 계약

```text
UNISEX
- 남녀공용/유니섹스라는 상품 대상 명시 문구
- 대상 상품 전용 남녀 사이즈 또는 옵션
- 대상 상품을 착용한 남성과 여성 모델이 모두 확인됨
- 정책으로 확정된 공용 상품 구조

UNDETERMINED
- 사람이나 명시 문구가 없음
- 상품 컷만 있고 전용 성별 구조가 없음
- 근거끼리 충돌함
- 디자인/스타일만으로 확신할 수 없음
```

검색이나 서빙에서 `UNDETERMINED` 상품을 양쪽 고객에게 보여야 한다면, 추론값을 `UNISEX`로
바꾸지 않고 별도의 노출 기본값으로 처리한다.

### 검증과 통과 기준

1. `7022989`를 포함한 애매 사례와 no-person 상품을 30개 이상 모은다.
2. 두 명 이상이 위 계약만 보고 독립적으로 라벨링한다.
3. 검수자 합의율이 85% 미만이면 문장을 보강하고 다시 검수한다.
4. 끝까지 합의되지 않는 상품은 `AMBIGUOUS` 검수 상태로 평가 분모에서 분리한다.
5. 이 계약이 승인되기 전에는 “애매하면 UNISEX” 규칙을 코드에 넣지 않는다.

## 6. E4 — 의류 옵션·사이즈표

### 2026-08-25 shadow 결과

- 공개 PDP 260개 요청 중 256개를 수집했고 4개 글로벌 전용 상품은 국내 API에서 제외됐다.
- 214개 상품에 상품 전용 실측표가 있었다.
- 옵션명·옵션값·실측표 안의 직접 성별 명시는 0건이었다.
- `실측 종류`와 `alpha size 조합`을 calibration에서 학습했을 때 표본 30개 이상·precision 99%
  조건을 만족한 규칙은 0개였다.
- `S|M` 조합은 calibration 11/11, validation+holdout 7/7이 여성으로 보였지만 모든 상품을 V501이
  이미 맞혔다. 표본도 작고 오답 개선이 0건이므로 자동 규칙으로 만들지 않는다.
- 플랫폼/파트너 등록 성별로 `UNDETERMINED`만 채우면 strict 정답이 223→225로 늘지만, 새 확정 5건
  중 3건은 잘못된 단일 성별이었다. 적용 precision 40%이므로 탈락시킨다.

따라서 현재 표본에서는 E4를 V502 자동 판정에 추가하지 않는다. 이후 29CM 원본 옵션을 수집하더라도
동일하게 직접 명시만 먼저 shadow 측정하고, 단순 사이즈 범위는 판정에 사용하지 않는다.

### 가설

모델이 없는 상품에서는 실제 판매 옵션과 상품 전용 실측표가 보조 근거가 될 수 있다. 하지만
`S/M/L/XL`, `FREE`, `100`처럼 단일 값만 보면 브랜드와 카테고리마다 의미가 달라 오히려 해롭다.

### 1단계: shadow 관찰값

처음에는 최종 판정에 사용하지 않고 다음 값만 저장한다.

```text
rawOptions
normalizedSizeSystem: KR_TOP | KR_BOTTOM | ALPHA | MEASUREMENT | UNKNOWN
productSpecificSizeTable: true | false
observedRange
candidateGender: MALE | FEMALE | UNISEX | NONE
reason
```

### 제한적인 후보 규칙

- 전체 등록 옵션을 사용하고 현재 재고만 사용하지 않는다.
- `S/M/L/XL`, `FREE`, 단일 숫자는 판정하지 않는다.
- 상의·하의·속옷 등 세부 카테고리별로 다른 size system을 적용한다.
- 상품 전용 표라는 연결이 확인된 실측값만 사용한다.
- 남녀 범위가 함께 있는 상품 전용 옵션/표는 공용 후보가 될 수 있다.
- `XL/2XL + 박시한 디자인`만으로 남성이라고 하지 않는다.

### 실험과 통과 기준

1. 현재 260개와 신규 표본의 등록 옵션·상품 전용 사이즈표를 수집한다.
2. 먼저 `정답을 보지 않고` size system과 candidate만 생성한다.
3. category×size-system별 적용 건수와 precision을 계산한다.
4. 표본이 30개 미만인 규칙은 자동 판정으로 승격하지 않는다.
5. precision 95% 미만인 규칙은 삭제하거나 review reason으로만 남긴다.
6. `7022989`처럼 검수자도 공용 가능성을 인정한 사례는 규칙 성공 사례로 세지 않는다.

## 7. E5 — 카테고리 기반 성별

### 가설

비키니, 여성용 속옷, 남성 드로즈처럼 상품 종류 자체가 성별을 포함하는 일부 leaf category는
이미지보다 안정적일 수 있다.

### 후보 변경

표준 카테고리의 leaf ID를 사용하는 allowlist를 만든다. 자연어 카테고리명 부분 일치나 LLM의
자유 추측은 사용하지 않는다.

카테고리 후보는 세 등급으로 관리한다.

- `DETERMINISTIC`: 반대 사례가 정책상 허용되지 않는 전용 카테고리
- `SUPPORTING`: 강한 보조 신호지만 단독 판정 금지
- `NO_SIGNAL`: 일반 티셔츠, 볼캡, 백팩처럼 카테고리만으로 판정 금지

### 실험과 통과 기준

1. D/O 후보 카테고리별로 현재 GT와 최근 운영 상품을 표본 추출한다.
2. 반대 성별 또는 공용으로 정상 판매되는 반례가 있는지 먼저 찾는다.
3. 반례가 하나라도 정상 사례라면 `DETERMINISTIC`에 넣지 않는다.
4. 표본 30개 미만 또는 precision 99% 미만인 카테고리는 보조 신호로만 둔다.
5. 카테고리 규칙 적용 범위 밖의 상품 결과가 완전히 같은지 확인한다.

## 8. E6 — 브랜드 포지셔닝·파트너 등록 성별·디자인 스타일

이 세 신호는 바로 판정 규칙으로 추가하지 않는다.

### 브랜드 포지셔닝

- 브랜드 전체를 한 성별로 하드코딩하면 공용 상품이나 캡슐 컬렉션을 틀릴 수 있다.
- 사용하려면 `브랜드×카테고리×유효기간×근거 출처`를 가진 버전 데이터가 필요하다.
- 초기에는 `BRAND_SUPPORTING_SIGNAL`로만 저장하고 최종 판정을 바꾸지 않는다.

### 파트너 등록 성별

- GT와 사실상 같은 원천이거나 셀러 오입력이면 평가 누수·오류 전파가 생긴다.
- 원천과 GT 생성 경로가 독립인지 먼저 확인한다.
- 초기에는 모델 결과와 충돌할 때 재검수 큐를 만드는 용도로만 사용한다.

### 디자인·스타일

- `박시함`, `어깨가 넓음`, `여성적인 실루엣`은 사람마다 판단이 다르다.
- 7022989처럼 단일 정답 합의가 어려운 사례를 만들 수 있다.
- 명시적인 상품 구조와 분리해 `STYLE_HEURISTIC`으로 기록하고 자동 판정에는 사용하지 않는다.

이 세 신호는 신규 holdout에서 독립적으로 precision 95% 이상을 보이기 전까지 V502 범위에서
제외한다.

## 9. E7 — GT 모호성 및 재검수 계약

GT 한 칸에 단일 라벨만 있으면 7022989처럼 `MALE`과 `UNISEX`가 모두 합리적인 상품도 무조건
오답 하나를 만든다.

검수 결과에 다음 상태를 추가한다.

```text
label: MALE | FEMALE | UNISEX | UNDETERMINED
reviewStatus: CLEAR | AMBIGUOUS | POLICY_CONFLICT
acceptableLabels: [MALE, UNISEX]
policyVersion
reviewEvidence
reviewerCount
```

- `CLEAR`만 strict accuracy의 주 분모로 사용한다.
- `AMBIGUOUS`는 별도 일치율로 보고하고 튜닝 근거에서 제외한다.
- `POLICY_CONFLICT`는 라벨 수정 대신 정책 결정 큐에 넣는다.
- 기존 GT는 자동으로 덮어쓰지 않고 변경 전후와 검수자를 남긴다.

## 10. E8 — fresh V501 기준선

현재 V501 비교 리포트는 최신 V101 썸네일과 저장된 V500 상세 근거를 조합한 replay다. V502 후보를
비교하기 전에 다음 입력을 같은 시점으로 다시 고정해야 한다.

- 상품명과 표준 카테고리
- 품절 포함 전체 등록 옵션
- 최신 상세 HTML과 추출된 text block
- 최신 상세 이미지 URL 집합
- V101 썸네일 이미지별 결과
- GT snapshot

동일한 frozen input으로 다음을 모두 계산한다.

```text
V501-fresh
V501 + E1
V501 + E2
V501 + E4-shadow
V501 + E5
```

V500 상세 결과를 재사용한 replay는 역사 비교용으로 보존하되 V501-fresh와 섞지 않는다.

### 2026-08-25 부분 fresh 결과

- 최신 공개 상세 이미지: 60개 상품, 987개 타일 수집, 공통 자산 제거 후 938개 타일 입력
- 상세 모델: `google/gemini-3.1-flash-lite`
- 상세 프롬프트: `product-gender-detail-resolution-v500-gender-evidence-contact-sheet-v7`
- 상세 호출: 60/60 성공
- V501 폴드: 211/236(89.41%), macro F1 87.19%
- 최신 상세가 실제 최종 준거가 된 40건: 23/40(57.50%)
- 단일 성별→UNISEX 오류: 남성 10건, 여성 4건

이 측정은 상세 이미지와 상세 프롬프트만 fresh이고 Verbatim textSignal은 저장값이다. 따라서 공식
V501-fresh 점수는 아니지만, 현재 결론형 상세 v7을 그대로 확대 적용하면 안 된다는 반증으로는
충분하다. 다음 실험은 다음 응답 계약을 사용한다.

```text
explicitTargetPhrases: [{text, imageId, targetLinked}]
targetWornModels: [{imageId, observedGender, confidence}]
productSpecificSizeEvidence: [{imageId, system, labels, targetLinked}]
irrelevantImages: [imageId]
unsupportedInferenceDetected: true | false
```

LLM은 이 관찰값만 반환하고 `productGender`를 만들지 않는다. reducer는 `targetLinked=true`인 직접
문구를 먼저 쓰고, 그다음 남녀 대상 착장 모델 조합을 사용한다. `일반적으로 남녀가 입을 수 있음`,
`오버핏`, `범용 디자인`은 어떤 라벨도 만들 수 없으며 기권한다.

## 11. V502 승격 순서

1. E3 정책 계약과 E7 GT 상태를 먼저 확정한다.
2. E8로 V501-fresh 기준선을 만든다.
3. E1 텍스트 오염 제거를 단독 평가한다.
4. E2 이미지 역할 분류를 shadow로 평가한 뒤 reducer를 평가한다.
5. E4 사이즈는 충분한 표본이 모일 때까지 shadow로 유지한다.
6. E5 카테고리는 99% 수준의 전용 category만 제한적으로 검토한다.
7. 통과한 후보만 하나씩 누적하고, 후보를 추가할 때마다 이전 단계 전체를 재측정한다.
8. 마지막 조합을 신규 holdout에서 한 번 평가하고 V502 승격 여부를 결정한다.

첫 구현 후보는 **E1 텍스트 오염 제거**다. 새로운 추론 신호를 추가하는 것이 아니라 잘못된 근거를
기권시키는 변경이라 범위가 작고, 현재 확인된 회귀와 직접 연결된다. 그다음은 E2이며, E4~E6은
데이터가 유효하다는 증거가 생기기 전까지 운영 판정에 넣지 않는다.
