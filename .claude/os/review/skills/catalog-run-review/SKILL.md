# 실행 심사

엔진이 낸 run을 **읽기만** 하고 다시 센다. 프로필도 어댑터도 정책도 읽지 않는다.
계약은 `.claude/os/review/contracts/handoff.md`에 있다.

```bash
python3 .claude/os/review/scripts/review_run.py --run .claude/os/runs/<프로필ID>
```

run이 하나뿐이면 `--run`을 생략할 수 있다. CI처럼 막아야 하는 자리에서는 `--strict`를 준다.

## 결과를 읽는 순서

1. **판정** — `FAIL`이면 여기서 멈춘다. 요약과 산출물이 서로 다른 실행의 것이므로
   무엇을 판정해도 근거가 흔들린다. 사이클을 다시 돌린 뒤에 다시 심사한다.
2. **검사 표** — `SKIPPED`를 먼저 본다. 건너뛴 검사는 통과가 아니라 **보지 못한 것**이다.
   대개 요약이 그 산출물을 선언하지 않아서다.
3. **지금 판정 가능한 건** — 미판정 건수보다 이 숫자가 사람이 할 일에 가깝다.
   충돌 없음과 미결 판례에 막힌 건을 빼고 남은 것이다.
4. **완료 조건** — `source`가 `recount`인 줄만 심사가 직접 센 값이다.
   나머지는 요약의 주장을 옮긴 것이므로 그 자체로는 근거가 아니다.

## 판정을 사람에게 옮길 때

지적을 그대로 읽어 주지 않는다. 무엇이 신뢰를 깨고 무엇이 잡음인지 갈라야 하면
`catalog-run-reviewer` 서브에이전트에 `run-review/`와 요약 경로를 넘긴다.

`REVIEW_LOAD`가 큰 run에서는 건별 판정을 시작하기 전에 **미결 판례부터 닫는다.**
막힌 건수가 가장 많은 판례 하나를 답하면 큐의 상당 부분이 한 번에 풀린다.
판례를 닫는 절차는 스킬 `catalog-interview`, 질문서는 `catalog-policy-golden-audit`이 맡는다.

심사는 아무것도 고치지 않는다. 큐도 요약도 사람 판정 원장도 이 스킬로는 바뀌지 않는다.
