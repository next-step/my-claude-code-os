# 엔진 → 심사 인계 계약

엔진과 심사는 서로를 부르지 않는다. **한 장의 산출물로만 만난다.**

```
engine  ──▶  runs/<프로필ID>/run-summary.json  ──▶  review  ──▶  runs/<프로필ID>/run-review/
```

## 왜 호출이 아니라 산출물인가

호출로 이으면 심사는 엔진의 함수 시그니처에 묶인다. 엔진이 인자를 하나 바꾸면 심사가 깨지고,
심사가 필요한 값이 생길 때마다 엔진에 반환값을 하나씩 더 붙이게 된다. 그 순간 둘은 한 덩어리다.

산출물로 이으면 세 가지가 따라온다.

1. **심사는 엔진이 없어도 돈다.** 어제 만든 run, 남이 준 run, 압축해서 보낸 run도 심사한다.
2. **심사는 속성을 모른다.** 프로필도 어댑터도 정책도 읽지 않는다. 읽는 것은 요약과
   그 요약이 선언한 경로뿐이다. 그래서 속성이 늘어도 심사는 그대로다.
3. **거짓말이 드러난다.** 요약이 말한 숫자를 산출물에서 다시 세는 것이 심사의 일이다.
   같은 함수가 낸 값을 그대로 받으면 다시 세는 의미가 없다.

## 인계 파일

`run-summary.json` 하나다. 엔진의 audit 어댑터가 사이클마다 **새로 쓰고**, 뒤따르는 엔진
스크립트들이 자기 산출물을 `artifacts`에 더한다. 심사는 이 파일을 진입점으로만 쓴다.

| 키 | 필수 | 심사가 이것으로 하는 일 |
|---|---|---|
| `generatedAt` | 예 | 심사 결과에 `basedOn`으로 박는다. 이 값이 다르면 심사는 옛 run의 것이다 |
| `artifacts.queueDirectory` | 예 | 큐 계약·진행률 재계산·판정 가능 건수의 입력 |
| `artifacts.*` (그 외 전부) | — | 선언한 것이 실제로 있는지 본다 |
| `artifacts.arbiterVerdicts` | 아니오 | 심판이 큐를 다 훑었는지, 지금 판정 가능한 건이 몇 건인지 |
| `artifacts.decisionLedger` | 아니오 | 진행률 재계산, 판정과 큐의 정합 |
| `reviewProgress` | 아니오 | 요약이 말한 진행률. 다시 센 값과 대조한다 |
| `policyLayer` | 아니오 | 추적되지 않는 정책 공백이 있는지 |

**선언하지 않은 것은 심사하지 않는다.** 경로를 관습으로 추측하기 시작하면 그것은 계약이 아니다.
대신 그 검사는 `SKIPPED`로 남고, 이유가 함께 적힌다. **건너뛴 검사는 통과가 아니다.**

## 방향은 한쪽이다

| 심사가 하는 것 | 심사가 하지 않는 것 |
|---|---|
| 요약과 선언된 산출물을 **읽는다** | 엔진 스크립트를 import하거나 실행한다 |
| `runs/<프로필ID>/run-review/`에만 **쓴다** | `run-summary.json`·큐·보고서를 고친다 |
| 다시 센 값과 요약의 값을 나란히 남긴다 | 사람 판정 원장 `review/decisions.json`에 쓴다 |
| 어느 검사를 건너뛰었는지 남긴다 | 프로필·어댑터·정책 문서를 읽는다 |

세 번째 줄이 이 계약의 핵심이다. 읽는 쪽이 원본을 고치면, 다음 사람은 어느 숫자가 원본이고
어느 숫자가 심사가 손댄 값인지 알 수 없다. 그래서 심사는 지적만 하고 고치지 않는다 —
이 OS가 GT와 정책에 대해 하는 일과 같다.

## 신선도

엔진은 사이클마다 `run-summary.json`을 새로 쓴다. 심사 결과는 `run-review/`에 따로 남으므로
사이클이 돌아도 지워지지 않는다. 그래서 심사 결과에는 언제나 `basedOn.generatedAt`이 박힌다.

```
run-review.json의 basedOn.generatedAt ≠ run-summary.json의 generatedAt
  → 이 심사는 지금 폴더의 run이 아니라 그 전 run을 본 것이다. 다시 돌린다.
```

## 새 속성에서

할 일이 없다. 어댑터가 공통 큐 계약과 `run-summary.json`을 쓰면 심사는 그대로 돈다.
심판 어댑터가 없으면 심판 관련 검사만 `SKIPPED`로 남는다.
