## 이 샘플이 정했던 것

한 상품이 한 카드다. 카드에 담긴 것은 넷뿐이었다.

1. 대표 이미지 한 장 (96px) — 목록을 훑을 때 상품을 알아보는 용도
2. 배지 — 이 제안을 얼마나 믿는지. 확신 · 정책적용 · 판단필요 · 카테고리오류
3. `현재 GT → 제안` 한 줄과 판독기가 낸 값·근거 출처
4. 왜 그렇게 보는지 한 문단

머리글에 쓴 문장이 산출물의 성격을 정했다 — **"GT 파일에는 반영하지 않았습니다.
판정만 주시면 적용합니다."** 이 문장은 지금도 `gt-fixes.html` 머리글에 살아 있다.

판독기가 실제로 본 사진을 크게 싣고, 인용한 장면을 표시하고, 원문 관찰을 접어 둔다.
"GT를 정답으로 가정하지 않는다"를 화면 구조로 말한다.

그 워크트리도 untracked다. 사라지면 같은 일이 반복된다.

## 렌더러가 다르게 하는 것

| 손으로 만든 것 | `gt-fixes.html` |
|---|---|
| 제목에 건수를 적었다 (`13건`) | 임베드된 데이터에서 브라우저가 센다 (프로젝트 규칙 8) |
| 배지를 손으로 골랐다 | 심판 `review/verdicts.jsonl`의 귀책·근거 강도에서 나온다 |
| 카테고리 오류를 같이 실었다 | 귀책이 실행이면 표지의 실행 결함 표로 간다 |
| 한 문단에 판독기·리뷰어 말을 섞었다 | 두 문장을 나눠 싣는다 |
| 사진을 data URI로 박아 어디서든 열렸다 | 원본 URL을 가리킨다. 원본이 사라지면 액자에 "못 불러왔다"고 적는다 |

마지막 줄이 아직 뒤처진 부분이다. 보고서를 다른 사람에게 넘길 때 사진이 함께 가지 않는다.
