# 세션 간 중계 (session-relay)

`session-board`가 "누가 무엇을 하고 있는가"를 **보여주는** 스킬이라면, 이 스킬은 그 결과를 근거로 다른 세션에게 **실제로 말을 거는** 스킬입니다.

## 언제 쓰는가

- 보드에서 **같은 파일을 두 세션이 함께 만지고 있는 게** 확인됐을 때
- `session-conflict-warn` 훅이 편집 직전에 경고를 띄웠을 때
- 다른 세션이 하던 작업의 결과나 결정을 알아야 이쪽 작업을 이어갈 수 있을 때
- 중복 작업이 보여 역할을 나눠야 할 때

**보드를 보지 않고 바로 보내지 않는다.** 무엇을 보낼지의 재료는 `session-board`에서 온다.

## 핵심 개념 — 왜 파일이 아니라 도구로 보내는가

이 저장소의 세션 인계 계층은 파일(`.claude/sessions/*.json`)로 만들어져 있는데, 실시간 대화만은 파일을 쓰지 않는다. 그 차이를 사용자에게 짚어준다.

| 채널 | 성격 | 쓰는 곳 |
|---|---|---|
| 세션 파일 (훅이 기록) | **비동기·영속** — 지금 없는 세션(아직 안 열린 미래의 세션)에게도 전달된다 | 인계, 충돌 감지 |
| `SendMessage` 도구 | **동기·실시간** — 지금 켜져 있는 세션에게만 닿는다 | 조율, 질문 |

파일 기반 메시지 큐를 따로 만들지 않은 이유가 여기 있다. 이미 실시간 채널이 내장돼 있는데 파일로 흉내 내면 실시간성만 잃는다.

## 실행 절차

1. **`ListAgents` 호출** — 지금 살아있는 피어 세션과 그 이름을 확인한다. 이름이 곧 주소다.
   - 출력 첫 줄에 **이 세션 자신의 이름**도 나온다. 그 값을 아래 3번에서 한 번 기록해 둔다.

2. **보드와 대조** — `session-board`의 집계 결과로 "그 세션이 무슨 작업 중인지"를 확인한다.
   `ListAgents`의 대괄호 ref와 세션 파일의 `session_id`는 **별도 id 공간**이므로 자동 매칭되지 않는다. 브랜치·최근 파일·마지막 메시지로 사람이 알아볼 수 있게 나란히 보여준다.

3. **자기 표시 이름 기록** (한 세션에 한 번이면 충분하다)
   ```
   node -e "const b=require('./.claude/lib/session-board.js');console.log(b.recordDisplayName({projectDir:process.cwd(),sessionId:'<내 세션 id>',displayName:'<ListAgents가 알려준 내 이름>'}))"
   ```
   - 이 한 필드만이 **스킬이 세션 파일에 쓰는 유일한 예외**다. 다른 필드는 절대 건드리지 않는다.
   - 왜 훅이 못 하는가: 훅은 도구를 호출할 수 없어서 `ListAgents`를 볼 수 없다. 자기 이름을 아는 주체는 세션 자신뿐이다.
   - 이걸 기록해 두면 **다른 세션이 이쪽을 이름으로 부를 수 있게 된다.** 안 하면 보드에 짧은 id로만 남는다.

4. **보낼 문구를 먼저 사람에게 보여주고 `AskUserQuestion`으로 승인받는다**
   - 승인 없이 먼저 보내지 않는다. 메시지는 상대 세션의 컨텍스트를 차지하고, 상대 세션 앞에 앉은 사람의 작업을 끊는다.
   - `os-retro-check`·`big-change-commit-check`가 "먼저 물어본다"를 강제하는 것과 같은 규율이다.

5. **`SendMessage({to: "<세션 이름>", message: "<승인된 문구>"})`**
   - 문구는 짧게. 무엇을·왜·상대에게 바라는 행동 한 가지를 담는다.
   - 예: `".claude/lib/session-board.js 를 제가 지금 고치고 있습니다. 5분만 기다려 주시거나, 먼저 하실 거면 알려주세요."`

6. **결과 보고** — 보냈다는 사실과 문구를 사용자에게 알린다. 답이 오면 그 내용을 반영해 하던 작업을 잇는다.

## 참고

- **자동 회신 금지.** 다른 세션에게 메시지를 받았다고 해서 이 스킬로 자동으로 되받아치지 않는다. 세션 A→B→A 왕복이 폭주하면 양쪽 컨텍스트가 다 타 버린다. 한 요청당 발신은 1회다.
  이 규칙은 훅으로 강제할 수 없다 — 발신 주체가 AI 판단이라 훅이 가로챌 지점이 없다. **문서로만 지켜지는 규칙**이라는 한계를 그대로 안다.
- 대상 세션이 `idle`이면 메시지는 전달되지만 즉시 처리되지 않을 수 있다. 답을 기다리며 멈춰 있지 말고 하던 일을 계속한다.
- **다른 세션 대신 파일을 고치지 않는다.** 저쪽이 하던 작업은 저쪽이 끝내게 두고, 이쪽은 조율만 한다.
- 세션 파일에는 `displayName` 외에 아무것도 쓰지 않는다. 기록은 훅의 몫이다.
- 지금 누가 살아있는지만 보고 싶다면 `session-board`로 충분하다. 이 스킬은 **말을 걸 때만** 쓴다.

## 예시

```
1) ListAgents
   이 세션: my-claude-code-os-25
   피어: my-claude-code-os-51 (interactive, waiting)

2) 보드 대조
   6752be… · 4분 전 · 30턴 · step2 · .claude/lib/session-board.js
   → my-claude-code-os-51 이 그 세션으로 보입니다(브랜치·파일 일치).

3) 승인 요청
   보낼 곳: my-claude-code-os-51
   보낼 말: "session-board.js 의 buildBoard를 제가 고치는 중입니다.
             혹시 같은 함수 작업 중이시면 알려주세요 — 아니면 제가 5분 안에 끝내겠습니다."
   → AskUserQuestion: 이대로 보낼까요?

4) 발신 완료. 답이 오면 반영하겠습니다.
```
