# /usage 스킬 — 스킬 사용 리포트

이 OS가 **자기 자신의 사용 패턴**을 읽어 개선점을 드러내는 스킬이다.
`PostToolUse(Skill)` 훅이 스킬 호출을 `.claude/skill-invocations.log`에 쌓고(write 절반),
이 스킬이 그 로그를 분석한다(read 절반). 둘이 합쳐져 "관찰 → 개선" 루프가 닫힌다.

## 사용법

```
/usage
```

무엇을 보여주나:
- **① 빈도** — 어떤 스킬을 얼마나 자주 부르나 (많이 쓰는 걸 더 빠르게/별칭 후보)
- **② 연쇄** — 바로 이어 부른 쌍 (`capture → plan`처럼) — 임계 이상 반복되면 콤보 스킬 제안
- **③ 유휴** — 등록됐지만 한 번도 안 불린 스킬 — 폐기/점검 후보

---

## 실행 절차

> **설계 포인트 — 정본(source of truth)을 읽는다**
> 사용 통계를 문서에 적어두면 즉시 낡는다. 이 스킬은 항상 실제 로그
> `.claude/skill-invocations.log`를 직접 스캔해 사실을 다시 길어 올린다.
> ([[skills]]가 SKILL.md를, [[remind-when]]이 crontab을 직접 읽는 것과 같은 철학.)
>
> **결정론적 조회 → 직접 처리**
> 빈도 집계·연쇄 추출·유휴 판정은 입력이 정해지면 출력도 정해지는 일이라 Agent가
> 필요 없다. 오케스트레이터가 Bash 한 번으로 처리하고, 임계 이상 반복된 연쇄에
> 대한 콤보 제안까지 스크립트가 결정론적으로 붙인다.

### Step 1: 리포트 생성 + 출력 (usage-report.sh 1회)

아래 Bash를 실행한다. **출력은 이미 완성된 최종 메시지이므로, 표로 다시 그리거나
재포맷하지 말고 그대로(verbatim) 사용자에게 relay한다** — 그래야 두 번째 LLM 턴이
사라져 체감 속도가 빨라진다.

```bash
.claude/skills/_shared/usage-report.sh
```

> 로그가 비어 있으면 스크립트가 "아직 기록된 호출이 없어요" 안내를 대신 출력한다.
> 표본이 10회 미만이면 "패턴이 얕다"는 주의를 먼저 붙여 과잉 해석을 막는다.

## 설계 노트 — 왜 이렇게 만들었나

- **AI 협업 학습 포인트**: 작업환경을 개선하는 "시스템 루프"는 감지→비교→교정의
  피드백 사이클이다. 이 스킬은 그 사이클의 **read(감지·비교)** 를 담당한다.
  write(훅)만 있고 read가 없으면 데이터는 쌓이기만 하고 개선으로 되돌지 못한다.
- **정직한 한계 표기**: 현재 로그 스키마엔 성공/실패 필드가 없어 "실패 반복"은
  감지하지 못한다. 이를 원하면 write 훅(log-skill-invocation.sh)이 `tool_response`
  상태까지 남기도록 스키마를 넓혀야 한다(후속 과제).
- **정본 직독**: 로그가 gitignore된 런타임 파일이라 사람마다 다르다. 그래서 문서에
  통계를 박지 않고 매번 실제 로그에서 다시 계산한다 — 항상 참인 상태만 보여준다.
