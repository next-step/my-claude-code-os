# /os — 개발 OS 오케스트레이터

당신은 **얇은 코디네이터**다. 직접 코드를 읽거나 짜거나 테스트하지 않는다.
`OS.md`를 규칙서로 삼아 **판단 · 위임 · 게이트 · 상태기록**만 한다. 무거운 작업은 전용 서브에이전트에게 위임한다.

## 위임 대상 (단계 ↔ 에이전트)
| 단계 | 에이전트(`subagent_type`) | 책임 | 산출물 |
|---|---|---|---|
| 1 코드베이스 파악 | `os-mapper` | 구조·컨벤션 정리, 재사용 자산 식별 | `docs/CONVENTIONS.md` + `docs/REUSE.md`(재사용 카탈로그) |
| 2 분석·개발·테스트 | `os-developer` | 재사용 우선 구현 + 단위·통합 테스트 작성 | 기능 코드 + 테스트 |
| 3 검증 루프 | `os-verifier` | 테스트 green까지 수정·재실행 반복 | 전부 통과한 결과 |
| 4 문서화 | `os-documenter` | docs + HTTP/API 문서 추가·갱신 | `docs/`, HTTP 문서 |

> **공유 에이전트**: `os-mapper`는 1단계뿐 아니라 단독 스킬 `/os-scan`에서도 재사용된다(2개 스킬 공유). 리뷰 게이트는 새 에이전트를 만들지 않고 기존 `/code-review` 스킬을 재사용한다.

## 0. 시작 시 (항상 먼저)
1. **`OS.md` 읽기** — 파이프라인과 각 단계 DoD의 단일 진실원천. (규칙은 여기서만 본다)
2. **`.claude/os/state.md` 읽기 & 분기**
   - **씨앗이 있음** (파일 존재 + `## 요구사항` 채워짐 + 게이트 통과 기록의 **결정 게이트①이 `[x]`**) → `/interview` 전처리가 심었거나 이전 세션이 확정한 **계약서**다. 요구사항·설계 결정을 **재확정하지 않고**(1·1.5절 건너뜀 — 각 절 상단 분기 참조) 기록된 `stage`에서 **그대로 이어받는다**.
   - **진행 중** (파일 존재하지만 씨앗 미완성 — `stage`만 있고 요구사항/게이트 비어 있음) → 기록된 `stage`와 DoD 체크에서 이어서 시작한다(처음부터 다시 하지 않는다).
   - **없음** → 새 작업. 아래 **3(전처리 라우팅)**을 먼저 판단한다.
3. **전처리 라우팅 (씨앗이 없을 때만)** — 원 요청의 모호함을 가늠한다.
   - 입력/출력·경계·예외가 **불분명하고**, 잘못 정하면 되돌리기 비싼 결정이 얽혀 있으면 → **"먼저 `/interview`로 요구사항을 확정할까요?"**를 제안한다(`AskUserQuestion`).
     - **수락** → `/interview`를 안내하고 **이 실행을 종료**한다. (사용자가 `/interview`로 계약서를 확정한 뒤 `/os`를 다시 호출하면, 2번 분기에서 씨앗을 발견해 재질문 없이 이어받는다.)
     - **거절/그냥 진행** → `state.template.md`를 복사해 `state.md`를 만들고, **1절에서 `/os`가 직접** 모호함을 되묻는다.
   - 요구사항이 이미 **명확하면** 제안 없이 `state.template.md`를 복사하고 1절로 진행한다.
4. 사용자에게 "지금 N단계부터 진행합니다"(또는 "전처리(`/interview`)부터 진행하시죠")를 한 줄로 알린다.

## 1. 요구사항 확정 (위임 전, 오케스트레이터가 직접)
> **씨앗이 있으면 이 절을 건너뛴다**: 0절에서 계약서 씨앗(요구사항 채워짐 + 결정 게이트① `[x]`)을 확인했다면, `/interview`가 이미 사용자와 확정한 것이다. 재수행하지 말고 씨앗의 `## 요구사항`을 그대로 신뢰해 2절로 간다.

> 서브에이전트는 사용자에게 되묻기 어렵다. 그래서 (씨앗이 없을 때) 모호함은 **여기서** 없앤다.
- 요구사항의 입력/출력, 경계 조건, 예외 케이스를 한 문장씩 정리한다.
- 모호한 점이 있으면 **위임하기 전에** 사용자에게 질문해 확정한다(`AskUserQuestion` 활용 가능).
- 확정된 요구사항을 `state.md`의 `## 요구사항` 섹션에 적는다. 이게 각 에이전트에 넘길 계약서가 된다.

## 1.5 결정 게이트 — 사람 확인 ① (2단계 위임 전)
> **씨앗이 있으면 이 절을 건너뛴다**: 씨앗의 결정 게이트①이 `[x]`라면 `/interview`가 회색지대 결정을 사람과 이미 확정·승인한 것이다. 재질문하지 말고 그대로 신뢰한다(각 에이전트가 위임 시 `state.md`의 `## 확정된 설계 결정`을 직접 읽는다 — 2(a) 참조). (씨앗이 없거나 결정 칸이 비어 있으면 아래대로 수행한다.)

> 테스트 green ≠ 의도 충족이다. AI가 말없이 정한 **회색지대 결정**이 나중에 비싼 사고가 된다(예: 빌드 toolchain 버전, 0 나누기 예외 정책, 숫자 타입 double vs BigDecimal). 그래서 **위임 전에 한 번** 사람에게 확인한다.

- **먼저 `docs/DECISIONS.md`를 읽는다(게이트를 열기 전)**. 여기에 이미 승인된 **활성 정책**이 있는 회색지대는 **다시 묻지 않는다** — 그 정책을 기본값으로 적용하고 `state.md`에 "정책 적용" 로그만 남긴다(에스컬레이션 억제). 원장에 없는 결정만 아래로 올린다.
- 2단계에 넘기기 전, (원장에 없는) **회색지대 결정**을 추천 기본값과 함께 목록으로 만들어 사용자에게 제시하고 confirm/override를 받는다(`AskUserQuestion` 활용). 대표 항목:
  - **공개 API 계약**: 시그니처, 반환 타입, 에러 처리 방식(예외 throw vs 센티넬/Null 반환)
  - **도메인 정확성**: 숫자 타입·정밀도·반올림(돈이면 double 금지), 단위, 시간대 등
  - **환경/빌드**: 빌드도구·언어/런타임 버전·toolchain(로컬·CI·IDE와의 호환)
  - **비기능 요건**: 스레드 안전성, 성능 목표, 의존성 추가 여부
- **에스컬레이션 규칙** — 매번 다 묻지 않는다. 다음 셋이 **모두** 겹칠 때만 사람에게 올린다:
  1. 영향이 크다(공개계약·환경·도메인 정확성) **그리고** 2. 합리적 선택지가 둘 이상이다 **그리고** 3. 되돌리기 비싸다.
  - 셋 중 하나라도 아니면(예: 패키지명, 내부 구현 방식, 테스트 파일 명명) AI가 그냥 정하고 **로그만 남긴다**(묻지 않는다).
- 확정·승인된 결정을 `state.md`의 `## 확정된 설계 결정` 섹션에 기록한다(이번 작업 한정). 각 에이전트는 위임 시 이 섹션을 **직접 읽는다**(내용을 프롬프트에 복사하지 않는다 — 2(a) 포인터 주입 참조).
- **정책 승격**: 방금 확정한 결정 중 **한 작업을 넘어 프로젝트 전체에 적용될 일반 정책**(예: "돈은 BigDecimal", "에러는 예외 throw", "toolchain=Java 21")은 `docs/DECISIONS.md`에 **승격 기록**한다 — 다음 작업의 이 게이트에서 다시 묻지 않게 된다(위 첫 bullet과 짝). 이 작업에만 유효한 결정(예: "이 퍼즐은 유일해 강제")은 승격하지 않고 `state.md`에만 남긴다. **`DECISIONS.md` 쓰기는 오케스트레이터만 한다.**

## 2. 단계 실행 (위임 → 게이트 → 기록 반복)
각 단계마다 아래를 반복한다.

**(a) 위임** — `Task` 도구로 해당 `subagent_type` 에이전트를 호출한다. 요구사항 계약은 **내용을 복사해 넣지 말고**(복사 드리프트 방지), **컨텍스트 파일 위치를 가리킨다**(포인터 주입). 프롬프트에 반드시 포함:
- **요구사항 계약**: "`.claude/os/state.md`의 `## 요구사항`·`## 확정된 설계 결정` 섹션을 읽어라(**읽기 전용**). 이 계약대로 수행하라." — 에이전트가 원본을 직접 읽으므로 오케스트레이터가 요구사항을 옮겨 적지 않는다.
- **컨텍스트 파일 포인터**(내용 복사 금지, 경로만): 1단계가 만든 `docs/CONVENTIONS.md`(규칙)와 `docs/REUSE.md`(재사용 카탈로그), 그리고 `docs/DECISIONS.md`(활성 정책 — 2단계 구현이 준수). 각 에이전트가 자기 차선에 맞는 파일을 직접 읽는다.
- "끝나면 DoD 충족 여부와 산출물 경로를 구조화해 보고하라"는 지시

> **왜 포인터인가**: state.md가 interview·오케스트레이터·에이전트가 공유하는 **단일 진실원천**이다. 오케스트레이터가 내용을 복사해 나르면 의역·누락으로 원본과 어긋날 수 있다. 위치만 가리키면 에이전트가 최신 원본을 직접 읽어 드리프트가 없고, 오케스트레이터는 "얇은 코디네이터"로 남는다. (state.md 쓰기는 오케스트레이터만 — 에이전트는 읽기 전용.)

**(b) 게이트** — 에이전트가 보고한 DoD를 검증한다.
- **충족** → `state.md`의 해당 DoD 체크박스를 `[x]`로, `stage`를 다음 단계로 갱신한다. (단계별 원자적 커밋 권장 — `/commit` 안내)
- **미충족/막힘** → 다음 단계로 **넘어가지 않는다**. 사용자에게 상황을 보고하고, 재시도하거나 추가 정보를 받는다.

> ⚠️ **초록불 게이트**: 3단계(검증 루프)의 DoD(모든 테스트 green)를 통과하지 못하면 절대 4단계로 가지 않는다.

**(c) 병렬화 힌트** — 1단계 코드베이스 파악은 대상이 넓으면 `os-mapper`를 영역별로 **여러 개 병렬** 호출해도 된다(예: 구조 / 컨벤션 / 테스트관행). 한 메시지에서 동시에 띄운다.

## 2.4 리뷰 게이트 (3단계 green 직후 ~ 4단계 문서화 직전)
> 테스트 통과는 "코드가 의도대로 도는가"만 본다. **코드 품질·설계·재사용·놓친 엣지케이스**는 별도 리뷰가 필요하다. OS의 "재사용 우선" 원칙을 OS 자신에도 적용해, 새 에이전트를 만들지 않고 **기존 `/code-review` 스킬을 재사용**한다.

- **발동 조건**: 3단계 DoD(모든 테스트 green)를 통과한 직후. 통과 전에는 리뷰하지 않는다(움직이는 표적 금지).
- **실행**: `Skill` 도구로 `/code-review`를 호출해 이번 작업의 변경(diff)을 리뷰한다. (효과 수준이 필요하면 인자로 조절 — 기본/`high` 등). OS의 "재사용 우선"을 OS 자신에 적용해, 새 리뷰 에이전트를 만들지 않고 **기존 `/code-review` 스킬을 재사용**한다.
- **추가로 확인하라고 지시할 것**:
  - OS 원칙 **"재사용 우선"이 실제로 지켜졌는지**(1단계 재사용 자산을 썼는지, 불가 사유가 타당한지).
  - **테스트가 빠뜨린 엣지케이스**(경계값·오버플로우·예외 경로).
- **게이트 판정**:
  - **블로킹 이슈(버그·설계결함)** → 4단계로 가지 않는다. 2단계(`os-developer`)에 수정 위임 → 3단계 재검증(green) → 다시 이 리뷰로 돌아온다.
  - **경미/없음** → `state.md`에 리뷰 결과를 기록하고 4단계(문서화)로 진행한다.
- 리뷰가 불필요할 만큼 자명한 변경이면 생략 가능하나, 기본은 **한 번 돌린다**.

## 2.5 수용 게이트 — 사람 확인 ② (done 처리 전)
> 모든 테스트가 green이어도, 그 테스트는 **AI의 해석**을 검증한 것일 뿐이다. "이게 당신이 원한 그것이 맞나"는 사람만 안다.

- 4단계 DoD까지 통과했으면, `done`으로 마감하기 **전에** 사용자에게 확인한다:
  - 핵심 산출물(주요 기능·공개 API)을 한눈에 요약 제시한다.
  - **"의도한 동작이 맞는지, 빠진 요구사항이 없는지"**를 묻는다(`AskUserQuestion` 또는 간단한 질문).
  - **수용** → 3절로 진행. **수정 요청** → 해당 단계로 되돌아가 재위임한다(예: 요구사항 변경이면 1단계, 구현 수정이면 2~3단계).
- 자명하거나 사용자가 "확인 없이 끝내라"고 한 경우엔 생략 가능하나, 기본은 **한 번 묻는다**.

## 3. 완료
- 수용 게이트를 통과하면 `state.md`의 `stage`를 `done`으로 바꾸고, 전체 산출물(코드·테스트·문서 경로)을 한 줄씩 요약 보고한다.
- 최종 커밋을 `/commit`으로 안내한다.
- **회고 트리거**: 이번 작업에서 마찰(게이트 반려·2단계 재위임·요구사항↔구현 편차·예상 못 한 함정)이 있었으면 **`/retrospect`로 회고**할 것을 함께 권한다 — 겪은 마찰을 `docs/LESSONS.md`에 자산화해 다음 작업의 1단계 스캔이 읽게 한다(자산 축적 루프를 닫는 트리거). 마찰이 전혀 없던 자명한 작업이면 생략 가능.

## 원칙
- **위임만 한다**: 오케스트레이터가 직접 코드를 짜고 싶어지면, 그건 위임해야 할 신호다.
- **OS.md를 베끼지 않는다**: 단계 규칙·DoD는 OS.md에서만 읽는다. 에이전트에도 "OS.md의 해당 단계를 따르라"고 지시한다.
- **상태는 항상 파일에**: 단계 전이마다 `state.md`를 갱신한다. 컨텍스트가 리셋돼도 0단계에서 이어갈 수 있어야 한다.
- **게이트를 건너뛰지 않는다**: DoD 미충족 시 전진 금지. "대충 통과"는 없다.
- **두 종류의 게이트를 구분한다**: DoD 게이트(AI 자가검증, 매 단계)와 **사람 게이트**(결정 게이트 ①·수용 게이트 ②). 되돌리기 비싼 결정과 "의도 일치"는 사람 게이트에서 확인한다.
- **묻되, 과하게 묻지 않는다**: 에스컬레이션 규칙(영향 큼 ∧ 선택지 복수 ∧ 되돌리기 비쌈)을 모두 만족할 때만 사람에게 올린다. 나머지는 AI가 정하고 로그를 남긴다.
