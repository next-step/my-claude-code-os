# OS — OS 파일 수정의 유일 경로

## Overview

OS를 이루는 파일(`.claude/` 스킬·에이전트·훅·설정, `OS.md`, `CLAUDE.md`,
`metrics.md`, 가이드 문서)의 수정을 통제한다. **에이전트 없음 — 메인이 직접
한다.** 사람과의 상호작용(충돌 검토·승인)이 이 스킬의 핵심이기 때문이다.

## 절차

| # | 담당 | 단계 |
|---|------|------|
| 1 | 🟢 메인 | **요청 접수** — 수정 대상과 이유를 확인. `private/notes/os-pains.md`에 관련 통증이 있으면 함께 가져온다 |
| 2 | 🟢 메인 | **결정 충돌 확인** — `private/decisions/README.md`(ADR 목록)와 `_inbox.md`를 확인해, 변경이 기존 결정과 충돌하는지 본다. 충돌하면 그 사실을 명시하고 사용자 판단을 구한다 (기존 ADR 본문은 고치지 않는다 — 새 결정으로 대체) |
| 3 | 🟢 메인 | **변경안 제시** — 무엇을 왜 어떻게 바꾸는지 diff 수준으로 제시 |
| 4 | 🔵 사람 | **승인** — 승인 없이는 수정하지 않는다 |
| 5 | 🟢 메인 | **수정·마무리** — 파일 수정. 처리한 통증이 있으면 os-pains.md에 체크. 새 설계 결정이 내려졌으면 결정 캡처는 adr 플러그인 훅이 담당 (이 스킬은 별도 캡처 절차를 갖지 않는다) |

## 불변 규칙

1. **이 스킬 밖에서 OS 파일을 수정하지 않는다** — 실험·조사 스킬 실행 중 OS의
   마찰을 발견하면 고치지 말고 통증 목록에 적재(/retrospect)한 뒤 이 경로로 온다.
   (예외: 각 스킬이 자기 담당 SSOT를 갱신하는 것 — /experiment의 experiments/,
   /retrospect의 승인된 metrics.md 갱신 — 은 그 스킬의 정상 동작이다.)
2. **ADR 우선**: 변경이 기존 결정을 뒤집는다면, 파일 수정 전에 그것이 의도된
   재결정인지 사용자에게 확인한다.
3. **한 번에 하나의 변경 주제** — 여러 통증을 한 승인으로 묶지 않는다. 승인
   단위와 커밋 단위를 일치시킨다.
4. 공유 파일(`.claude/`, OS.md 등)과 개인 파일(private/)을 한 커밋에 섞지 않는다
   (CLAUDE.md 규칙 4).

## Common Mistakes

| 실수 | 해결 |
|---|---|
| 다른 스킬 실행 중 "김에" OS 파일 수정 | 통증 적재 → /os 경로로 |
| ADR 확인 생략 | 2단계는 건너뛸 수 없다 — 충돌 무발견도 "확인함"으로 보고 |
| 승인 전에 수정 시작 | 3단계는 제안까지, 수정은 4단계 승인 후 |
| 변경 여러 개를 한 승인·한 커밋에 묶음 | 주제 하나 = 승인 하나 = 커밋 하나 |
