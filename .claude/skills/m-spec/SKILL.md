# /m-spec — 요구를 시나리오로

파이프라인의 첫 단계다. OS.md §3-1 을 실행한다.

## 실행 순서

1. **phase 설정** — `.claude/phase` 에 `spec` 을 쓴다.
   ```bash
   echo "spec" > .claude/phase
   ```
2. **사이클 번호 결정** — `specs/` 의 기존 `NNN-spec.md` 중 최대 번호 +1 (없으면 `001`).
3. **spec-writer 스폰** — 사람의 요구 한 줄을 전달한다. spec-writer 가 모호성 인터뷰 → 시나리오 도출을 수행한다. 인터뷰 질문이 사람에게 전달되도록 한다.
4. **conflict-analyzer 스폰** — spec-writer 의 초안 시나리오와 `specs/` 전체를 전달해 충돌·중복·영향 분석을 받는다. (독립 컨텍스트 — spec-writer 와 분리)
5. **통합** — 충돌 분석 결과를 `specs/NNN-spec.md` 의 "충돌 분석" 섹션에 넣어 완성한다.

## 게이트: 사람 승인 (개입 1/3)
아래를 사람에게 제시하고 **명시적 승인**을 받는다 (H4):
- 의도 일치 (요구 원문 ↔ 시나리오)
- 시나리오 누락·중복 없음
- 기존 스펙 충돌 해소됨

승인 전에는 /m-plan 으로 진행하지 않는다.

## 산출물
`specs/NNN-spec.md` (요구 원문 + Q&A + 시나리오 + 범위 밖 + 충돌 분석)

## 주의
- 코드/테스트는 이 단계에서 만들지 않는다.
- 사람이 승인하지 않으면 멈춘다.
