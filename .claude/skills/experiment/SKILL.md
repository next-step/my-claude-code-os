# Experiment — 실험 파이프라인 오케스트레이터

## Overview

대표 색상 추출 개선 실험 1회를 9단계 루프로 완주시킨다.
메인(이 스킬을 수행하는 오케스트레이터)은 **흐름 지휘·판정·기록**만 하고,
리서치/적용/측정은 서브에이전트(`experiment-researcher`, `experiment-applier`,
`experiment-measurer`)에 위임한다. **사람 개입은 1·4·9단계에서만** 발생해야 한다.

## 시작 전 컨텍스트 로드

1. `metrics.md` — "개선"의 정의와 판정 기준
2. `private/project.md` — 대상 프로젝트의 실제 위치·실행법 (**있으면 이것이 SSOT**).
   없으면 사용자에게 대상 프로젝트 위치와 실행법을 질문한다. 공유본 `project.md`는
   추상 개요일 뿐 실행 정보가 없다.
3. `experiments/` — 기존 기록 (다음 실험 번호 = 기존 최대 번호 + 1)

## 9단계 절차

| # | 담당 | 단계 |
|---|------|------|
| 1 | 🔵 사람 | **후보 선정** — `/suggest` 결과가 있으면 제시, 없으면 기존 기록의 "다음 실험 후보" 섹션에서 후보를 추려 제시. 선택은 반드시 사람이 한다 |
| 2 | 🟢 메인 | **이력 조회** — `experiments/`에서 관련 기록·교훈을 요약 |
| 3 | 🟣 researcher | **리서치** — 스폰 입력: 후보, 이력 요약, `knowledge/` 경로, 대상 프로젝트 컨텍스트 문서 경로(`private/project.md`). 리서치 노트(텍스트)만 회수 |
| 4 | 🔵 사람 | **진행 승인** — 노트 요약 + 측정 계획을 제시하고 승인 대기. 수정 요청 시 3단계 반복 |
| 5 | 🟣 applier | **적용·커밋** — 스폰 입력: 승인된 방안, 실험 번호(NNNN)와 실험명, 대상 저장소 경로·실행법(`private/project.md` 내용), 재시도면 직전 측정 표+실패 가설. 커밋 해시 + 변경 요약만 회수 |
| 6 | 🟣 measurer | **측정** — 스폰 입력: `metrics.md`의 측정 기준, 대상 저장소 경로·실행법, 베이스라인 기준 커밋, 측정할 커밋. 측정 결과 표만 회수 |
| 7 | 🟢 메인 | **결과 기록** — `experiments/NNNN-<실험명>.md` 작성/갱신 (아래 기록 규칙 준수) |
| 8 | 🟢 메인 | **기준 판정** — `metrics.md` 기준. 미달이고 시도 3회 이하면 5단계로 재시도, 아니면 9단계로 |
| 9 | 🔵 사람 | **인계·판정** — 기준 충족 시 이전 기록과 비교 요약 후 채택 여부를 묻는다. 3회 초과 시 상태를 요약해 인계한다 |

- 5~8단계는 **검증 루프 — 적용~측정 시도 총 3회까지** (최초 1회 + 재시도 최대 2회).
  재시도 시 직전 측정 결과와 실패 원인 가설을 applier에게 반드시 전달한다.
- 9단계에서 "채택" 판정이 나도 **정식 반영(사내 브랜치 이동·push·PR)은 이 스킬의
  범위 밖** — 사용자가 직접 수행한다. 스킬은 채택 사실을 기록에 남기는 것까지만 한다.
- 사이클 종료 시(판정 확정 후) applier를 한 번 더 스폰해 **대상 저장소 쪽 상세
  실험 노트**를 작성·커밋시킨다 (이중 기록). 이 스폰에는 applier가 직접 보지 못한
  정보를 반드시 전달한다: 시도별 측정 결과 표 전체, 최종 판정과 근거, 분석(배운 것),
  다음 실험 후보.

## 불변 규칙

1. **기록 격리**: 이 저장소(OS)의 실험 기록에는 대상 프로젝트의 파일명·함수명·코드
   조각·내부 URL·아키텍처 상세를 쓰지 않는다. 일반화된 서술만 허용
   (예: "k-means 기반 추출기의 배경 추정 휴리스틱"). 실물 예시: `experiments/0001-배경-픽셀-사전-제외.md`.
2. **이중 기록**: 코드 수준 상세(파일·커밋·재현법)는 대상 저장소 안의 실험 노트에
   남긴다. OS 기록에는 "상세는 대상 저장소 실험 노트 참조" 한 줄만.
3. **대상 저장소 안전 규칙**: 절대 push하지 않는다. 변경은 `experiment/NNNN-<이름>`
   로컬 브랜치에 격리하고, 커밋은 실험 단위로 한다.
4. **측정 산출물 커밋 금지**: 임시 측정 스크립트·합성 이미지는 커밋하지 않는다.
   대상 저장소에 정착된 평가 하니스가 있으면 그것을 사용한다 (`private/project.md` 참조).
5. **결정 캡처는 adr 플러그인 담당**: 실험 중 설계 결정이 내려지면 adr 캡처 규칙이
   처리한다. 이 스킬은 별도의 결정 기록 절차를 갖지 않는다.

## 기록 포맷 (experiments/NNNN-<실험명>.md)

`experiments/0001-배경-픽셀-사전-제외.md`를 템플릿으로 따른다:

- 상단 메타: 날짜 / 판정 (✅ 채택 · ❌ 기준 미달 · ⏸ 인계) / 한 줄 요약
- 본문: 배경·가설 / 시도한 것 / 측정 / 배운 것 / 다음 실험 후보

## Common Mistakes

| 실수 | 해결 |
|---|---|
| 사람 게이트(1·4·9) 외 단계에서 질문 | 5~8은 자동 구간. 판단 재료가 부족하면 기본값으로 진행하고 9단계에서 보고 |
| 서브에이전트의 원자료(코드 diff, 스크립트 출력 전문)를 대화에 그대로 노출 | 반환 계약(요약만)을 프롬프트에 명시하고, 위반 시 요약만 옮겨 적는다 |
| OS 기록에 코드 정보 유입 | 기록 작성 후 파일명·함수명·경로 패턴이 없는지 확인 |
| 재시도 시 직전 실패 정보 누락 | 5단계 재스폰 프롬프트에 직전 측정 표와 실패 가설을 포함 |
