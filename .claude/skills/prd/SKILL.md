# /prd — 요구사항 수집 → PRD 확정 (① 무엇)

[OS.md](../../../OS.md) 개발 흐름의 **① "무엇을·왜" 단계 전체**를 담당한다.
예전엔 요구사항(사람이 `docs/requirements/`에 작성) → PRD(정제)로 **두 산출물**이었지만, 이제 **하나로 합쳐**
`/prd`가 **수집부터 확정까지** 책임진다. 산출물은 `docs/prd/<slug>.md` **하나**다.

> 왜 합쳤나: requirements와 PRD는 **둘 다 "무엇"**(날것 vs 정제)이라 한 주제를 두 문서로 쓰는 중복이었다.
> "무엇/어떻게" 경계는 PRD(①)와 Plan(②) 사이에만 두고, ① 안의 수집·정제는 한 스킬로 묶는다.

전달된 인자: ``
- 인자가 있으면 → 개발할 **기능 설명**(slug 추정 + 수집 재료)으로 사용한다.
- 인자가 없으면 → "어떤 기능의 요구사항을 정리할까요?"라고 한 줄로 묻고 시작한다.

이 스킬의 범위는 **① 무엇(PRD 확정)까지**다. ② Plan부터는 `/plan`·`/feature`에서 한다.

---

## 진행 순서

### [준비] 기능 이름(slug) 정하기

기능 설명에서 짧은 파일명용 slug를 정한다(영문 kebab-case 권장).
예: "다크모드 토글" → `dark-mode-toggle`. 산출물 경로는 **하나**다.

```
docs/prd/<slug>.md            # 이 스킬의 유일한 산출물 (수집 씨앗 → 정제 PRD)
```

디렉토리가 없어도 `Write`가 자동 생성한다.

---

### ① 요구사항 수집 — "무엇을·왜" 확보

PRD를 만들려면 먼저 재료(요구사항)가 필요하다. **세 갈래 중 상황에 맞게** 재료를 확보한다.

1. **`docs/prd/<slug>.md` 초안이 이미 있으면** (예: `/interview`가 질문으로 캐 씨앗을 넣어둠)
   → `Read`로 읽어 그걸 재료로 삼는다. (사람이 쓴 내용은 존중 — 임의로 바꾸지 않는다.)
2. **사용자가 러프한 설명·요구를 줬으면**(인자 또는 대화) → 그걸 재료로 삼는다.
   애매하거나 비면 **한두 개만 짚어 확인**한다 — 무비판 긍정 금지(모순·비현실적이면 되묻는다).
3. **재료가 거의 없으면** → 사람에게 두 선택지를 안내하고 **멈춘다**:
   - "핵심만 러프하게 적어 주세요(무엇을 / 왜 / 원하는 동작 정도)", 또는
   - "질문으로 정리하고 싶으면 `/interview`를 쓰세요 — 캐낸 내용을 이 PRD 초안에 씨앗으로 넣어 줍니다."

> 예전의 "빈 요구사항 템플릿을 사람이 채우게 하고 멈추는" 단계는 **없앤다** — 러프 초안 또는 `/interview` 수집으로 대체.
> 수집은 **"무엇을/왜"까지**다. "어떻게"(설계·코드 조사)는 ② `/plan` 몫 — 여기서 파고들지 않는다.

---

### ② PRD 생성 — PRD 서브에이전트 호출

재료를 확보했으면 `Task` 도구로 **PRD 작성 서브에이전트**를 띄운다.
(초안 파일이 있으면 `Read`로 최신 내용을 다시 확보해 넘긴다.)

- `subagent_type`: `general-purpose`
- `description`: `"PRD 작성"`
- `prompt`: 아래 내용을 채워서 전달한다.

```
당신은 PRD(제품 요구사항) 작성 전문가다. 코드는 아직 보지 마라.
아래 "수집된 요구사항"을 구조화된 PRD로 정리하라.
사람이 준 내용을 임의로 바꾸지 말고, 비거나 모호한 부분만 "열린 질문"으로 모아라.

수집된 요구사항:
<수집 재료 본문 — 초안 파일 또는 대화에서 확보한 "무엇을/왜">

다음 형식의 마크다운으로만 답하라(설명 문장 없이 문서 본문만):
# PRD — <기능 이름>
## 문제 (왜 필요한가)
## 목표 (이 기능이 해결하는 것)
## 사용자 시나리오 (기대 동작)
## 범위 밖 (이번에 안 하는 것)
## 제약 / 조건
## 열린 질문 (사람 확인이 필요한 점)
[수집에서 비었거나 모호했던 점을 질문으로. 각 질문 아래 "**답변:** _(여기에 작성)_" 줄을 둔다.]
```

서브에이전트가 돌려준 PRD 본문을 **그대로** `docs/prd/<slug>.md`에 `Write`로 저장한다.
(수집 씨앗 초안이 있었으면 **정제 PRD로 덮어쓴다** — 한 파일이 날것 → 정제로 진화한다.)

---

### ③ PRD 검토 루프 — ★게이트★ (잘못된 점 확인 → 수정 → 반복)

PRD를 만들었으면 바로 확정하지 않는다. **검토 → 수정 → 다시 검토**를 사람이 만족할 때까지 돈다.

**3-1. 검토 서브에이전트 호출 (AI가 AI의 PRD를 점검)**

`Task` 도구로 **공유 검토자 서브에이전트(`reviewer`)** 를 띄운다. 적대적 검토 행동은 reviewer
에이전트 정의([.claude/agents/reviewer.md](../../agents/reviewer.md))에 있으니, 여기서는 **기준·대상·판정 형식만** 넘긴다.

- `subagent_type`: `reviewer`
- `description`: `"PRD 검토"`
- `prompt`:

```
[기준] 수집된 요구사항 (사용자 러프 초안 또는 /interview 수집 내용):
<수집 재료 본문>

[대상] 생성된 PRD:
<PRD md 본문>

[판정 형식]
## 판정: 큰 문제 없음 | 지적 있음
## 짚은 점
- (분류: 누락/모순/모호/오류) 내용 — 어떻게 고칠지
```

**3-2. 사람에게 보고하고 멈춘다**

PRD 요약 + 검토 서브에이전트가 짚은 점을 함께 보고한다.

```
✅ PRD 작성 완료 → docs/prd/<slug>.md

[PRD 요약]
- 문제: ...
- 목표: ...

[검토에서 짚은 점]
- (누락) ... → 이렇게 보완 제안
- (모호) ... → 이렇게 명확화 제안
(없으면: 큰 문제 없음)

여기는 ① 무엇(요구사항) 확정 게이트입니다.
- 고칠 점을 알려주시면 PRD를 수정합니다(이 루프를 반복).
- PRD의 "열린 질문"은 md 파일의 "답변:" 줄에 직접 채우셔도 됩니다.
- 확정되면 "확정" / "Plan 진행"이라고 알려 주세요. → ① 단계를 마칩니다.
```

**3-3. 수정 반영**

사람이 고칠 점을 주면 PRD를 고친다. 작은 수정은 `Edit`로, 큰 재구성은 ②의 서브에이전트를
다시 호출해 다시 만든다. 고친 뒤 다시 3-2로 돌아가 보고한다. **확정 신호가 올 때까지 반복.**

> 왜 루프인가: 요구사항은 한 번에 완성되지 않는다. "만들고 → 틀린 거 확인 → 고치고"를
> 반복하는 게 정상이다. 그 반복을 스킬이 구조로 만들어 매번 같은 품질로 돌게 한다.

---

### 마침

사람이 "확정"하면 이 스킬은 끝난다. **PRD를 임의로 ② Plan·③ 구현으로 넘기지 않는다.**
다음 단계는 `/plan` 또는 `/feature` 오케스트레이터가 이어받는다.

---

## 수용 기준 (이 스킬이 제대로 동작하는지 검증)

- [ ] 요구사항 수집을 **세 갈래(초안 파일 / 러프 설명 / 없으면 안내·멈춤)** 로 처리한다. 별도 `docs/requirements/` 파일을 만들지 않는다.
- [ ] `docs/prd/<slug>.md` 초안이 있으면 덮어쓰기 전에 **읽어 재료로 쓰고**, 사람이 쓴 내용을 존중한다.
- [ ] 재료가 비면 추측으로 PRD를 지어내지 않고 **러프 초안 또는 /interview를 안내하며 멈춘다**.
- [ ] ② PRD 생성과 ③ PRD 검토가 각각 **별도의 `Task` 서브에이전트**로 일어난다.
- [ ] ③ 게이트에서 멈추고, 사람이 "확정"할 때까지 수정 루프를 반복한다.
- [ ] 확정 전에는 Plan/구현으로 넘어가지 않는다.

---

## 안전 규칙

- **게이트를 넘지 않는다.** 사람의 확정 전에는 다음 단계로 가지 않는다.
- **사람이 쓴 요구사항을 임의로 바꾸지 않는다.** 비거나 모호한 것만 질문("열린 질문")으로 남긴다.
- **수집은 "무엇을/왜"까지.** 코드 조사·설계는 ② `/plan` 몫 — 여기서 하지 않는다.
- **모든 산출물은 저장소 안에** 둔다(`docs/prd/`). (CLAUDE.md 규칙 1)
- 서브에이전트가 빈 결과/오류를 돌려주면 그대로 알리고 멈춘다. 추측으로 채우지 않는다.
- 이 스킬은 **문서 작성**만 한다. 코드 파일을 수정하지 않는다.
