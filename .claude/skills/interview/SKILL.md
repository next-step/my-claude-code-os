# /interview — 요구사항·맥락 인터뷰 (개발 전처리)

개발을 시작하기 **전에** 사용자와 대화해 요구사항의 **모호함을 제거**하고,
`/os`가 재질문 없이 곧바로 개발을 이어갈 수 있는 **계약서**를 확정하는 스킬이다.
`/os`를 대체하지 않는다. `/os`의 **앞단(전처리)** 으로 붙어, 확정 계약서를
`.claude/os/state.md`에 씨앗으로 남기고 손을 뗀다.

> 얇은 전처리 스킬 — 여기서는 코드·테스트를 만들지 않는다. **계약서만 확정한다.**
> 개발·테스트·문서화는 인터뷰가 끝난 뒤 `/os`가 한다.

---

## 철학

이 인터뷰의 목적은 단 하나 — 개발 착수 전에 **값비싼 모호함을 제거**하는 것이다.

- 모호함은 대개 '안 말한 것'(실패·경계·예외)에 숨는다. 그러니 정상 동작보다
  **잘못된 입력·경계값을 집요하게 캐묻는다.**
- 백지 질문은 모호한 답을 부른다. **구체적 초안을 제시하고 "틀린 곳을 짚게"** 한다.
- 말보다 예시다. 애매하면 **입력 하나 → 기대 출력 하나**를 반드시 받아낸다.
- '무엇을(요구)'과 '어떻게(결정)'를 섞지 않는다. 섞이면 의도가 흐려진다.
- 그러나 **모든** 모호함을 좇지 않는다. 남은 모호함이 코드를 바꾸지 않거나
  나중에 싸게 고칠 수 있으면(`/os`의 초록불 원칙) 멈춘다.
- **선택과 집중**: 1~10 모든 케이스를 대응할 수는 없다. **발생 가능성 높은 케이스는 지금 대응**하고,
  낮은 케이스는 `[보류]`로 남겨 이슈 발생 시 처리한다. 단 발생 가능성이 낮아도 **터지면 치명적·비가역**이면 한 번은 확인한다.
- **조건부 재사용**: 코드는 재사용성을 최대화하되, **사이드이펙트 위험이 크면**(예: 서비스 장애)
  재사용보다 **개별 분리**한다. 인터뷰는 이 '재사용 vs 격리'를 결정으로 확정하고, 실행 규율은 `CONVENTIONS.md`·개발 단계가 지킨다.

끝내기 전, 확정된 계약서를 **되비춰 사용자 승인**을 받는다.

---

## 목표 산출물 — `/os`의 계약서 스키마

인터뷰의 모든 질문은 아래 칸 중 하나를 채우기 위해 존재한다. 이 칸에 닿지 않는 질문은 잡음이다.

**요구사항**
- 한 줄 요약
- 입력/출력
- 경계 조건
- 예외 케이스

**확정된 설계 결정** (회색지대 — 사람이 confirm/override)
- 공개 API 계약(시그니처·반환·에러 처리)
- 도메인 정확성(숫자 타입·정밀도·단위 등)
- 환경/빌드(빌드도구·런타임/toolchain 버전)
- 비기능 요건(스레드 안전성·성능·의존성)
- AI 자체 결정(묻지 않고 정한 항목 로그)

이 스키마는 `.claude/os/state.md`(및 `state.template.md`)의 섹션과 1:1로 대응한다.

---

## 절차

### 0. 받기
- 사용자의 원 요청을 받는다(예: "할인 계산기 만들어줘").
- 위 계약서 스키마를 목표로 삼는다. (코드·테스트는 만들지 않는다.)

### 1. 초안 계약서 채우기 — *초안 반사*
- 원 요청에서 채울 수 있는 칸을 **즉시 채운다**. 사용자에게 백지로 묻지 않는다.
- 근거 없이 추측해 채운 칸은 반드시 `[가정]` 태그를 붙인다(검증 대상 표시).

### 2. 모호함 신호등 매기기 — *시그니처 장치*
각 칸에 상태를 부여한다. 무엇을 🔴(지금)로, 무엇을 🟡(보류)로 볼지는 **두 축**으로 판정한다:
**발생 가능성**과 **값비쌈**(영향 큼 ∧ 되돌리기 비쌈).

| | 값싸게 복구 가능 | 터지면 치명·비가역 |
|---|---|---|
| **발생 가능성 높음** | 🔴 지금 확정 | 🔴 지금 확정 |
| **발생 가능성 낮음** | 🟡 보류(주석) | 🔴 한 번은 확인 |

- **🟢 명확** = 이미 확정된 칸. 건드리지 않는다.
- **🔴** = 지금 캐물어 확정할 대상.
- **🟡 보류** = 발생 가능성 낮고 값싸게 복구 가능 → 심문하지 않고 `[보류: 발생가능성 낮음 — 이슈 시 대응]` 태그로 남긴다.
- `[가정]`이 붙은 칸은 최소 🟡 이상으로 본다(사용자 확인 전이므로).
- 발생 가능성은 우선 내가 추정해 라벨링하고, 되비추기(6)에서 사용자가 교정한다.

### 3. 좁혀 묻기 (🔴만) — *음의 공간 + 예시 주도*
- 🟢·🟡(보류)은 놔두고 **🔴 칸만** 질문한다. 한 번에 다 묻지 말고 영향 큰 것부터.
- **실패·경계·예외를 우선 캐묻는다**: "잘못된 입력이 오면? 경계값(0, 최대)에서는? 무엇이 예외인가?"
- 추상적 답이 오면 반드시 **예시로 환원**: "입력 하나와 그때 기대하는 출력 하나를 주세요."
- **재사용 vs 격리**가 걸린 요구는 사이드이펙트 위험을 함께 묻는다: "이 로직이 다른 곳과 공유되면 장애가 번질 위험이 있나요?" → 위험이 크면 격리로 결정한다.
- 회색지대 **'결정'** 항목은 `AskUserQuestion`으로 **추천값 + 대등한 선택지**를 제시해 confirm/override 받는다.
  (유도 질문 금지 — 선택지는 한쪽으로 기울지 않게.)

### 4. 요구 vs 결정 분리해 기록 — *섞지 않기*
- 답을 채울 때 '무엇을(요구)'과 '어떻게(결정)'를 각 섹션에 나눠 넣는다.
- 예: "BigDecimal 써" → **요구**=정확한 금액(반올림 오차 없음) / **결정**=BigDecimal 사용.
- **재사용 vs 격리** 결정은 `확정된 설계 결정`의 *비기능 요건* 칸에 **근거(사이드이펙트 위험)와 함께** 적는다.
- **🟡 보류** 케이스는 `예외 케이스` 칸에 `[보류]` 태그로 적어 둔다(누락이 아니라 의도적 미룸 — 2단계에서 `// TODO:` 주석으로 이어짐).

### 5. 멈춤 판정 — *값비싼 모호함만*
- 신호등을 다시 본다. (무엇이 🔴/🟡인지는 절차 2의 2축 판정을 따른다.)
- **멈춘다**: 🔴가 하나도 없을 때(전부 🟢 또는 🟡 보류). **🟡 보류는 남아 있어도 멈춤을 막지 않는다.**
- **계속한다**: 🔴가 남았으면 3번으로 돌아간다.
- 무한 심문 금지. 완벽이 아니라 **'시작하기 충분'** 에서 멈춘다(보류·나머지는 `/os` 초록불이 잡는다).

### 6. 되비추기 + 승인 — *안전장치(필수)*
- 완성된 계약서를 한눈에 요약해 제시하고 묻는다: **"제가 이해한 계약서는 이렇습니다. 이대로 착수할까요? 틀린 곳은?"**
- 수정 요청 → 해당 칸을 고치고 다시 되비춘다. 승인 → 확정.
- 이 단계는 생략하지 않는다. '말한 것'과 '진심'의 간극을 여기서 닫는다.

### 7. 핸드오프 — state.md 씨앗 심기 (*㉯의 핵심*)
- `.claude/os/state.md`를 만들어(이미 있으면 사용자에게 덮어쓸지 확인) 아래를 채운다:
  - `stage: 1`, `started_at: <오늘>`, `updated_at: <오늘>`
  - `## 요구사항` — 확정된 4칸
  - `## 확정된 설계 결정` — 확정된 5칸
  - `## 게이트 통과 기록`: `- [x] 결정 게이트 ① — 사람 (인터뷰에서 회색지대 결정 확정·승인)`
  - (나머지 DoD·산출물·로그 칸은 `state.template.md` 형식대로 비워 둔다 — `/os`가 채운다.)
- (선택) `docs/missions/<이름>.md`에 영구 사본을 남긴다(미션 원천 기록).
- 사용자에게 안내하고 종료: **"계약서를 확정했습니다. 이제 `/os`로 개발을 이어가세요."**

## 참고

- **`/os`와의 경계(전처리 ㉯)**: 이 스킬은 `/os`를 수정하지 않는다. **`state.md`를 공유 인터페이스**로 삼아, 인터뷰가 채운 계약서를 `/os`가 0절에서 발견해 "이어서" 개발을 시작한다(요구사항·결정 게이트①을 재질문하지 않음). 코드가 아니라 **데이터(계약)로 재사용**한다.
- **결정 게이트① 흡수**: 인터뷰가 회색지대 결정을 사람과 확정하므로, 사실상 `/os`의 결정 게이트①(사람 확인)을 앞당겨 수행한다. 그래서 씨앗에 그 게이트를 `[x]`로 체크한다. (수용 게이트②는 여전히 `/os`가 done 전에 수행한다.)
- **쓰기 범위**: `.claude/os/state.md` 생성/기록, (선택) `docs/missions/`. 그 외 소스·테스트는 건드리지 않는다.
- **자명한 요청이면**: 모호함이 처음부터 전부 🟢이면 1~5 루프를 건너뛰고 6·7만 수행할 수 있다. 단 되비추기(6)는 항상 한다.
- 이 스킬의 철학과 실제 동작이 어긋나면, **위 `## 철학` 섹션을 기준으로** 절차를 고친다(철학이 단일 진실원천).
