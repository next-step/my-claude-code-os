# 인수기준 — "실패 원장에서 최근 7일치만 뽑아 보여주는 스킬"

요구사항: "실패 원장에서 최근 7일치만 뽑아 보여주는 스킬이 필요해."

## 인수기준

AC-1. Given `.claude/atdd-failure-ledger.json`에 entries가 있으면, When 스킬을 실행하면, Then 각 entry의 `recordedAt`이 현재 시각 기준 최근 7일(168시간) 이내인 것만 걸러서 보여줘야 한다.

AC-2. Given entries 중 `recordedAt`이 7일보다 오래된 것이 있으면, When 스킬을 실행하면, Then 그 항목들은 결과 목록에서 제외되어야 한다.

AC-3. Given 최근 7일 이내에 해당하는 entries가 하나도 없으면, When 스킬을 실행하면, Then "최근 7일간 기록된 실패가 없습니다" 안내 메시지를 보여주고 끝나야 한다.

AC-4. Given `.claude/atdd-failure-ledger.json` 파일 자체가 없거나 entries가 비어 있으면, When 스킬을 실행하면, Then "아직 기록된 인수 테스트 실패가 없습니다"라고 안내해야 한다.

AC-5. Given 필터링된 최근 7일 entries를 보여줄 때, When 결과를 출력하면, Then 원장에 기록된 원래 순서(시간순 append 순서)를 그대로 유지해야 한다 — 별도의 정렬 로직을 새로 추가하지 않는다.

AC-6. Given 결과를 표시한 뒤, When 스킬이 끝나면, Then `.claude/atdd-failure-ledger.json` 원장 파일에는 어떤 내용도 쓰지 않아야 한다(읽기 전용).

AC-7. Given 스킬이 "최근 7일" 경계를 계산하면, When 현재 시각과 비교하면, Then 명확히 정의된 하나의 시각 기준(예: UTC)을 일관되게 사용해야 한다.

## 분해 근거

- AC-1/AC-2: "최근 7일치만 뽑아"가 핵심 동작이라 정상 필터링(포함)과 경계 초과 배제를 대칭으로 나눴다.
- AC-3/AC-4: "결과 없음"이 두 가지 다른 원인(원장 자체가 없음/비어있음 vs 최근 7일 내 항목만 없음)에서 생길 수 있어, 기존 `failure-ledger` 스킬의 안내 문구와 구분되게 각각 인수기준으로 뽑았다.
- AC-5: 정렬은 요구사항 원문에 없는 기능이라 신규 기능으로 넣지 않고, 대신 "원래 순서를 바꾸지 않는다"는 형태로 범위를 최소화했다. (1차 셀프 체크에서 `policy-reviewer`가 "같은 AC가 2회 이상 FAIL이면 반복 실패로 강조 표시"하는 항목(AC-6, 당시 번호)을 요구사항에 없는 신규 기능으로 지적해 FAIL 판정 → 해당 항목을 제거하고, 정렬 관련 항목도 "정렬 로직 추가 금지"로 다시 표현해 범위 확장을 막았다.)
- AC-6: "뽑아 보여주는" 동작이 쓰기를 포함하지 않는다는 점을 명시해, 원장은 훅만 기록한다는 저장소 관례(`failure-ledger` 스킬과 동일)를 유지했다.
- AC-7: "최근 7일"의 경계(어느 시각 기준으로 7일 전인지)가 요구사항 원문에 명시돼 있지 않은 미해결 가정이라, 하나의 기준(예: UTC)을 일관되게 쓰도록 요구해 모호성을 드러냈다.

## 셀프 체크 (policy-reviewer)

- 1차 판정: FAIL — "반복 실패 강조 표시" 항목이 요구사항에 없는 신규 기능이라는 지적.
- 지적 반영: 해당 항목 제거, 정렬 항목을 "원래 순서 유지(정렬 로직 추가 금지)"로 재정의.
- 2차 판정: PASS — 정상 경로/경계 초과/두 가지 빈 결과 케이스/읽기 전용/시각 기준 일관성을 범위 이탈 없이 커버한다고 확인.
- 리뷰어가 남긴 참고(FAIL 사유는 아님): `recordedAt` 누락·파싱 불가, 원장 JSON 손상 같은 비정상 데이터 처리는 이번 인수기준 범위 밖으로 남겼다. 필요하면 별도 요구사항으로 다뤄야 한다.
