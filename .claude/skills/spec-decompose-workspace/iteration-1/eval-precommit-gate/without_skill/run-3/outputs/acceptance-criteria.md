# 인수기준 — 커밋 전 테스트 초록불 확인 훅

요구사항: 커밋 전에 테스트가 초록불인지 확인하고, 빨간불이면 되묻는 훅을 만든다.

## AC-1: 훅 실행 시점
- Given 사용자가 `git commit`을 실행하려는 시점에
- When pre-commit 훅이 트리거되면
- Then 훅은 커밋이 실제로 기록되기 전에 테스트 스위트를 실행한다.

## AC-2: 테스트 전부 통과 시 정상 진행
- Given 프로젝트의 테스트 스위트를 실행했을 때
- When 모든 테스트가 통과(초록불)하면
- Then 훅은 별도 개입 없이 커밋을 그대로 진행시킨다.

## AC-3: 테스트 실패 시 되묻기
- Given 테스트 스위트를 실행했을 때
- When 하나 이상의 테스트가 실패(빨간불)하면
- Then 훅은 커밋을 바로 막지 않고, 사용자에게 "테스트가 실패했는데 계속 커밋하시겠습니까?" 형태로 되묻는다.

## AC-4: 되묻는 프롬프트에 실패 정보 포함
- Given 테스트 실패로 되묻기가 발생했을 때
- When 사용자에게 확인 메시지를 보여줄 때
- Then 실패한 테스트의 이름(또는 개수)과 같은 최소한의 판단 근거를 함께 보여준다.

## AC-5: 사용자 응답에 따른 분기
- Given 되묻기 프롬프트가 표시된 상태에서
- When 사용자가 "계속 진행"을 선택하면 커밋이 진행되고, "취소"를 선택하면 커밋이 중단된다.
- Then 각 선택에 따라 실제 커밋 여부가 그에 맞게 갈린다.

## AC-6: 테스트 실행 자체의 오류와 테스트 실패를 구분
- Given 테스트 명령을 실행했을 때
- When 테스트 러너 자체가 비정상 종료(설정 오류, 명령 없음, 타임아웃 등)한 경우
- Then 이를 "테스트 실패(빨간불)"와 구분하여 별도 오류 메시지로 사용자에게 알린다.

## AC-7: 테스트 명령 설정 가능
- Given 프로젝트마다 테스트 실행 명령이 다를 수 있으므로
- When 훅을 설정할 때
- Then 실행할 테스트 명령을 설정 파일(또는 환경변수)로 지정할 수 있어야 한다.

## AC-8: 실행 시간 제한
- Given 테스트 스위트 실행이 지나치게 오래 걸릴 경우를 대비해
- When 테스트 실행 시간이 정해진 타임아웃을 초과하면
- Then 훅은 실행을 중단하고 타임아웃 사실을 사용자에게 알린 뒤 커밋 여부를 다시 확인한다.

## AC-9: 비대화형 환경에서의 기본 동작
- Given CI 등 사용자 응답을 받을 수 없는 비대화형 환경에서
- When 테스트가 실패했을 때
- Then 되묻지 않고 사전에 정의된 기본 동작(예: 커밋 차단)을 따른다.

## AC-10: 훅 우회 옵션
- Given 긴급 상황 등으로 테스트 검증을 건너뛰어야 할 때
- When 사용자가 명시적인 우회 옵션(예: `--no-verify` 또는 별도 플래그)을 사용하면
- Then 훅 실행 자체를 건너뛸 수 있다. 단, 이 경우도 우회했다는 사실이 남도록 한다.

## 범위 밖
- 테스트 커버리지 기준(퍼센트) 강제는 다루지 않는다.
- 특정 언어/프레임워크의 테스트 러너 구현은 다루지 않는다.
- 커밋 메시지 형식 검증은 다루지 않는다.
