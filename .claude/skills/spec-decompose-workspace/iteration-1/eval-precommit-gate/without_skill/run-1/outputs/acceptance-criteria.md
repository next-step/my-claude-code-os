# 인수기준: 커밋 전 테스트 상태 확인 훅

## AC1 — 커밋 시도 시 테스트가 실행된다
- Given: 사용자가 `git commit`을 실행한다
- When: 커밋이 실제로 기록되기 전에 훅이 동작한다
- Then: 훅은 저장소에 정의된 테스트 명령을 실행한다

## AC2 — 테스트가 모두 초록불이면 커밋을 그대로 진행한다
- Given: 훅이 실행한 테스트가 전부 통과했다
- When: 커밋 프로세스가 계속된다
- Then: 사용자에게 아무것도 되묻지 않고 커밋이 정상적으로 완료된다

## AC3 — 테스트가 빨간불이면 커밋을 막지 않고 되묻는다
- Given: 훅이 실행한 테스트 중 하나 이상이 실패했다
- When: 훅이 이 사실을 감지한다
- Then: 커밋을 강제로 차단(deny)하지 않고, 실패한 테스트가 있음을 알리며 계속 진행할지 사용자에게 확인을 구한다

## AC4 — 되묻는 메시지에는 실패 정보가 포함된다
- Given: 테스트가 실패해 되묻기가 발생했다
- When: 사용자에게 확인 메시지가 표시된다
- Then: 메시지에는 실패한 테스트 이름(또는 실패 개수)과 실패 로그 요약이 포함된다

## AC5 — 사용자가 "계속 진행"을 선택하면 커밋이 진행된다
- Given: 되묻기 메시지가 표시된 상태다
- When: 사용자가 빨간불이어도 커밋을 계속하겠다고 응답한다
- Then: 훅은 커밋을 막지 않고 그대로 통과시킨다

## AC6 — 사용자가 "중단"을 선택하면 커밋이 취소된다
- Given: 되묻기 메시지가 표시된 상태다
- When: 사용자가 커밋을 중단하겠다고 응답한다
- Then: 커밋이 기록되지 않고 훅이 종료된다

## AC7 — 테스트 명령 자체가 존재하지 않거나 설정되지 않은 경우
- Given: 저장소에 정의된 테스트 실행 명령이 없다
- When: 훅이 테스트를 실행하려 시도한다
- Then: 훅은 에러로 죽지 않고, 테스트를 찾을 수 없다는 사실을 알린 뒤 커밋을 막지 않고 통과시킨다

## AC8 — 테스트 실행 자체가 비정상 종료(크래시)된 경우
- Given: 테스트 실행 명령이 (실패가 아니라) 실행 도중 예외로 죽는다
- When: 훅이 이 상황을 감지한다
- Then: 이를 "빨간불"과 구분해 별도로 사용자에게 알리고, 임의로 통과 또는 차단을 단정하지 않는다

## AC9 — 훅은 판단만 하고 결정은 사람이 한다
- Given: 테스트 결과가 초록불이 아닌 모든 경우
- When: 훅이 되묻기를 수행한다
- Then: 훅 스스로 커밋 여부를 최종 결정하지 않고, 항상 사람의 응답을 기다린 뒤 그 결정을 따른다

## AC10 — 훅 동작이 기록으로 남는다
- Given: 훅이 실행되어 테스트 결과를 확인했다
- When: 결과가 초록불이든 빨간불이든
- Then: 실행 시각, 결과, (되묻기가 있었다면) 사용자 응답이 로그로 남아 이후 조회할 수 있다

## 범위 밖 (이번에 다루지 않음)
- 어떤 테스트 프레임워크를 쓰는지에 따른 명령어 자동 감지 로직의 세부 구현
- 특정 파일만 변경됐을 때 관련 테스트만 골라 실행하는 최적화
- CI 환경(비대화형)에서의 되묻기 대체 동작 정의

## 미해결 가정
- "되묻는다"는 훅이 커밋을 중단(block)하고 사람에게 확인을 요청하는 방식을 의미한다고 가정했다 (완전 자동 진행이 아님)
- 테스트 명령은 저장소에 이미 정의되어 있다고 가정했다 (예: package.json의 test 스크립트, 또는 지정된 커스텀 명령)
- 훅은 git의 pre-commit 단계에서 실행된다고 가정했다
