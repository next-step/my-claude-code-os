# 인수기준 — 실패 원장 최근 7일 조회 스킬

원 요구사항: "실패 원장에서 최근 7일치만 뽑아 보여주는 스킬이 필요해."

참고: 원장 파일은 `.claude/atdd-failure-ledger.json`이며 `entries` 배열에 `recordedAt`(ISO 타임스탬프), `status`(FAIL/RESOLVED), `total`/`pass`/`fail`, `failedTests`, `command` 필드를 가진다(실제 파일 확인).

## 인수기준

1. **AC-1 (기간 필터링)**
   Given 원장에 여러 시점의 `entries`가 있을 때
   When 스킬을 실행하면
   Then 실행 시점(now) 기준 `now - 7일` 이후에 `recordedAt`이 찍힌 항목만 화면에 표시한다 (7일 이전 항목은 제외).

2. **AC-2 (경계값)**
   Given 어떤 항목의 `recordedAt`이 정확히 "7일 전" 시각과 같거나 그 이후일 때
   Then 그 항목은 포함된다 (경계는 inclusive). 정확히 7일보다 더 오래된 항목은 제외된다.

3. **AC-3 (정렬)**
   Given 필터링된 항목이 여러 개일 때
   Then 최신순(내림차순, `recordedAt` 기준)으로 정렬해 보여준다.

4. **AC-4 (표시 항목)**
   Given 필터링된 항목 각각에 대해
   Then 최소한 `recordedAt`, `status`, `total`/`pass`/`fail` 개수, `failedTests` 목록을 사람이 읽을 수 있는 형태로 보여준다.

5. **AC-5 (빈 결과)**
   Given 최근 7일 안에 해당하는 항목이 하나도 없을 때
   Then 오류를 내지 않고 "최근 7일간 기록된 실패가 없습니다" 류의 안내 문구를 보여준다.

6. **AC-6 (원장 파일 없음/비어 있음)**
   Given `.claude/atdd-failure-ledger.json` 파일이 존재하지 않거나 `entries`가 빈 배열일 때
   Then 스킬이 예외로 죽지 않고 "원장이 없다"는 취지의 안내를 보여준다.

7. **AC-7 (손상된 항목 방어)**
   Given 특정 `entries` 항목에 `recordedAt`이 없거나 파싱 불가능한 값일 때
   Then 해당 항목은 건너뛰고(전체 실행이 중단되지 않고) 몇 건을 건너뛰었는지 알 수 있게 표시한다.

8. **AC-8 (읽기 전용)**
   Given 스킬을 실행해도
   Then `.claude/atdd-failure-ledger.json` 파일 내용은 어떤 방식으로도 수정·삭제되지 않는다 (기록은 훅의 몫, 조회 스킬은 읽기만 한다).

9. **AC-9 (상태 구분 없이 전량 표시 — 가정)**
   Given `status`가 `FAIL`이든 `RESOLVED`이든
   Then 최근 7일 조건만 만족하면 둘 다 표시한다.
   (미해결 가정: 요구사항 원문이 "실패"만 볼지 "실패+해결" 이력을 다 볼지 명시하지 않아, 전량 표시로 가정했다. FAIL만 보고 싶다면 별도 상태 필터 옵션이 추가 요구사항으로 필요하다.)

## 범위 밖 (이번 인수기준에 포함하지 않음)

- 같은 AC/테스트가 반복 실패하는지 분석하는 기능(집계·패턴 분석)은 포함하지 않는다 — 이번 요청은 "최근 7일 필터링/표시"로 한정한다.
- 7일 이외의 기간(30일, 사용자 지정 범위 등) 옵션은 포함하지 않는다.
- 원장 파일 포맷 변경이나 마이그레이션은 포함하지 않는다.

## 미해결 가정 (요약)

- "최근 7일"의 기준 시각은 스킬 실행 시각(now)이며, 로컬 타임존이 아닌 원장에 기록된 타임스탬프의 타임존(UTC로 보임, `Z` 접미사)을 그대로 비교한다고 가정했다.
- FAIL/RESOLVED 상태 구분 없이 모두 보여주는 것으로 가정했다(AC-9).
