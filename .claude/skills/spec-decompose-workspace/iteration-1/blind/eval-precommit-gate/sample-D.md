# 인수기준: 커밋 전 테스트 초록불 확인 훅

## 요구사항 원문

"커밋 전에 테스트가 초록불인지 확인하고 빨간불이면 되묻는 훅을 만들려고 해."

## 인수기준

AC-1. Given 사용자가 git commit을 실행하려 할 때, When PreToolUse 훅이 발동하면, Then 훅은 커밋이 완료되기 전에 테스트 스위트를 실행해야 한다.

AC-2. Given 테스트 스위트를 실행한 결과 모든 테스트가 통과했을 때, When 훅이 결과를 판정하면, Then 훅은 커밋을 그대로 진행시키고 사용자에게 개입하지 않아야 한다.

AC-3. Given 테스트 스위트를 실행한 결과 하나 이상의 테스트가 실패했을 때, When 훅이 결과를 판정하면, Then 훅은 커밋을 자동으로 차단하지 않고 사용자에게 계속 진행할지 되물어야 한다.

AC-4. Given 훅이 실패를 이유로 되묻는 상황에서, When 사용자가 "계속 진행"을 선택하면, Then 커밋이 실행되어야 한다.

AC-5. Given 훅이 실패를 이유로 되묻는 상황에서, When 사용자가 "중단"을 선택하면, Then 커밋이 실행되지 않아야 한다.

AC-6. Given 테스트 명령이 존재하지 않거나 실행 자체가 오류로 끝났을 때, When 훅이 이 상황을 감지하면, Then 훅은 이를 "빨간불"과 동일하게 취급해 사용자에게 되물어야 한다.

AC-7. Given git commit이 아닌 다른 git 하위 명령(예: status, diff, log)이 실행될 때, When 훅의 발동 조건을 검사하면, Then 훅은 테스트를 실행하거나 개입하지 않아야 한다.

AC-8. Given 테스트 스위트 실행이 정해진 시간 안에 끝나지 않을 때, When 타임아웃이 발생하면, Then 훅은 커밋을 무기한 막지 않고 실패로 간주해 사용자에게 되물어야 한다.

## 분해 근거

- AC-2와 AC-3을 분리: 정상 경로(초록불)와 예외 경로(빨간불)는 각각 하나의 조건만 검증하도록 나눴다.
- AC-4/AC-5: "되묻는다"는 응답이 진행/중단 두 갈래로 갈리므로, 되묻기 자체와 각 응답 결과를 별도 인수기준으로 분리했다.
- AC-6: "빨간불"이 테스트 실패만이 아니라 테스트 실행 자체의 오류(명령 부재 등)까지 포함할 수 있는 경계 상황이라, 같은 처리(되묻기)로 편입했다.
- AC-7: 훅의 발동 범위를 git commit으로 한정해, 다른 git 명령까지 건드리는 과도한 개입을 방지했다.
- AC-8: 대규모 테스트 스위트에서 훅이 응답 없이 무기한 멈추는 예외 상황을 별도로 반영했다.

## 셀프 체크 (policy-reviewer)

판정: **PASS**

근거:
- 정상 경로(AC-1, AC-2)와 실패 경로(AC-3~AC-6)를 모두 다룬다.
- "되묻는다"는 원문 표현을 사용자의 두 응답(계속/중단)까지 분기해 검증 가능한 형태로 구체화했다(AC-4, AC-5).
- "빨간불이면"이 테스트 실패만을 뜻하지 않을 수 있다는 암묵적 경계(테스트 명령 부재, 실행 오류, 타임아웃)를 AC-6, AC-8로 커버했다.
- AC-7로 git commit 외 하위 명령에는 개입하지 않음을 명시해 훅의 발동 범위를 명확히 했다.

참고(FAIL 사유 아님): AC-1의 "PreToolUse 훅"은 구현 메커니즘 명칭이라 원문에는 없는 표현이지만, Claude Code 훅 구현 맥락상 자연스러운 구체화로 판단됨.
