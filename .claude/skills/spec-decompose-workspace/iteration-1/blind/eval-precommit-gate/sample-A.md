# 인수기준 — 커밋 전 테스트 초록불 확인 훅

## 요구사항 원문

> 커밋 전에 테스트가 초록불인지 확인하고 빨간불이면 되묻는 훅을 만들려고 해.

## 인수기준

AC-1. Given 커밋을 시도하면, When pre-commit 훅이 실행되면, Then 훅은 커밋 전에 테스트를 자동으로 실행해야 한다.

AC-2. Given 테스트 실행 결과가 전부 통과(초록불)이면, When 훅이 결과를 판정하면, Then 커밋을 차단하지 않고 그대로 진행시켜야 한다.

AC-3. Given 테스트 실행 결과에 하나 이상 실패(빨간불)가 있으면, When 훅이 결과를 판정하면, Then 커밋을 즉시 막지 않고 사용자에게 계속 진행할지 되물어야 한다.

AC-4. Given 사용자가 되묻는 질문에 "그래도 커밋 진행"을 선택하면, When 훅이 응답을 받으면, Then 커밋이 진행되어야 한다.

AC-5. Given 사용자가 되묻는 질문에 "중단"을 선택하거나 응답하지 않으면, When 훅이 처리하면, Then 커밋이 진행되지 않아야 한다.

AC-6. Given 테스트 명령 실행 자체가 실패(명령을 찾을 수 없음, 타임아웃 등 실행 오류)하면, When 훅이 이를 감지하면, Then 이를 "테스트 실패(빨간불)"와 구분해 사용자에게 알려야 한다.

## 분해 근거

- AC-1은 정상 경로(자동 실행) 하나만 검증한다.
- AC-2/AC-3은 요구사항 문구 "초록불인지 확인하고 빨간불이면 되묻는"이 말하는 두 갈래 분기를 그대로 나눈 것이다. AC-3은 `.claude/context/hook-discipline.md`의 "훅은 막지 않는다 — deny 대신 경고나 되묻기" 원칙에 맞춰 차단이 아니라 되묻기로 명시했다.
- AC-4/AC-5는 "되묻는다"는 동작이 실제 분기를 가지려면 응답 이후 처리가 필요하므로, 되묻기 자체와 응답 처리를 별도 항목으로 나눴다.
- AC-6은 "테스트 실행 자체 실패(예: 명령 오류)"와 "테스트가 실행되어 실패함(빨간불)"을 구분하는 경계 상황이다. 이 구분이 없으면 초록불/빨간불 판정 자체가 불가능한 상태를 놓치게 된다.

## 셀프 체크 (policy-reviewer 독립 리뷰)

- 1차 판정: **FAIL** — AC-7("프로젝트별로 테스트 명령을 지정할 수 있어야 한다")이 요구사항 원문에 없는 범위 확장이라는 지적을 받아 제거함.
- 2차 판정(수정 후, AC-1~AC-6만): **PASS** — 정상 경로·두 갈래 분기·응답 후 처리·경계 상황(실행 오류)까지 요구사항 문구 범위 안에서 커버한다고 판정됨. 단, "테스트 없음(빈 스위트)" 같은 극단 케이스는 다루지 않으나 원 요구사항 수준에서 누락으로 보지 않는다는 단서가 붙음.
