# 인수기준 — 커밋 전 테스트 초록불 확인 훅

과제: 커밋 전에 테스트가 초록불인지 확인하고, 빨간불이면 되묻는 훅.

## AC-1. 훅이 커밋 시점에 실행된다
- Given: 저장소에 변경사항이 스테이징되어 커밋을 시도한다
- When: `git commit`을 실행한다
- Then: 실제 커밋이 생성되기 전에 훅이 먼저 실행된다

## AC-2. 훅이 테스트를 실행한다
- Given: 훅이 트리거되었다
- When: 훅 로직이 동작한다
- Then: 프로젝트에 정의된 테스트 명령(예: `npm test`, `node --test` 등)을 실행하고 종료 코드(exit code)를 확인한다

## AC-3. 테스트가 초록불이면 커밋을 그대로 진행한다
- Given: 테스트 실행 결과 모든 테스트가 통과했다 (exit code 0)
- When: 훅이 결과를 판단한다
- Then: 사용자에게 별도로 묻지 않고 커밋을 정상 진행시킨다

## AC-4. 테스트가 빨간불이면 커밋을 즉시 중단하지 않고 되묻는다
- Given: 테스트 실행 결과 하나 이상 실패했다 (exit code 0이 아님)
- When: 훅이 결과를 판단한다
- Then: 커밋을 곧바로 거부(deny)하지 않고, 실패 사실을 알리며 "그래도 커밋을 진행할지"를 사용자에게 확인받는다

## AC-5. 사용자가 진행을 선택하면 커밋이 완료된다
- Given: 테스트가 빨간불이라 되묻는 상태다
- When: 사용자가 "그래도 진행"을 선택한다
- Then: 커밋이 정상적으로 완료된다

## AC-6. 사용자가 중단을 선택하면 커밋이 취소된다
- Given: 테스트가 빨간불이라 되묻는 상태다
- When: 사용자가 "중단"을 선택하거나 응답하지 않는다
- Then: 커밋이 생성되지 않고, 실패한 테스트를 확인하라는 안내가 표시된다

## AC-7. 실패한 테스트 목록/요약이 사용자에게 보인다
- Given: 테스트 실행 결과 실패가 있다
- When: 사용자에게 확인을 요청한다
- Then: 어떤 테스트(들)가 실패했는지 요약(테스트 이름 또는 실패 개수 등)을 함께 보여준다

## AC-8. 테스트 명령이 저장소에 정의되어 있지 않은 경우를 처리한다
- Given: 프로젝트에 테스트 실행 명령이 설정되어 있지 않다
- When: 훅이 테스트를 실행하려 한다
- Then: 훅은 에러로 멈추지 않고, 테스트 명령을 찾을 수 없다는 사실을 알리고 커밋을 막지 않는다(또는 명시적으로 설정하라고 안내한다)

## AC-9. 훅이 없던 이전 커밋 동작을 깨뜨리지 않는다
- Given: 이 훅이 새로 추가되었다
- When: 테스트가 모두 통과하는 정상적인 커밋을 수행한다
- Then: 기존과 동일하게 별도 대기나 추가 입력 없이 커밋이 완료된다 (훅 도입 이전과 체감 동작이 같다)

## AC-10. 되묻는 절차는 자동화된 스크립트/CI 환경에서 무한 대기하지 않는다
- Given: 사용자 입력을 받을 수 없는 비대화형(non-interactive) 환경에서 커밋이 시도된다
- When: 테스트가 빨간불이다
- Then: 무한정 사용자 입력을 기다리지 않고, 사전에 정의된 기본 동작(예: 실패로 처리하여 커밋 차단, 또는 타임아웃 후 차단)으로 종료한다
