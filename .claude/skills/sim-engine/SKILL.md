# sim-engine — 모의 시뮬 엔진 (하루 루프 E단계)

> 설계 근거: docs/interviews/2026-07-08-daily-trading-loop.md (Q19~Q27)

투자 위원회(B단계)가 만든 **의도**(투자계획서의 진입 대기 주문)를, 장중 라이브 시세로 **실제
체결·보유**로 옮기는 엔진이다. 계획서는 '무엇을 하려는가'만 담고, 이 스킬이 갱신하는
포트폴리오(`data/portfolio.md`)가 **'지금 실제로 무엇을 들고 있나'의 단일 진실원천**이다.
급변이 오면 축약 긴급위를 자동 소집해 즉시 시장가로 모의 대응한다.

**전부 모의(페이퍼)다.** 이 엔진의 무인 자동 체결은 실주문이 아니다(trading-principles 루프 층 1).

작업 전 규약·정의를 Read로 먼저 읽는다:
- `.claude/context/record-conventions.md` — 상태(제자리 갱신) vs 사건(append) 분리, 기록물 5종·경로 규약.
- `.claude/context/market-glossary.md` — KRX 호가단위표·한 틱 관통 체결 규칙(결정론 사실).
- `.claude/context/trading-principles.md` — 무결성 가드레일(지어낸 값 금지)·루프 층(모의·긴급 시장가 예외).
- `.claude/context/committee-personas.md` — 위원회 7인 명단·공통 규약 인덱스. 긴급위는 이 명단에서 급변 대응 렌즈만 골라 같은 `committee-*` 에이전트를 **긴급 모드로 스폰**해 재사용한다(렌즈 정의는 각 에이전트 md가 진실원천).

## 이 엔진이 소유/하지 않는 것

- **소유**: 실제 체결·보유·현금·평가손익(`data/portfolio.md` 제자리 갱신), 체결 이벤트 박제
  (`data/fills/`), 긴급위 소집·긴급 회의록(`data/minutes/`에 '긴급' 표기 append).
- **안 함**: 주문 수량 계산(위원회가 계획서에 확정 — Q25), 정규 계획 수립(B단계 몫),
  9시 기동 트리거(항목 10 몫). 계획에 없는 기능을 붙이지 않는다(뼈대 우선/YAGNI).

## 결정론 코어 — 스크립트 두 개

판단·서술은 이 SKILL(LLM)이, **체결 판정·틱·임계 비교 같은 결정론 규칙은 스크립트**가 소유한다.

| 스크립트 | 역할 |
|----------|------|
| `scripts/krx_tick.py` | 가격대별 호가단위(한 틱). market-glossary 호가단위표의 진실원천. |
| `.claude/skills/sim-engine/scripts/fill_engine.py` | 한 틱 관통 체결 판정 + 1분 폴링 루프 + 긴급 임계 감지. `krx_tick.py`·`.claude/lib/quote.py`를 재사용(복붙 금지). |

```bash
# 한 틱(호가단위) 단건 조회
python3 "$CLAUDE_PROJECT_DIR/scripts/krx_tick.py" 70000            # → 100

# 순수 체결 판정(네트워크 없음) — 단건 확인·디버깅용
python3 "$CLAUDE_PROJECT_DIR/.claude/skills/sim-engine/scripts/fill_engine.py" \
    check --side buy --limit 70000 --price 69900                   # → filled:true, fill_price 70000

# 순수 긴급 임계 판정(네트워크 없음)
python3 "$CLAUDE_PROJECT_DIR/.claude/skills/sim-engine/scripts/fill_engine.py" \
    emergency --price 165000 --stoploss 165000 --anchor 180000
```

## 체결 규칙 (E1 · Q22·Q23)

- **대상**: 투자계획서(`data/investment-plan.md`)의 상태 라벨이 `대기`인 진입 주문만.
- **한 틱 관통**(보수적): 매수 지정가는 현재가가 **지정가 −1틱** 이하로, 매도 지정가는 **지정가 +1틱**
  이상으로 뚫려야 체결. 틱은 `krx_tick.py`로 산출.
- **체결가는 지정가로 기록**(관통가 아님). **수량은 계획서가 정한 값 그대로**(엔진은 재계산 안 함).

## 실행 절차

### 1단계 — watchlist 조립
계획서·포트폴리오를 읽어 폴링 루프에 넘길 watchlist JSON을 만든다.
- `data/investment-plan.md`의 **`대기` 주문** → `orders`(code·name·side·limit·qty).
- `data/portfolio.md`의 **보유 종목** → `positions`(code·name·qty·avg·stoploss). 손절가는
  계획서 종목 계획에서 가져온다.
- 감시할 지수 → `indices`(예: `["KOSPI","KOSDAQ"]`). 지수 급변 감시가 불필요하면 비운다.
- **포트폴리오가 없으면**(장 첫 가동) 초기 자본 **100만원·현금 100만원·보유 없음**으로
  `data/portfolio.md`를 새로 만든다(Q21). `data/` 하위 디렉터리는 `mkdir -p`로 만든다.

```json
{
  "orders":    [{"code":"005930","name":"삼성전자","side":"buy","limit":70000,"qty":10}],
  "positions": [{"code":"000660","name":"SK하이닉스","qty":5,"avg":180000,"stoploss":165000}],
  "indices":   ["KOSPI","KOSDAQ"]
}
```

### 2단계 — 1분 폴링 루프 가동 (E2 · Q19)

**반드시 백그라운드 프로세스로 띄운다**(`run_in_background: true`). poll은 15:30까지 안 끝나므로
포그라운드로 실행하면 한 턴이 6.5시간 블로킹되고 이벤트를 라이브로 못 받는다.

```bash
# run_in_background: true 로 실행 — 이 턴은 즉시 끝내고, 이벤트가 오면 재호출된다.
python3 "$CLAUDE_PROJECT_DIR/.claude/skills/sim-engine/scripts/fill_engine.py" \
    poll --watchlist <watch.json 경로>
```
- 09:00~15:30 동안 네이버 현재가를 1분(±지터·재시도) 폴링한다. 차단 회피(지터)·재시도·백오프는
  스크립트 튜닝 상수로 반영돼 있다.
- 루프는 이벤트를 **JSON 한 줄씩 emit**한다: `fill`(체결)·`emergency`(긴급 임계)·`fetch_fail`
  (시세 조회 실패)·`session_end`(장 마감). 메인 스킬이 이 이벤트를 받아 아래 3·4단계를 수행한다.
- **실행 모델(토큰 비용의 핵심):** 1분 폴링은 **순수 파이썬+네트워크라 토큰을 쓰지 않는다.**
  poll을 백그라운드로 던진 뒤 이 턴은 끝내고, 스크립트가 **이벤트 한 줄을 emit할 때만** LLM이
  재호출돼 3·4단계를 수행한다. 체결·긴급이 없는 정상 폴링은 아무것도 emit하지 않으므로, 조용한 장은
  하루 종일 유휴(토큰 0)다. **토큰 비용은 폴링 횟수가 아니라 이벤트 수에 비례한다.**
- **시세를 못 읽으면**(`fetch_fail`) 값을 지어내지 않는다 — 스킵하고 다음 폴링을 기다린다(무결성).
  연속 실패는 매 분 emit하지 않고 첫 실패·`FETCH_FAIL_REMIND_MIN`(15분) 간격으로 합쳐 알린다
  (LLM 재호출 스팸 방지). 한 번 성공하면 상태가 초기화돼 다음 실패가 새 알림으로 잡힌다.
- 단건 확인이 필요하면 `--once`(1회 폴링)로 코드 경로만 돌린다.

### 3단계 — 체결 반영: 포트폴리오 제자리 갱신 + 체결 로그 append (E3 · Q20·Q27)
`fill` 이벤트가 오면:
1. **포트폴리오 상태 제자리 갱신**(`data/portfolio.md`, 상태 문서 — 이력 쌓지 않음):
   - 매수: 현금 −(체결가×수량), 보유에 수량 추가, **평단 재계산**
     (`새 평단 = (기존 평단×기존수량 + 체결가×신규수량) ÷ 총수량`).
   - 매도: 보유 수량 차감(전량이면 제거), 현금 +(체결가×수량), 실현손익 반영.
   - 평가손익은 최신 현재가 기준으로 갱신한다(현재가는 quote 출처만).
2. **체결 로그 append**(`data/fills/YYYY-MM-DD.md`, 사건 로그 — 박제): 종목·수량·체결가·시각·
   판정 근거(이벤트 `basis`). 같은 날 재실행은 `-2`,`-3` 접미사로 새 파일(record-conventions 2).
3. **계획서 상태 라벨 갱신**(`data/investment-plan.md`): 그 종목을 `대기`→`진행중`(부분/보유)
   또는 `완료`(청산·목표 달성)로 제자리 수정. 값은 복제하지 않고 라벨만 바꾼다.

### 4단계 — 긴급위 자동 발동 (E4 · Q26·Q27)
`emergency` 이벤트가 오면(종목 급락·손절가 도달·지수 급변 — 임계는 `fill_engine.py` 튜닝 상수):
1. **축약 3~4인 소집(에이전트 부분집합 스폰)**: 정규 위원회와 **같은 `committee-*` 에이전트**를
   급변 대응 렌즈만 골라 스폰한다(새 페르소나·정의 중복 금지 — 렌즈 정의는 각 에이전트 md가
   진실원천). 기본 소집 = **리스크(`committee-risk`)·기술(`committee-technical`)·수급
   (`committee-flow`)**, 필요 시 회의론자(`committee-skeptic`)를 더한다. 각 에이전트에 넘기는 것:
   메인이 조립한 **긴급 사실판**(발동 임계·해당 종목 현재가·보유/손절/비중 현황) + **모드=긴급**.
   - **속도 우선(정규 수렴 루프와 다름)**: 긴급위는 최대 5R 수렴 루프를 돌리지 않는다. 관련 렌즈를
     **한 번에 병렬 스폰**해 개회 주장(AGREE/DISSENT)을 받고, 메인이 **즉시 종합해 결론**을 낸다
     (trading-principles 루프 층 3 — 급변 대응 속도를 위한 예외). 리스크가 강하게 DISSENT하면
     한 라운드만 더 반박을 받아 조정하되, 관통 대기 없이 그 분 안에 마무리한다.
2. **즉시 시장가 모의 체결**(관통 대기 없음): 결정된 주문을 **그 분 현재가 기준**으로 즉시 체결한다
   (trading-principles 루프 층 3 — 긴급위 즉시 시장가 예외, 모의 층에 한함).
3. **즉시 반영**: 바뀐 보유·손절·비중을 포트폴리오·계획서에 바로 반영하고, 체결을 체결 로그에
   append한다(3단계와 동일 규약).
4. **긴급 회의록 append**: `data/minutes/YYYY-MM-DD.md`에 **'긴급' 표기**로 append한다
   (record-conventions Q27 — 별도 긴급 로그를 두지 않고 회의록 로그를 공유). 담는 것: 발동 임계·
   소집 에이전트별 핵심 주장 한 줄·결정·즉시 체결 결과.

## 무결성 가드레일 (위반 불가)
- **출처 없는 수치 금지.** 현재가·체결가 근거는 `quote.py`(네이버) 출처만. 못 읽으면 스킵하고
  "확인 불가"로 둔다(지어내지 않는다 — trading-principles 무결성 1·3).
- **모든 체결에 근거를 남긴다.** 체결 로그의 판정 근거(basis)·긴급 회의록이 회고의 검증 원본이다.
- **튜닝 상수 변경은 사람 승인 후.** 임계값·폴링 간격 등 `fill_engine.py` 상수는 회고가 표본으로
  제안하고 사람이 승인해야 바꾼다(무결성 4·5 — 소표본 자동 튜닝 금지).
