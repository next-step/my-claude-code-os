# /m-plan — 시나리오를 테스트로

파이프라인 2단계. OS.md §3-2 를 실행한다. **선행 조건: 해당 사이클의 spec 이 사람 승인을 받았을 것.**

## 실행 순서

1. **phase 설정** — `.claude/phase` 에 `plan` 을 쓴다.
   ```bash
   echo "plan" > .claude/phase
   ```
2. **인터페이스 스케치** — 승인된 `specs/NNN-spec.md` 를 읽고, 모듈·타입·공개 인터페이스(시그니처)를 스케치한다. **구현 코드는 쓰지 않는다.**
3. **태스크 목록** — 각 시나리오 `SNNN` 이 매핑된 태스크 목록을 만든다.
4. **test-writer 스폰** — 시나리오 목록 + 인터페이스 스케치를 전달한다. test-writer 는 구현을 보지 않고(H2) 컴파일되는 **실패하는** 테스트를 만든다 (시나리오 1개 = 테스트 ≥1개). test-writer 가 RED 러너 출력 전문을 반환하게 한다.
5. **대응표 작성** — 시나리오 ID → 테스트 함수명 대응표를 `specs/NNN-plan.md` 에 기록한다.

## 게이트: 대응표 확인 (개입 2/3)
모든 시나리오가 테스트에 **1:1 이상** 커버되는지 사람이 확인한다 (H4). 누락된 시나리오가 있으면 test-writer 로 돌아간다.

## 산출물
- `specs/NNN-plan.md` (인터페이스 스케치 + 태스크·시나리오 대응표)
- `src/test/kotlin/**` 실패하는 테스트 코드
- RED 상태 러너 출력 전문

## 주의
- 프로덕션 코드는 만들지 않는다 (다음 단계 /m-build).
- 범위 밖(OS.md 토이 프로젝트 제약) 항목은 제안하지 않는다.
