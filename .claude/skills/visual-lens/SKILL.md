# visual-lens — 관점별 전담 눈 병렬 정밀 진단

`visual-judge`(한 눈)는 스샷 한 장에서 레이아웃·색·타이포를 **한꺼번에** 훑는다. 그래서 한 각에
눈이 쏠리면 다른 각을 뭉개고 지나간다. 이 스킬은 같은 스샷을 **관점별 전담 눈(렌즈)** 으로 나눠
**병렬**로 보게 한다 — 각 렌즈가 자기 각만 파고드니 커버리지가 올라간다.

→ `visual-confidence` 와 축이 다르다: confidence 는 **같은 눈 N번**(안정성), 이 스킬은 **다른 눈 여러 개**(사각지대 커버리지). 판정 레벨·블라인드 원칙의 배경(rubric)은 이 스킬 호출 시 훅(inject-context)이 자동 주입한다 — 파일을 다시 Read 하지 않는다.

역할 경계:
- **이미 촬영된 스샷**(`screenshots/<키>/*.png`)만 쓴다. 촬영·갤러리 빌드는 하지 않는다(필요하면 `visual-check` 가 먼저 만들어 둔다).
- 각 렌즈 판정은 **독립·블라인드**: 렌즈 에이전트는 *정답도, 다른 렌즈 결과도* 모른 채 자기 각만 보고 답한다.
- **재활용**: 렌즈는 새 에이전트가 아니라 **공유 `visual-judge` 를 렌즈 지시와 함께 재사용**한다(판정 기준이 한 곳에 모여 일관된다).

## 렌즈 3종 (전담 각)

| 렌즈 | 무엇만 보나 | 판정에서 뺄 것 |
|------|-------------|----------------|
| **layout(레이아웃)** | 정렬 틀어짐·요소 겹침·넘침·잘림·비율 어색 | 색, 폰트 자체 품질 |
| **color(색·대비)** | 배경에 묻혀 안 읽히는 텍스트, 대비 부족, 색 충돌 | **화면 전체의 균일한 절대 색차** — 프레임 안에 기준이 없어 눈으론 못 잡음(코드 측정 몫) |
| **typo(타이포)** | 글자 크기·자간·줄바꿈·잘림·폰트 어색 | 레이아웃 정렬, 색 |

> 색 렌즈의 한계는 의도된 선긋기다: AI 눈은 "이 프레임 안에서 어긋나 보이나"는 잡아도, 고립·균일 색 어긋남은 못 잡는다. 그건 `measurements.json`(코드 측정)의 몫이다.

## 절차

### 1. 대상 정하기
- 컴포넌트 키 기본값: `card`. 사용자가 지정했으면 그 키.
- 범위 — 사용자가 변형을 명시했으면 그 변형(들). 아니면 **AskUserQuestion** 으로 고른다:
  - `특정 변형 1개 정밀 진단` — 어색해 보이는 그 변형만 각도별로 파헤치기(가장 흔한 용도).
  - `전체 변형` — 관점별 매트릭스로 훑기(토큰 더 씀).
- 전제 확인:
```bash
cd demo-app && ls screenshots/<키>/measurements.json screenshots/<키>/*.png >/dev/null 2>&1 \
  && echo OK || echo "촬영 먼저 필요 — visual-check 로 캡처하세요"
```
스샷이 없으면 여기서 멈추고 `visual-check` 로 먼저 촬영하도록 안내한다.

### 2. 대상 변형 목록 뽑기
```bash
cd demo-app && node -e "const m=require('./screenshots/<키>/measurements.json'); console.log(m.map(x=>x.id).join(' '))"
```
- "특정 변형" 모드면 그 id 하나만. "전체" 모드면 전부.

### 3. 변형마다 렌즈 3개 병렬 판정 (`visual-judge` 재사용)
각 변형에 대해 **`visual-judge` 서브에이전트 3개**(렌즈당 1개)를 **한 메시지에서 동시에** 띄운다(Agent 도구, `subagent_type: visual-judge`). 한 호출당 넘기는 것은 **스샷 1장 경로 + 그 렌즈 지시 한 줄**뿐이다. **정답·다른 렌즈 결과는 절대 넘기지 않는다.**

렌즈 지시(프롬프트에 그대로 넣는다 — `<경로>` 치환):
- **layout**: `<경로> 를 판정해줘. 단 이번엔 **레이아웃만** 본다 — 정렬 틀어짐·요소 겹침·넘침·잘림·비율. 색이나 폰트 자체 품질은 판정에 넣지 마라.`
- **color**: `<경로> 를 판정해줘. 단 이번엔 **색의 대비·가독성만** 본다 — 배경에 묻혀 안 읽히는 텍스트, 대비 부족, 색 충돌. 화면 전체가 균일하게 다른 색인지 같은 절대 색차는 판정 대상이 아니다(눈으론 못 잡음).`
- **typo**: `<경로> 를 판정해줘. 단 이번엔 **타이포그래피만** 본다 — 글자 크기·자간·줄바꿈·잘림·폰트 어색함. 레이아웃 정렬이나 색은 판정에 넣지 마라.`

`visual-judge` 는 두 줄(근거 + 레벨)로 답한다 → **마지막 줄 단어(ok/warn/error)** 를 그 렌즈의 레벨로, 첫 줄을 근거로 모은다.

> 참고: 판정 일꾼은 `visual-check`·`visual-confidence` 와 같은 `visual-judge` 다. 여기서는 model/effort 를 바꾸지 않고(=sonnet/low 그대로) **각도만 좁혀** 쓴다. 정밀도가 부족하면 그때 렌즈 전용 에이전트로 분리하는 것을 검토한다(지금 규모엔 재사용이 가볍다).

### 4. 변형별 종합 — 최악 렌즈가 종합 판정
한 변형의 3개 렌즈 레벨 중 **가장 나쁜 것**(error > warn > ok)을 그 변형의 `overall` 로 한다.
`screenshots/<키>/lens.json` 에 기록:
```json
{
  "<id>": {
    "lenses": {
      "layout": { "level": "ok",   "note": "정렬·비율 정상." },
      "color":  { "level": "warn", "note": "배경에 제목이 다소 묻힘." },
      "typo":   { "level": "ok",   "note": "글자 잘림 없음." }
    },
    "overall": "warn"
  }
}
```

### 5. 표로 보고
**특정 변형 모드** — 렌즈별 세로 표:
```
🔬 <키> / <변형> 정밀 진단 (렌즈 3종)

| 렌즈 | 판정 | 근거 |
|------|------|------|
| 레이아웃 | 정상 | 정렬·비율 정상. |
| 색·대비 | ⚠ 주의 | 배경에 제목이 다소 묻힘. |
| 타이포 | 정상 | 글자 잘림 없음. |

종합: ⚠ 주의 — 색·대비 렌즈에서. (레이아웃·타이포는 정상)
```
**전체 모드** — 변형 × 렌즈 매트릭스(칸은 레벨), 종합이 나쁜 변형을 강조.

- 어느 렌즈에서 걸렸는지를 **콕 집어** 준다(한 눈으론 뭉개졌을 각). 이게 이 스킬의 값이다.
- 색 렌즈가 "정상"이어도 절대 색차는 못 본 것일 수 있음을 필요 시 한 줄로 명시한다(코드 측정 병행 권유).
