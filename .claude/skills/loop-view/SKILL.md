# Loop View — 루프가 실제로 어떻게 흘러갔는지 로그에서 재생한다

`feature-loop`는 구간을 지휘하지만 **지나간 뒤에는 아무것도 남기지 않는다.** 남는 것은 훅이 쓴 로그 두 개뿐이고,
그건 JSONL이라 눈으로 읽히지 않는다. 읽히지 않는 관측은 `OS.md` 원칙 5에서 없는 것과 같다.

이 스킬의 목적은 예쁜 그림이 아니라 **세 가지를 눈으로 확인하는 것**이다.

| 관측 | 내려야 할 결정 |
|---|---|
| 사람이 같은 자리에서 매번 불려 나온다 | 그 개입을 오른쪽으로 밀 수 있는가(원칙 6). 훅으로 옮길 수 있는가 |
| 어떤 구간의 왕복이 유독 많다 | 그 역할을 쪼갤 신호인가(`OS.md` 2절) |
| 읽는 범위 제한 없이 나간 호출이 있다 | 규칙 3이 그 구간에서 새고 있는가 |

따라서 **이 스킬의 실패는 "그림이 안 예뻐서"가 아니라 "로그에 없는 것을 있는 것처럼 그려서"** 일어난다.
로그는 루프의 일부만 담는다. 4절 해석 규칙과 5절 금지가 그 빈 곳을 메우려는 충동을 막는다.

## 0. 데이터 출처 — 무엇이 기록되고 무엇이 빠지는가

| 출처 | 파일 | 담는 것 |
|---|---|---|
| 왕복 | `.claude/agent-handoff.jsonl` | 메인 ↔ 서브에이전트 한 왕복 = 두 줄(`dispatch` / `return`) |
| 개입 | `.claude/human-intervention.jsonl` | 루프가 멈추고 사람을 부른 순간(`ask`)과 사람이 답한 순간(`answer`) |
| 루프 | `projects/*/loops/NNN-*` | 디렉터리. **로그가 없어도 목록에 나온다** |

**로그에 들어오지 않는 것** — 보고할 때 이 한계를 숨기지 않는다.

- **관문 결과와 되돌림.** `criteria-lint.py` FAIL로 ②를 다시 돈 일은 어디에도 안 남는다. 흐름도의 화살표는 항상 한 방향이다
- **배포 여부.** ⑤는 서브에이전트가 없어 왕복이 안 생긴다. 「도달 구간에 ⑤가 없다」는 배포 안 됨이 아니다
- **루프 세션 밖의 일.** `loop-session.sh`가 `feature-loop`로 시작한 세션에만 표식을 단다. 그 밖은 통째로 빠진다
- **훅 설치(2026-08-30) 이전 루프.** 001·002가 여기 해당한다. 돌지 않은 것이 아니다
- **서브에이전트가 실제로 한 일.** 로그에 남는 건 프롬프트 요약 2줄과 바이트 수뿐이다

### 한 세션에 오케스트레이터가 둘일 수 있다

`feature-loop`를 끝내고 같은 세션에서 `skill-forge`를 이어 돌리면 **그 왕복도 이 루프에 이어붙는다.**
세션이 하나이기 때문이다. 그래서 스크립트는 **루프의 주인 오케스트레이터 구간만 기본으로 보여준다.**

가르는 근거는 **사람이 친 `/스킬명`** 하나뿐이다. 그 입력부터 다음 `/스킬명`까지가 그 오케스트레이터의 구간이고,
`.claude/skills/`에 실제로 있는 이름일 때만 전환으로 친다.
**라벨 모양으로 가르지 않는다** — 「`검토자`는 `skill-forge` 것」은 추측이고, 라벨은 언제든 바뀐다.

접힌 구간은 헤더의 `범위` 줄이 몇 건인지·언제인지 말해 준다. `--all-orch`로 펼친다.
첫 `/스킬명` 이전 줄은 주인을 모르므로 접지 않고 그대로 둔다.

구간 표의 `그중 ~N`은 그 구간의 왕복 중 몇 개가 **세션으로 이어붙인 것**인지다. 접기와는 다른 축이다.

### 루프 귀속은 절반이 추정이다

훅은 프롬프트에서 루프 경로를 못 찾으면 `loop`을 `-`로 둔다(추측해서 쓰면 틀린 데이터가 굳으므로).
그래서 실제 로그는 대부분 `-`다. 스크립트는 **같은 세션 안에서만** 이어붙이고 그 줄에 `~`를 붙인다.
세션 밖 추측(「최근에 고친 루프일 것」)은 하지 않는다. `~`가 붙은 줄은 사실이 아니라 이어붙인 것이다.

## 1. 순서 — 목록 먼저, 그다음 하나

### ① 루프 목록을 내고 고르게 한다

```bash
python3 .claude/skills/loop-view/view.py --list
```

출력을 **그대로** 보여준 뒤 `AskUserQuestion`으로 고르게 한다. 선택지는 **가장 최신 3~4개**만 올린다.
그보다 옛 루프는 위 표에 이미 번호와 함께 찍혀 있으므로 사용자가 「Other」에 이름을 적으면 된다.

사용자가 처음부터 루프를 지목했으면(`003 보여줘`, `삭제 루프 흐름`) **이 단계를 건너뛴다.**
목록은 고르기 위한 것이지 매번 거쳐야 하는 관문이 아니다.

### ② 고른 루프의 흐름을 시각화한다

```bash
python3 .claude/skills/loop-view/view.py 003            # 003 · 003-delete-note · 제품/003-... 모두 받는다
python3 .claude/skills/loop-view/view.py 003 --full     # 접은 진행 알림까지 전부
python3 .claude/skills/loop-view/view.py 003 --mermaid  # 흐름도(mermaid flowchart)
python3 .claude/skills/loop-view/view.py 003 --all-orch # 같은 세션의 다른 오케스트레이터 구간까지
```

즉석에서 `jq`나 `awk` 파이프라인을 새로 짜지 않는다. 같은 루프를 볼 때마다 다른 그림이 나오면 그건 재생이 아니다.
스크립트가 부족하면 **스크립트를 고친다.** 일회용 명령으로 우회하지 않는다.

## 2. 출력 읽는 법

```
 20:24  ②    ─▶ PM: 수용 기준 작성            4.4KB  격리✓  feature-pm
 20:24  ②    ◀─ PM: 수용 기준 작성               0B  2s  ⚠ 빈 응답
~20:59  ④    ─▶ Reviewer: 기준 대조           2.4KB  격리✗  general-purpose
 21:12  ▣    ◀─ 사람입력 진행                     6B  26s
```

| 기호 | 뜻 |
|---|---|
| `─▶` / `◀─` | 내보냄 / 돌아옴. 사람 줄에서는 루프가 물음 / 사람이 답함 |
| `②③④` | `feature-loop`의 단계 번호. ①·⑤는 서브가 없어 왕복이 안 생긴다 |
| `▣` · `▣?` | 사람 개입 · 그중 사람에게 **물은** 것 |
| `~` | 루프 이름이 그 줄에 없어 **세션으로 이어붙인** 줄 |
| `격리✓` / `격리✗` | 이 호출에 **읽는 범위 제한이 걸려 있었는지**. 판정이 아니라 관측이다 |
| 맨 끝 열 | 어떤 **역할 타입**으로 띄웠는지(`.claude/agents/`). `general-purpose`면 도구 제한이 안 걸린 호출이다 |
| `⚠ 빈 응답` | `return`이 빈 채로 찍혔다. 서브가 배경으로 돌았다는 뜻 |
| `자동` | `<task-notification>`. 훅은 `사람입력`으로 남기지만 사람이 친 것이 아니다 |
| `범위` 줄 | 같은 세션의 다른 오케스트레이터 구간을 몇 건 접었는지 |

## 3. 해석 규칙 — 타협하지 않는다

1. **`dur_s`를 서브에이전트의 작업 시간으로 읽지 않는다.** `⚠ 빈 응답`이 붙은 왕복은 배경 실행이라
   `return`이 즉시 찍혔다. 2초는 디스패치에 걸린 시간이지 일한 시간이 아니다.
2. **`격리✗`를 규칙 위반으로 단정하지 않는다.** 프롬프트에도, 띄운 역할 타입의 정의에도 그 문장이
   없었다는 사실만 기록된 것이다. 지적할 값은 있지만 판정은 프롬프트를 직접 봐야 한다.
   **`격리✓`가 무엇으로 충족됐는지는 로그의 `isolation_by`에 있다**(`prompt` / `agent`).
   맨 끝 열이 `feature-*`면 에이전트 파일이, `general-purpose`면 프롬프트가 들고 있던 것이다.
3. **`kind`를 원칙 6의 네 단계(의사결정 → 승인 → 기준 제공 → 시작 버튼)로 재분류하지 않는다.**
   훅이 일부러 하지 않은 일이다. 추측한 분류를 출력에 쓰면 그게 사실로 굳는다. 분류는 사람이 요약을 읽고 한다.
4. **`~` 줄을 확정 사실처럼 말하지 않는다.** 「이 루프에서 그랬다」가 아니라 「같은 세션에 있었다」까지가 근거다.
5. **루프 하나로 경향을 말하지 않는다.** 「사람 개입이 많다」는 두 루프 이상을 비교한 뒤에 할 말이다.
6. **숫자는 스크립트 출력에서만 인용한다.** 눈대중으로 합산하거나 반올림해 다시 쓰지 않는다.
7. **접힌 구간을 「없었던 일」로 쓰지 않는다.** `범위` 줄이 몇 건을 접었는지 말해 준다.
   그 왕복은 실제로 있었고, 다만 다른 오케스트레이터의 것이다. 왕복 수를 인용할 때 어느 범위인지 함께 밝힌다.
8. **루프 세션 안에서 이 스킬을 부르면 목록 선택이 그 루프의 개입으로 기록된다.** 보는 행위가 관측을 바꾼다.
   `feature-loop`가 도는 중에 불렀다면 그 사실을 밝히고, 방금 늘어난 `의사결정` 한 줄을 경향으로 읽지 않는다.

## 4. 금지

- ❌ **로그를 고쳐 그림을 맞추지 않는다.** 두 `.jsonl`은 append-only 관측 기록이다. 읽기만 한다
- ❌ **로그에 없는 구간을 그리지 않는다.** 관문 되돌림·배포 성공 여부는 기록되지 않는다. 없으면 없다고 쓴다
- ❌ **「도달 구간에 ⑤가 없다」를 루프 미완으로 보고하지 않는다.** ⑤는 원래 왕복이 안 생긴다
- ❌ **「로그 없음」을 「돌지 않은 루프」로 쓰지 않는다.** 훅 설치 이전 구간이다
- ❌ **이 스킬 안에서 `feature-loop`를 부르거나 서브에이전트를 띄우지 않는다.** 이건 뷰어지 오케스트레이터가 아니다
- ❌ **훅·설정을 임의로 고치지 않는다.** 로그가 비면 무엇이 빠졌는지 알리고, 고칠 것은 제안까지만 한다

## 5. 보고 형식

스크립트 출력을 그대로 보여준 뒤 **관찰 → 근거 → 제안** 세 줄을 붙인다. 표만 던지지 않는다.

```
(스크립트 출력)

관찰: ④ Reviewer만 왕복 3회로 병렬이고, 그 셋 모두 읽는 범위 제한 없이 나갔습니다.
근거: 흐름의 20:59~21:00 세 줄이 전부 `격리✗`입니다.
제안: feature-loop 4절 프롬프트 규격에서 Reviewer 쪽에 그 문구가 빠졌는지 확인해 보세요.
```

제안은 **최대 2개**. 데이터가 뒷받침하지 않는 제안은 하지 않는다.

`--mermaid`로 뽑은 흐름도는 그대로 붙여 보여준다. 사용자가 공유할 페이지를 원할 때만 아티팩트로 낸다.

## 6. 인자

| 인자 | 동작 |
|---|---|
| (없음) · `--list` | 루프 목록, 최신순 |
| `003` · `003-delete-note` · `review-scheduler/003-delete-note` | 그 루프의 흐름 |
| `--full` | 접은 진행 알림(`알림`·질문 없는 `턴종료`)까지 모두 |
| `--all-orch` | 같은 세션에서 다른 오케스트레이터가 돈 구간까지 포함 |
| `--mermaid` | 흐름을 mermaid flowchart로 |
| `--json` | 기계용 출력 (문서에 넣거나 다른 도구로 넘길 때) |
| `--root PATH` | 저장소 루트 지정 |

종료 코드 — `0` 정상 / `1` 루프를 못 찾음(후보를 함께 출력) / `2` 저장소 루트가 아님.

## 출력 전 자기 점검

- [ ] 목록을 먼저 보여주고 골랐는가 (사용자가 루프를 지목한 경우는 건너뛰어도 된다)
- [ ] 숫자와 시각을 스크립트 출력에서 그대로 옮겼는가 (직접 세지 않았는가)
- [ ] `~`가 붙은 줄을 확정 사실처럼 쓰지 않았는가
- [ ] 왕복 수를 인용할 때 접힌 구간이 있었는지 함께 밝혔는가
- [ ] `dur_s`를 작업 시간으로, `격리✗`를 위반 판정으로 읽지 않았는가
- [ ] `kind`를 원칙 6의 네 단계로 재분류하지 않았는가
- [ ] 로그가 없거나 깨진 줄이 있었다면 그 사실을 알렸는가
- [ ] 제안이 2개 이하이고, 각각 출력의 어떤 줄에서 나왔는지 말할 수 있는가
