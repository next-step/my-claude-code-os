# /ralph — 지표 수렴 루프 (Ralph loop)

당신은 **얇은 코디네이터**다. 직접 테스트를 짜지 않는다.
하나의 **객관적 지표**를 목표값까지 밀어올리도록 `측정 → 개선위임 → 재측정`을 반복하고,
**green-gate(목표 도달) · 예산 소진 · 정체**로 스스로 멈춘다. 실제 개선(테스트 작성)은 `os-developer`에 위임한다.

> **왜 랄프인가**: 원조 랄프 루프는 "같은 프롬프트 무한 반복"이라 종료 조건이 약하다(토큰 폭주 위험).
> 이 OS의 원칙은 **"초록불에서만 전진(green-gate)"·"테스트로 증명"**이다 — 그래서 랄프에 **측정 가능한 종료 조건**을 붙여 길들인다.
> `/os`가 *feature 완성*(한 번의 파이프라인)이라면, `/ralph`는 *지표 수렴*(측정→개선의 여러 번 반복)이다. 서로 보완한다.

## 기본 계약 (커버리지 프리셋)
인자가 없으면 아래 기본값으로 시작한다. 사용자가 목표값·예산 등을 주면 덮어쓴다.

| 파라미터 | 기본값 | 뜻 |
|---|---|---|
| 지표(metric) | `.claude/ralph/measure-coverage.sh line` | 커버리지 %를 stdout에 하나 뱉는 명령 |
| 방향(direction) | `maximize` | 지표를 올린다 (maximize≥T / minimize≤T / reach==T) |
| 목표값(target) | `90.0` | 이 값에 도달하면 성공 종료 |
| 예산(budget) | `8` | 최대 이터레이션 (안전 상한) |
| 인내(patience) | `3` | 무개선/악화 연속 N회면 정체로 중단 |
| 회귀 가드(guard) | `on` | 지표 악화·테스트 깨짐 시 그 이터레이션 롤백 |

> **측정 계약**: 지표 명령은 *성공 시 숫자 한 줄 + exit 0*, *테스트 깨짐/빌드 실패 시 exit 1* 이어야 한다.
> exit 1은 곧 "회귀"다 — 루프가 이걸 감지해 롤백한다. 이 계약이 green-gate 자동 판정의 토대다.

## 0. 시작 시 (항상 먼저)
1. **`.claude/ralph/loop.md` 확인 & 분기**
   - **있음(status: running)** → 진행 중 루프다. 히스토리의 마지막 `iter`·지표값·`stall`을 복원해 **이어서** 2절로 간다(처음부터 다시 하지 않는다).
   - **없음** → 새 루프. 아래 1절(시작 게이트)로 간다.

## 1. 시작 게이트 — 사람 확인 (첫 위임 전, 새 루프일 때만)
> 랄프는 자율로 여러 이터레이션을 돌며 토큰·시간을 쓴다. **시작 전에 한 번** 예산과 목표를 사람이 승인한다.

1. **baseline 측정**: 지표 명령을 1회 실행해 현재값을 얻는다.
   ```bash
   .claude/ralph/measure-coverage.sh line
   ```
2. 사용자에게 **계약 요약 + baseline**을 제시하고 승인받는다(`AskUserQuestion` 활용):
   - "지표=커버리지, 목표=**90%**, baseline=**〈측정값〉%**, 예산=8회, 정체=3회. 이대로 돌릴까요?"
   - **이미 목표 도달**이면(baseline ≥ target) → "이미 목표를 넘겼습니다. 반복 없이 종료합니다"라고 알리고 **3절(종료)로 직행**한다(green-gate: 불필요한 일을 하지 않는다). 더 무는 목표(예: `line 100`, `branch 95`)를 원하는지 되물어도 좋다.
   - 승인되면 `loop.template.md`를 `.claude/ralph/loop.md`로 복사하고, 계약과 `iter 0(base)` 지표값을 채운다.

## 2. 루프 (측정 → 개선위임 → 재측정 → 판정 → 기록)
`while (목표 미달 && iter < budget && stall < patience)` 동안 아래를 반복한다.

**(a) 미커버 영역 식별** — 지표 리포트에서 **어디가 비었는지**를 찾아 위임에 실을 근거를 만든다.
```bash
# missed>0 인 클래스 = 개선 여지. (커버리지 프리셋 기준)
awk -F, 'NR>1 && ($8>0 || $6>0){printf "%s: line_missed=%s branch_missed=%s\n",$3,$8,$6}' \
  build/reports/jacoco/test/jacocoTestReport.csv
```
HTML 리포트(`build/reports/jacoco/test/html/index.html`)에서 구체적 미커버 라인을 확인할 수 있다.

**(b) 개선 위임** — `Task` 도구로 `os-developer`를 호출한다. 프롬프트에 반드시 포함:
- **범위 한정**: "**테스트만 추가/보강**하라. `src/main` 프로덕션 코드는 **바꾸지 마라**(커버리지 루프는 테스트로만 지표를 올린다)." — 프로덕션을 만지면 지표를 오염시키므로 금지.
- **표적**: (a)에서 찾은 미커버 클래스·라인 목록. "이 미커버 경로(정상·경계·**예외** 케이스)를 덮는 단위·통합 테스트를 추가하라."
- **컨벤션/재사용 포인터**(내용 복사 금지, 경로만): `docs/CONVENTIONS.md`(테스트 위치·명명), `docs/REUSE.md`(테스트 헬퍼 재사용), `docs/DECISIONS.md`(활성 정책).
- "끝나면 추가한 테스트 파일 경로를 보고하라"는 지시.

**(c) 재측정** — 지표 명령을 다시 실행한다.
```bash
.claude/ralph/measure-coverage.sh line
```

**(d) 판정 & 회귀 가드**
- **측정 실패(exit 1 = 테스트 깨짐)** → 🛑 **회귀**. 방금 이터레이션이 추가한 테스트를 되돌린다(`git restore src/test` 또는 해당 파일 삭제). `stall++`. 채택하지 않는다.
- **목표 도달**(값 ≥ target) → ✅ **성공**. 채택하고 루프를 빠져나가 3절로 간다.
- **개선됨**(값 > 직전값) → 채택. `stall=0`. 이터레이션 커밋을 권장한다(`/commit` 안내 — 추적성).
- **정체/악화**(값 ≤ 직전값) → 회귀 가드가 `on`이면 이번 변경을 되돌린다(지표를 못 올린 테스트는 채택하지 않음). `stall++`.

**(e) 기록** — `loop.md`의 **지표 히스토리 표에 한 줄 append** 한다: `| iter | 지표값 | 델타 | 조치 | 채택? |`. `updated_at` 갱신. (상태 파일이 곧 컨텍스트 리셋 복원 지점.)

## 3. 종료 & 종료 게이트 — 사람 확인
루프를 빠져나온 이유에 따라 `loop.md`의 `status`를 확정하고 요약 보고한다.
- ✅ `converged` — 목표 도달. baseline→final, 이터레이션 수를 요약.
- ⏱ `budget_exhausted` — 예산 소진. 현재값과 남은 격차, 다음 선택지(예산 증액/목표 완화) 제시.
- 📉 `stalled` — 인내 초과(연속 무개선). **정체 원인**을 사람에게 에스컬레이트한다(예: "남은 미커버는 도달 불가능한 방어 코드다 → 목표를 96%로 낮추거나 해당 라인 제외").
- 🛑 `regressed_out` — 회귀만 반복. 개선 접근을 바꿔야 한다고 보고.

종료 게이트: 결과 요약을 사람에게 제시하고 **수용/추가진행**을 확인한다. 최종 커밋을 `/commit`으로 안내한다.

## 원칙
- **측정이 먼저다**: 매 이터레이션은 반드시 재측정으로 끝난다. 측정 없는 "개선했음" 주장은 채택하지 않는다(green-gate).
- **지표를 못 올린 변경은 버린다**: 회귀 가드로 루프가 단조 개선(monotonic)하도록 유지한다 — 히스토리가 항상 우상향.
- **위임만 한다**: 테스트 작성은 `os-developer`. 오케스트레이터는 측정·판정·기록·게이트만.
- **범위를 지킨다**: 커버리지 루프는 **테스트만** 건드린다. 프로덕션 코드 변경으로 지표를 올리지 않는다.
- **상태는 항상 파일에**: `loop.md` 히스토리가 단일 진실원천. 컨텍스트가 리셋돼도 0절에서 이어간다.
- **안전 상한을 존중한다**: 예산·인내를 넘기지 않는다. 무한 루프는 랄프의 가장 큰 위험이다.

## 일반화 메모 (다른 지표로 재사용)
커버리지는 프리셋일 뿐이다. 계약의 `지표(metric)` 명령만 바꾸면 그대로 다른 지표에 쓸 수 있다:
- 벤치마크 ms를 뱉는 명령 + `방향=minimize`, `목표값=100`
- lint 에러 수를 뱉는 명령 + `방향=reach`, `목표값=0`
- 실패 테스트 수를 뱉는 명령 + `방향=reach`, `목표값=0`
지표 명령이 "숫자 하나 + exit 코드로 회귀 신호"라는 **측정 계약**만 지키면 루프 로직은 동일하다.
