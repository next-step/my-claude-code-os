# ralph — 랄프 루프 (목표 달성까지 반복 실행)

`git-commit` · `skill-stat` 처럼 **정해진 순서**를 따른다.
목표를 못 맞춰도 지표를 조작하거나 "대충 됐다"고 넘기지 않는다 — 상한 이터레이션에 닿으면 중단으로 보고한다.

랄프 루프의 원리(Day3 강의자료):

- 진행 상황을 LLM 기억이 아니라 **파일**에 저장한다 → 컨텍스트가 오염되면 세션을 버리고
  새 에이전트가 파일에 쌓인 결과를 보고 이어간다.
- 그래서 이 스킬은 **이터레이션마다 새 서브에이전트**를 띄운다. 서브에이전트는 호출마다 새 세션이라
  이전 이터레이션을 기억하지 못하고, `PROMPT.md` 와 `lessons.md` 만이 유일한 맥락이다
  (`OS.md` §5 원칙 6 "공유는 정의 재사용이지 기억 공유가 아니다" 와 같은 구조).

## 파라미터

| 이름 | 필수 | 기본값 | 설명 |
| --- | :---: | --- | --- |
| `목표` | O | — | 자연어 종료 상태. `PROMPT.md` 에 고정된다. 예: "삭제 endpoint 추가 — 성공 204, 없는 id 404" |
| `지표` | O | — | **셸에서 O/X 가 나오는 명령.** 종료코드 0 = 통과. 예: `cd sandbox/board && python3 -m pytest -q` |
| `--slug` | X | 목표에서 생성 | 루프 산출물 폴더 이름 (`maintenance/loops/<slug>/`) |
| `--최대-이터` | X | `10` | 이 횟수에 닿으면 목표 미달이어도 중단 (Day3 자료: "또는 20턴 후 중단" 상한 개념) |
| `--연속-통과` | X | `2` | 지표를 연속 N회 통과해야 진짜 종료 (비결정성 흡수 · Sellop 사례의 "연속 3번 통과") |
| `--작업폴더` | X | 프로젝트 루트 | 서브에이전트가 수정할 범위 힌트 |

## 절차

### 0. 선행 조건

- `지표` 명령을 **지금 한 번 그대로 실행**해 본다. 명령이 에러(문법·경로)로 죽으면 루프를 시작하지 않고
  사용자에게 지표를 다시 받는다. "실패(종료코드 ≠ 0)"는 정상 — 그게 시작 상태다.
- `지표` 가 테스트 통과를 포함하면, **테스트 파일을 고쳐서 통과시키는 치팅**을 막을 장치가 지표 안에 있는지 본다.
  없으면 0단계에서 테스트 파일들의 체크섬을 스냅샷하고, 지표 뒤에
  `&& shasum -a 256 <테스트파일들> | diff -q - <스냅샷>` 를 붙여 확장한다.

### 1. 루프 폴더 준비

`maintenance/loops/<slug>/` 를 만들고 세 파일을 둔다.

- **`PROMPT.md`** — 한 번 쓰고 고정. 이터레이션마다 그대로 주입된다. 담을 것:
  - `## 목표` — `목표` 파라미터 원문
  - `## 완료 판정` — `지표` 명령 전문. "이 명령의 종료코드가 0이어야 한다"
  - `## 제약` — 수정 허용 범위(`--작업폴더`), 건드리면 안 되는 것(테스트 파일 등),
    "너는 독립 컨텍스트다. 이 파일과 lessons.md 외의 맥락은 없다"
  - `## 반환 형식` — 이터레이션 끝에 서브에이전트가 돌려줄 3줄: 무엇을 바꿨나 / 지표 결과 / 다음 이터가 알아야 할 교훈
- **`lessons.md`** — 헤더 한 줄만 두고 시작. 이후 **append 전용**.
- **`result.md`** — 이터별 스냅샷 표의 헤더만 두고 시작:
  `| 이터 | 상태 | 무엇을 바꿨나 | 지표 결과 |`

### 2. 베이스라인 측정

`지표` 명령을 1회 실행해 시작 상태를 `result.md` 의 `이터 0` 행에 적는다 (보통 FAIL).

### 3. 이터레이션 루프

`streak = 0`. `iter = 1` 부터 `--최대-이터` 까지 반복:

1. **서브에이전트 스폰** — `Task` 로 `general-purpose`(또는 프로젝트에 맞는 코딩 에이전트) 1개.
   프롬프트에 넣을 것: `PROMPT.md` 전문 + `lessons.md` 전문 + 직전 이터의 지표 실패 로그(있으면).
   지시: "독립 컨텍스트에서 목표를 향해 `--작업폴더` 안의 코드를 고쳐라. 지표 명령을 직접 돌려 확인해도 되지만
   **최종 판정은 메인이 한다.** 끝나면 `PROMPT.md` 의 `## 반환 형식` 대로 3줄만 반환하라."
2. **메인이 지표 판정** — 서브에이전트가 끝나면 **메인 세션이** `지표` 명령을 실행한다.
   종료코드 0 → `PASS`, 아니면 `FAIL`. 출력은 마지막 20줄만 캡처한다(메인 컨텍스트 절약).
3. **`lessons.md` append** — `## 이터 {iter} ({PASS|FAIL})` 아래 세 줄:
   `- 바꾼 것:` / `- 지표:` / `- 교훈:` (서브에이전트 반환 + 메인 판정 결과를 합쳐서).
   **덮어쓰지 않는다.**
4. **`result.md` 행 추가** — `| {iter} | {PASS/FAIL} | {한 줄 요약} | {지표 결과 요약} |`
5. **종료 조건**:
   - `PASS` → `streak += 1`. `streak == --연속-통과` 면 **성공 종료**.
   - `FAIL` → `streak = 0`.
   - `iter == --최대-이터` 인데 아직이면 **중단 종료**.

### 4. 마무리 보고

- 결과(성공 / 중단), 총 이터레이션 수, `result.md` 경로를 보고한다.
- 성공이면 `--작업폴더` 의 최종 `git diff --stat` 를 요약한다.
- 중단이면 `lessons.md` 에서 반복적으로 걸린 지점을 3줄 이내로 짚고, 다음 시도에 바꿀 만한 것을 제안한다.
- **커밋하지 않는다.** 사용자가 결과를 보고 직접 `/git-commit` 을 부른다.

## 하지 말 것

1. **지표를 사람 눈으로 판정하지 않는다.** "잘 도는 것 같다"로 PASS 처리 금지 — 오직 지표 명령의 종료코드.
2. **`--최대-이터` 없이 돌리지 않는다.** 상한 없는 루프 금지.
3. **Headless(`claude -p`) 무한 bash 루프로 구현하지 않는다.** `Task` 서브에이전트 방식만.
   (Day3 자료 §엔지니어링 01: 앤트로픽이 Headless 에 별도 과금·민감, 현재는 서브에이전트 권장)
4. **메인 세션이 직접 목표 코드를 고치지 않는다.** 코딩은 매 이터 새 서브에이전트에 위임한다 —
   그래야 이터레이션별 독립 컨텍스트가 유지된다.
5. **`lessons.md` 를 덮어쓰지 않는다.** append 만. 이력이 지워지면 루프가 같은 실수를 반복한다.
6. **지표가 테스트를 포함할 때, 서브에이전트가 테스트 파일을 고쳐 통과시키게 두지 않는다.**
   0단계의 치팅 방지 장치(체크섬 diff 등)를 지표에 반드시 포함한다.
7. 목표를 못 맞췄는데 맞춘 것처럼 보고하지 않는다. 중단은 중단으로 적는다.

## Gotcha

- **지표 명령에 `| tail` 같은 파이프를 붙이면 종료코드가 파이프 마지막 명령의 것이 된다** —
  `pytest` 가 실패해도 `tail` 이 0 을 내서 **거짓 PASS** 가 난다. 지표는 `&&` 로만 연결하고
  (`pytest -q && shasum ... | diff -q ...`), 출력은 별도 파일로 리다이렉트한 뒤 필요한 줄만 본다.
  (board-delete 루프 1회차, 2026-09-09)
