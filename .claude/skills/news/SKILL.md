# News — 오늘의 AI 뉴스 다이제스트

오늘 나온 AI 뉴스 **30건**을 수집해 중복 없이, 출처 링크와 함께 정리한다.

이 스킬의 실패는 "못 찾아서"가 아니라 **"그럴듯한 걸 지어내서"** 일어난다.
검색 결과가 부족할 때 기억으로 빈칸을 채우는 것이 유일하게 치명적인 실패다. 아래 검증 규칙이 그것을 막는다.

## 0. 기준 날짜 확정

먼저 Bash로 오늘 날짜를 확인한다. 컨텍스트의 날짜를 믿지 말고 실제로 조회한다.

```bash
date +%Y-%m-%d
```

"오늘"의 기본 범위는 **최근 24시간**이다. 주말·공휴일이라 뉴스가 적으면 48시간까지 넓히되,
**넓혔다는 사실을 결과에 반드시 명시한다.**

## 1. 수집 — 토픽 버킷별 병렬 검색

`AI 뉴스` 한 번만 검색하면 같은 기사 30개가 나온다. 반드시 버킷으로 쪼갠다.

| # | 버킷 | 검색어 예시 |
|---|---|---|
| 1 | 모델 릴리스 | 새 모델 출시, 버전 업데이트, 벤치마크 결과 |
| 2 | 제품·기능 | AI 제품 출시, 기존 서비스의 AI 기능 추가 |
| 3 | 연구·논문 | 주요 논문, 연구 성과, arXiv 화제작 |
| 4 | 기업·투자 | 펀딩 라운드, 인수합병, 실적 발표 |
| 5 | 정책·규제 | 법안, 규제 동향, 소송, 저작권 분쟁 |
| 6 | 오픈소스 | 오픈 웨이트 모델, 주요 저장소 릴리스 |
| 7 | 인프라·반도체 | GPU·칩, 데이터센터, 전력, 클라우드 |
| 8 | 사건·안전·논란 | 사고, 유출, 오용, 안전성 논란, 인력 이동 |

**버킷당 4~5건**을 목표로 검색한다(32~40건 확보 → 정제 후 30건).
**WebSearch 호출은 한 응답에 여러 개를 동시에 보낸다.** 순차 호출하면 8배 느려진다.

한국어·영어 양쪽으로 검색한다. 국내 소식은 한국어 검색에서만 나오고,
글로벌 소식은 영어 검색이 빠르다.

사용자가 토픽을 지정했다면(예: `/news 반도체`) 해당 버킷에 가중치를 두되, 나머지 버킷도 최소 1건씩은 유지한다.

## 2. 검증 — 이 규칙은 타협하지 않는다

각 항목은 아래를 **전부** 만족해야 목록에 올린다.

1. **출처 URL이 있다.** 링크 없는 항목은 버린다. 기억에 의존해 링크를 구성하지 않는다.
2. **발행일이 기준 범위 안이다.** 검색엔진은 오래된 기사를 자주 올려보낸다. 날짜를 확인하고, 확인이 안 되면 버린다.
3. **요약이 검색 스니펫의 복붙이 아니다.** 스니펫만으로 내용이 불충분하면 WebFetch로 본문을 읽는다.
   특히 헤드라인 TOP 3는 **반드시 본문을 확인**한다.
4. **숫자·고유명사는 출처에 실제로 있는 값이다.** 투자 금액, 벤치마크 점수, 파라미터 수를 추정해 쓰지 않는다.

## 3. 중복 제거

같은 사건을 여러 매체가 보도한 것은 **1건**으로 합친다.
채택 우선순위: **1차 출처**(회사 공식 블로그·릴리스·논문 원문) > 전문 매체 > 일반 매체 > 애그리게이터.

합쳐진 경우 요약 끝에 `(외 N개 매체 보도)`를 붙인다.

## 4. 출력 형식

30건을 그냥 나열하면 읽히지 않는다. 반드시 헤드라인을 먼저 뽑는다.

```markdown
# AI 뉴스 다이제스트 — YYYY-MM-DD

수집 30건 · 기준 범위 최근 24시간

## 오늘의 헤드라인

1. **[제목](URL)** — 왜 오늘 가장 중요한지 한 줄
2. **[제목](URL)** — 〃
3. **[제목](URL)** — 〃

---

## 모델 릴리스

**1. [제목](URL)**
출처 · 발행일
무엇이 일어났는지 1~2줄.
→ 의미: 왜 중요한지 한 줄.

**2. [제목](URL)**
...

## 제품·기능
...
```

번호는 버킷을 가로질러 **1~30 연속**으로 매긴다. 총 몇 건인지 즉시 보이게 하기 위해서다.
빈 버킷은 섹션 자체를 생략한다(`해당 없음`이라고 쓰지 않는다).

## 5. 30건이 안 될 때

**절대 채우지 않는다.** 실제 개수를 밝히고, 부족한 이유를 한 줄로 적는다.

```
수집 24건 (목표 30건 미달 — 주말이라 신규 보도가 적음)
```

24건의 진짜 뉴스가 30건의 절반이 가짜인 목록보다 낫다.
목록을 채우려고 관련성 낮은 기사나 오래된 기사를 끌어오는 것도 같은 실패다.

## 6. 저장 (선택)

사용자가 `--save`를 붙였거나 저장을 요청하면 `docs/news/YYYY-MM-DD.md`에 쓴다.
같은 날짜 파일이 이미 있으면 **덮어쓰기 전에 사용자에게 확인**한다.

## 출력 전 자기 점검

응답을 내보내기 직전에 아래를 확인한다. 하나라도 아니면 고치고 나서 출력한다.

- [ ] 모든 항목에 클릭 가능한 출처 URL이 있는가
- [ ] 같은 사건이 두 번 등장하지 않는가
- [ ] 모든 항목의 발행일이 기준 범위 안인가
- [ ] 요약이 제목을 다시 쓴 것에 그치지 않는가 (`→ 의미` 줄이 제목의 반복이 아닌가)
- [ ] 30건이 아니라면 실제 개수와 이유를 밝혔는가
- [ ] 본문을 읽지 않고 스니펫만으로 쓴 항목이 헤드라인 TOP 3에 있지 않은가
