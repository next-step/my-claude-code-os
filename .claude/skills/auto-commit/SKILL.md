# Auto Commit

코드 변경사항을 분석해서 의미 있는 커밋 메시지를 한국어로 자동 생성하고 커밋까지 수행합니다.

인자로 브랜치명을 받으면 해당 브랜치에, 없으면 현재 브랜치에 커밋합니다.

---

## 1단계: 브랜치 확인 및 변경사항 파악

먼저 커밋 대상 브랜치를 결정합니다:

```bash
# 현재 브랜치 확인
git branch --show-current
```

- 인자로 브랜치명이 주어진 경우: `git checkout <브랜치명>` 으로 전환 후 진행
- 인자가 없는 경우: 현재 브랜치 그대로 진행

확인된 브랜치명에서 커밋 메시지의 scope를 추출합니다 (규칙은
[conventions.md](../../docs/commit-conventions.md) "scope 결정 기준" 참고):

- 브랜치명에 `/`가 있으면 마지막 `/` 뒤 세그먼트를 scope로 사용
  (예: `feature/add-button` → `add-button`, `feature/team/add-button` → `add-button`)
- 브랜치명에 `/`가 없으면(`main`, `step1` 등) scope 없이 진행

그 다음 변경사항을 파악합니다:

```bash
git status
git diff HEAD
git diff --cached
```

staged 파일과 unstaged 파일을 모두 확인합니다. 변경사항이 없으면 사용자에게 알리고 종료합니다.

---

## 2단계: 변경사항 분석

diff 내용을 읽고 다음을 파악합니다:

- 어떤 파일이 추가 / 수정 / 삭제되었는가
- 코드에서 실제로 무엇이 바뀌었는가 (함수 추가, 버그 수정, 설정 변경 등)
- 변경의 **목적**이 무엇인가 — 이것이 커밋 메시지의 핵심이 됩니다

---

## 3단계: 커밋 메시지 생성

커밋 메시지 형식(타입 선택 기준, subject 작성법, 예시)은 [conventions.md](../../docs/commit-conventions.md) "커밋 메시지" 섹션을 따릅니다. scope는 1단계에서 추출한 브랜치 기반 scope를 사용합니다.

---

## 4단계: 사용자에게 확인 요청

생성한 메시지를 다음 형식으로 보여줍니다:

```
생성된 커밋 메시지:
──────────────────────────────────────
feat(login): 사용자 로그인 기능 추가

JWT 기반 인증으로 보안을 강화하고
세션 유지 기능을 구현했습니다.
──────────────────────────────────────

이 메시지로 커밋할까요?
수정하려면 원하는 메시지를 입력해 주세요.
```

사용자가 수정을 요청하면 수정된 메시지로 다시 보여주고 재확인합니다.

---

## 5단계: 커밋 실행

사용자가 확인하면 다음 순서로 실행합니다:

```bash
# 1. 변경사항 스테이징 (이미 staged된 파일이 있으면 그것만 사용)
git add -A

# 2. 커밋
git commit -m "$(cat <<'EOF'
<확인된 커밋 메시지>
EOF
)"

# 3. 최종 상태 확인
git status
```

커밋 완료 후 어떤 파일이 포함되었는지 간략히 알려줍니다.

---

## 주의사항

- 사용자의 명시적 승인 없이 자동으로 커밋하지 말 것
- `--no-verify` 등 훅 우회 플래그는 사용자가 명시적으로 요청할 때만 사용
