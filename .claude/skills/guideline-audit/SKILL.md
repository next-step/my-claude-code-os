# 지침 감사

개인 지침끼리 어긋났는지 본다. **고치지는 않는다.**

## 왜 이 스킬이 있는가

2026-09-08에 지침 9개를 전수로 읽어 보니 **의미가 모순되는 쌍은 사실상 없었다.** 대신 진짜 위험이 다른 데 있었다 — 같은 규칙이 여러 파일에 값으로 중복 선언돼 있고(실측 8종이 평균 3곳씩), 하나만 바꾸면 조용히 어긋나는데 아무 테스트도 잡지 않았다.

그래서 이 스킬이 보는 것은 "지침이 서로 반대말을 하는가"가 아니라 **"같은 말을 하기로 한 자리들이 여전히 같은 말을 하는가"** 다.

## 실행 절차

### 1. 기계 검사

```bash
node -e 'const {auditGuidelines}=require("./.claude/lib/guideline-audit.js");
const r=auditGuidelines({projectDir:process.cwd()});
console.log(JSON.stringify({violations:r.violations, notes:r.notes, counts:r.counts, skipped:r.skipped.length}, null, 2));'
```

- **`violations`** — 상수 불일치, 인용한 파일 없음. 사실 문제라 그대로 보고한다.
- **`notes`** — 주제가 겹치는데 상호 참조가 없는 쌍. **위반이 아니다.** 겹침은 충돌일 수도, 역할 분담일 수도 있다.
- **`skipped`** — 해석하지 않은 인용(글로브·플레이스홀더·스킬 이름). 개수만 보고한다. 이 검사가 무엇을 안 보는지 드러내기 위한 값이다.

### 2. 겹침 후보가 있으면 판정을 위임한다

`notes`에 오른 쌍마다 `Agent` 도구로 `guideline-reviewer`를 호출한다.

- **전달하는 것**: 지침 두 개의 **전문**, 겹친다고 지목된 주제 이름.
- **전달하지 않는 것**: 왜 후보로 뽑혔는지에 대한 네 판단, 기계 검사 결과, "충돌 같다"는 사전 의견.

호출자의 짐작이 같이 가면 판정이 그 짐작을 확인하는 쪽으로 기운다. 이 저장소는 그 오염을 실측으로 관찰했다 — 오염은 리뷰어가 아니라 **결과를 정리하는 호출자 층**에서 났다(`docs/context-ab-test.md` 실험 3).

### 3. 결과를 축소하지 않고 보고한다

리뷰어가 낸 판정을 **개수 그대로** 올린다. "이건 사실 문제 아닌 것 같다"고 네가 미리 걸러내지 않는다. 판단 근거를 덧붙이는 것은 되지만, 항목을 지우거나 합치지 않는다. 무엇을 반영할지는 사람이 정한다.

### 4. 한계를 함께 말한다

`auditGuidelines()`가 돌려주는 `caveat`을 **초록불일 때도 반드시 같이 말한다.**

> 위반 0개는 "지침이 서로 모순되지 않는다"는 뜻이 아니다. 등록된 상수와 해석 가능한 인용만 본다.

초록불을 품질 보증으로 읽는 것이 이 저장소가 반복해 겪은 실패다.

## 보고 형식

```
지침 감사

상수 <N>종 · 주제 등록 <N>개 · 해석 안 한 인용 <N>건

[위반] <N>건
  - <상수 이름>: <파일>이(가) "<기대 문구>"를 더 이상 말하지 않습니다

[겹침 후보] <N>건 — 리뷰어 판정
  - <지침A> ↔ <지침B> (<겹치는 주제>) → COMPATIBLE: <한 줄 이유>

한계: <caveat>
```

- 위반이 0건이면 그 줄은 "없음" 한 줄로 끝낸다.
- `skipped` 목록은 전부 늘어놓지 않는다. 개수만 보이고, 사용자가 물으면 그때 낸다.

## 하지 않는 것

- **지침 파일을 고치지 않는다.** 무엇을 어떻게 고칠지는 사람의 결정이다.
- 등록부(`docs/guideline-constants.json`)를 자동으로 채우지 않는다. 새 상수를 등록하는 것도 사람의 판단이다.
- 리뷰어 판정을 자동으로 반영하지 않는다. 같은 입력에 다른 판정이 나올 수 있어 재현되지 않는다.
- 겹침 후보를 위반으로 승격시키지 않는다.
