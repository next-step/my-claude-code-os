# 일일 개발 회고 (daily-review)

하루 작업을 돌아봐 **회고 저널**을 남기는 오케스트레이터 스킬이다. 결정적 데이터 집계는 `scripts/daily_review.py`(테스트된 순수 함수)가, 질적 회고 작성은 `retro-writer` 서브에이전트가 맡는다.

```
① daily_review.py 집계  →  ② retro-writer 회고 작성  →  ③ .claude/journal/YYYY-MM-DD.md 저장
```

> 💡 **왜 데이터와 회고를 나누나?** "오늘 커밋 몇 개, 무슨 타입"은 결정적이라 스크립트로 집계해 **테스트로 고정**하고, "좋았던/아쉬웠던 점"은 판단이라 **서브에이전트**가 쓴다. 이 OS가 곳곳에서 쓰는 "결정적 vs 질적" 분리 패턴이다.
>
> 💡 **왜 회고를 만든 사람이 직접 안 쓰나?** 자기 하루를 자평하면 편향된다. `retro-writer`가 커밋·테스트 같은 결과물을 독립 시선으로 평가한다(writer↔reviewer 분리와 같은 철학).

## 사용 시점
- "오늘 회고", "일일 회고해줘", "오늘 개발 돌아보자", "retro" 같은 요청을 받았을 때 (보통 하루 작업·커밋을 마친 뒤)

## 절차

### ① 데이터 집계
- `Bash`로 `python3 scripts/daily_review.py`를 실행해 **오늘 커밋 요약**(수·타입 분포)과 **이전 회고의 미해결 액션아이템**(`.claude/journal/`의 `- [ ]`)을 모은다.
- 테스트 상태가 필요하면 `python3 -m unittest discover -s tests`로 green 여부를 확인한다.

### ② 회고 작성
- `retro-writer` 서브에이전트를 호출한다. **①의 집계 데이터 + 이월 액션아이템**을 프롬프트에 담아 넘긴다(에이전트는 맥락을 공유하지 않으므로 명시적으로 전달).
- retro-writer는 `.claude/guidelines/retro-guideline.md`를 따라 다섯 섹션(좋았던/아쉬웠던/보완사항/커밋 요약/지표)을 작성한다.

### ③ 저장 & 보고
- retro-writer가 `.claude/journal/YYYY-MM-DD.md`에 저장한다(없으면 디렉터리 생성).
- 사용자에게 회고 요약과 이월/신규 액션아이템 개수를 보고한다.

## 주의사항
- **회고 저널만 쓴다.** 이 스킬은 코드·테스트·문서를 수정하지 않는다.
- 커밋이 없는 날이면 그 사실을 그대로 적는다(빈 회고를 지어내지 않는다).
- 심각도·판정을 내리는 스킬이 아니다. 평가는 정직하게, 과장 없이.
