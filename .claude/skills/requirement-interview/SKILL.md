# 모호한 요구사항 인터뷰 (requirement-interview)

한 줄짜리 모호한 요구사항을 받아 **질문으로 빈틈을 메우고, 합의된 내용을 브리프 한 장으로 동결한 뒤 멈추는** 스킬입니다. ATDD 파이프라인의 01.5단계를 담당합니다.

```
01   요구사항 (사람)
1-1  (조건부) Skill(ui-spec-from-image)   ← 이미지가 있으면 인터뷰보다 먼저. 이미지가 답한 질문은 묻지 않기 위해
01.5 Skill(requirement-interview)         ← 여기
02   Skill(spec-decompose)                 ← 입력이 원문이 아니라 브리프
```

이 스킬의 본질은 질문을 잘하는 것이 아니라 **합의 전에 구현으로 넘어가지 못하게 막는 게이트**입니다. 질문은 수단입니다.

## 언제 쓰는가

**진입 조건(형식으로 판정한다 — "모호해 보인다"는 감각으로 판단하지 않는다)**: 요구사항 원문만 읽고 아래 6개 슬롯을 채워 본다. **3개 이상 못 채우면 인터뷰에 들어간다.** 2개 이하면 인터뷰하지 않고 그대로 02단계로 넘긴다 — 이미 명확한 요청에 질문을 붙이는 것이 이 스킬의 가장 흔한 실패다.

| 슬롯 | 묻는 것 |
|---|---|
| 목표 | 한 문장으로 무엇을 이루려는가 |
| 현재 상태 | 지금 실제로 무슨 일이 일어나는가 (추측이 아니라 확인된 사실) |
| 기대 동작 | 대신 무슨 일이 일어나야 하는가 |
| 완료 조건 | 무엇이 관측되면 끝인가 |
| 범위 밖 | 이번에 하지 않을 것 |
| 미해결 가정 | 아직 못 정해서 가정으로 둔 것 |

**슬롯은 채워졌는지만이 아니라 무엇으로 채워졌는지도 본다 (Hard Facts).** `현재 상태`와 `완료 조건`에 등장하는 대상은 **실제 경로·명령·수치**로 적는다. 제품명이나 개념어를 위치로 받지 않는다 — "통계 파일"이 아니라 `.claude/skill-usage-stats.json`, "테스트 돌리면"이 아니라 `node --test .claude/tests/`다. 개념어가 오면 **"정확한 경로가 뭔가요?"** 라고 되묻는다. 추상적 합의만으로는 실행할 수 없고, 개념어로 채워진 슬롯은 검증기를 통과하면서 실행 시점에 무너진다. *(ouroboros `interview`의 Hard Facts Before Closure)*

**탈출구는 반드시 제공한다.** 첫 질문 라운드에 항상 "인터뷰 건너뛰고 바로 진행" 선택지를 넣는다. 사용자가 선택하면 즉시 중단하고, 못 채운 슬롯을 `미해결 가정`으로 적어 호출한 쪽에 넘긴다. 빠져나갈 구멍이 없는 게이트는 반드시 우회당하고, 우회는 기록이 남지 않는다.

## 실행 절차

1. **컨텍스트 먼저 읽는다 (질문보다 앞선다)**
   - `ui-spec.md`가 함께 주어졌으면 먼저 읽는다. **이미지가 이미 답한 것은 절대 묻지 않는다.**
   - 저장소를 `Grep`/`Glob`/`Read`로 훑어 관련 근거를 최소 1개 찾는다. 질문에는 `파일:줄` 형태로 근거를 인용한다.
   - **자동 확정과 확인 질문을 구분한다.**
     - `package.json`·설정 파일 등 **명시된 사실**은 사람에게 묻지 않고 자동 확정한 뒤 통보한다 (`ℹ️ 확정: 의존성 없음 — node:test 사용, package.json 부재`).
     - **코드에서 추론한 것**은 자동 확정하지 않고 확인형으로 묻는다 ("`lib/stats.js:44`에서 count 정렬을 봤습니다. 이 정렬을 유지하는 게 맞나요?").
     - 코드가 알려주는 것은 *현재 사실*이지 *바람직한 상태*가 아니다. 이 둘을 섞는 순간 인터뷰가 현상 추인이 된다.
   - **자동 확정이 3회 연속되면 다음 질문은 반드시 사람에게 던진다.** 그러지 않으면 인터뷰가 아니라 통보가 된다.

2. **요청을 분류하고 질문 예산을 정한다**

   | 분류 | 뜻 | 질문 예산 |
   |---|---|---|
   | `spike` | 될지 안 될지 확인하는 탐색 | 1~2개 |
   | `bounded` | 기존 코드에 대한 한정된 변경 | 3~5개 |
   | `architectural` | 새 구조·새 기능 | 최대 8개 |

   분류를 사용자에게 한 문장으로 알리고 시작한다. **인터뷰 도중 범위가 커지면 임의로 예산을 늘리지 말고 재분류를 선언한 뒤 다시 시작한다** — 슬쩍 늘리는 것이 질문 피로의 주범이다.

3. **질문한다**
   - **한 라운드에 최대 3개.** 번호를 붙이고 메시지 맨 끝에 둔다.
   - 선택형이면 `AskUserQuestion`을 쓴다. 모든 질문에 **추천안**과 **"지금 안 정함"** 선택지를 항상 포함한다. 사용자가 모호하게 요청한 이유는 대개 *아직 안 정했기 때문*이지 설명을 안 해서가 아니다. "지금 안 정함"을 고르면 그 항목은 `미해결 가정`으로 내려간다.
   - 선택지가 5개 이상이면 **하나도 버리지 말고** 라운드를 나눈다.
   - 가장 결손이 큰 슬롯부터 묻는다. 한 슬롯을 깊게 파느라 나머지가 빈 채로 남지 않게, **매 라운드 끝에 남은 결손 슬롯을 한 줄로 보여준다**(원장).
   - **원장 옆에 자기점검을 한 줄 붙인다: "다음 질문이 인수기준을 바꾸는가, 표현만 다듬는가?"** 후자면 예산이 남아도 멈추고 5단계 초안으로 간다. **예산은 상한이지 목표가 아니다** — 8문항 예산을 "8개는 물어야 한다"로 읽는 순간 인터뷰가 심문이 된다. 새 질문이 문구 다듬기나 엣지 케이스 논쟁만 낳고 있다면, 그건 이미 끝났다는 신호다. *(ouroboros `seed-closer`)*

4. **예산을 다 썼는데 슬롯이 남으면**
   - 더 묻지 않는다. 남은 슬롯을 **가정으로 바꿔 `미해결 가정`에 적고** 그 사실을 사용자에게 알린다.
   - 가정을 만드는 것 자체는 금지가 아니다. **가정이 적히는 자리를 브리프 한 곳으로 고정**하는 것이 규칙이다(`spec-decompose`는 자기 가정을 만들지 않고 여기 적힌 것만 인용한다). 이 항목들은 04단계 승인 화면에 반드시 노출된다.

5. **초안을 보여주고, 목표 한 줄에 반증 테스트를 건다** (2단 구성)

   **5-1. 초안 오독 잡기.** 브리프 초안 전체를 제시하고 **"이게 맞나요? 무엇을 잘못 이해했나요?"** 라고 묻는다. "괜찮나요?"가 아니라 **틀린 곳을 지목하게 하는** 질문이어야 한다.

   **5-2. 목표 한 줄 반증.** 목표를 한 문장으로 재진술한 뒤, 승인을 구하지 말고 **반증 테스트**를 건다:

   > **"남이 이 줄만 읽어도 사용자님이 생각한 결과에 도달할까요?"** — `그대로 진행` / `문구 수정` / `범위 누락`

   "승인해 주세요"는 통과를 유도하지만, 이 질문은 **틀렸을 조건**을 상상하게 만든다. 통과시키기 쉬운 질문은 게이트가 아니다.

   - **루프는 최대 2회.** 두 번 돌고도 목표 줄이 맞아떨어지지 않으면 문구를 억지로 고치지 말고, 결손이 남은 슬롯으로 되돌아가 그쪽을 다시 묻는다. 목표 줄이 안 맞는 것은 대개 표현 문제가 아니라 합의가 덜 된 문제다.
   - **한 줄로 압축하는 곳은 여기 한 곳뿐이다.** 인터뷰 중의 다른 답변은 라벨로 줄이지 말고 이유·제약·범위를 그대로 슬롯에 옮긴다. 답변을 한 줄로 뭉개면 다음 질문의 품질이 같이 떨어진다. *(ouroboros `interview`의 Restate 게이트 / 압축 금지 원칙)*

6. **저장하고 검증한다**
   - `docs/interview/YYYY-MM-DD-<slug>.md`로 저장한다. 형식은 아래 예시와 동일해야 한다(검증기가 `## 슬롯명` 제목에 의존한다).
   - 저장 후 반드시 검증기를 돌리고 결과를 사용자에게 보여준다:
     ```bash
     node -e "const{validateBrief,readBrief}=require('./.claude/lib/interview-brief.js');console.log(JSON.stringify(validateBrief(readBrief(process.argv[1])),null,2))" docs/interview/<파일명>.md
     ```
   - `ok: false`면 지적된 슬롯을 보완한 뒤 다시 돌린다. `warnings`는 통과를 막지 않지만 사용자에게 그대로 전달한다.
   - **검증기가 보는 것은 형식과 완결성뿐이다.** 슬롯이 *채워졌는지*는 보지만 *무엇으로 채워졌는지*는 보지 않는다 — "통계 파일"이라고만 적힌 브리프도 초록불이 뜬다. 초록불이 "인터뷰가 잘 됐다"는 뜻이 아니라는 점을 사용자에게 한 줄로 짚어 준다.
   - **검증기 통과를 종료 근거로 삼지 않는다.** 저장 직전에 Hard Facts를 눈으로 한 번 더 확인한다: 경로·명령·수치가 개념어로 남아 있지 않은가. 남아 있으면 예산과 무관하게 그 항목을 `미해결 가정`으로 내리고 그 사실을 밝힌다.

7. **동결하고 멈춘다**
   - 저장된 브리프는 **인터뷰 종료 시점의 스냅샷으로 동결**한다. 이후 04단계에서 사람이 인수기준을 고쳐도 **브리프는 갱신하지 않는다.** 두 문서를 동기화하는 정책은 반드시 깨지므로, 진실 원천을 AC 한쪽으로 몰고 브리프는 "그때 무엇에 합의했는가"의 기록으로만 남긴다.
   - `spec-decompose`를 포함해 **어떤 다음 스킬도 호출하지 않고 멈춘다.** 다음을 정하는 것은 호출한 쪽(사람 또는 `atdd-orchestrator`)의 몫이다.

## 참고

- **되돌아오는 경로**: 06단계에서 3회 실패해 돌아올 때, *AC가 요구사항을 잘못 번역한 것*이면 02단계로, *요구사항 자체가 틀렸거나 빠진 것*이면 이 스킬로 돌아온다. **01.5 재진입은 사이클당 1회로 제한한다** — 스펙 논의는 값싸지만 무한 재인터뷰는 진행 자체를 막는다.
- **민감정보**: 브리프는 저장소에 커밋된다. 회사 내부 정보나 민감한 내용은 애초에 브리프에 적지 않는다(`.claude/context/README.md`의 원칙과 동일).
- **의도적으로 하지 않는 것**: 모호성 점수화, 인터뷰 상태 영속화, 외부 이슈 트래커 연동. 이 저장소엔 이미 04단계 사람 승인 게이트와 `policy-reviewer` 커버리지 판정이 있어 세 번째 게이트는 중복이고, 그 게이트가 LLM 주관 점수라면 셋 중 신뢰도가 가장 낮다.
- **진입 경로는 셋이다**: 사용자의 직접 호출, `atdd-orchestrator`의 01.5단계 위임, 그리고 `.claude/context/requirement-gate.md`의 요청 게이트. 게이트는 가벼운 변경을 대화 안에서 처리하고 **본격 경로만 이 스킬로 넘긴다** — 오타 수정에까지 브리프가 쌓이지 않게 하기 위해서다.
- **외부 사례에서 가져온 것**: Hard Facts 게이트와 Restate 반증 테스트, 품질 기반 종료는 [ouroboros](https://github.com/Q00/ouroboros)의 `interview`·`seed-closer`에서, 정량화 강제와 모호어 금지 목록은 [gstack](https://github.com/garrytan/gstack)의 `/spec`에서, 분류 3종(`spike`/`bounded`/`architectural`)과 일방향 래칫은 [superpowers](https://github.com/obra/superpowers)의 `brainstorming` 정본에서 왔다. 결론만이 아니라 출처를 남기는 것은 나중에 "이 규칙이 왜 있지"를 되물을 수 있게 하기 위해서다.
- 검증 로직은 `.claude/lib/interview-brief.js`에 있고 `.claude/tests/interview-brief.test.js`(AC-1~11)가 지킨다. 마크다운 지시문은 테스트할 수 없으므로 **검증할 것은 코드로, 보여줄 것은 지시문으로** 나눈다.

## 무엇을 적으면 안 되는가 (정량화 강제)

브리프는 **02단계가 그대로 인수기준으로 번역할 문서**다. 모호어가 한 줄 들어가면 그 자리에서 AC 한 개가 검증 불가능해진다. 측정할 수 없으면 모호하게 적지 말고 **"미상 — [방법]으로 측정"** 이라고 적어 `미해결 가정`으로 내린다. *(gstack `/spec`의 안티패턴 목록)*

| ❌ 이렇게 적지 않는다 | ✅ 이렇게 적는다 |
|---|---|
| "잘 동작한다", "엣지 케이스를 처리한다" | "30일 지난 주문은 4개 역할 모두에서 HTTP 410을 돌려준다" |
| "인증 모듈 어딘가" | `lib/stats.js:44` |
| "성능이 개선된다" | "p95 응답이 800ms → 300ms" 또는 "미상 — `node --test`의 소요 시간으로 측정" |
| "파일 몇 개" | "파일 3개" (세어서 적는다) |
| "기존 코드가 잘 되어 있으니 그대로 쓴다" | 실제로 읽고 확인한 뒤 `파일:줄`로 인용한다 |

## 예시 (브리프 형식)

```markdown
# 인터뷰 브리프: skill-stat에 최근 사용 스킬 추가

- 요구사항 원문: "skill-stat에 마지막으로 쓴 스킬도 보여줬으면 좋겠어"
- 분류: bounded
```
