# plan — 확정된 방향을 실행 큐로 옮기기

> 설계 근거: [docs/interviews/2026-07-05-dev-workflow-redesign.md](../../../docs/interviews/2026-07-05-dev-workflow-redesign.md) (Q7, Q11, Q12)

목적: **이미 확정된 방향**(인터뷰 결과든, 사용자가 대화 중 직접 정한 것이든)을 "다음에 뭘 구현할지" 순서가 있는 실행 큐로 바꾸는 것.
이 스킬은 `docs/TODO.md`와 `docs/plans/`를 갱신할 뿐, **구현하지 않는다.** 구현은 사용자가 별도로 지시한다(5단계 워크플로우의 다음 단계).

## 문서 역할 분담 (전제)

- **`docs/OS.md`**: 프로젝트의 큰 틀(주제·원칙·로드맵·스킬별 설계와 이유)만 담당하는 서사형 문서. 자주 갱신하지 않는다.
- **`docs/TODO.md`**: 순서가 있는 "다음 구현 항목" 큐. 체크박스로 진행 상태만 보여준다.
- **`docs/plans/<topic>.md`**: TODO 항목 하나의 상세 계획(목표·범위·구현 단계·건드릴 파일·설계 근거).

이 스킬은 TODO.md와 plans/를 주로 다루고, **OS.md는 구조 자체가 바뀔 때만** 건드린다(아래 4단계 참고).

## 실행 절차

### 1단계 — 입력 파악
- 인터뷰 기록(`docs/interviews/*.md`, `outcome: 확정`)이 주어지면 그 파일을 읽어 결정 내용을 확인한다.
- 인터뷰 없이 사용자가 대화 중 직접 방향을 확정한 경우, 그 확정 내용을 그대로 입력으로 삼는다.
- 방향이 아직 애매하면(트레이드오프가 있는 선택지가 남아 있으면) 이 스킬을 진행하지 말고 `interview` 스킬을 먼저 쓰도록 안내한다. **plan은 이미 결정된 것만 다룬다.**

### 2단계 — 현재 상태 파악
`docs/TODO.md`(없으면 아래 템플릿으로 생성)와 `docs/OS.md`를 읽어 현재 큐와 큰 틀을 파악한다.

### 3단계 — 항목 쪼개기 (초안 확인)
- 확정된 방향을, **한 번의 구현 세션에서 끝낼 수 있는 크기**의 순서 있는 항목들로 쪼갠다.
- 이미 큐에 있는 항목과 겹치거나 순서에 영향을 주면 재배치한다.
- 쪼갠 항목 목록(제목 + 한 줄 설명 + 예상 순서)을 사용자에게 보여주고 확인받는다. *왜:* 쪼개는 단위·순서 자체가 판단이 들어가는 지점이라, 파일로 쓰기 전에 한 번 확인받아야 엉뚱한 순서로 큐가 쌓이는 걸 막는다.
- 확인 후 조정 요청이 있으면 반영하고 다시 확인받는다.

### 4단계 — 기록
1. **항목별 상세 계획**: 각 항목을 `docs/plans/<topic>.md`로 새로 쓴다(아래 템플릿). 기존 파일과 주제가 겹치면 그 파일을 갱신한다.
2. **TODO.md 갱신**: `docs/TODO.md`의 큐에 체크박스 항목을 추가하고, 각 항목에서 해당 `docs/plans/<topic>.md`를 링크한다.
3. **OS.md 갱신 판단**: 이번 결정이 원칙·로드맵·스킬 구성 자체를 바꾸는 **구조적 변경**이면 OS.md 본문도 갱신한다(이유 포함, CLAUDE.md의 OS.md 작성 규칙을 따른다). 특정 항목의 구현 상세일 뿐이면 OS.md는 건드리지 않는다.

### 5단계 — 마무리
사용자에게 갱신한 `docs/TODO.md` 항목과 `docs/plans/` 파일 경로를 알리고 종료한다. **구현을 시작하지 않는다** — 다음 단계는 사용자가 별도로 지시한다.

## 템플릿

### docs/TODO.md 최초 생성 시

```markdown
# TODO

> 순서가 있는 "다음 구현 항목" 큐. 서사·설계 이유는 [docs/OS.md](./OS.md)에, 항목별 상세 계획은 `docs/plans/`에 있다.
> 이 문서는 `plan` 스킬이 갱신한다.

## 큐

- [ ] <항목 제목> — [상세 계획](./plans/<topic>.md)
```

### docs/plans/<topic>.md

```markdown
---
topic: <topic>
status: <대기 | 진행중 | 완료>
source: <이 계획의 근거. 인터뷰 링크가 있으면 그 경로, 없으면 "대화 중 확정">
---

# <항목 제목>

## 목표
<이 항목이 끝나면 무엇이 되어 있어야 하나. 1~3문장.>

## 범위
- 포함: <이번에 할 것>
- 제외: <일부러 미루는 것>

## 구현 단계
1. ...
2. ...

## 건드릴 파일
- <경로> — <왜>
```

## 하지 말 것
- **구현하지 않는다.** 파일 생성·수정 등 실제 구현은 이 스킬 밖의 일이다.
- 방향이 아직 안 정해졌는데 임의로 쪼개 넣지 않는다(→ `interview`로 안내).
- 항목 쪼개기 확인 없이 바로 TODO.md/plans에 쓰지 않는다(3단계 확인 생략 금지).
