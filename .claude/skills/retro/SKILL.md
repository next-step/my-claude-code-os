# /retro — 세션 회고 → 스킬 개선 제안 (판단만, 적용은 사람)

이 OS를 **쓸수록 좋아지게** 만드는 스킬이다. 방금 굴린 세션에서 스킬들이 어디서 **마찰**을 냈는지
돌아보고, 그걸 없앨 **SKILL.md 한 줄 수정 제안**을 스킬(범주)별로 뽑아 `docs/retro/`에 남긴다.

> 역할 분리 — **관찰·수집은 /retro(오케스트레이터), 개선 판단은 독립 `reviewer`.**
> 이 스킬은 세션의 마찰 신호를 모아 브리프로 만들고, 그 스킬의 프롬프트를 고칠지는
> **격리된 적대적 검토자**에게 던진다(자기 세션을 자기가 미화하지 않도록). `/verify`와 같은 모양이다.
>
> **제안만 한다. 스킬 파일을 직접 고치지 않는다.** 실제 반영은 사람이 검토 후 `/quick` 급으로.
> (스킬 수정 = OS 구성요소 변경 → OS.md 게이트 원칙 대상. 자동 자기수정은 프롬프트 드리프트를 부른다.)

전달된 인자: `$ARGUMENTS`
- 인자가 있으면 → 회고 초점(특정 스킬명 또는 "이번 /impl만" 같은 범위)으로 쓴다.
- 없으면 → **이 세션 전체**를 대상으로 한다.

---

## 진행 순서

### 1. 마찰 신호 수집 — "세션 마찰 브리프"

이 스킬은 **세션 안에서** 돌기 때문에, 대화 기록(transcript)을 파싱할 필요가 없다 —
**너(모델)가 그 세션을 직접 겪었다.** 겪은 것을 근거로, 아래 두 출처에서 신호를 모은다:

1. **살아있는 세션 맥락(주 신호)** — 이번 세션에서 실제로 있었던 마찰을 사실로 적는다.
2. **`.claude/skill-usage.log`(하드 신호·범주 근거)** — 어떤 스킬이 몇 번 호출됐는지. (형식: `시각<TAB>스킬명`)
   ```bash
   LOG=".claude/skill-usage.log"   # Bash 도구의 cwd = 프로젝트 루트. $CLAUDE_PROJECT_DIR는 훅에서만 채워지니 여기선 쓰지 말 것.
   test -f "$LOG" && tail -n 40 "$LOG" | cut -f2 | sort | uniq -c | sort -rn
   ```
   (로그엔 session id가 없어 "이번 세션" 경계는 완벽하지 않다 — 맥락 지식으로 보정하고, 애매하면 그렇게 밝힌다.)

**무엇이 "마찰"인가** (근거 있는 신호만 — 없으면 지어내지 말 것):
- `/verify` **재시도·재구현 라운드**가 여러 번 돌았다 (지시가 부족해 헛돈 흔적).
- **사용자 교정·되돌림** — "그거 아니야", 다시 시켜서 고침, 산출물 폐기.
- **가드 발동** — 승인 게이트 되물음, 루프 상한, 진척 없음 감지.
- 서브에이전트가 **지시 누락으로 되물었거나** 엉뚱하게 갔다(프롬프트에 빠진 조건).
- 스킬이 **헤맨 지점**(스펙 모순·낡은 문구·모호한 분기).

산출: 스킬별로 묶은 짧은 브리프. 마찰이 **없던** 스킬은 "이번엔 깨끗"으로 남기고 넘어간다.

### 2. 개선 판단 디스패치 — 독립 `reviewer`에게 (마찰이 있던 스킬마다)

마찰이 관찰된 **스킬마다** `Task`로 공유 검토자(`subagent_type: reviewer`)를 띄운다(병렬 가능).
마찰 없는 스킬엔 에이전트를 띄우지 않는다(낭비 금지·없는 개선 금지). 각 reviewer에 넘길 것:

- **[대상]** 그 스킬의 `.claude/skills/<name>/SKILL.md` (경로).
- **[기준]** 1단계 브리프의 **그 스킬 마찰 사실** + (관련되면) 그 스킬 자신의 "수용 기준·안전 규칙".
- **[관점]** "이 마찰을 **유발하거나 방치한 프롬프트 문구**가 어디인가? **SKILL.md에 넣거나 고칠 한 줄**은 무엇인가? 마찰 근거 없는 개선은 제안하지 말 것. 스킬을 무겁게 만드는 제안(원칙 7 위반)도 피할 것."
- **[판정 형식]** 개선 제안 목록 — 항목마다 **무엇을 / 왜(어떤 마찰) / 어떻게(고칠 문구)**. 고칠 게 없으면 "이번엔 없음"도 유효한 판정.

> 왜 독립 검토자인가: 자기가 방금 돌린 세션을 자기가 채점하면 합리화가 낀다. 판단은 격리된 reviewer에게.

### 3. 제안 문서화 — `docs/retro/<날짜>-<주제>.md`

reviewer들이 낸 제안을 **스킬(범주)별로 묶어** 한 파일로 쓴다(`Write`). 파일명은
`docs/retro/<YYYY-MM-DD>-<짧은주제>.md` (날짜는 주어진 currentDate). 형식:

```
# 회고 — <날짜> · <세션 주제 한 줄>

## 요약
쓴 스킬: /impl(3라운드) · /verify(3) · … · 마찰 관찰: N건 · 개선 제안: M건

## 스킬별 개선 제안
### /impl
- [제안] 무엇을 / 왜(이번 세션의 어떤 마찰) / 어떻게(SKILL.md 어느 문구를 어떻게)
- …
### /verify
- 이번엔 없음 (깨끗)

## 이월(다음에도 보이면 반영) — 근거 약한 1회성 신호
- …
```

- **1회성이라 근거가 약한 신호**는 지우지 말고 "이월"에 남긴다(다음 세션에 또 보이면 승격).
- **스킬 프롬프트가 아니라 "일하는 방식"(행동) 교훈**이면, 여기 말고 **auto-memory의 `feedback`**로 저장하도록 사람에게 권한다(경계: /retro=스킬 프롬프트, memory=행동 지침).

### 4. 보고 게이트 — ★멈춤★

제안 파일 경로와 스킬별 제안 수를 한눈 요약으로 보고하고 **멈춘다.**

```
🔁 회고 완료 — 제안 M건 (스킬 K종) · docs/retro/<파일>
스킬별: /impl 2 · /verify 0 · …
다음: 제안을 검토하고, 승인한 것만 /quick 급으로 해당 SKILL.md에 반영하세요.
```

- **스킬을 자동으로 고치지 않는다.** 승인·반영은 사람 몫(게이트).

## 수용 기준 (이 스킬이 제대로 동작하는지 검증)

- [ ] 세션 맥락 + `skill-usage.log`에서 **근거 있는 마찰만** 수집한다(없는 문제 지어내지 않음).
- [ ] 개선 판단을 직접 하지 않고 **마찰이 있던 스킬마다 독립 `reviewer`에 위임**한다(자기 채점 금지).
- [ ] 제안을 **스킬(범주)별로** 묶어 `docs/retro/`에 남긴다. 마찰 없는 스킬엔 제안을 만들지 않는다.
- [ ] **스킬 파일을 직접 수정하지 않고** 보고 게이트에서 멈춘다(적용은 사람 `/quick`).
- [ ] 근거 약한 1회성 신호는 버리지 않고 "이월"로 남긴다.

---

## 안전 규칙

- **판단만·제안만.** 스킬 프롬프트를 자동으로 고치지 않는다(드리프트·열화 방지). 반영은 사람 게이트.
- **셀프 채점 금지.** 자기 세션의 개선 판단은 격리된 reviewer에게 던진다.
- **없는 개선 지어내지 않기.** 마찰 근거가 없으면 "이번엔 깨끗". 억지 제안은 스킬만 무겁게 한다(원칙 7).
- **얇게 유지.** 이 스킬도 오케스트레이터일 뿐 — 무거운 메타 로직을 넣지 않는다.
- 서브에이전트가 빈 결과·오류를 돌려주면 그대로 알리고 멈춘다.

## 참고 / 범위 밖

- **지금은 수동 트리거만.** "매 세션 종료마다 자동"으로 돌리려면 SessionEnd 훅이 헤드리스 `claude -p "/retro"`
  를 부르게 하거나 `/schedule`(cron)로 야간 배치하면 된다 — **무한 재귀 가드가 필수**라, 제안 산출물이
  쓸모 있다고 검증된 뒤에 붙인다. (추후 확장)
- **auto-memory와의 경계:** 행동 지침(일하는 방식) 학습은 memory의 `feedback`이 이미 담당. `/retro`는 그게
  못 건드리는 **스킬 프롬프트 개선**이라는 빈칸을 채운다.
- `docs/retro/`의 제안은 **큐**다 — 반영되면 그 항목을 처리 완료로 표시하거나 지운다.
