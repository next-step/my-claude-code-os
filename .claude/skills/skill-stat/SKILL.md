# Skill Stat — 내가 만든 스킬이 실제로 불리는지 세어본다

스킬을 만드는 일은 쉽다. 어려운 것은 **그 스킬이 실제로 불리는지 아는 것**이다.
안 불리는 스킬은 사라지지 않고 남아서 컨텍스트만 차지하고, 잘 불리는 스킬은 왜 잘 되는지 모르면 복제할 수 없다.

이 스킬의 목적은 숫자를 예쁘게 보여주는 게 아니라 **세 가지 결정을 내리는 것**이다.

| 관측 | 내려야 할 결정 |
|---|---|
| 0회인 스킬이 있다 | `description`의 트리거 문구가 내가 실제 쓰는 말과 다른가? 아니면 이 스킬 자체가 불필요한가? |
| 한 스킬이 호출을 독점한다 | 그 스킬이 너무 많은 일을 하고 있는가? 쪼갤 값어치가 있는가? |
| 손으로 반복한 작업이 로그에 없다 | 스킬로 만들 후보다 |

따라서 이 스킬의 실패는 "숫자를 못 뽑아서"가 아니라 **"근거 없는 숫자로 잘못된 결정을 유도해서"** 일어난다.
3절의 해석 규칙이 그것을 막는다.

## 0. 데이터 출처 — 무엇이 기록되고 무엇이 빠지는가

호출 기록은 `PostToolUse` 훅이 남긴다. 통계를 말하기 전에 **이 로그가 무엇을 담는 파일인지** 먼저 알아야 한다.

| 출처 | 파일 | 담는 것 |
|---|---|---|
| `hook` (기본) | `.claude/skill-usage.jsonl` | 훅이 기록한 호출. `{ts, skill, session}` 한 줄 = 한 호출 |
| `transcript` | `~/.claude/projects/<프로젝트>/*.jsonl` | 세션 기록에 남은 `Skill` 툴 호출. 훅 설치 **이전** 구간을 메운다 |
| (참고) | `.claude/skill-usage.json` | 훅이 만든 집계 스냅샷. **파생물이다.** 통계는 항상 원본 `.jsonl`에서 센다 |

**로그에 들어오지 않는 것** — 보고할 때 이 한계를 숨기지 않는다.

- **슬래시 커맨드로 부른 호출.** `/commit`은 Skill 툴을 거치지 않고 프롬프트로 직접 확장되므로
  `PostToolUse(Skill)` 훅이 발화하지 않는다. 자연어로 부른 호출("커밋해줘")만 기록된다.
  `--source transcript`도 Skill 툴 호출만 세므로 이 구간을 메우지 못한다
- 스킬 없이 손으로 지시한 작업. "커밋해줘"가 아니라 직접 `git commit`을 시킨 경우는 기록되지 않는다
- 훅 설치 이전의 호출 (`--source both`로 일부 복원 가능)
- 다른 프로젝트에서의 호출. 훅은 프로젝트 설정이라 이 저장소 안의 호출만 센다
- 실패한 호출. 훅은 `PostToolUse`에 걸려 있어 **성공적으로 로드된 호출**만 센다

## 1. 실행 — 집계는 스크립트에 맡긴다

```bash
python3 .claude/skills/skill-stat/stat.py                  # 전체 구간
python3 .claude/skills/skill-stat/stat.py --since 7d       # 최근 7일
python3 .claude/skills/skill-stat/stat.py --source both    # 훅 설치 이전까지 포함
python3 .claude/skills/skill-stat/stat.py --json           # 기계용 출력
```

즉석에서 `jq`나 `awk` 파이프라인을 새로 짜지 않는다. 같은 질문에 실행할 때마다 다른 숫자가 나오면 그건 통계가 아니다.
스크립트가 부족하면 **스크립트를 고친다.** 일회용 명령으로 우회하지 않는다.

### 로그가 비어 있을 때

`기록된 스킬 호출이 없습니다`가 나오면 훅이 동작하지 않는 것이다. 순서대로 확인한다.

```bash
cat .claude/settings.json                      # PostToolUse에 matcher "Skill" 항목이 있는가
ls -l .claude/hooks/log-skill-usage.sh         # 존재하고 실행권한(x)이 있는가
which jq                                       # 훅이 jq에 의존한다
```

훅이 없거나 방금 설치했다면, 그 사실을 **먼저 알리고** `--source transcript`로 세션 기록에서 센다.
설정 파일을 임의로 수정하지 않는다. 훅 설치·수정이 필요하면 무엇을 바꿀지 제안하고 사용자 확인을 받는다.

## 2. 출력 읽는 법

```
스킬 호출 통계 · 출처 훅 로그 · 시간 KST
기록 구간 2026-08-20 11:27 ~ 2026-08-26 18:36 (7일)
총 24회 · 스킬 6종 · 세션 4개 (세션당 평균 6.0회)

스킬       호출  비중                        최근 호출
commit        9  ████████░░░░░░░░░░░░   38%  08-25 20:37
news          5  ████░░░░░░░░░░░░░░░░   21%  08-24 14:35
spec     *    4  ███░░░░░░░░░░░░░░░░░   17%  08-25 22:15
* 프로젝트/사용자 스킬 디렉터리에 파일이 없는 스킬 (플러그인·내장 또는 삭제됨)
```

- **기록 구간** — 통계의 유효 범위다. 이걸 빼고 숫자만 옮기면 사용자가 전체 기간으로 오해한다
- **`*` 마커** — 내가 만든 스킬이 아니라 플러그인·내장 스킬이다. "내 OS를 쓰고 있나 vs 기본 도구를 쓰고 있나"를 가른다
- **한 번도 호출되지 않은 스킬** — 파일은 있는데 호출이 0인 스킬. 3절 2번 규칙과 함께 읽는다

## 3. 해석 규칙 — 타협하지 않는다

1. **표본이 20회 미만이면 비율(%)을 해석하지 않는다.** 횟수만 말한다.
   3회 중 2회는 67%가 아니라 "3번 중 2번"이다.
2. **0회를 "쓸모없는 스킬"로 단정하지 않는다.** 먼저 기록 구간을 본다.
   로그가 이틀치인데 그 스킬이 주 1회짜리 작업용이면 0회는 정상이다.
   슬래시 커맨드(`/이름`)로만 부른 스킬도 0회로 보인다(0절). 트리거 문구를 고치기 전에 이것부터 배제한다.
3. **로그에 없는 기간을 추정해 채우지 않는다.** "설치 전에도 비슷했을 것"이라고 쓰지 않는다.
4. **`skill-stat` 자신의 호출은 기본 제외한다.** 통계를 보는 행위가 통계를 바꾼다(관측자 효과).
   포함해서 보고 싶으면 `--include-self`를 쓰고, 포함했다는 사실을 밝힌다.
5. **숫자는 스크립트 출력에서만 인용한다.** 눈대중으로 합산하거나 반올림해 다시 쓰지 않는다.
6. **호출 횟수는 가치가 아니다.** 자주 불린 스킬이 좋은 스킬이라는 보장은 없다.
   `commit`처럼 원래 빈도가 높은 작업은 상단에 오는 게 당연하다. 빈도와 중요도를 섞지 않는다.

## 4. 보고 형식

스크립트 출력을 그대로 보여준 뒤, **관찰 → 근거 → 제안** 세 줄을 붙인다. 표만 던지지 않는다.

```
(스크립트 출력)

관찰: 7일간 24회 중 commit이 9회로 가장 많고, 만든 스킬 3종 중 skill-stat은 0회입니다.
근거: 기록 구간이 7일이라 주기가 긴 작업은 아직 표본이 부족합니다.
제안: skill-stat의 description에 실제로 쓰는 말("스킬 통계 보여줘")이 들어 있는지 확인해 보세요.
```

제안은 **최대 2개**. 데이터가 뒷받침하지 않는 제안은 하지 않는다.
"더 많은 스킬을 만드세요" 같은 일반론은 제안이 아니다.

## 5. 인자

| 인자 | 동작 |
|---|---|
| (없음) | 전체 구간 통계 |
| `--since 7d` \| `24h` \| `2026-08-01` | 해당 시점 이후만 |
| `--source hook` \| `transcript` \| `both` | 데이터 출처. 기본 `hook`. `both`는 훅 로그 첫 기록 시점을 경계로 합친다 |
| `--top N` | 표에 보일 스킬 수 (기본 15) |
| `--days N` | 일별 그래프에 보일 최근 일수 (기본 21) |
| `--include-self` | `skill-stat` 자신의 호출도 포함 |
| `--json` | JSON 출력 (다른 도구·문서에 넣을 때) |
| `--log PATH` / `--root PATH` | 로그·프로젝트 경로 지정 (다른 저장소 통계를 볼 때) |

사용자가 자연어로 범위를 말하면 인자로 옮긴다. "이번 주" → `--since 7d`, "어제부터" → `--since 24h`,
"처음부터 다" → `--source both`.

## 출력 전 자기 점검

- [ ] 숫자를 스크립트 출력에서 그대로 옮겼는가 (직접 세지 않았는가)
- [ ] 기록 구간과 데이터 출처를 함께 알렸는가
- [ ] 표본이 20회 미만인데 비율을 해석하지 않았는가
- [ ] 0회 스킬을 "필요 없다"로 단정하지 않았는가
- [ ] 훅 미설치·로그 없음·깨진 줄이 있었다면 그 사실을 알렸는가
- [ ] 제안이 2개 이하이고, 각각 위 표의 어떤 숫자에서 나왔는지 말할 수 있는가
