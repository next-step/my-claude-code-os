# Research — 지식 유입 오케스트레이터

## Overview

조사 주제 1개를 받아 `knowledge/<주제>.md` 지식 문서 1개로 만든다.
메인(이 스킬을 수행하는 오케스트레이터)은 **분해·확인·보고**만 하고,
조사는 `research-investigator`(병렬 ×N), 취합·작성은 `research-curator`에
위임한다. 조사 원자료는 메인 대화에 유입시키지 않는다.

## 절차

| # | 담당 | 단계 |
|---|------|------|
| 1 | 🟢 메인 | **주제 접수·분해** — 주제를 서로 독립적인 하위 주제 2~4개로 동적 분해한다 (고정 계열 없음 — ADR-0018). 기존 `knowledge/` 문서를 훑어 이미 있는 지식은 하위 주제에서 제외하거나 "갱신" 관점으로 좁힌다 |
| 2 | 🔵 사람 | **분해안 확인** — 하위 주제 목록과 각각의 조사 관점을 제시하고 확인받는다. 수정 요청 시 1단계 반복 |
| 3 | 🟣 investigator ×N | **병렬 조사** — 하위 주제 1개씩 스폰 (한 메시지에 동시 스폰 — 조사끼리 독립이므로 병렬). 스폰 입력: 하위 주제, 조사 관점, 실험 맥락 요약. 조사 노트(텍스트)만 회수 |
| 4 | 🟣 curator | **취합·작성** — 스폰 입력: 주제, 조사 노트 전체, `knowledge/` 경로, (갱신이면) 기존 문서 경로. `knowledge/<주제-슬러그>.md` 작성 후 경로+목차 요약만 회수 |
| 5 | 🟢 메인 | **보고** — 문서 경로와 목차 요약을 사용자에게 전달. 다음 활용처(`/suggest`, `/experiment`)를 한 줄 안내 |

## 불변 규칙

1. **knowledge 격리**: `knowledge/` 문서에는 대상 프로젝트의 파일명·함수명·코드
   조각·내부 URL을 쓰지 않는다. **일반 기법 지식만** 담는다 (기록 격리 원칙의
   knowledge판 — 실험 이력·측정 결과는 `experiments/` 담당, 여기 중복 기록 금지).
2. **원자료 미유입**: 조사 원자료(웹 문서 본문 전문, 검색 결과 목록)는 메인 대화에
   올리지 않는다. investigator의 반환 계약(요약 노트만)을 스폰 프롬프트에 명시하고,
   위반 시 요약만 옮겨 적는다.
3. **중복 조사 방지**: 같은 주제의 knowledge 문서가 이미 있으면 새 파일 대신
   기존 문서 갱신을 기본으로 한다 (curator에게 기존 경로를 전달).
4. **knowledge/ 디렉터리는 첫 실행이 만든다** — curator가 문서 작성 시 생성.

## 분해 가이드 (1단계)

- 하위 주제는 **서로 독립적**이어야 한다 — 한 조사의 결과가 다른 조사의 입력이
  되면 병렬이 아니라 순차 문제이므로, 그 경우 주제를 다시 쪼갠다.
- 2~4개 범위를 지킨다. 2개로 안 쪼개지면 그냥 1개짜리 조사로 진행해도 된다
  (스폰 1개 — 병렬은 수단이지 목적이 아니다).
- 분해 예시: "배경 감지 기법" → ① 테두리/모서리 통계 기법 계열, ② 세그멘테이션
  기반 기법 계열, ③ 상용/오픈소스 라이브러리의 실전 처리 사례.

## Common Mistakes

| 실수 | 해결 |
|---|---|
| 분해안 확인(2단계) 없이 바로 스폰 | 사람 게이트는 분해안 확인 1곳 — 반드시 거친다 |
| investigator를 순차로 하나씩 스폰 | 조사끼리 독립이므로 한 메시지에 동시 스폰 |
| 조사 결과를 메인이 직접 knowledge에 작성 | 작성은 curator 담당 — 메인은 요약만 회수 |
| knowledge 문서에 실험 결과·대상 코드 정보 유입 | 작성 후 파일명·함수명·측정 표가 없는지 확인 |
| 이미 있는 지식을 재조사 | 1단계에서 기존 knowledge/ 목록을 먼저 훑는다 |
