# knowledge — 새로 알게 된 것 기록

세션에서 튀어나온 새 키워드·개념을 흘리지 않고 `knowledge.md`에 짧게 축적한다. retro가 *작업의 결정·트레이드오프*라면, 이건 *용어집* — "X가 뭔지 + 어디 보면 되는지".

## 위치
- 파일: **컨테이너 루트** `my-claude-code-os/knowledge.md`. 크로스-OS 지식이라 특정 OS가 아니라 컨테이너 루트에 둔다. 어느 OS 폴더에서 작업하든 그 기준 `../knowledge.md`(루트를 직접 열었으면 `./knowledge.md`).
- 이 스킬 자체도 루트 `.claude/skills/knowledge/`에 있어 airflow-os·stock-os 어디서 작업하든 로드된다(조상 `.claude`도 탐색되므로).

## 언제 쓰나
- 세션에서 **처음 알게 된 키워드**를 설명하게 됐을 때 (예: 빌트인 서브에이전트, 어떤 CLI 개념).
- "이거 knowledge에 남겨줘 / 새로 안 거 정리" 또는 `/knowledge`.
- 이미 아는 것·레포에서 바로 유도되는 것(코드 구조, 파일 위치)은 **안 남긴다** — 새로 알게 된 것만.

## 어떻게 쓰나
1. **새 키워드만 추린다** — 이번에 실제로 새로 안 것. 추측·미화 금지.
2. **불릿 3~5개, 짧게** — 키워드 = 한 줄 정의. 설명할 게 많으면 그만큼, 아니면 진짜 간략히.
3. **공식 문서 링크를 확인하고 넣는다** — 기억으로 URL 박지 말 것. `WebFetch`로 살아있는지 확인하고, 리다이렉트되면 **최종 URL**을 넣는다. (예: `docs.claude.com` → `code.claude.com`으로 이전됨.) 공식이 없으면 신뢰 가능한 출처(위키 등), 그것도 없으면 링크 생략.
4. **섹션에 맞춰 추가** — 관련 섹션이 있으면 그 아래, 없으면 `## <주제>` 하나 만든다. 파일이 없으면 새로 만든다.

## 형식
```markdown
## <주제>

- **<키워드>** — <한 줄 정의>. [공식 문서](<확인된 URL>)
```

## 원칙
- **새 지식만, 짧게.** 용어집이지 에세이가 아니다. 커지면 섹션만 늘린다.
- **죽은 링크 금지.** 넣기 전 실제로 열어 확인. 리다이렉트면 최종 URL.
- **retro와 섞지 않는다.** 작업의 "왜"는 retro로, 재사용할 "용어"는 여기로.
