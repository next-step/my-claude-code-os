# /code-run — 클릭 실행형 재현 프로그램 스킬 (코드실행!)

`/code` 분석 결과를 받아, **논문의 동작과 보고된 결과를 "깃허브 코드가 실행된 것처럼" 재현하는 클릭 실행형 프로그램**을 만든다. 사용자는 터미널·설치 없이 파일을 **더블클릭**하면 브라우저에서 바로 본다.

> 핵심 원칙 (이 스킬의 정체성 — loop.txt 반영으로 개정됨):
> 1. **클릭 실행** — 산출물은 단일 `index.html`. 더블클릭하면 어떤 PC에서든 즉시 실행된다. 터미널·pip·GPU 불필요.
> 2. **자급식(self-contained)** — 외부 CDN/네트워크/파일 의존성 0. CSS·JS 인라인, 자산은 data URI. 인터넷 없이도 돈다.
> 3. **"코드가 실행된 것처럼"** — 실제 공식 레포의 데모/추론 실행 화면을 흉내 낸다: 콘솔 로그 스트림, 진행바, 파이프라인 단계 애니메이션, 결과 패널. 논문이 **실제로 보고한 수치**(FPS·지연·벤치마크 점수 등)를 화면에 재현한다.
> 4. **정직성** — 무거운 실모델을 브라우저에서 돌릴 수는 없다. 이것은 **문서 기반 재현 시뮬레이션**이며, 앱 안 배너와 `05_run.md` 상단에 그 사실을 명시한다. 논문 수치는 "논문 보고값"으로 라벨링하고 지어내지 않는다.

> 슬래시 이름: `/code-run` (원 요청의 `/코드실행!`에 해당).

## 입력 (우선순위)
1. `output/<slug>/04_runcard.md` (있으면 최우선 — 실행 사실 요약 카드)
2. `output/<slug>/04_code.md` (논문↔코드 매핑, 진입점, 하이퍼파라미터)
3. `output/<slug>/01_analysis.md` (보고된 지표·벤치마크·성능 테스트 — 재현 대상의 정본)
4. `output/<slug>/app/LEARNINGS.md` (있으면 — 이전 루프에서 배운 것. implement-loop가 인계)
5. `output/<slug>/app/scorecard.json` (있으면 — 이전 점수와 미달 항목. 그걸 우선 개선)

없으면 먼저 `/analyzer`·`/code`를 돌려야 한다.

## 절차
1. **재현 대상 선정** — 위 입력에서 이 논문을 대표하는 **관찰 가능한 동작 1~3개**와 **논문이 보고한 핵심 수치**를 추린다.
   - 파이프라인 단계(예: 증류 Stage 1→2→3), 입출력(before/after), 효율 메커니즘(예: 마스크 캐시·토큰 프루닝), 성능 지표(FPS·지연·정확도·벤치마크 표).
   - 논문에 **성능 테스트/벤치마크가 있으면 반드시 재현 목록에 포함**한다(loop.txt #2).
2. **개선 우선순위 반영** — `LEARNINGS.md`와 직전 `scorecard.json`이 있으면, 거기 적힌 미달 항목(`must_fix`, 낮은 점수 기준)을 이번 빌드에서 **먼저** 고친다.
3. **프로그램 설계** — 단일 `index.html` 안에:
   - **실행 화면**: 상단에 "실행" 버튼(또는 자동 시작). 누르면 공식 레포 추론을 흉내 낸 콘솔 로그가 스트리밍되고, 파이프라인 단계가 진행바/애니메이션으로 흐른다.
   - **결과 패널**: 논문이 보고한 지표를 실시간 카운터/표/그래프로 표시(예: FPS 게이지, 지연 ms, 벤치마크 점수 표). 각 수치 옆에 **"논문 보고값"** 출처 라벨.
   - **인터랙션**: 파라미터 토글(예: 캐시 on/off, step 수)을 두어 "코드를 돌리는" 감각을 준다. 토글에 따라 화면 수치가 논문이 말한 방향으로 변해야 한다(예: 캐시 off → FPS 하락).
   - **정직성 배너**: 상단에 "문서 기반 재현 시뮬레이션 — 실제 가중치 추론 아님. 수치는 논문 보고값." 고지.
   - **원본 링크**: 공식 레포/프로젝트 페이지 URL을 명시.
4. **자급식 검증** — 파일 하나로 완결. 외부 요청 0(스크립트·폰트·이미지 전부 인라인/data URI). `file://`로 열어도 콘솔 에러 없이 돌아야 한다.
5. **재현 명세 발행** — `output/<slug>/app/REPRODUCE.md`에, 이 앱이 **무엇을·어떤 논문 보고값으로** 재현하는지 표로 남긴다(→ `/score`가 이 파일과 앱을 채점 근거로 읽는다).
6. **오픈 가이드 발행** — `output/<slug>/05_run.md`를 "**이 파일을 더블클릭해서 여세요 + 무엇을 보게 될지**"로 정리(터미널 명령이 아니라 클릭 실행 안내).

## 산출물
- **`output/<slug>/app/index.html`** (필수, 정본) — 단일·자급식·클릭 실행형 재현 프로그램.
- **`output/<slug>/app/REPRODUCE.md`** — 재현 항목 ↔ 논문 보고값 매핑 표(채점 입력).
- **`output/<slug>/05_run.md`** — 클릭 실행 가이드(아래 템플릿).

### `05_run.md` 템플릿
```markdown
# 실행 리포트: <제목>

> **문서 기반 재현 시뮬레이션**입니다. 실제 가중치로 추론하지 않으며, 화면 수치는 모두 **논문 보고값**입니다.
> 원본 공식 레포: <URL>

## 실행 방법 (터미널 불필요)
1. `output/<slug>/app/index.html` 를 **더블클릭** — 기본 브라우저에서 바로 열립니다.
2. 상단 "실행" 버튼을 누르면 추론 파이프라인이 재생됩니다.

## 무엇을 보게 되는가
- <파이프라인 단계 애니메이션 설명>
- <재현되는 논문 보고 지표: 예 12.66 FPS, 79ms/frame, 벤치마크 표>
- <인터랙션 토글과 기대 반응>

## 재현 대상 ↔ 논문 근거
- (표: 화면 요소 → 논문에서 보고한 값/섹션)

## 정직성 고지
- 브라우저에서 실모델을 돌리지 않음. 무거운 추론이 필요한 값은 논문 보고값을 재생.
```

## 실행 주체 규칙 (개정)
- **기본값: 클로드가 프로그램을 "만든다". 사용자는 더블클릭만 한다.** 터미널·설치를 요구하지 않는다.
- 원한다면 클로드가 자체적으로 자급식 검증(파일 존재·외부요청 0·구문 오류 0)까지 한다. 단, **실제 논문 모델 가중치로 추론했다고 주장하지 않는다** — 화면 수치는 논문 보고값 재생임을 항상 명시.
- 논문에 없는 수치를 지어내지 않는다. 보고값이 없는 항목은 "논문 미보고"로 표기.

## 에이전트 간 소통 (협업 규약)
같은 논문을 다루는 **analyzer·code·code-run** 은 독립 컨텍스트로 돌기 때문에, 서로 소통하는 유일한 수단은 공용 게시판 **`output/<slug>/CHANNEL.md`** (파일 기반 blackboard)다. 이 스킬은 재현 프로그램을 만들며 **가장 많이 질문하는 소비자**다.
- **시작 전**: `CHANNEL.md`가 있으면 `Read`로 읽고, `analyzer`/`code`가 남긴 답변(`→ code-run RESOLVED`)을 이번 빌드에 반영한다. 나(`→ code-run`) 앞으로 온 OPEN 질문이 있으면 답한다.
- **막히면 물어라**: 재현에 꼭 필요한데 `01_analysis.md`/`04_code.md`에 (a) 없거나, (b) 모순되거나, (c) 조건이 불명확한 정보(예: "79ms가 몇 프레임 기준인가", "정확한 벤치마크 표 값", "진입점 스크립트")가 있으면, **지어내지 말고** 아래 형식으로 질문을 남긴다:
  - `## Q<n> [code-run → analyzer] (OPEN)` — 논문 내용·수치 관련
  - `## Q<n> [code-run → code] (OPEN)` — 저장소·실행·코드 관련
  (파일 끝에 append, 기존 삭제 금지. 답은 다음 루프에서 analyzer/code가 채운다.)
- **정직성**: 답을 못 받은 항목은 앱에 "논문 미보고/미확정"으로 표기하고 추정치를 지어내지 않는다.

## Fallback (원본 실제 실행을 원하는 사용자용)
- 사용자가 "진짜 가중치로 원본을 돌리고 싶다"고 명시하면, `05_run.md` 하단에 원본 레포 clone→env→weights→run 터미널 블록을 **부록**으로 덧붙인다(개정 전 방식). 기본 산출물은 어디까지나 클릭 실행형 `app/index.html`이다.

## 품질 기준
- `index.html`은 **더블클릭 한 번으로**, 인터넷 없이, 콘솔 에러 없이 끝까지 재생돼야 한다.
- 화면에 나오는 모든 정량 수치는 **논문 보고값에 근거**하고 출처가 라벨링돼야 한다(지어내기 금지).
- 논문의 **성능 테스트/벤치마크가 있으면 앱에 반드시 포함**.
- `REPRODUCE.md`의 각 항목이 앱에서 실제로 관찰 가능해야 한다(`/score`가 이를 검증).
- 완료 후 `app/index.html` 경로와 "이 파일을 더블클릭하세요" 안내를 보고.
