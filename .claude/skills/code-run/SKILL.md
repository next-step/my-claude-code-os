# /code-run — 클릭 실행형 재현 프로그램 스킬 (코드실행!)

`/code` 분석 결과를 받아, **논문의 동작과 보고된 결과를 "깃허브 코드가 실행된 것처럼" 재현하는 클릭 실행형 프로그램**을 만든다. 사용자는 터미널·설치 없이 파일을 **더블클릭**하면 브라우저에서 바로 본다.

> 핵심 원칙 (이 스킬의 정체성 — loop.txt 반영으로 개정됨):
> 1. **실제 동작 우선 (Working Implementation First)** — 애니메이션·목업으로 논문 수치를 "보여주는" 데 그치지 말고, **가능한 범위에서 논문의 실제 태스크를 실제 입력에 대해 진짜로 수행**하라. 논문의 핵심 알고리즘 기여(효율 메커니즘·자료구조·처리 절차)는 브라우저에서 **실제로 구현**하고, 그 결과로 나온 **측정값**(실측 FPS·prune%·정확도 등)을 화면에 낸다. (아래 "실제 동작 구현" 절 참고)
> 2. **클릭 실행** — 산출물은 단일 `index.html`. 더블클릭하면 어떤 PC에서든 즉시 실행된다. 터미널·pip·GPU 불필요.
> 3. **자급식(self-contained)** — 외부 CDN/네트워크/파일 의존성 0. CSS·JS 인라인, 자산은 data URI. 인터넷 없이도 돈다. (사용자가 고르는 로컬 파일 입력은 `File`/`URL.createObjectURL`로 처리 — 네트워크 요청 아님, 허용.)
> 4. **정직성** — 대형 학습 가중치(예: 확산 백본)는 브라우저에서 못 돌린다. 그 부분만 **정직하게 라벨된 경량 대체 연산**으로 두고, 논문의 알고리즘 기여는 실제로 돌린다. 실제로 돌린 것과 대체/모사한 것을 앱 배너와 `05_run.md`에 명확히 구분해 고지한다. 논문 보고값은 "논문 보고값", 앱이 실제 측정한 값은 "실측값"으로 각각 라벨(지어내기 금지).

> 슬래시 이름: `/code-run` (원 요청의 `/코드실행!`에 해당).

## 실제 동작 구현 (Working Implementation) — 최우선 지침
목표는 "논문에서 말한 걸 실제로 해보는" 프로그램이다. 단순 수치 재생이 아니다.
- **실제 입력을 받는다**: 사용자가 자기 파일(예: 동영상·이미지·텍스트)을 업로드하거나, 앱이 내장한 **절차적 생성 샘플**(자산 없이 코드로 만든 입력)을 쓴다. 입력 없이도 바로 돌아가야 한다.
- **논문의 핵심 알고리즘을 진짜로 구현한다**: 그 논문의 대표 기여가 자료구조/알고리즘/처리 파이프라인이면(대형 학습 가중치가 아니라면) 브라우저에서 실제로 계산한다.
  - 예) LiveEdit → **동영상 편집을 실제로 수행**: 프레임을 실제로 디코딩(`<video>`+canvas)하고, 스트리밍 인과 처리(chunk 단위)로 프레임을 편집하며, **AR-지향 마스크 캐시를 실제 구현**(프레임 간 L2 차이로 편집/정적 영역 이진 마스크 산출 → 정적 영역은 캐시 재사용, 편집 영역만 재계산 → 실측 prune%·FPS 산출). 편집 연산 자체(확산 백본)는 실제 가중치를 못 쓰므로 **경량 편집 연산자**(예: 지시 기반 색/영역 변환)로 대체하되 그 사실을 라벨.
- **대체는 최소화하고 라벨한다**: 브라우저에서 불가능한 부분만 대체하고, "이 부분은 실제 알고리즘 / 이 부분은 경량 대체"를 앱에 표시.
- **실측값을 낸다**: 실제 실행에서 측정한 값(FPS·처리시간·prune%·화질 지표 등)을 화면에 내고, 논문 보고값과 **나란히** 비교한다(둘을 혼동하지 않게 각각 라벨).
- 이 지침이 불가능한 논문(순수 대형모델 추론밖에 없는 경우)이면, 그 사유를 명시하고 최대한 관찰 가능한 부분 동작이라도 실제로 구현한다(무작정 애니메이션으로 후퇴 금지 — 왜 불가한지 적는다).

## 입력 (우선순위)
1. `output/<slug>/04_runcard.md` (있으면 최우선 — 실행 사실 요약 카드)
2. `output/<slug>/04_code.md` (논문↔코드 매핑, 진입점, 하이퍼파라미터)
3. `output/<slug>/01_analysis.md` (보고된 지표·벤치마크·성능 테스트 — 재현 대상의 정본)
4. `output/<slug>/app/LEARNINGS.md` (있으면 — 이전 루프에서 배운 것. implement-loop가 인계)
5. `output/<slug>/app/scorecard.json` (있으면 — 이전 점수와 미달 항목. 그걸 우선 개선)

없으면 먼저 `/analyzer`·`/code`를 돌려야 한다.

## 절차
1. **실제 태스크 선정** — 위 입력에서 이 논문의 **실제 태스크**(예: 동영상 편집)와 그것을 뒷받침하는 **핵심 알고리즘 기여**(예: AR 마스크 캐시·스트리밍 인과 처리)를 정한다. 이것이 앱에서 **실제로 돌 대상**이다. 논문의 **성능 테스트/벤치마크**도 함께 목록화(loop.txt #2)해 실측값과 비교한다.
2. **개선 우선순위 반영** — `LEARNINGS.md`와 직전 `scorecard.json`이 있으면, 거기 적힌 미달 항목(`must_fix`, 낮은 점수 기준)을 이번 빌드에서 **먼저** 고친다.
3. **프로그램 설계** — 단일 `index.html` 안에:
   - **입력**: 사용자 파일 업로드(로컬, 네트워크 아님) + 내장 절차적 샘플(입력 없이도 동작). 예: 동영상 파일 또는 코드로 생성한 움직이는 장면.
   - **실제 실행부(정본)**: "실행" 버튼 → 논문의 실제 태스크를 **진짜로 수행**한다. 프레임 실제 디코딩/처리, 핵심 알고리즘 실제 계산(예: L2 차이 기반 편집/정적 마스크 → 정적 영역 캐시 재사용, 편집 영역만 재계산), **실제 출력**(편집된 프레임/영상, 스크러버, 마스크 오버레이) 생성. 대형 가중치 부분만 라벨된 경량 대체 연산.
   - **결과 패널**: 앱이 **실측한 값**(실측 FPS·처리시간·prune%·화질 등)과 **논문 보고값**을 나란히 표시(각각 라벨). 논문에 성능 테스트가 있으면 그 항목을 실측과 대비.
   - **인터랙션**: 실제로 동작에 영향을 주는 컨트롤(예: 캐시 on/off, τ 임계, chunk 크기). 토글에 따라 **실측 지표가 실제로 변해야** 한다(모사 아님).
   - **정직성 배너**: 상단에 "이 부분은 논문 알고리즘 실제 구현 / 이 부분(가중치)은 경량 대체 · 실측값 vs 논문 보고값 구분" 고지.
   - **원본 링크**: 공식 레포/프로젝트 페이지 URL을 명시.
4. **자급식 검증** — 파일 하나로 완결. 외부 **네트워크** 요청 0(스크립트·폰트·이미지 전부 인라인/data URI). 사용자 로컬 파일 입력(`File`/`URL.createObjectURL`/`FileReader`)은 네트워크가 아니므로 허용. `file://`로 열어도 콘솔 에러 없이 돌아야 한다.
5. **재현 명세 발행** — `output/<slug>/app/REPRODUCE.md`에, 이 앱이 **무엇을·어떤 논문 보고값으로** 재현하는지 표로 남긴다(→ `/score`가 이 파일과 앱을 채점 근거로 읽는다).
6. **오픈 가이드 발행** — `output/<slug>/05_run.md`를 "**이 파일을 더블클릭해서 여세요 + 무엇을 보게 될지**"로 정리(터미널 명령이 아니라 클릭 실행 안내).

## 산출물
- **`output/<slug>/app/index.html`** (필수, 정본) — 단일·자급식·클릭 실행형 재현 프로그램.
- **`output/<slug>/app/REPRODUCE.md`** — 재현 항목 ↔ 논문 보고값 매핑 표(채점 입력).
- **`output/<slug>/05_run.md`** — 클릭 실행 가이드(아래 템플릿).

### `05_run.md` 템플릿
```markdown
# 실행 리포트: <제목>

> **문서 기반 재현 시뮬레이션**입니다. 실제 가중치로 추론하지 않으며, 화면 수치는 모두 **논문 보고값**입니다.
> 원본 공식 레포: <URL>

## 실행 방법 (터미널 불필요)
1. `output/<slug>/app/index.html` 를 **더블클릭** — 기본 브라우저에서 바로 열립니다.
2. 상단 "실행" 버튼을 누르면 추론 파이프라인이 재생됩니다.

## 무엇을 보게 되는가
- <파이프라인 단계 애니메이션 설명>
- <재현되는 논문 보고 지표: 예 12.66 FPS, 79ms/frame, 벤치마크 표>
- <인터랙션 토글과 기대 반응>

## 재현 대상 ↔ 논문 근거
- (표: 화면 요소 → 논문에서 보고한 값/섹션)

## 정직성 고지
- 브라우저에서 실모델을 돌리지 않음. 무거운 추론이 필요한 값은 논문 보고값을 재생.
```

## 실행 주체 규칙 (개정)
- **기본값: 클로드가 프로그램을 "만든다". 사용자는 더블클릭만 한다.** 터미널·설치를 요구하지 않는다.
- 원한다면 클로드가 자체적으로 자급식 검증(파일 존재·외부요청 0·구문 오류 0)까지 한다. 단, **실제 논문 모델 가중치로 추론했다고 주장하지 않는다** — 화면 수치는 논문 보고값 재생임을 항상 명시.
- 논문에 없는 수치를 지어내지 않는다. 보고값이 없는 항목은 "논문 미보고"로 표기.

## 에이전트 간 소통 (협업 규약)
같은 논문을 다루는 **analyzer·code·code-run** 은 독립 컨텍스트로 돌기 때문에, 서로 소통하는 유일한 수단은 공용 게시판 **`output/<slug>/CHANNEL.md`** (파일 기반 blackboard)다. 이 스킬은 재현 프로그램을 만들며 **가장 많이 질문하는 소비자**다.
- **시작 전**: `CHANNEL.md`가 있으면 `Read`로 읽고, `analyzer`/`code`가 남긴 답변(`→ code-run RESOLVED`)을 이번 빌드에 반영한다. 나(`→ code-run`) 앞으로 온 OPEN 질문이 있으면 답한다.
- **막히면 물어라**: 재현에 꼭 필요한데 `01_analysis.md`/`04_code.md`에 (a) 없거나, (b) 모순되거나, (c) 조건이 불명확한 정보(예: "79ms가 몇 프레임 기준인가", "정확한 벤치마크 표 값", "진입점 스크립트")가 있으면, **지어내지 말고** 아래 형식으로 질문을 남긴다:
  - `## Q<n> [code-run → analyzer] (OPEN)` — 논문 내용·수치 관련
  - `## Q<n> [code-run → code] (OPEN)` — 저장소·실행·코드 관련
  (파일 끝에 append, 기존 삭제 금지. 답은 다음 루프에서 analyzer/code가 채운다.)
- **정직성**: 답을 못 받은 항목은 앱에 "논문 미보고/미확정"으로 표기하고 추정치를 지어내지 않는다.

## Fallback (원본 실제 실행을 원하는 사용자용)
- 사용자가 "진짜 가중치로 원본을 돌리고 싶다"고 명시하면, `05_run.md` 하단에 원본 레포 clone→env→weights→run 터미널 블록을 **부록**으로 덧붙인다(개정 전 방식). 기본 산출물은 어디까지나 클릭 실행형 `app/index.html`이다.

## 품질 기준
- **실제로 동작**해야 한다: 실제(또는 절차적 샘플) 입력에 대해 논문의 태스크를 수행하고 **진짜 출력**을 낸다. 애니메이션만으로 태스크 수행을 흉내 내면 안 된다.
- 논문의 **핵심 알고리즘 기여가 실제 코드로 구현**돼 있어야 한다(모사·하드코딩된 결과 금지). 컨트롤을 바꾸면 **실측 지표가 실제로 변해야** 한다.
- 정량 수치는 **출처가 라벨링**돼야 한다: 앱이 측정한 값은 "실측값", 논문에서 온 값은 "논문 보고값"(지어내기 금지). 브라우저 불가로 대체한 부분은 명시.
- `index.html`은 **더블클릭 한 번으로**, 인터넷 없이(로컬 파일 입력 제외), 콘솔 에러 없이 동작해야 한다.
- 논문의 **성능 테스트/벤치마크가 있으면 앱에 포함**해 실측과 대비.
- `REPRODUCE.md`의 각 항목이 앱에서 실제로 관찰 가능해야 한다(`/score`가 이를 검증).
- 완료 후 `app/index.html` 경로와 "이 파일을 더블클릭하세요" 안내를 보고.
