# /capture 스킬 — 할일 캡처 오케스트레이터

키워드 하나만 던지면 분류부터 저장까지 자동으로 처리한다.

> **참조 정본**: 이 스킬은 아래 정본을 따른다. 관련 판단 시 먼저 Read한다.
> - `.claude/context/categories.md` — 카테고리 6종 + 분류 규칙 (Step 2)
> - `.claude/context/data-model.md` — todos 스키마 + 저장 구조 (Step 3)
> - `.claude/context/status-lifecycle.md` — capture는 `draft`를 생성한다

> **응답 속도 설계 (정직한 한계 포함)**
> `/capture` 체감 지연 = ① 모델 추론 턴 + ② 저장 네트워크 왕복. 이 스킬 코드로 줄일 수
> 있는 건 ②와 "모델 턴 수"뿐이고, ①(요청을 이해하고 도구 호출을 발행하는 모델 추론)은
> 물리적 바닥이라 **완전한 end-to-end 1초 보장은 불가능하다.** 그래서 스킬이 제어 가능한
> 범위를 전부 최적화했다: (1) 분류를 서브에이전트 → 메인 인라인으로(콜드스타트 제거, Step 2),
> (2) 저장을 동기 네트워크 → 즉시 로컬 + 백그라운드 동기로(0.48s 왕복 제거, Step 3).
> 결과적으로 저장 단계는 서브에이전트 0 · 동기 네트워크 대기 0 · bash ≈10ms 로 수렴한다.

## 사용법

```
/capture 장보기
/capture 스프링 강의 듣기
```

---

## 두 실행 경로 — 저장은 공유, 분류만 다르다

같은 `/capture`라도 **어디서 들어오느냐**에 따라 분류 방식이 갈린다. 저장은 두 경로 모두
`capture-fast.sh`(로컬 즉시 + 백그라운드 동기)로 수렴하는 **단일 출처**다.

| 경로 | 분류 | 이유 |
|------|------|------|
| **대화형** (Claude Code 안에서 `/capture`) | 아래 Step 2 — **메인 모델이 표 보고 직접** | 이미 떠 있는 모델이라 추론 1스텝이면 끝. 신조어·애매한 입력도 문맥으로 잘 잡는다. |
| **텔레그램** (봇으로 `/capture`) | `_shared/classify.sh` — **사전 기반(모델 0)** | 텔레그램 경로는 `claude -p` 콜드 스타트(~10s)를 우회해야 노티스가 2초 안에 나간다. 모델을 못 부르므로 사전으로 분류한다. |

즉 텔레그램 경로는 `telegram-listener.sh → capture.sh → (classify.sh + capture-fast.sh)`로
모델 없이 순수 bash(~0.03s)로 처리된다. 사전 분류는 대표 키워드는 정확하지만 한 글자
모호어(예: "약")는 놓칠 수 있다 — 속도를 위한 의도된 트레이드오프이며, 카테고리는 나중에
`/plan`에서 조정할 수 있다.

> 세 표현(이 표 Step 2 · `classifier-agent.md` · `classify.sh`)은 같은 분류 규칙의 다른
> 표현이다. 규칙을 바꾸면 셋을 함께 갱신한다.

## 실행 절차

### Step 1: 입력 파싱

스킬 인자에서 키워드를 추출한다.

- 키워드가 없으면: "캡처할 내용을 입력해주세요. 예: `/capture 장보기`" 출력 후 종료.

---

### Step 2: 카테고리 분류 (메인이 직접)

> **속도 포인트 — 가벼운 판단은 서브 에이전트를 띄우지 않는다**
> "키워드 1개 → 6개 중 1개 단어"는 별도 추론 컨텍스트가 필요 없는 가벼운 판단이다.
> 서브 에이전트를 띄우면 콜드 스타트(시스템 프롬프트 로딩 + 추론 라운드 1회)만큼의
> 오버헤드가 분류 난이도에 비해 과도하다. 그래서 이 스킬을 실행 중인 **메인 컨텍스트가
> 아래 표를 보고 그 자리에서 직접** `category`를 정한다. (Step 3의 저장을 Bash로 직접
> 하는 것과 같은 원리 — 오케스트레이터는 가벼운 일은 흡수하고 무거운 일만 위임한다.)

아래 표에 따라 Step 1 키워드에 가장 가까운 카테고리 **한 단어**를 골라 `category`에 저장한다.

| 카테고리 | 해당 키워드 예시 |
|---------|---------------|
| 스터디 | 강의, 책, 자격증, 세미나, 공부, 학습, 과제, 읽기 |
| 업무 | 미팅, 리포트, 데드라인, 리뷰, 회의, PR, 발표, 제안서 |
| 일상 | 장보기, 청소, 약속, 취미, 쇼핑, 요리, 빨래 |
| 건강 | 병원, 운동, 약, 검진, 헬스, 산책, 수면 |
| 금융 | 납부, 이체, 세금, 보험, 카드, 환전, 저축 |
| 기타 | 위 카테고리에 해당하지 않는 것 |

분류 규칙: ① 가장 가까운 카테고리를 고른다. ② 두 카테고리에 걸치면 더 구체적인 쪽
(예: "헬스장 등록비 납부" → 건강). ③ 확실하지 않으면 기타.

> 위 표는 `.claude/context/categories.md`(정본)의 요약이다. 규칙을 바꿀 때는 **정본을
> 먼저** 고치고, 위 표 · `_shared/classifier-agent.md` · `_shared/classify.sh`를 함께 맞춘다.

---

### Step 3: draft 저장 (즉시 응답 + 백그라운드 동기)

> **속도 포인트 — 저장을 크리티컬 패스에서 뺀다**
> 저장은 결정론적이라 Bash로 직접 하지만, `notion.sh write`는 curl 동기 POST 로 네트워크
> 왕복(실측 ~0.48s)을 하는 동안 사용자를 기다리게 한다. 할일 캡처는 "빨리 받아 적고 잊는"
> 행위라 저장 완료까지 기다릴 이유가 없다. `capture-fast.sh`는 로컬 outbox 에 항목을 즉시
> durable 하게 남기고(≈10ms), Notion 반영은 detached 백그라운드로 던진 뒤 곧바로 반환한다.
> → 사용자 체감 응답에서 0.48s 네트워크 왕복이 사라진다. 유실은 없다 — 백그라운드 write 가
> 실패하면 항목이 outbox 에 남아 `capture-flush.sh`로 재시도된다.

키워드와 Step 2에서 정한 `category`를 인자로 넘겨 호출한다. (`captured_at`은 스크립트가
현재 시각으로 채운다.)

```bash
.claude/skills/_shared/capture-fast.sh "{키워드}" "{category}"
```

출력은 확인용 flat JSON(`{id_local, title, category, status, captured_at, synced:"background"}`)이며,
네트워크 대기 없이 즉시 돌아온다. Notion 의 실제 page id 는 백그라운드에서 부여되므로 여기서
기다리지 않는다.

---

```
✅ 캡처 완료!

📝 {키워드}
🏷️  카테고리: {category}
📌 상태: draft (구체화 필요)

/plan 을 실행하면 언제·어떻게 할지 구체화할 수 있어요.
```
