# /coverage — 커버리지 무인 루프 (랄프 루프 · 커버리지 전용)

[OS.md](../../../OS.md)의 **저위험 grind 트랙**이다. `app/` 코드를 기준으로 **테스트를 보태**,
테스트 커버리지가 목표에 닿을 때까지 **사람 개입 없이 반복(수렴)**한다.

> 왜 무인이 되나: 커버리지는 **값싸게·객관적으로 매 라운드 재는 지표(fitness function)** 라,
> "이만하면 됐다"를 사람이 판단해줄 필요가 없다 — 지표가 목표에 닿았는지가 곧 종료 조건이다.
> `/quick`의 위험도 스케일링을 **무인 루프까지** 넓힌 것. 단, 무인의 안전은 전적으로 아래 **안전판**에서 나온다.

> ⚠️ **OS 불변식 예외.** 이 스킬은 사람 게이트 없이 코드를 쓴다 — OS.md의 "게이트 통과 전 구현 금지"
> 불변식의 **명시적 예외**다. 정당화의 조건은 셋: **① 테스트 추가라는 저위험 범위**, **② 정량 지표가 방어**,
> **③ 예산 상한·서킷브레이커·사후 보고 게이트.** 셋 중 하나라도 깨지면 무인을 멈추고 사람에게 넘긴다.

전달된 인자: `[목표%] [대상]`
- **목표%** 없으면 → **85**. **대상** 없으면 → `app/`. 측정 명령 기본: `.venv/bin/pytest --cov=<대상> --cov-report=term-missing`.
- 예: `/coverage 85 app/` · `/coverage 90` · `/coverage`(둘 다 기본값).

## 진행 순서

### [준비] preflight — 도구·시작 전제 ★안전★

1. **커버리지 도구 확인**: `.venv/bin/python -c "import pytest_cov"`. 없으면 `.venv/bin/pip install pytest-cov`로 설치.
   (설치도 실패하면 멈추고 사람에게 보고 — 지표를 못 재면 루프가 성립하지 않는다.)
2. **워킹 트리 확인**: `git status --porcelain`이 비어 있어야 한다. **dirty면 멈추고** "기존 변경과 롤백이 섞이니 먼저 커밋/스태시하라"고 보고. (라운드 롤백의 전제)
3. **브랜치 확인**: 기본 브랜치(main)면 멈추고 작업 브랜치를 권한다.
4. **baseline 확보**: 현재 HEAD를 롤백 기준점으로 기억한다.

### 1. 측정 — 라운드 시작

`.venv/bin/pytest --cov=<대상> --cov-report=term-missing` 실행 → **현재 커버리지 %** 파싱, **덜 덮인 파일·라인** 식별.

- **목표 달성**이면 → 6(종료·달성).
- 아니면 다음으로. (매 라운드 한 줄 진행: `라운드 2/8 · 커버리지 71%→? · 목표 85%`)

### 2. 테스트 추가 — 무인, tests/ 에만

덜 덮인 지점을 겨냥해 **`tests/` 아래에 테스트를 추가·보강**한다. **`app/` 프로덕션 로직은 건드리지 않는다.**
- 손댈 게 크고 다발이면 → `Task`(`general-purpose`)에 **좁게 디스패치**하되 `.claude/context/backend-conventions.md`(+`flow-rules.md`)를 **프롬프트에 실어** 넘긴다(격리 컨텍스트라 편집 훅이 안 닿음). 작으면 인라인 `Write`/`Edit`.

### 3. 라운드 검증 — 진척 인정 (게이밍 방지) ★핵심★

한 라운드가 "진척"으로 인정되려면 **셋 다** 만족해야 한다:
1. **전체 테스트 그린** — `.venv/bin/pytest -q` 통과.
2. **커버리지 상승** — 직전 라운드보다 % 상승(유의미 폭; 미세 상승 반복 게이밍 경계).
3. **reviewer 스팟체크 통과** — `Task`(`subagent_type: reviewer`)로 이번에 추가한 테스트를 적대 검토.
   - 넘길 것: **[기준]** "테스트는 실제 동작을 검증해야 한다(무어서션·빈·항상참·중복 테스트 금지)", **[대상]** 추가/수정한 테스트 파일 경로, **[객관 신호]** `.venv/bin/pytest -q`, **[판정 형식]** `통과 | 지적있음`.

### 4. 체크포인트 / 롤백

- **진척 인정** → `git add -A && git commit`으로 **라운드 체크포인트**(메시지: `test : 커버리지 라운드 R — X%→Y%`).
- **후퇴/실패**(커버리지 하락·테스트 깨짐·reviewer 지적) → 그 라운드를 **즉시 롤백**(`git checkout -- .` / `git reset --hard <baseline-or-last-checkpoint>`). 진척으로 세지 않는다.

### 5. 루프 제어 — 안전판 ★무한/폭주 금지★

매 라운드 끝에 종료 조건을 점검한다:
- **예산 상한**: 최대 **8라운드** · **30분** 벽시계(+토큰 예산) 중 하나라도 닿으면 **즉시 중단·보고**.
- **진척 없음 가드**: 커버리지가 **K=2라운드 연속** 상승 없으면 "막힘"으로 중단.
- **서킷브레이커**: 변경이 **`tests/` 밖(app/ 로직·스키마·설정)** 으로 번지면 **자동 중단 → 사람**. (범위를 테스트 추가로 못박기 = 무인의 안전)
- **에스컬레이션**: "테스트만으로는 커버리지가 안 오른다(프로덕션 코드가 테스트 불가능한 구조)"로 판단되면 루프 탈출 → **설계문제로 `/plan`·`/impl`(게이트 경로) 권고**하고 사람 보고.

### 6. 종료 보고 — ★멈춤★

```
✅ 커버리지 목표 달성 — 라운드 R · 시작 X% → 최종 Y% (목표 T%)
또는  ⚠️ 예산/막힘 중단 — 최종 Y% (목표 T%), 사유: ...
또는  ↩ 서킷브레이커/설계문제 — /plan·/impl 권고 (사유: ...)

[요약] 라운드 R · 커버리지 추이 X%→…→Y% · 추가 테스트 파일 N개
[건강도] 루프 건강도 H · 5차원 루브릭 (효율·진척·안전·품질·수렴 — 아래 7)
[감사 로그] 라운드별: 커버리지·그린 여부·reviewer 판정·체크포인트/롤백
```

- 라운드 체크포인트 커밋은 남기되 **자동 푸시하지 않는다**(④ 마무리는 사람 — `/commit`·`/push`).

---

### 7. 루프 건강도 — 자가 측정·누적 ★"나아지는지" 재기★

목표 달성 여부(커버리지 %)와 **별개로**, **루프 자체가 얼마나 건강하게 돌았나**를 잰다.
> 커버리지 %는 *과제*가 됐나를, 건강도는 *루프*가 잘 돌았나를 잰다. 실행을 거듭하며 **나아지는지**를
> 보려면 루프 자신을 재는 자가 필요하다. 값은 모두 **감사 로그(6)에서 계산**된다 — 새 측정을 추가하지 않는다.

**① 한 줄 수식**
```
루프 건강도 = 진척 인정 라운드 / 전체 시도 라운드      (0~1 · 높을수록 헛돎 적음)
```
진척 인정 = 그린 + 커버리지↑ + reviewer 통과 셋 다. 롤백·막힘 라운드는 분모에만 든다.

**② 5차원 루브릭** (각 0·1·2점, 감사 로그에서 산출)

| 차원 | 2점(좋음) 기준 |
|------|----------------|
| 효율 | 목표 도달까지 라운드 ≤ 예산의 절반 |
| 진척성 | 진척 인정률 ≥ 0.8 |
| 안전 | 롤백·서킷브레이커·에스컬레이션 0건 |
| 품질 | reviewer **첫 통과율** ≥ 0.8 (게이밍 없이 한 번에 질 좋은 테스트) |
| 수렴 | 막힘·예산초과 없이 목표 도달 |

**③ 누적 — 실행 간 개선 추적** (필수1의 "축적"과 연결)

`docs/coverage-health.md`에 **이번 실행 한 줄을 append**한다(파일 없으면 아래 헤더와 함께 생성).
실행마다 쌓아 **여러 번 돌린 걸 비교**하면 루프가 나아지는지(롤백률↓·품질↑) 눈에 보인다.

```
| 날짜 | 대상 | 시작→최종% | 라운드 | 건강도 | 효율·진척·안전·품질·수렴 | 결과 |
|------|------|-----------|--------|--------|--------------------------|------|
| 2026-07-14 | app/ | 94.6→98.0 | 2 | 0.50 | 2·1·1·1·2 | 달성 |
```

- 날짜는 **절대 날짜**(YYYY-MM-DD · doc-conventions). 이 로그 쓰기는 **루프 종료 후 보고 단계**의 기록이라
  라운드별 서킷브레이커(테스트 변경이 밖으로 번짐) 대상이 아니다.
- 이 파일도 **자동 푸시하지 않는다** — ④ 마무리에서 사람이 커밋한다.

## 재활용 (원칙 3.2)

- **루프 뼈대**(최대 N·진척없음·에스컬레이션 분기): [`/impl`](../impl/SKILL.md) 패턴을 따른다.
- **라운드 검증**(적대 검토): 공유 [`reviewer`](../../agents/reviewer.md) 재활용 — 여기선 기준·대상만 준다.
- **신규는 둘뿐**: ① 커버리지 러너(`pytest --cov` 실행 → % 파싱 → 목표 비교, 덜 덮인 지점 식별) ② 범위 서킷브레이커(변경이 `tests/`에 한정되는지 감시).

## 수용 기준 (이 스킬이 제대로 동작하는지 검증)

- [ ] preflight에서 **커버리지 도구·워킹트리·브랜치**를 확인하고, 안 맞으면 멈춘다.
- [ ] `app/` 프로덕션 로직을 건드리지 않고 **`tests/`에만 테스트를 추가**한다.
- [ ] 진척 인정 = **전체 그린 + 커버리지 상승 + reviewer 통과 셋 다**(하나라도 빠지면 롤백).
- [ ] **예산 상한·진척없음 K=2**로 무한 루프에 빠지지 않는다.
- [ ] 변경이 `tests/` 밖으로 번지면 **서킷브레이커로 중단→사람**.
- [ ] 목표 달성/중단 시 **커버리지 추이·감사 로그와 함께 보고하고 멈춘다**(자동 푸시 금지).
- [ ] 종료 시 **루프 건강도(수식) + 5차원 루브릭**을 감사 로그에서 산출하고, `docs/coverage-health.md`에 이번 실행을 **한 줄 append**해 실행 간 비교가 쌓이게 한다.

## 안전 규칙

- **테스트만 추가한다.** `app/` 로직·스키마·설정을 고쳐야 커버리지가 오르면 — 그건 이 스킬이 아니라 **설계문제 에스컬레이션**.
- **셀프 채점 금지.** 테스트 품질 판정은 `reviewer`가 한다(무어서션으로 숫자만 올리는 게이밍 차단).
- **무인 ≠ 무제한.** 예산·진척없음·서킷브레이커 가드는 **끌 수 없다**. 애매하면 중단이 안전한 쪽.
- **롤백 가능 유지.** 라운드마다 체크포인트, 후퇴는 즉시 롤백. **자동 푸시·PR·머지 금지.**
- 하위 일꾼(`reviewer`·디스패치 에이전트)이 빈 결과·오류를 돌려주면 그대로 알리고 멈춘다.
