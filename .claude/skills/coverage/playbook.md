# /coverage 플레이북 — OS층 (이식됨)

> **무엇:** `/coverage` 루프가 실행 경험에서 회수한 "마찰점 → 권고" **lesson**의 축적소.
> 루프가 다음 실행에서 이걸 읽어 같은 벽에 덜 부딪힌다.
> **왜 스킬 디렉토리에 두나:** lesson은 스킬이 읽는 데이터(메모리)이지 산출물(docs)이 아니다. 스킬과 함께 이식돼야 다른 프로젝트에서도 교훈이 따라간다.

## ⚠️ 층 규칙 — 이 파일엔 OS층(일반) lesson만

lesson은 `app/`(도그푸딩 예시 하나)에서 나오지만, 이 파일은 **스킬과 함께 이식**된다. 그래서:

- **여기(OS층):** 프로젝트 무관한 일반 교훈만. 예 — "async 타임아웃 분기는 mock clock이 필요하다", "예외 분기부터 겨냥하면 라운드당 커버리지 이득이 크다".
- **`app/` 전용 지식은 금지.** 예 — "`app/auth.py`는 `fake_redis` fixture가 필요" 같은 특정 모듈 지식 → **프로젝트층 플레이북**(`.claude/context/coverage-playbook.md`)에 쓴다. 그 파일은 이식 시 새 프로젝트에 맞게 리셋된다(= `backend-conventions.md`와 같은 프로젝트 카드 취급).
- **애매하면 프로젝트층으로.** OS층 오염(app 지식이 이식됨)이 이 기능 최대 리스크다 — 불확실할 땐 이식 안 되는 쪽(프로젝트층)이 안전 기본값이다.

## 쓰는 법 / 읽는 법 (모두 무인 — SKILL.md 로직 수술만 사람 게이트)

- **루프 시작 시:** `status: 검증됨` lesson을 읽어 이번 라운드 전략에 참고한다.
- **루프 종료 시:** 이번 실행의 마찰점을 `status: 후보` lesson으로 아래 목록에 append한다.
- **검증(승격/강등):**
  - 후보 lesson이 적용된 실행에서 **성과 지표(= 커버리지 목표 도달 여부)** 가 실제로 개선될 때만 `후보 → 검증됨` 승격.
  - **⚠️ Goodhart 가드:** 대리지표(라운드 수·후퇴율·트립·막힘)만 좋아지고 커버리지 도달이 개선 안 되면 **승격하지 않는다.** lesson이 "안전한 시도 회피"로 대리지표만 꾸미는 자기강화 게이밍을 막는다.
  - 검증됨 lesson이 이후 실행에서 성과 기여 없으면 → `강등`. **강등 후 3실행 연속 무효 → 폐기**(목록에서 제거).
- **크기 관리:** 후보는 최대 20개까지만 유지(넘으면 오래된 무효 후보부터 정리). 신호·권고가 겹치는 lesson은 병합한다.

## lesson 스키마

| 필드 | 뜻 |
|------|-----|
| id | `L###` 일련번호 |
| 제목 | 한 줄 요약 |
| 마찰 유형 | 커버실패 / 롤백 / 서킷브레이커 / 막힘 / 에스컬레이션 |
| 신호 | **언제** 적용하나 — 감사 로그에서 무엇을 보면 이 lesson을 꺼내나 |
| 권고 | **무엇을** 다르게 할지 (구체 행동) |
| 층 | OS (이 파일은 항상 OS) |
| status | 후보 / 검증됨 / 강등 |
| 근거 | 어느 실행·라운드에서 왔나 + 관측한 **성과 지표 변화** |

**append 양식 (복사해서 채운다):**

```
### L### — <한 줄 제목>   [status: 후보]
- 마찰 유형: <커버실패|롤백|서킷브레이커|막힘|에스컬레이션>
- 신호: <감사 로그의 어떤 패턴을 보면 적용>
- 권고: <무엇을 다르게 할지>
- 층: OS
- 근거: <YYYY-MM-DD 실행 · 라운드 R> — <커버리지 도달 여부 등 성과 변화>
```
