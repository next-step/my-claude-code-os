# task-impl

ticket-start 브리핑을 받아 개발 단위(태스크)로 분해하고,
태스크 하나씩 구현 → 확인 → 커밋을 반복해 작업을 완료한다.

`/ticket-start` → **/task-impl** → `/dev-loop` 흐름의 중간 단계.

**v1.1 변경:** 0단계에 프로젝트 도메인 파악 단계 추가, 공용 문서 참조 경로 수정.
**v1.2 변경:** 태스크 목록을 `docs/tasks.md`로 영속화, 랄프 모드(외부 루프 반복 실행) 추가.

---

## 0단계: 입력 파악

**인자가 "랄프 반복"이면** 아래 단계를 모두 건너뛰고 [랄프 반복 실행](#랄프-반복-실행)으로 바로 이동한다.

`docs/tasks.md`가 이미 존재하고 미체크 태스크가 남아 있으면 재개 여부를 먼저 묻는다. 재개를 선택하면 1~2단계를 건너뛰고 남은 태스크부터 3단계를 진행한다.

아래 순서대로 입력을 찾는다:

1. **`docs/ticket-briefing.md` 파일**: 먼저 Read로 파일 존재 여부를 확인한다. 있으면 해당 내용을 브리핑으로 사용한다.
2. **직전 대화의 ticket-start 브리핑**: "## 티켓 브리핑:" 형식으로 시작하는 텍스트
3. **자유 형식 설명**: 사용자가 직접 작업 범위를 설명한 텍스트

셋 다 없으면 다음을 묻는다:

```
작업 범위를 설명해 주세요.
ticket-start 브리핑 텍스트를 붙여넣거나, 할 일을 직접 설명해도 됩니다.
```

입력을 확보한 뒤, `~/.claude/docs/project-domain-detection.md`를 Read 도구로 읽고 해당 절차에 따라 프로젝트 도메인을 파악한다. 생성된 한 줄 요약은 1단계 태스크 분해와 3단계 구현 시 컨텍스트로 활용한다.

이어서 `~/.claude/docs/code-conventions.md`를 Read 도구로 읽고 해당 절차에 따라 코드 컨벤션을 파악한다. 파악된 컨벤션은 3단계 구현 시 코드 스타일 기준으로 활용한다.

이어서 아래 파일들을 순서대로 확인해 **커밋 컨벤션**을 감지한다:

```
commitlint.config.js / .commitlintrc / .commitlintrc.json
CONTRIBUTING.md
.github/COMMIT_CONVENTION.md
docs/commit-convention.md
```

- **감지 시**: 타입 목록·언어·스코프 필수 여부 등 규칙 요약을 메모하고 `[컨벤션 감지됨: <파일명>]` 출력 후 1단계로 이동
- **미감지 시**: 기본 Conventional Commits 규칙 사용 (아래 C단계 참조)

## 1단계: 태스크 분해

입력에서 다음을 추출한다:

- 요구사항 요약
- 영향받는 파일 / 컴포넌트 목록
- 사이드이펙트 체크리스트 (있는 경우)

그 다음 **개발 단위(태스크)** 로 쪼갠다.

### 분해 기준

| 기준          | 설명                                                                         |
| ------------- | ---------------------------------------------------------------------------- |
| 논리적 완결성 | 하나의 태스크 = 하나의 커밋으로 설명 가능한 변경                             |
| 의존성 분리   | A가 완료돼야 B를 시작할 수 있는 경우 순서를 명시                             |
| 파일 응집도   | 같은 파일/컴포넌트를 건드리는 변경은 하나의 태스크로 묶음                    |
| 크기 제한     | 태스크 하나가 너무 크면 재분할 (기준: 파일 3개 초과 또는 200줄 초과 예상 시) |

---

## 2단계: 태스크 목록 확인

분해 결과를 아래 형식으로 출력한다:

```
## 개발 태스크 목록

총 N개 태스크 | 예상 커밋 N개

┌───┬──────────────────────────────┬─────────────────────────┬──────┐
│ # │ 태스크 제목                     │ 대상 파일                 │ 의존 │
├───┼──────────────────────────────┼─────────────────────────┼──────┤
│ 1 │ [제목]                        │ [파일명, 파일명]           │  -   │
│ 2 │ [제목]                        │ [파일명]                  │  1   │
│ 3 │ [제목]                        │ [파일명, 파일명]           │  1   │
└───┴──────────────────────────────┴─────────────────────────┴──────┘

각 태스크 상세:

**태스크 1: [제목]**
- 대상: [파일명]
- 변경 내용: [무엇을 어떻게]
- 커밋 메시지 예상: `feat(xxx): [요약]`

**태스크 2: [제목]**
...

이 순서대로 진행할까요?
수정하려면 알려주세요. (예: "2와 3 순서 바꿔줘", "1번 빼줘", "4번 추가: ...")
문제없으면 "시작"이라고 입력해 주세요.
```

사용자가 수정을 요청하면 목록을 업데이트하고 다시 보여준 뒤 재확인한다.
"시작" 또는 승인 의사를 받으면 확정된 목록을 `docs/tasks.md`에 저장한 뒤 3단계로 이동한다.

### docs/tasks.md 포맷

진행 상태의 단일 원본(source of truth). 새 컨텍스트가 이 파일만 읽고 이어서 작업할 수 있어야 한다.

```markdown
# 태스크 목록

브리핑: docs/ticket-briefing.md (없으면 요구사항 한 줄 요약)
완료 조건: 아래 태스크 전부 체크

- [x] 1. 토큰 갱신 훅 추가 (abc1234) | 의존: -
- [x] 2. API 클라이언트에 훅 연결 (def5678) | 의존: 1
  - 메모: refreshToken 만료 정책이 기획서에 없어 7일로 가정
- [ ] 3. 만료 시 로그아웃 처리 | 의존: 1
- [ ] 4. 에러 토스트 연결 | 의존: 3
```

**메모 규칙:** 코드만 봐서는 알 수 없는 것만 기록한다 — 가정, 계획 이탈, 보류 사유. 구현 과정 서술은 금지 (기록은 코드와 커밋 메시지가 담당).

## 3단계: 태스크 구현 루프

확정된 태스크 목록을 순서대로 처리한다.

### 사전 평가: 실행 모드 결정

아래 기준을 확인한다:

- **사용자가 랄프 모드를 요청** 또는 **태스크 수가 많아 한 대화로 끝내기 어려운 규모(기준: 태스크 수 ≥ 8)** → **랄프 모드** 제안 (아래 랄프 모드 절차 따름)
- **태스크 수 ≥ 5** 또는 **모든 태스크 의존 = `-`** → **에이전트 위임 모드** (아래 위임 절차 따름)
- 그 외 → **직접 실행 모드** (각 태스크마다 A→B→C 루프)

---

#### 랄프 모드 절차

이 대화에서는 구현하지 않는다. `docs/tasks.md` 저장(2단계에서 완료)을 확인한 뒤, 루프 진입 전 점검을 하고 안내만 출력하고 종료한다.

**1. 진입 전 점검**: 태스크 목록에 불명확한 부분이 있으면 지금 사용자에게 질문해 해소하고 tasks.md에 반영한다. 루프 반복 중에는 질문할 수 없으므로, 모호함은 반드시 여기서 제거한다.

**2. 안내 출력 후 종료**:

```
랄프 모드 준비 완료. docs/tasks.md에 N개 태스크가 저장되었습니다.

아래 명령으로 루프를 시작하세요:

/loop /task-impl 랄프 반복

각 반복은 새 컨텍스트에서 태스크 하나를 구현·커밋하고 종료합니다.
전체 완료 시 루프가 자동 정지하며, 이후 /dev-loop 로 검증·PR을 진행하세요.
```

---

#### 에이전트 위임 모드 절차

**1. 위임 전 준비**: 태스크 목록 전체를 검토해 불명확한 부분을 사용자에게 질문하고 해소한다.

**2. 에이전트 프롬프트 작성**: 각 태스크마다 아래 내용을 포함한다.

> 다음 태스크를 구현하고 커밋하세요.
>
> **태스크**: [태스크 제목]
> **대상 파일**: [파일 목록]
> **변경 내용**: [상세 설명]
> **커밋 컨벤션**: [감지된 규칙 or 기본 Conventional Commits]
> **이전 태스크 완료 정보**: [의존 태스크 SHA 및 변경 요약 / 없으면 '없음']
>
> 규칙:
>
> - 불명확한 부분은 추측하지 말고 `[CLARIFICATION_NEEDED: 질문]` 형식으로 반환
> - `.env` 등 민감 파일 감지 시 커밋 중단 후 `[SECURITY_ALERT: 파일명]` 반환
> - 완료 후 마지막 줄에 `[SHA: abc1234]` 형식으로 커밋 SHA 출력

**3. 실행 방식**:

- 의존 = `-` 태스크들: 단일 메시지에 여러 Agent 호출로 병렬 실행
- 의존 있는 태스크: 앞 태스크 완료 후 순차 실행

**4. 반환값 처리**:

- `[CLARIFICATION_NEEDED]` → 사용자에게 질문 후 해당 에이전트 재실행
- `[SECURITY_ALERT]` → 경고 출력 후 전체 중단
- `[SHA: ...]` → SHA 기록 후 다음 태스크로

---

#### 직접 실행 모드

각 태스크마다 아래 A → B → C를 반복한다.

### A. 태스크 시작 알림

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
태스크 [N/전체] 시작: [태스크 제목]
대상 파일: [파일명 목록]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### B. 구현

대상 파일을 먼저 Read로 읽은 뒤, 태스크 내용에 따라 Edit/Write로 변경한다.

- 기존 파일 수정: Read → Edit (최소한의 변경, 스타일은 기존 코드에 맞춤)
- 새 파일 생성: Write
- 구현 중 불명확한 부분이 생기면 즉시 사용자에게 질문하고 진행 (추측하지 않음)

### C. 커밋

**1. 커밋 메시지 생성**

0단계에서 감지된 컨벤션이 있으면 해당 규칙을 따른다.
감지된 컨벤션이 없으면 [conventions.md](../../docs/commit-conventions.md) "커밋 메시지" 섹션의 기본 규칙을 따른다.

**2. 보안 체크**

커밋 전 민감 파일 포함 여부를 확인한다.

```bash
git diff --cached --name-only | grep -E '\.env|secrets|credentials'
```

감지 시 **반드시 경고** 후 중단.

**3. 커밋 실행**

커밋 메시지를 정보용으로 한 줄 출력한 뒤 즉시 실행한다:

```
[커밋] feat(auth): 토큰 만료 시 자동 갱신 로직 추가
```

```bash
git add -A
git commit -m "$(cat <<'EOF'
<생성된 커밋 메시지>
EOF
)"
```

커밋 완료 후 SHA를 기록하고, `docs/tasks.md`의 해당 태스크를 체크(`[x]`) + SHA 표기로 갱신한 뒤 다음 태스크로 이동한다. (위임 모드에서는 `[SHA: ...]` 반환을 받을 때마다 동일하게 갱신한다.)

## 랄프 반복 실행

`/task-impl 랄프 반복`으로 호출됐을 때의 절차. **한 반복 = 태스크 하나.** 새 컨텍스트에서 실행되므로 대화 기억에 의존하지 않고 파일과 git 이력만으로 상황을 파악한다.

1. **상태 파악**: `docs/tasks.md`를 Read. 파일이 없으면 `BLOCKED: docs/tasks.md 없음 — /task-impl로 태스크 분해를 먼저 실행하세요`를 출력하고 종료(루프 중지). `git log --oneline -5`로 직전 반복의 커밋을 확인한다.
2. **종료 판정**:
   - 모든 태스크가 체크됨 → **`DONE`** 출력 후 종료. 루프 실행 중이면 루프를 정지시킨다.
   - 미체크 태스크가 전부 `⏭ 보류` 상태 → **`BLOCKED: <보류 사유 요약>`** 출력 후 종료(루프 중지). 사람의 판단이 필요한 상태.
3. **태스크 선택**: 미체크 태스크 중 의존이 모두 체크된 첫 번째 하나를 선택한다.
4. **구현**: 직접 실행 모드 B단계와 동일하게 구현하되, **사용자에게 질문하지 않는다**:
   - 불명확한 부분 → 합리적 가정을 세워 진행하고, 가정을 tasks.md 메모로 기록
   - 진행 불가(수동 작업 필요, 가정이 위험한 정책 판단 등) → 해당 태스크에 `⏭ 보류: 사유` 메모를 남기고 커밋 없이 종료 (다음 반복은 다음 태스크로 진행)
5. **tasks.md 갱신**: 해당 태스크 체크 + 필요시 메모 한 줄. 메모 규칙(가정/이탈/보류만) 준수.
6. **커밋**: 직접 실행 모드 C단계와 동일 (컨벤션 준수, 보안 체크). tasks.md 갱신분도 같은 커밋에 포함한다. 커밋 후 tasks.md의 태스크에 SHA를 표기하는 것은 다음 커밋에 포함돼도 무방하다 — 별도 커밋을 만들지 않는다.
7. **반복 종료**: 아래 한 줄을 출력하고 즉시 종료한다. 다음 태스크로 넘어가지 않는다.

```
[랄프 N/전체] 태스크 N 완료: <제목> (<SHA>) — 남은 태스크 M개
```

## 4단계: 최종 요약 출력

모든 태스크가 완료되면 아래 형식으로 요약한다:

```
╔══════════════════════════════════════════════════╗
║          /task-impl 완료 요약                    ║
╠══════════════════════════════════════════════════╣
║  태스크 1: [제목]   → ✅ abc1234                 ║
```

## 중단 / 재개 처리

진행 상태의 원본은 `docs/tasks.md`이므로, 언제 중단하든 파일만 최신이면 재개할 수 있다.

구현 중 사용자가 "중단", "잠깐 멈춰", "나중에 계속" 등을 입력하면 `docs/tasks.md`를 현재 상태로 갱신한 뒤:

```
현재까지 완료된 태스크:
- ✅ 태스크 1: [제목] (abc1234)
- ✅ 태스크 2: [제목] (def5678)

남은 태스크:
- ⏳ 태스크 3: [제목]
- ⏳ 태스크 4: [제목]

진행 상태는 docs/tasks.md에 저장되었습니다.
재개하려면 "/task-impl"(재개 여부를 물음) 또는 "/loop /task-impl 랄프 반복"으로 이어서 진행하세요.
```

---

## 주의사항

- 2단계 확인 후에는 각 태스크 구현 완료 즉시 자동으로 커밋한다 (태스크별 중간 확인 없음)
- 태스크 하나를 구현하는 중 다른 파일을 임의로 수정하지 않는다 (사이드이펙트 방지)
- 구현 중 불명확한 요구사항이 있으면 추측하지 않고 즉시 질문한다 (예외: 랄프 반복 중에는 질문 대신 가정 기록 또는 보류 처리)
- `.env`, 비밀키, 개인정보 파일이 감지되면 반드시 경고 후 중단한다
- `--no-verify` 등 훅 우회 플래그는 사용자가 명시적으로 요청할 때만 사용한다
- 각 태스크는 독립적으로 빌드 가능한 상태(컴파일 에러 없음)로 구현한다
