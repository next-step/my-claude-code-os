# 시스템 루프 건강도 (loop-health)

## 랄프 루프와 무엇이 다른가

| | 랄프 루프 | 이 스킬 |
|---|---|---|
| 보는 것 | 정해진 과제 안의 지표 | 과제를 만드는 루프 자체 |
| 최적화 | 국소 — 목표까지 끌어올린다 | 전역 — 루프를 다시 짠다 |
| 끝나는 조건 | 지표가 목표값에 닿음 | 없다. 계속 재는 것이다 |

## 실행

```bash
node -e "console.log(JSON.stringify(require('./.claude/lib/loop-health.js').auditLoopHealth({projectDir:process.cwd()}), null, 2))"
```

집계는 전부 `auditLoopHealth`가 합니다. **여기서 덧셈을 다시 하지 마십시오** — 호출부마다 다시 세면 사람마다 다른 수치를 말하게 됩니다(`context-experiment.md`가 `summarizeBudget`에 대해 정한 것과 같은 규약).

## 무엇을 보여주는가

### 점수 — 분모를 반드시 함께 말한다

`score.value`는 **`검사기가 실제로 본 항목 중 위반이 아닌 비율`**입니다. "일어날 수 있는 모든 나쁜 일" 중의 비율이 아닙니다.

보고할 때 `value`만 쓰지 말고 `numerator/denominator`와 `definition`을 같이 적습니다. 점수가 `1.00`이면 그것은 **"우리가 가진 검사기가 전부 초록불이다"**라는 뜻이고, 그 이상은 아닙니다.

### 네 축

| 축 | 무엇을 | 어디서 |
|---|---|---|
| 위생 `hygiene` | 낡은 수치, 지침 모순, 등록 정합성 | `freshness.js` · `guideline-audit.js` · `context-inject.js` |
| 신뢰도 `reliability` | 지금 빨간불인가, 두 번 이상 깨진 AC가 있는가 | `.claude/atdd-failure-ledger.json` |
| 자율성 `autonomy` | 랄프 루프가 `done`으로 끝난 비율 | `experiments/ralph/runs/*/summary.json` |
| 세금 `tax` | 상시 로드 자수, 온디맨드 자수 | `summarizeBudget` |

**네 축을 한 숫자로 합치지 않았습니다.** 재발 AC 1건과 낡은 수치 1건은 무게가 다른데, 가중치를 정할 근거가 아직 없습니다. 근거 없는 가중치로 한 숫자를 만들면 그 숫자가 무엇을 뜻하는지 아무도 모르게 됩니다.

### 위임 폭 `coverage` — 사람이 적는 루브릭

가장 중요한 축인데 **자동으로 재지 못합니다.** 루프 단계 목록이 코드 어디에도 없기 때문입니다. `docs/loop-delegation.json`에 사람이 단계별 담당 주체를 적고, 이 스킬은 읽기만 합니다.

`owner`는 넷입니다 — `human`(매번 사람) · `mixed`(AI가 하고 사람이 결정) · `ai`(AI가 함) · `system`(훅·테스트가 함).

단계를 위임했으면 `owner`를 올리고 `delegatedTo`에 스킬·에이전트·훅 이름을 적습니다. **`humanRemains`를 비워 두지 마십시오** — "아무것도 안 남았다"는 주장은 대개 틀렸고, 그 틀림이 드러나는 곳이 이 칸입니다.

루브릭이 없으면 `coverage`는 `null`로 나갑니다. 0으로 채우지 않습니다 — 0은 "사람이 하는 단계가 하나도 없다"로 읽혀 점수를 실제보다 좋아 보이게 만듭니다.

## 추세는 어떻게 보나

**스냅샷을 자동으로 쌓지 않습니다.** 훅이 파일을 쓰면 `git status`에 잡혀 `big-change-commit-check.js`가 무한 재발동합니다 — 이 저장소가 이미 두 번 겪은 버그입니다(`hook-discipline.md`). 추세가 필요하면 실행 결과를 사람이 `docs/`에 적어 남깁니다.

## 하지 않는 것

- **점수를 품질 보증으로 제시하지 않는다.** `blindSpots`를 항상 함께 냅니다. 초록불일 때도 냅니다.
- **위임 폭 루브릭을 스스로 고치지 않는다.** 무엇을 위임했는지는 사람이 정합니다. AI가 자기 담당 범위를 스스로 넓혀 적으면 이 축은 측정이 아니라 자기 신고가 됩니다.
- **새로 측정하지 않는다.** 기존 감사기 다섯 개의 출력을 모으기만 합니다. 같은 것을 두 곳에서 재면 두 수치가 갈라집니다.
- **축을 합쳐 한 숫자로 내지 않는다.** 근거 있는 가중치가 생기기 전까지는 그렇습니다.

## 이 지표가 보지 못하는 것

`blindSpots`에 코드로 박아 두었습니다. 요약하면 이렇습니다.

- **지침을 실제로 지켰는가** — 마크다운 지시문은 테스트할 수 없습니다.
- **위임한 판단이 옳았는가** — 서브에이전트의 PASS/FAIL이 맞는지는 아무도 안 봅니다.
- **검사기 자신의 결함** — 랄프 루프의 결함 두 개(명령 target 미측정, 실패 세션 오집계)는 둘 다 **점수가 초록불인 상태에서** 사람이 찾았습니다. 이 지표는 그런 종류를 구조적으로 못 봅니다.
