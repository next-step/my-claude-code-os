# 이미지 → UI 스펙 추출 (ui-spec-from-image)

화면 목업 이미지를 읽어 레이아웃·컴포넌트·텍스트·색상을 구조화된 문서로 옮기는 스킬입니다. ATDD 파이프라인에서 요구사항에 이미지가 첨부된 경우 02단계(`spec-decompose`) **앞**에 오는 준비 단계이며, `atdd-orchestrator`가 이 스킬을 조건부로 위임합니다.

## 언제 쓰는가

사용자가 직접 "이미지로 UI 스펙 뽑아줘", "이 목업 분석해줘"라고 요청하거나, `atdd-orchestrator`가 요구사항에 이미지가 첨부된 것을 확인하고 02단계 전에 위임할 때 사용한다.
**이 스킬은 UI 스펙 문서를 제시하고 멈추는 것까지만 한다. 인수기준으로 변환하지 않고(그건 spec-decompose의 몫), 구현·테스트도 하지 않고(acceptance-test-write/tdd-implement의 몫), 스펙이 요구사항을 충분히 담았는지 판정하지도 않는다(policy-reviewer의 몫).**

## 실행 절차

1. **이미지 확인**
   - 입력으로 받은 이미지 경로(들)를 `Read` 도구로 읽는다. 텍스트 컨텍스트(요구사항 원문 일부)가 함께 주어졌다면 참고하되, 이미지에 없는 내용을 상상해서 채우지 않는다.

2. **feature-slug 결정**
   - 요구사항이나 화면 성격에서 케밥 표기 슬러그를 정한다(예: 로그인 화면 → `login-page`, 설정 화면 → `settings-screen`). 이후 모든 산출물 경로에 이 슬러그를 쓴다.

3. **원본 이미지를 프로젝트 안으로 저장**
   - `CLAUDE.md` 규칙("클로드 OS 관련 모든 파일은 반드시 프로젝트 안에 만들 것")에 따라, 사용자가 프로젝트 밖 경로의 이미지를 줬다면 반드시 `.claude/tests/fixtures/<feature-slug>/mockup.<원본 확장자>`로 복사한다. 이미 프로젝트 안에 있다면 그 경로를 그대로 이 위치로 정리한다.

4. **UI 스펙 문서 작성**
   - `.claude/tests/fixtures/<feature-slug>/ui-spec.md`에 다음을 구조화해서 적는다:
     - **레이아웃**: 화면을 몇 개 영역으로 나눌 수 있는지, 각 영역의 배치(상단/중앙/하단, 좌/우 등)
     - **컴포넌트 목록**: 버튼/입력창/텍스트/이미지 등 각 요소의 종류, 대략적 위치, 존재 여부
     - **텍스트 콘텐츠**: 이미지에 보이는 텍스트를 원문 그대로(레이블, 버튼 문구, 안내문 등)
     - **색상**: 배경/버튼/텍스트 등 주요 요소의 색상을 가능한 한 hex 값으로 추정(정확한 hex를 알 수 없으면 "진한 파란색 계열"처럼 서술하고 확신 정도를 밝힌다)
     - **상태/인터랙션 단서**: 이미지에서 유추 가능한 상호작용(예: 버튼이 비활성 상태로 보임, 입력창에 placeholder 텍스트가 있음) — 확실하지 않으면 단정하지 않고 "~로 보임" 식으로 표시

5. **멈춤**
   - `ui-spec.md` 내용과 저장 경로(`mockup.*`, `ui-spec.md`), feature-slug를 제시한 뒤 멈춘다. 인수기준으로 변환하지 않고, 호출한 쪽(사람 또는 `atdd-orchestrator`)이 다음을 결정하게 넘긴다.

## 참고

- 이 스킬의 산출물은 `spec-decompose`(02단계, UI AC 생성)와 `policy-reviewer`(03단계, 원본 이미지 대조 판정) 양쪽에서 참조된다. 특히 `policy-reviewer`는 이 문서가 아니라 **원본 이미지 자체**를 최종 판정 근거로 쓰므로, `mockup.*` 사본이 원본과 시각적으로 동일하게 저장되어야 한다.
- 이미지에서 확인할 수 없는 내용은 추측으로 채우지 않는다. 불확실한 항목은 "~로 보임"처럼 확신 정도를 표시해, 이후 03단계 리뷰나 05단계 AC 작성에서 잘못된 확신으로 이어지지 않게 한다.
- 여러 화면(예: 로그인 전/후)이 이미지 여러 장으로 주어지면 화면별로 섹션을 나눠 하나의 `ui-spec.md`에 정리한다.

## 예시

```
사용자: (이미지 첨부: settings-mockup.png) "설정 화면에 저장 버튼이 있어야 한다"

[ui-spec-from-image] feature-slug: settings-screen
  → .claude/tests/fixtures/settings-screen/mockup.png 로 원본 저장
  → .claude/tests/fixtures/settings-screen/ui-spec.md 작성:

레이아웃:
- 상단: 헤더 영역 (텍스트 "설정")
- 중앙: 폼 영역 (라벨 + 입력창 2개)
- 하단: 액션 영역 (버튼 1개, 우측 정렬)

컴포넌트 목록:
- h1 텍스트: "설정" (헤더 영역)
- input(text): 라벨 "이름"
- input(text): 라벨 "이메일"
- button: 텍스트 "저장" (하단 우측)

텍스트 콘텐츠:
- 헤더: "설정"
- 버튼: "저장"

색상:
- 배경: #ffffff (흰색)
- 저장 버튼 배경: #2563eb로 추정 (진한 파란색 계열, hex는 근사치)
- 저장 버튼 텍스트: #ffffff

상태/인터랙션 단서:
- 저장 버튼은 활성 상태로 보임 (색이 진하고 그림자 없음)

여기까지 정리했습니다. 인수기준 분해는 spec-decompose의 몫이라 멈춥니다.
```
