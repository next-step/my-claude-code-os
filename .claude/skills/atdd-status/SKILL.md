# ATDD OS 현황 (atdd-status)

지금 이 저장소의 ATDD OS가 **무엇으로 구성돼 있고 어디까지 동작하는지**를 한 화면으로 보여주는 점검용 스킬입니다. 파이프라인을 실행하지 않고, 상태만 조회합니다.

OS를 계속 키워 나가다 보면 "내가 지금 뭘 만들어 놨더라"를 잊게 됩니다. 이 스킬은 그 질문에 답합니다.

## 언제 쓰는가

사용자가 "OS 지금 상태 어때", "어디까지 만들었지", "파이프라인 현황", "atdd status" 등을 물을 때 사용한다.
**이 스킬은 조회 전용이다. 어떤 파일도 만들거나 수정하지 않고, 파이프라인을 실행하지도 않는다.**

## 실행 절차

1. **구성요소 수집**
   - `.claude/skills/` 하위 디렉터리 목록 → 스킬 이름과 개수
   - `.claude/agents/` 의 `.md` 파일 목록 → 서브에이전트 이름과 개수
   - `.claude/hooks/` 의 파일 목록과 `.claude/settings.json` 의 훅 등록 상태 → 훅 개수와 매처

2. **파이프라인 단계 매핑**
   - `OS.md`에 정의된 7단계 각각에 대해 담당 구성요소와 동작 여부를 표로 정리한다.
   - 01 요구사항(사람) / 02 `spec-decompose` / 03 `policy-reviewer` / 04 AskUserQuestion / 05 `acceptance-test-write` / 06 `tdd-implement` / 07 `failure-ledger` + 훅
   - 담당 파일이 실제로 존재하는지 확인해 ✅(동작) / 🔧(뼈대만) / ⏳(미구현)으로 표시한다.

3. **현재 초록불/빨간불 판정**
   - `.claude/atdd-failure-ledger.json` 의 마지막 항목을 본다. `RESOLVED`면 🟢, `FAIL`이면 🔴, 파일이 없으면 "아직 테스트를 돌린 적 없음".
   - 자세한 실패 이력은 `failure-ledger` 스킬로 볼 수 있다고 안내만 하고, 여기서 전체 이력을 다시 늘어놓지 않는다.

4. **공유 서브에이전트 관계 표시**
   - 어떤 서브에이전트가 어떤 스킬들에서 재사용되고 있는지 간단한 화살표 도식으로 보여준다.
   - 재사용되는 에이전트가 있으면 그 점을 짚어준다 — 이 OS의 설계 의도가 드러나는 부분이기 때문이다.

5. **요약 한 줄**
   - "스킬 N개 + 서브에이전트 M개 + 훅 K개, 7단계 중 X단계까지 실제 동작, 현재 🟢/🔴" 형태로 마무리한다.

## 참고

- 스킬 호출 **횟수** 통계는 이 스킬의 몫이 아니다 — `skill-stat`이 담당한다. 여기서는 "무엇이 있는가"만 다루고, "얼마나 썼는가"는 `skill-stat`으로 안내한다.
- 실패 **이력**도 이 스킬의 몫이 아니다 — `failure-ledger`가 담당한다. 여기서는 현재 초록불/빨간불 한 줄만 본다.

## 예시

```
ATDD OS 현황

구성: 스킬 7개 · 서브에이전트 2개 · 훅 2개

| 단계 | 담당 | 상태 |
|-----|------|-----|
| 01 요구사항 | 사람 | ✅ |
| 02 정책 분해 | spec-decompose | ✅ |
| 03 독립 리뷰 | policy-reviewer (에이전트) | ✅ |
| 04 정책 승인 | AskUserQuestion | ✅ |
| 05 실패 테스트 | acceptance-test-write | ✅ |
| 06 TDD 구현 | tdd-implement | ✅ |
| 07 실패 원장 | failure-ledger + atdd-failure-log 훅 | ✅ |

공유 서브에이전트:
  acceptance-test-write ─┐
                         ├─▶ test-reviewer
  tdd-implement         ─┘

→ 7단계 전부 동작. 현재 🟢 초록불 (마지막 기록: RESOLVED)
   호출 횟수는 skill-stat, 실패 이력은 failure-ledger 로 확인하세요.
```
