# retrospect — 세션 회고로 OS를 복리로 키우기

세션이 끝날 때 stock-os를 한 뼘 더 좋게 만드는 메타 루프다. 핵심은 두 가지 — **매 회고 최소 1개의
변화(즉시 수정 또는 신규 lesson)를 남긴다**는 것, 그리고 그 결과가 **SessionStart 훅을 통해 다음
세션에 되먹임**되어 축적된다는 것. 회고가 write-only 무덤이 되지 않게, 열린 이슈는 계속 다음 세션으로
넘어가 하나씩 닫힌다.

```
[SessionStart 훅 주입: 열린 이슈+최근 lesson]  ─→  세션 작업  ─→  /retrospect
        ▲                                                            │ ①즉시개선 ②이슈기록/해결 ③lesson누적
        └──────────────────── 다음 세션에 되먹임 ◀────────────────────┘
```

이 스킬은 **메인 컨텍스트에서** 실행한다. 세션에서 실제로 무슨 일이 있었는지는 메인만 알기 때문에
subagent로 위임하지 않는다(월말 복기의 monthly-reviewer와 구조가 다른 이유).

## 절차

작업 양식은 [[_template]](`06_retrospect/_template.md`)를 참고한다. 별도 회고 문서를 저장할 필요는
없고, 결과를 lessons.md·issues.md에 반영하고 3줄 요약만 보여준다.

### 1. 세션 스캔 (메인)
이번 세션에서 한 일, 막혔던 지점, 반복된 비효율, 사용자가 정정해준 부분을 훑는다.
SessionStart로 주입됐던 **열린 이슈를 이번에 건드렸는지** 먼저 확인한다(닫을 기회).

### 2. 분류
관찰한 문제를 둘로 나눈다.
- **(a) 즉시 개선 대상** = 작고·안전하고·되돌리기 쉬움 (문서 오타, 체크리스트 한 줄, 스킬 문구 보정,
  깨진 wikilink 등).
- **(b) 이슈 기록 대상** = 크거나·판단이 필요하거나·설계 변경을 수반 (새 subagent, 루프 구조 변경 등).

### 3. 즉시 개선 (안전한 1건 우선)
(a) 중 가장 값진 1건을 **실제로 수정**한다. 여러 개가 사소하면 묶어도 되지만, 회고 중에 큰 리팩터를
몰래 시작하지 않는다(그건 (b)로). `.claude/` 안 파일을 고칠 땐 머신 종속 절대경로를 넣지 말 것
(absolute-path-guard가 차단; 상대경로·`$CLAUDE_PROJECT_DIR` 사용). `os.md`의 규칙을 바꾸는 개선이면
SSOT 정합성을 위해 관련 섹션(§2 구조맵 등)도 함께 갱신한다.

### 4. 이슈 기록 / 해결 (`06_retrospect/issues.md`)
- 신규 (b) 문제는 파일 상단에 **`상태: 열림`** 으로 append. 번호 `#NNN`은 기존 최대치 +1.
- 이번 세션에 해결된 열린 이슈는 그 자리에서 `상태: 해결 (오늘 날짜)`로 갱신하고 해결 메모를 채운다.
- 원인을 모르면 "미상"으로 두고 추정하지 않는다.

### 5. lesson 누적 (`06_retrospect/lessons.md`)
이번 세션에서 **일반화 가능한 배움 ≥1개**를 파일 상단에 append한다. 태그로 구분:
`[시스템]`(OS·워크플로우·협업) / `[투자]`(투자 판단·시장 이해). "다음에 어떻게 적용"까지 적어야
죽은 기록이 안 된다. 이번에 딱히 새 배움이 없으면, 최소한 §3의 즉시 개선 자체를 한 줄 lesson으로 남겨
**"1개 변화" 보장**을 지킨다.

### 6. 마무리 (3줄 요약)
사용자에게 보여준다: (1) 고친 것 (2) 기록한 것(이슈/lesson) (3) 다음 세션이 이어받을 열린 이슈.
변화가 0건이면 회고가 실패한 것 — 최소 lesson 1줄은 반드시 남긴다.

## 가드레일

- **최소 1개 변화 보장**: 모든 회고는 즉시 개선 또는 신규 lesson 중 최소 하나를 남긴다. 아니면 미완.
- **사실 기반**: 단정·질책 대신 "사실 + 사례 + 개선 액션". 세션에서 실제 일어난 일만 근거로.
- **추정 금지**: 원인·데이터가 없으면 빈칸/"미상". 지어내지 않는다.
- **보존 append**: lessons·issues는 기존 내용을 지우지 않고 위에 쌓는다. 이슈 해결은 그 자리 상태 갱신.
- **작게**: 회고 중 개선은 안전·소규모 1건까지. 큰 변경은 이슈로 남겨 다음에 제대로 한다.
- **경계 유지**: 매매 단위 감정·손익은 [[trade-journal]]로. 여기는 시스템/일반 규칙.
- **비대화 방지(아카이빙)**: lessons·issues가 커지면(대략 화면 2~3개 분량 초과) 해결된 이슈와
  오래된 lesson을 `06_retrospect/archive/`로 옮겨 현행 파일을 가볍게 유지한다. 자동화가 아니라
  회고 중 손으로 정리하는 트리거이며, 파일이 아직 작으면 하지 않는다.
