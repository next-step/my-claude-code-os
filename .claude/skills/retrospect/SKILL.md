# Retrospect

티켓 하나가 끝난 시점에 "어떤 가정을 했고, 뭐가 틀렸고, 같은 실수를 반복하고 있진 않은지"를 정리합니다.
회고 리포트는 `docs/retrospects/`에 누적 저장되고, 반복되는 패턴은 규칙 문서 승격을 제안합니다.

`/dev-pr` 성공 시 자동 호출되며, 수동으로 `/retrospect`를 실행할 수도 있습니다.

---

## 0단계: 재료 수집

아래 파일들을 확인합니다. **존재하는 것만 읽고, 없으면 조용히 건너뜁니다** (에러 아님):

| 재료 | 내용 |
| --- | --- |
| `docs/tasks.md` | 태스크별 가정/이탈/보류 메모 (task-impl 산출물) |
| `docs/ticket-briefing.md` | 수정 범위, 미정의 정책 답변 (ticket-start 산출물) |
| `docs/interview-spec.md` | 확정 결정, 가정 목록 (interview 산출물) |
| `.claude/qa-report.md` | QA FAIL/BLOCKED 항목 (playwright-qa-tester 산출물) |
| `.claude/review-report.md` | 리뷰 이슈 목록, 루프 횟수 (dev-pr 산출물) |
| `docs/retrospects/*.md` | 이전 회고 리포트 — 반복 패턴 탐지의 비교 대상 |
| `.claude/skill_calls.log` | 스킬 호출 이력 — 목표 지표 채점 중 자동화 커버리지 산정용 |

커밋 이력도 수집합니다:

```bash
git branch --show-current
git log main..HEAD --oneline
```

`fix:` 커밋 수로 수정 루프 규모를 파악합니다.

**조기 종료:** 재료 파일이 하나도 없고 `main..HEAD` 커밋도 없으면 아래를 출력하고 종료합니다:

```
회고할 재료가 없습니다.
티켓 작업(task-impl, dev-test, dev-pr)을 진행한 뒤 다시 실행해 주세요.
```

## 1단계: 분석

수집한 재료로 세 가지 질문에 답합니다.

### 1-1. 가정 검증

`docs/tasks.md` 메모와 `docs/interview-spec.md`의 가정 항목을 추립니다.
추린 가정을 AskUserQuestion으로 사용자에게 확인합니다 — "이 가정이 맞았나요?"

- 가정이 4개를 초과하면 정책 판단·데이터 구조 등 **틀렸을 때 파급이 큰 것부터 최대 4개**만 질문
- 틀린 가정(❌)은 "다음 액션" 항목으로 기록 (후속 수정 필요)
- 가정이 하나도 없으면 이 단계를 건너뜀

### 1-2. 보류/이탈 정리

`⏭ 보류` 태스크와 계획 이탈 메모를 모아 "사람 판단 필요" 목록을 만듭니다.

### 1-3. 반복 패턴 탐지

이번 티켓의 리뷰 이슈 유형(`.claude/review-report.md`)과 QA FAIL 유형을,
`docs/retrospects/`의 이전 리포트에 기록된 유형과 대조합니다.

**같은 유형이 누적 2회 이상 등장하면 규칙 승격 후보**로 표시합니다.
(예: "useEffect 의존성 배열 누락"이 이전 회고와 이번 리뷰에 모두 등장 → 후보)

### 1-4. 목표 지표 채점

`OS.md`의 "목표 지표 (프로젝트별 루브릭)" 표 기준으로 4개 지표를 채점합니다.
**이 프로젝트의 로컬 파일만 사용** — 다른 프로젝트 데이터는 참조하지 않습니다. 기준 자체는 `OS.md`에만 정의되어 있으므로 여기서 점수 밴드를 다시 나열하지 않고 그대로 따릅니다.

| 지표 | 계산 방법 |
| --- | --- |
| 자동화 커버리지 | `.claude/skill_calls.log`에서 최근 30일 내 호출된 스킬 종류 수 ÷ `OS.md` 로드맵에 정의된 스킬 종류 수 |
| 개입 빈도 | 1-1, 1-2에서 집계한 이번 티켓의 가정+보류+이탈 메모 개수 |
| 재작업률 | `.claude/review-report.md`의 리뷰 재시도(루프) 횟수 (없으면 커밋 이력의 `fix:` 커밋 수로 대체) |
| 반복 실수 감소 | 1-3에서 **이번에 새로** 규칙 승격 후보가 된 이슈 유형 수 |

재료가 없어 계산할 수 없는 지표는 `-`로 표기하고 총점 계산에서 제외합니다 (억지로 임의 점수를 매기지 않음).

## 2단계: 회고 리포트 저장

`docs/retrospects/YYYY-MM-DD-<브랜치명 slug>.md`로 저장합니다.

- 디렉토리가 없으면 생성
- **항상 새 파일로 저장** — 기존 리포트를 덮어쓰지 않음 (누적이 반복 패턴 탐지의 재료)
- 브랜치명 slug: `/`를 `-`로 치환 (예: `feature/login` → `feature-login`)

### 리포트 포맷

```markdown
# 회고: <브랜치명 / 티켓 한 줄 요약>

날짜: YYYY-MM-DD | 브랜치: <branch> | 커밋: N개 (fix N개)

## 가정 검증

- ✅ <가정> — 맞음
- ❌ <가정> — <사용자 확인 결과, 실제 정책>

## 보류·이탈

- <항목> — <사유>

## 리뷰·테스트 지표

- 리뷰 루프: N회 | 수용된 WARNING: N건 | QA FAIL: N건

## 발견된 패턴

- <이슈 유형> — 이번 N건, 누적 N건 (규칙 승격 후보 ⬆ / 관찰 중)

## 목표 지표 채점

- 자동화 커버리지: N점 (상/중/하)
- 개입 빈도: N점 (상/중/하)
- 재작업률: N점 (상/중/하)
- 반복 실수 감소: N점 (상/중/하)

## 다음 액션

- [ ] <틀린 가정 후속 조치 / 보류 해소 등>
```

해당 없는 섹션은 `- 없음` 한 줄로 표기합니다 (섹션 자체를 지우지 않음 — 이후 회고에서 파싱 일관성 유지).

---

## 2.5단계: 스코어카드 누적

1-4에서 채점한 결과를 `docs/retrospects/scorecard.md`에 한 줄 추가합니다.

- 파일이 없으면 헤더와 함께 새로 만듭니다
- **항상 append** — 기존 행은 수정/삭제하지 않음 (추세 비교가 목적)
- 계산 불가(`-`) 지표는 총점 분모에서 제외 (예: 3개만 계산되면 `8/9`)

### 포맷

```markdown
# 목표 지표 스코어카드

| 날짜 | 브랜치 | 자동화 커버리지 | 개입 빈도 | 재작업률 | 반복 실수 감소 | 총점 |
| --- | --- | --- | --- | --- | --- | --- |
| 2026-07-13 | feature/login | 3 | 2 | 3 | 3 | 11/12 |
```

## 3단계: 교훈 승격 제안

1단계에서 규칙 승격 후보(누적 2회 이상)가 있을 때만 진행합니다.
**후보가 없으면 건너뜁니다 — 매번 억지로 규칙을 만들지 않습니다.**

후보마다 반영처를 분류하고 규칙 초안을 작성합니다:

- **코드 스타일/패턴 관련** → `.claude/docs/code-conventions.md`에 추가할 규칙 초안
- **Claude 행동 교정 관련** (질문 누락, 범위 초과 등) → 프로젝트 `CLAUDE.md`에 추가할 규칙 초안

AskUserQuestion으로 초안을 보여주고 승인 여부를 묻습니다.
**승인된 것만** 해당 파일 끝에 append합니다. 승인 없이 규칙 문서를 수정하지 않습니다.

승격된 규칙은 회고 리포트의 "발견된 패턴" 항목에 `→ 규칙 승격됨 (<파일명>)`으로 표기합니다.

## 4단계: 최종 요약 출력

```
╔══════════════════════════════════════════════════╗
║          /retrospect 완료 요약                   ║
╠══════════════════════════════════════════════════╣
║  리포트:      docs/retrospects/<파일명>          ║
║  가정 검증:   ✅ N개 / ❌ N개                    ║
║  규칙 승격:   N건 (code-conventions.md 등)       ║
║  다음 액션:   N건                                ║
║  목표 지표:   N/12점 (scorecard.md 기록)         ║
╚══════════════════════════════════════════════════╝
```

- ❌ 가정이나 다음 액션이 있으면 요약 아래에 목록으로 다시 보여줍니다
- 규칙 승격이 없었으면 `규칙 승격:   없음 (반복 패턴 미발견)` 으로 표기합니다
- 계산 불가 지표가 있으면 분모를 그만큼 줄여 표기합니다 (예: `8/9점`)

---

## 주의사항

- 재료 파일이 없다고 실패하지 않습니다 (있는 것만으로 회고)
- 규칙 문서(CLAUDE.md, code-conventions.md)는 사용자 승인 없이 절대 수정하지 않습니다
- 회고 리포트는 항상 새 파일로 저장합니다 (기존 리포트 덮어쓰기 금지)
- 자동 실행(dev-pr 경유)일 때도 가정 검증 질문은 생략하지 않습니다
- 회고는 기록과 제안까지만 합니다 — 코드 수정은 하지 않습니다
- 목표 지표 점수 밴드는 `OS.md`에만 정의합니다 — 이 스킬에 기준을 중복 작성하지 않습니다
- `scorecard.md`는 항상 append이며, 다른 프로젝트의 스코어카드와 합치지 않습니다 (프로젝트별 독립 채점)
