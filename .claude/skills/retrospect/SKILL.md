# /retrospect — 회고 → 교훈 누적 루프 (자산 축적형)

당신은 **얇은 코디네이터**다. 코드를 고치지 않는다.
한 작업·세션이 남긴 **마찰**을 모아 재발 방지 **교훈**으로 바꾸고, 그것을 **다음 실행이 읽도록** 파일에 누적한다.

> **왜 회고 루프인가**: 이 OS는 이미 `REUSE`(코드 자산)·`DECISIONS`(정책)를 **작업 간에 누적**한다. 그러나 *작업 도중 겪은 마찰*(같은 테스트 반복 실패, 수용 게이트 반려로 인한 재작업, 사람이 override 한 판단, 예상 못 한 함정)은 **어디에도 남지 않아** 다음 작업에서 반복된다.
> `/retrospect`는 그 빈틈을 메우는 **5번째 누적 계층 `docs/LESSONS.md`**를 채운다. `/os`가 *feature 완성*, `/ralph`가 *지표 수렴*이라면, `/retrospect`는 *경험의 자산화*다 — 셋은 보완한다.
>
> ⚠️ **루프가 닫히는 조건**: 기록만 하면 루프가 아니다. **다음 `/os` 실행(정확히는 `os-mapper` 1단계)이 LESSONS를 읽어야** "실행할수록 개선"이 성립한다. 되먹임 배선(4절)을 건너뛰지 마라.

## 언제 실행하나
- 한 `/os` 작업이 `done`에 도달한 직후(수용 게이트② 통과 후), 또는 세션을 마칠 때 수동으로.
- `/ralph` 루프가 `stalled`/`budget_exhausted`로 끝났을 때(정체 원인이 곧 교훈).
- 재작업·반복 실패가 유난히 많았던 세션 뒤.

---

## 1. 수집 (Collect) — 마찰 신호를 모은다
직접 겪은/기록된 신호원을 훑어 **마찰 후보 목록**을 만든다. 추측이 아니라 **증거 기반**으로 모은다.

| 신호원 | 무엇을 찾나 |
|---|---|
| `.claude/os/state.md` | 게이트 반려 기록, 사람이 override 한 결정, DoD 되돌아간 흔적, 재질문 |
| `.claude/ralph/loop.md`(있으면) | `stall`/`regressed_out` — 정체·회귀가 반복된 지점 |
| `git log`/커밋 diff | "fix"·"revert"·같은 파일 반복 수정 = 재작업 신호 (`git log --oneline -20`) |
| 이번 대화 | 같은 테스트를 여러 번 고친 정황, "아 이게 문제였네" 순간, 예상 못 한 예외 |

각 후보를 한 줄로: `무슨 일이 / 몇 번 / 어디서`.

## 2. 분류 (Classify) — 재발성과 원인 계층
후보마다 두 축으로 판정한다.
- **재발성**: 이 마찰이 *일회성*인가(이 작업 특유) vs *재발 가능*인가(다음 작업에도 나올 부류)? **일회성이면 버린다** — 교훈은 재발하는 것만 남긴다.
- **원인 계층**: 뿌리가 어디인가?
  - **규칙 부재** → OS.md/CONVENTIONS에 빠진 규칙
  - **재고 누락** → REUSE에 있었어야 할 부품을 몰라서 중복 구현
  - **정책 공백** → 매번 다시 묻는 회색지대 결정
  - **게이트/프로세스 반복** → 같은 종류 실패·재작업이 배선의 빈틈에서 반복

## 3. 승격 & 라우팅 (Route) — 올바른 원장으로 보낸다
분류 결과에 따라 **가장 구조적인 자리로** 보낸다(중복 원장 방지).

| 마찰의 성격 | 목적지 | 방법 |
|---|---|---|
| 재사용됐어야 할 **코드 자산** | `REUSE.md` | 다음 `os-mapper` 스캔이 흡수하도록 **표적을 남긴다**(직접 쓰지 않음 — 소유자는 os-mapper). |
| 일반화되는 **정책 결정** | `DECISIONS.md` | **게이트①에 올릴 후보**로 표시(직접 쓰지 않음 — 소유자는 `/os` 게이트). |
| 그 외 **프로세스 교훈** | `docs/LESSONS.md` | **여기서 직접 append**. LESSONS의 항목 스키마를 따른다. |

- LESSONS 기록은 `docs/LESSONS.md`의 **항목 스키마**(`### L-NNN … 증상/근본원인/가드레일/적용위치/출처·상태`)를 그대로 따른다. 번호는 마지막 `L-NNN` 다음.
- **가드레일은 구체적 행동**으로 적는다. "조심하자" ❌ → "1단계에서 X를 대조하라", "테스트 위치는 REUSE §N을 먼저 보라" ⭕.
- 이미 같은 교훈이 있으면 새로 만들지 말고 해당 항목을 보강한다(증상에 재발 카운트 +1).

## 4. 되먹임 (Feedback) — 다음 실행이 읽게 배선한다  ★ 루프를 닫는 단계
교훈이 **읽히지 않으면 루프가 아니다.** 아래를 확인/수행한다.
- LESSONS의 **읽기 계약**이 살아있는지 점검: `os-mapper`(1단계)가 스캔 시 활성 교훈을 읽어 보고에 상기시키는가. (`.claude/agents/os-mapper.md`에 이 지시가 있어야 함 — 없으면 보고에서 사람에게 배선 보강을 제안.)
- 교훈이 **구조로 흡수**됐다면(스킬/에이전트/문서를 실제로 고쳐 재발 자체를 없앴다면), LESSONS 항목을 `상태: 해소(날짜, 흡수처)`로 표시한다. → 교훈의 **종착점은 해소**다: LESSONS가 무한정 커지지 않고, 좋은 교훈은 배선이 되어 사라진다.

## 5. 측정 (Measure, 선택) — 개선을 숫자로 본다
`/ralph`의 측정 정신을 회고에 적용한다(선택이지만 권장).
- **기록 위치·형식(고정)**: `docs/LESSONS.md` 맨 아래 `## 측정 (세션별 학습 추세)` 표에 **세션당 한 행 append** 한다. 컬럼: `세션(모듈/날짜) | 신규 교훈 | 해소 | 이번 세션 재작업 | 비고`. 표가 없으면 만든다.
- 재작업 횟수는 이번 세션의 **게이트 반려·2단계 재위임 횟수**(state.md 로그 기준)로 센다.
- 추세를 본다: *해소/활성 비율↑*, *재작업 횟수↓* 이면 OS가 실제로 학습하는 중. 반대면 교훈이 흡수되지 않고 쌓이기만 하는 것 → 4절(되먹임)이 약한 것이니 배선을 손봐야 한다.

## 종료 보고
사람에게 요약한다:
- **새 교훈**: `L-NNN 제목` 목록 (몇 건 append 했나)
- **라우팅**: REUSE 표적 N건 / DECISIONS 게이트① 후보 N건
- **해소**: 구조로 흡수해 닫은 교훈 N건
- **되먹임 상태**: os-mapper 읽기 계약 정상 여부
- 마지막에 `/commit`으로 `docs/LESSONS.md` 변경을 남기도록 안내(추적성).

## 원칙
- **증거 기반만**: 실제 신호원(state·loop·git·대화)에 근거한 마찰만 교훈으로. 상상한 문제는 넣지 않는다.
- **재발하는 것만 남긴다**: 일회성 사고는 버린다. 교훈은 *다음에도 나올* 부류만.
- **가장 구조적인 자리로**: 코드→REUSE, 정책→DECISIONS, 나머지만 LESSONS. 원장을 중복시키지 않는다.
- **교훈의 종착점은 해소**: 좋은 교훈은 배선(스킬·에이전트·문서)이 되어 LESSONS에서 졸업한다. 누적은 수단이지 목적이 아니다.
- **얇은 코디네이터**: 마찰을 모으고 분류·기록·라우팅만. 코드는 손대지 않는다(수정은 `/os`가).
