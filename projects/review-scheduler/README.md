# review-scheduler — 학습 기록 + 복습 스케줄러

배운 것을 한 줄로 등록하면 **간격 반복**으로 다음 복습일을 계산해 준다.

## 내가 이걸 왜 매일 쓰는가

`projects/README.md` 규약 4의 답이다. 이 칸이 비면 관측이 돌아오지 않는다.

지금 4주 과정을 하고 있어 **등록할 것이 매일 생긴다.** 그리고 복습 알림을 실제로 열었는지가
그대로 관측이 된다 — 안 열었으면 알림 방식이 틀린 것이고, 그게 다음 루프 PM의 입력이다.
외부 사용자가 없는 프로젝트에서 루프를 닫는 방법은 **내가 사용자인 제품**을 만드는 것뿐이다.

## 왜 이 제품이 채점기에 잘 맞나

간격 반복 계산은 **순수 함수**다. 입력(난이도·복습 이력)과 출력(다음 복습일)이 명확해
수용 기준이 그대로 테스트가 된다. `OS.md` 3절 1번 관문을 손대지 않고 통과한다.

## 구조

**여기에 적지 않는다.** 패키지 구조·저장 방식·API 형태는 `feature-loop` ③에서 **Developer가 정한다.**
미리 적어두면 그건 지시된 결론이 되고, 서브에이전트가 이 파일을 읽는 순간 격리가 깨진다.
실제 구조는 `app/`이 답이다. 문서와 코드가 어긋나면 코드가 맞다.

도메인 계산을 프레임워크에서 분리하라는 제약은 `feature-loop` ③이 들고 있다.
**문서가 아니라 스킬이 들고 있어야** 서브를 부를 때마다 실제로 전달된다(`OS.md` 원칙 4).

## 관문

| 구간 | 무엇으로 판정하나 |
|---|---|
| 1 기획 | `python3 .claude/skills/feature-loop/criteria-lint.py projects/review-scheduler/loops/NNN-*/criteria.md` |
| 2 구현 | `cd projects/review-scheduler/app && ./gradlew test` |
| 3 리뷰 | 회귀 없음 + 지적 반영은 사람이 결정 (반박자는 아직 없음) |
| 4 배포 | 되돌릴 수 있는가. 사람이 버튼 |

- **2026-08-30 · 003 루프 — 오늘 넣은 관측 훅이 첫 실사용에서 두 군데 새는 것이 보였다.**

  PM은 산출물 경로를 받아서 붙었고, Developer·Reviewer는 **격리를 지킨 대가로 로그에서 익명이 됐다.**

  (2) **격리 점검이 문구 일치에 의존한다.** `'다른 파일을 읽지'` 를 grep하는데, 리뷰어 프롬프트는
  "`app/` 밖의 저장소 파일을 읽지 마라"라고 써서 **격리를 지켰는데도 `isolation_line: false`로 찍혔다.**
  관측이 아니라 오탐이다. 훅이 문장의 꼴을 보는 한 `criteria-lint.py`와 같은 한계를 갖는다.
