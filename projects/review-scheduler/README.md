# review-scheduler — 학습 기록 + 복습 스케줄러

배운 것을 한 줄로 등록하면 **간격 반복**으로 다음 복습일을 계산해 준다.

## 내가 이걸 왜 매일 쓰는가

`projects/README.md` 규약 4의 답이다. 이 칸이 비면 관측이 돌아오지 않는다.

지금 4주 과정을 하고 있어 **등록할 것이 매일 생긴다.** 그리고 복습 알림을 실제로 열었는지가
그대로 관측이 된다 — 안 열었으면 알림 방식이 틀린 것이고, 그게 다음 루프 PM의 입력이다.
외부 사용자가 없는 프로젝트에서 루프를 닫는 방법은 **내가 사용자인 제품**을 만드는 것뿐이다.

## 왜 이 제품이 채점기에 잘 맞나

간격 반복 계산은 **순수 함수**다. 입력(난이도·복습 이력)과 출력(다음 복습일)이 명확해
수용 기준이 그대로 테스트가 된다. `OS.md` 3절 1번 관문을 손대지 않고 통과한다.

## 구조

**여기에 적지 않는다.** 패키지 구조·저장 방식·API 형태는 `feature-loop` ③에서 **Developer가 정한다.**
미리 적어두면 그건 지시된 결론이 되고, 서브에이전트가 이 파일을 읽는 순간 격리가 깨진다.
실제 구조는 `app/`이 답이다. 문서와 코드가 어긋나면 코드가 맞다.

도메인 계산을 프레임워크에서 분리하라는 제약은 `feature-loop` ③이 들고 있다.
**문서가 아니라 스킬이 들고 있어야** 서브를 부를 때마다 실제로 전달된다(`OS.md` 원칙 4).

## 관문

| 구간 | 무엇으로 판정하나 |
|---|---|
| 1 기획 | `python3 .claude/skills/feature-loop/criteria-lint.py projects/review-scheduler/loops/NNN-*/criteria.md` |
| 2 구현 | `cd projects/review-scheduler/app && ./gradlew test` |
| 3 리뷰 | 회귀 없음 + 지적 반영은 사람이 결정 (반박자는 아직 없음) |
| 4 배포 | 되돌릴 수 있는가. 사람이 버튼 |

## OS로 되먹인 것

바깥 루프의 입력이다. 이 제품을 만들며 **`OS.md`가 어떻게 바뀌었는지**를 적는다.
쪼갤 신호가 발동했는지, 관문을 고쳤는지, 규칙이 틀렸는지.

- **2026-08-30 · 001 루프 ② ③** — 이 README의 「구조 (계획)」 때문에 PM과 Developer 양쪽에 손으로
  "읽지 마라"를 넣어야 했다. 같은 병목 2회 관측 → `OS.md` 4절 **규칙 3을 고쳤다**
  ("전체 대화를 넘기지 않는다" → "넘긴 것만 본다. 저장소 문서도 스스로 읽게 두지 않는다").
  두 오케스트레이터의 프롬프트 규격·금지·자기 점검에 박고, 이 README에서 구조 스케치를 지웠다.
- **2026-08-30 · 001 루프 ②** — `criteria-lint.py`가 **5/5 PASS**를 준 기준에서 사람 승인이 구멍을 두 번 잡았다
  (영속성 미보장 / 복습일 계산 규칙 부재). `OS.md` 6절의 "채점기가 통과시킨 기준이 필요한 기준이라는
  보장은 없다"가 **문서의 주장이 아니라 관측**이 됐다. 고칠 것은 없고, 사람 승인 단계가 일한 사례로 남긴다.
- **2026-08-30 · 001 루프 ⑤ — 가장 비싼 발견.** 수용 기준 4개를 **전부 충족했는데 제품을 쓸 수 없었다.**
  기준이 데이터와 동작만 말하고 "사람이 이걸 어떻게 부르는가"를 한 줄도 담지 않아, 진입점 없이
  관문(exit 0)과 리뷰 3건을 전부 통과했다. 배포하려는 순간에야 드러났다.
  형식 채점기는 문장의 꼴을 보고 리뷰어는 기준 대비 코드를 본다 — **기준 자체에 빠진 것**은 둘 다 못 본다.
  **고칠 방향(1회 관측, 미적용):** `feature-loop` ①의 「받을 것」에 *"이 기능을 사람이 어떻게 부르는가"* 를 추가하면
  그것이 PM 프롬프트로 들어가 기준이 생긴다. 두 번째 관측이 나오면 규격에 박는다(`OS.md` 2절).
- **2026-08-30 · 001 루프 ⑤ — 관측 수집 방법을 ①에서 확인하지 않았다.** ①에서 "관측은 SQL로 공짜로 얻는다"고
  판단해 PM이 낸 "개수를 조회할 수 있다" 기준 두 개를 반려했는데, 실제로 세려니 H2 jar 경로·버전·
  **빈 사용자명**(`sa` 아님)까지 맞춰야 했다. 공짜가 아니었다. **PM의 원안이 부분적으로 옳았다.**
  관측 방법은 정해두는 것으로 부족하고 **①에서 한 번 돌려봐야** 한다.
- **2026-08-30 · 001 루프 ③ — 관문이 "실패할 수 없는 테스트"를 잡지 못한다.** 초록불은 그 지적에 대해
  아무 정보도 주지 않는다. 확인 방법은 코드를 일부러 망가뜨려 빨간불이 되는지 보는 것뿐이었고
  (`@Transient` 주입 → exit 1), 이번엔 사람이 프롬프트에 손으로 요구해서 일어났다. **1회 관측.**
