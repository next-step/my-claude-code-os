## 도전과제2 — 결과 (2026-09-15)

> 5차원 루브릭 + 랄프 루프 2시간 이상 실행, 각 이터레이션별 결과물이 어떻게 변해가는지 스냅샷으로 남기기.

**"2시간 이상"은 두 번 다 못 채웠다 — 원인이 서로 다르다.** 인터뷰로 아래 "정한 것"
5개를 확정하고 두 차례 실행했다:

| 루프 | 대상 | 이터 | 경과 | 종료 사유 |
| --- | --- | --- | --- | --- |
| [`board-search`](loops/board-search/result.md) | 검색+페이지네이션+정렬 | 3/24 | 0:08 | **성공** — 연속 PASS 2회. 대상이 모델에게 너무 쉬웠다 |
| [`board-comments`](loops/board-comments/result.md) | 댓글(중첩 리소스)+PATCH 낙관적 동시성 | 2/16 | 0:06 | **사용자 중단**(세션 usage 한도 97% 근접) — 코드는 게이트 통과 상태로 멈춤, streak 1/2 |

1회차가 조기 수렴한 이유는 모델 능력 문제가 아니라 **대상이 sandbox 코드일 수밖에
없다는 구조적 제약** 때문이었다 — 상세 분석과 함의는
[`loops/RETRO-sandbox-difficulty.md`](loops/RETRO-sandbox-difficulty.md) 참고.
2회차는 그래서 대상 난이도를 올렸지만(중첩 리소스+동시성 제어), 그것도 같은 패턴
(이터 1은 테스트커버리지 축만 미달, 이터 2에서 즉시 만점)을 반복했고, 이번엔 usage
한도로 중간에 멈췄다. `board-comments`는 재개하면(새 오케스트레이터를 이터 3부터
스폰) 아마 바로 성공 종료됐을 상태이지만, 실제로 연속 PASS 2회를 못 채웠으니
**성공으로 기록하지 않는다** (`ralph/SKILL.md` "하지 말 것 7").

### 이미 갖춰진 도구

- `.claude/skills/ralph/SKILL.md` — 목표·측정 지표를 파라미터로 받는 랄프 루프 스킬. 이미
  board-delete 건으로 검증됨(2회 이터레이션 성공). 이번엔 이 스킬을 **다른 목표로 더 오래(2시간+)
  돌리는 것**이 과제.
- 랄프 루프의 지표(`지표` 파라미터)는 **셸에서 종료코드 0/1을 내는 명령이어야 한다**
  (`ralph/SKILL.md` "하지 말 것 1" — 사람 눈 판정 금지). 5차원 루브릭으로 평가하려면
  "LLM이 5개 관점으로 채점 → 기준 미달이면 exit 1, 통과면 exit 0"을 내는 **채점 스크립트를
  먼저 만들어야** 지표로 쓸 수 있다. (참고 사례: Sellop 샵빌더의 7차원 게이트형 루브릭 —
  가장 낮은 차원이 전체를 결정하는 "게이트" 방식이 하나의 선택지.)

### 정한 것 (인터뷰로 확정 — `maintenance/interviews/2026-09-15-ralph-rubric-loop.md`)

1. **무엇을 5차원 루브릭으로 평가할 것인가** — `sandbox/board` API 새 기능. 코드
   대상이라 pytest 로 정답을 객관 채점할 수 있고, 계약(테스트 파일)을 미리 못박아
   치팅도 막을 수 있어서 선택. (1회차: 검색+페이지네이션+정렬 / 2회차: 댓글+PATCH
   낙관적 동시성)
2. **5개 차원이 무엇인가** — ①정확성(pytest 하드 게이트) ②엣지케이스 ③응답일관성
   ④가독성 ⑤테스트커버리지. ②~⑤는 독립 judge 서브에이전트가 1~5점, **게이트형**
   (전부 3점 이상이어야 통과) — Sellop 7차원 사례 참고.
3. **채점자(judge)를 누가/어떻게 하는가** — 코드를 고친 서브에이전트와는 별도로,
   오케스트레이터(메인)가 매 이터 지표 PASS 시에만 **새 독립 judge 서브에이전트**를
   스폰. 자가채점 편향을 막으려는 목적. 셸 스크립트가 아니라 LLM 서브에이전트라서,
   지표(셸 exit code)는 ①만 담당하고 ②~⑤는 오케스트레이터가 judge 응답을 파싱해
   합산 판정한다 — 표준 `ralph` 스킬(지표=셸 명령 하나)의 변형.
4. **`--최대-이터`·`--연속-통과` 값** — `--연속-통과 2`(board-delete 선례 동일).
   `--최대-이터`는 넉넉히(1회차 24, 2회차 16) 잡고 **경과 시계시간을 이터마다 기록**해
   시간 상한(1회차 2시간, 2회차 1시간)에 먼저 도달하면 그쪽으로 종료 — 실제로는 둘 다
   시간이 아니라 다른 이유(성공/usage 한도)로 먼저 멈췄다.
5. **스냅샷을 어떻게 남길지** — 매 이터(PASS/FAIL 무관) `app.py`(+생성됐다면
   `*_extra.py`)를 `snapshots/iter-N/` 에 전체 파일 복사. diff 는 나중에 `diff` 로
   직접 뜰 수 있어 저장 시점엔 스냅샷이 더 단순했다.
