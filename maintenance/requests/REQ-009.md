## 1. 요청 원문

sandbox/board/README.md 의 API 명세 표가 최신이 아닙니다. DELETE /posts/<id>, PATCH /posts/<id>
엔드포인트가 빠져 있어요. 최신 상태로 갱신해주세요.

### 추가 확인 (intake-interview → 담당자 응답)

- 범위: DELETE·PATCH 두 행만이 아니라, `GET /posts`의 실제 쿼리 파라미터(`sort`/`page`/`size`/`q`)와
  `X-Total-Count` 응답 헤더까지 포함해 표 전체를 최신화

## 2. 접수 정리 (/intake)

- 유형: 버그 (문서-코드 불일치)
- 영향 범위: `sandbox/board/README.md` API 명세 표만. 코드 변경 없음
- 재현 방법 / 기대 결과: 표에는 GET(단순)/POST/GET-단건만 있지만, 실제 `app.py`에는
  DELETE·PATCH·검색/페이지네이션까지 구현돼 있어 문서와 코드가 어긋남

## 4. 스펙 (/spec) — 내부 처리인 경우

- 목표: `sandbox/board/README.md` 의 API 명세 표를 `app.py` 실제 동작과 일치시킨다.

- 범위 / 범위 밖:
  - 범위: `README.md` "API 명세" 표 — `DELETE`·`PATCH` 행 추가, `GET /posts` 행에 쿼리
    파라미터(`q`/`page`/`size`/`sort`)와 `X-Total-Count` 헤더 반영
  - 범위 밖: 코드 변경 없음. `app.py`·테스트 파일은 건드리지 않는다(다른 세션이 작업 중이기도 함)

- 영향 파일:
  - `sandbox/board/README.md` 만

- 구현 접근:
  - 기존 표 형식(메서드/경로/동작/응답, `·` 구분자) 그대로 따라 행을 추가·수정
  - `app.py` 를 실제로 읽어 각 엔드포인트의 상태코드·에러 메시지·조건을 정확히 옮긴다
    (지어내지 않고 코드 그대로 반영)

- 완료 기준 (검증 가능하게):
  1. 표에 `DELETE /posts/<id>` 행 존재 — `204` 성공 / `404` + `{"error": "not found"}`
  2. 표에 `PATCH /posts/<id>` 행 존재 — `200` 성공 / `400` + `{"error": "title is required"}` /
     `404` + `{"error": "not found"}`
  3. `GET /posts` 행에 `q`(부분일치, 대소문자 무시) · `page`(기본 1) · `size`(기본 10, 최대 100) ·
     `sort`(asc 기본/desc) 파라미터와 `X-Total-Count` 헤더 설명이 반영됨
  4. 표의 각 서술이 `app.py` 코드와 `grep`/직접 대조로 일치 확인 가능
  5. 코드 파일 diff 없음 (`git diff --stat -- sandbox/board/app.py sandbox/board/tests/` 가 비어 있음)

- 위험 / 롤백:
  - 위험: 다른 세션이 `app.py`를 동시에 계속 수정 중이면 문서화 시점의 스냅샷과 최신 코드가
    다시 어긋날 수 있음 — 이번 스펙은 **작업 시점 기준 최신 상태**를 반영하는 것으로 범위를 한정
  - 롤백: 문서만 되돌리면 됨, 코드 영향 없음
