## 1. 요청 원문

POST /posts에서 body 필드에 문자열이 아닌 값(숫자, 객체 등)이 와도 지금은 그냥 저장되는데,
title처럼 타입 검증해서 막아주세요.

### 추가 확인 (intake-interview → 담당자 응답)

- 빈 문자열/공백만/생략된 body: title과 달리 **계속 허용** — 비정상적인 타입(숫자·객체 등)만 막는다
- `{"body": null}`: 생략과 동일하게 처리 (기본값 빈 문자열로 저장)
- `PATCH /posts/<id>`: 이번 범위 밖 — POST만, PATCH는 그대로 둔다 (PATCH는 애초에 body 수정 기능 없음)

## 2. 접수 정리 (/intake)

- 유형: 버그 (검증 누락)
- 영향 범위: `sandbox/board` `POST /posts` 만. `PATCH`는 범위 밖
- 재현 방법 / 기대 결과: `POST /posts {"title": "글", "body": 123}` → 지금은 `201`로 그냥 저장됨.
  `body`가 문자열이 아니면 `400`으로 거부돼야 함
- 완료 기준(초안):
  1. `body`가 문자열이 아닌 값(숫자/객체/배열/불린)이면 `400` + `{"error": "body must be a string"}`
     (title과 다른 메시지 — title은 "필수", body는 "타입만" 문제이므로)
  2. `body` 생략, 빈 문자열, 공백만, `null` — 전부 지금처럼 허용 (빈 문자열로 저장)
  3. 기존 테스트 전부 통과 + 새 케이스 추가

## 4. 스펙 (/spec) — 내부 처리인 경우

- 목표: `sandbox/board` `POST /posts` 에서 `body` 필드가 문자열이 아니면 `400`으로 거부한다.
  `title`과 달리 빈 값·생략은 허용한다(타입만 검증).

- 범위 / 범위 밖:
  - 범위: `app.py` `create_post()` 의 body 처리 로직 수정
  - 범위 밖: `PATCH /posts/<id>` (body 수정 기능 자체가 없음, 이번 요청과 무관)

- 영향 파일:
  - `sandbox/board/app.py` — `create_post()` 의 `body = data.get("body", "")` 다음에 타입 검사 추가
  - `sandbox/board/tests/test_board.py` 또는 신규 파일 — body 검증 테스트 추가

- 구현 접근:
  - `body`가 `None`이 아니고 `isinstance(body, str)`이 아니면 `400` + `{"error": "body must be a string"}`
  - `body`가 `None`(명시적 null 포함, `.get`의 기본값 케이스도)이면 빈 문자열로 취급 — 거부하지 않음
  - title과 다른 에러 메시지 사용 (title은 "필수", body는 "타입"이 문제이므로 의미가 다름)

- 완료 기준 (검증 가능하게):
  1. `POST {"title": "글", "body": 123}` → `400` + `{"error": "body must be a string"}`, 저장 안 됨
  2. `POST {"title": "글", "body": {}}` / `[]` / `true` → 동일하게 `400`
  3. `POST {"title": "글"}` (body 생략) → `201`, body는 빈 문자열로 저장 (기존 동작 유지)
  4. `POST {"title": "글", "body": null}` → `201`, body는 빈 문자열로 저장 (생략과 동일 취급)
  5. `POST {"title": "글", "body": "  "}` (공백만) → `201`, 그대로 저장 (거부 안 함)
  6. 기존 테스트 전부 통과 + 새 케이스 추가, `cd sandbox/board && python3 -m pytest -q` 통과

- 위험 / 롤백:
  - 위험: title 검증 로직을 그대로 복붙하면 "빈 값 거부"까지 같이 들어갈 수 있음 — body는
    빈 값을 허용해야 하므로 조건을 다르게 짜야 함(이 부분이 REQ-001·REQ-002와 다른 지점)
  - 롤백: 추가한 타입 검사 한 블록만 제거하면 원상복구
