## 1. 요청 원문

sandbox/board 게시판 API에서 POST /posts 가 제목이 비어 있거나(빈 문자열, 공백만)
title 필드 자체가 없어도 글을 그대로 저장한다. 빈 제목은 거부해야 한다.

### 추가 확인 (intake-interview → 담당자 응답)

- 거부 응답: `400` + `{"error": "title is required"}` (기존 `{"error": …}` 컨벤션 따름).
- "빈 제목" 판정: `title` 이 문자열이 아니거나(`null`·숫자 등), `str.strip()` 결과가 빈 문자열이면 거부.
  대상 = `""`, 공백/탭/개행만, `title` 키 없음, `null`, 비문자열.
- 저장 형태: 통과한 제목은 **입력값 그대로 저장**(trim 하지 않음). "전부 공백"일 때만 거부.
- 이번 범위: title 빈 값 거부만. `body` 검증·제목 길이 상한·중복 제목은 범위 밖.
- 우선순위: P3 (연습 시스템, 막힌 작업 없음).
- 다른 클라이언트 조율 / 기존 데이터 마이그레이션: 불필요 (연습용, 인메모리 저장).

## 2. 접수 정리 (/intake)

- 유형: 버그 (입력 검증 누락)
- 영향 범위: `sandbox/board` — `POST /posts` 엔드포인트. 게시글 작성 경로만. 조회·목록은 무관.
- 재현 방법 / 기대 결과:
  - 재현: `POST /posts` 에 `{"title": "", "body": "x"}` 또는 `{"title": "   "}` 또는 `{"body": "x"}` 전송 → 현재 `201` 로 저장됨.
  - 기대: 위 요청은 `400` + `{"error": "title is required"}` 로 거부. 저장되지 않음.
- 완료 기준(초안):
  1. 빈 제목(`""`), 공백만(`"   "`), `title` 키 없음, `null`, 비문자열 → 각각 `400` + `{"error": "title is required"}`, `posts` 에 저장 안 됨.
  2. 유효한 제목(공백이 앞뒤에 있어도 내용이 있으면) → 기존대로 `201`, 입력값 그대로 저장.
  3. 기존 테스트 4건(목록/작성/조회/404) 회귀 없이 통과.
  4. 빈 제목 3종을 각각 검증하는 테스트 추가.

## 4. 스펙 (/spec) — 내부 처리인 경우

- **목표**: `POST /posts` 가 내용 없는 제목(빈 문자열·공백만·키 없음·`null`·비문자열)을
  `400` + `{"error": "title is required"}` 로 거부하고 저장하지 않도록 한다.
  내용 있는 제목은 기존대로 `201`, 입력값 그대로 저장.

- **범위**:
  - `sandbox/board/app.py` `create_post()` 에 title 검증 가드 1블록 추가.
  - `sandbox/board/tests/test_board.py` 에 거부 케이스 테스트 추가.
  - `sandbox/board/README.md` 의 "알려진 한계" 에서 이 항목 제거, 명세표에 `400` 조건 한 줄 반영.
- **범위 밖**:
  - `body` 필드 검증, 제목 길이 상한, 중복 제목 금지 — 손대지 않는다.
  - 응답 스키마(`{id,title,body}`), id 시퀀스 방식, 인메모리 저장 구조 — 불변.
  - `null`/비문자열을 `422` 로 분리하지 않는다 — 모두 `400` 단일.

- **영향 파일**:
  - `sandbox/board/app.py:23-33` `create_post()` — 가드는 id 발번(L30) **이전**.
  - `sandbox/board/app.py:35-39` `get_post()` — 따를 에러 응답 패턴 `jsonify({"error": …}), <status>`.
  - `sandbox/board/tests/test_board.py` — 기존 픽스처·스타일 그대로 케이스 추가.
  - `sandbox/board/README.md:20-34` — 명세표 + 알려진 한계.

- **구현 접근**:
  ```python
  title = data.get("title")          # 기본값 None → "키 없음"과 null을 한 경로로 통합
  body = data.get("body", "")
  if not isinstance(title, str) or not title.strip():
      return jsonify({"error": "title is required"}), 400
  # 통과: title 은 str + 내용 있음 → 원본 그대로 저장 (strip 하지 않음)
  ```
  - `isinstance(title, str)` 를 **먼저** 검사 → `None`·숫자·리스트에 `.strip()` 호출로 인한 `AttributeError`(500) 방지.
  - 공백 판정은 파이썬 `str.strip()`(탭·개행·유니코드 공백 포함) 기준으로 충분한 것으로 확정.
  - `next_id` 증가·`posts` 저장은 가드 통과 후에만 → 거부 시 id 시퀀스 소비 안 됨.
  - 대안(빈 문자열만 체크, `data.get("title","")` 유지)은 비문자열·`null` 을 못 걸러 채택 안 함.

- **완료 기준 (검증 가능하게)**:
  1. `POST {"title": ""}` → `400` + 바디 `{"error": "title is required"}`, 직후 `GET /posts` 결과가 `[]`.
  2. `POST {"title": "   "}` (공백/탭/개행만) → `400` + `{"error": "title is required"}`, 직후 `GET /posts` 가 `[]`.
  3. `POST {"body": "x"}` (title 키 없음) → `400` + `{"error": "title is required"}`, 직후 `GET /posts` 가 `[]`.
  4. `POST {"title": null}` → `400` + `{"error": "title is required"}`, 직후 `GET /posts` 가 `[]`.
  5. `POST {"title": 123}` (비문자열) → `400` + `{"error": "title is required"}`, 직후 `GET /posts` 가 `[]`, 응답이 **500 아님**.
  6. 거부 직후 `POST {"title": "안녕"}` → `201` 이고 `id == 1` (거부가 id 를 소비하지 않음).
  7. `POST {"title": "  가  "}` → `201`, 저장·응답 title 이 `"  가  "` 원본 그대로.
  8. `tests/test_board.py` 의 기존 4개 테스트 함수 **코드는 수정하지 않는다** (파일 diff 는 추가만).
  9. 위 1~7 을 커버하는 신규 테스트가 추가되어 `cd sandbox/board && python3 -m pytest` 가 기존 4건 포함 **전체 통과**.
  10. `README.md` 갱신 — `/verify` 가 다음을 확인:
      - 명세표(`## API 명세` 표)의 `POST` `/posts` 행 응답 칸에
        `400 · {"error": "title is required"}` (title 없음/빈 값/공백만/비문자열) 이 추가됨.
      - "알려진 한계" 절의 빈 제목 항목(`- POST /posts 가 … 검증이 없다.` 줄)이 삭제됨 —
        `grep -c "빈 제목" sandbox/board/README.md` 결과 `0`.

- **위험 / 롤백**:
  - 회귀 위험: (a) 가드를 id 발번 뒤에 두면 `id==1` 기대가 깨짐 → 발번 전 배치. (b) `isinstance` 선검사 누락 시 비문자열에서 500 → 순서 고정. (c) 저장 시 `strip()` 하면 완료 기준 7 위반 → 저장은 원본.
  - 롤백: 단일 커밋으로 넣고, 문제 시 `git revert`. `app.py` 가드 블록 + 신규 테스트 제거로 원상복구. 인메모리라 데이터 마이그레이션 불필요.

### 배포 노트

  거부 응답은 `400` + `{"error": "title is required"}`. 내용이 있는 제목은 이전과 동일하게
  저장되며, 제목 앞뒤 공백은 다듬지 않고 입력한 그대로 보존한다.
- **변경 파일 / 커밋**:
  - `sandbox/board/app.py` — `create_post()` 에 제목 검증 추가
  - `sandbox/board/tests/test_board.py` — 검증 테스트 8케이스 추가 (기존 4건 유지)
  - `sandbox/board/README.md` — API 명세 갱신
  - 커밋: (핸드오프 시점 미커밋 — `step1` 브랜치에서 커밋 예정)
- **확인 방법** (담당자용):
  1. 앱 실행: `cd sandbox/board && python3 app.py`
  2. `curl -s -X POST localhost:5000/posts -H 'Content-Type: application/json' -d '{"title":"","body":"x"}'`
