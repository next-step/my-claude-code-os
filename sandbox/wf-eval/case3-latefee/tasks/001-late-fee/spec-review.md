## 반영 내역

### 적용
- **[P-001-4]** 정가 상한과 기본 연체료 하한을 "① 할증적용액을 정가로 캡 → ② 결과가 기본 연체료보다 낮으면 끌어올림"이라는 명시적 2단계 우선순위 체인으로 재서술하고, 정가가 기본 연체료보다 낮은 경계 사례(정가 1,000원·인기·3일 → 1,500원, 할증 미반영)를 별도 예시로 추가해 "인기 도서인데 할증이 반영 안 되는" 상황을 우연한 버그가 아닌 명시적·결정론적 규칙으로 확정했다. 서브에이전트가 제안한 대안 공식(`기본연체료 × 할증배수`를 하한으로 사용)은 대수적으로 `max(정가, 할증적용액) >= 할증적용액`이 항상 성립해 `min(할증적용액, max(정가, 할증적용액)) = 할증적용액`으로 귀결됨을 검증했다 — 이는 정가 상한(P-001-4 자체의 존재 이유이자 request.md line 7)을 모든 입력에서 완전히 무력화하므로 채택하지 않았다.
- **[P-001-6]** 실제 청구액을 `max(정가, 30일째 기준 P-001-1~5 적용 연체료)`로 재정의해 30일→31일 전환 시 청구액이 감소하는 역전을 제거했다(서브에이전트 제안 그대로 채택, 정가 8,000원 사례 재검산: 30일째 10,000원 → 31일째 max(8000,10000)=10,000원, 감소 없음).
- **[P-001-7]** 위 P-001-6 변경에 맞춰 예시를 갱신(청구액 8,000원 → 10,000원으로 수정, 참고 누적치 17,500원은 변동 없음).
- **[P-001-3]** "인기 도서 여부는 계산 시점 입력값을 그대로 사용하며 이력 조회 없음"을 규칙에 명문화(동작 변경 없는 명확화, 개선 지적 반영).

### 확정 (신규 기본값)
- **[P-001-8, 신규]** 연체일수는 0 이상의 정수만 유효 입력, 그 외(음수·비정수)는 오류로 처리한다는 정책을 신설했다. 근거: request.md·초안 spec 모두 이 입력 범위에 대해 침묵했고, 서브에이전트가 제시한 반례(연체일수 -1, 0.5)에 대해 spec이 무답이었음. 기본값 근거: 연체료 계산이라는 도메인 특성상 음수/비정수 연체일수는 정의역 밖의 입력이므로 명시적 오류로 막는 것이 조용한 오계산보다 안전.

### 보류
- **[P-001-4, 개선]** "정가 상한"과 "기본 연체료 하한"을 별도 정책 ID로 분리하라는 지적은 동작을 바꾸지 않는 명확한 개선이지만, 분리 시 정책 총수가 8개(P-001-1~7 + 신규 P-001-8)에서 9개로 늘어나 spec 스킬의 "정책 3~7개, 8개 초과 시 범위 분리 검토" 기준을 넘어선다. 이번 리뷰에서는 P-001-4 본문에 2단계 우선순위 체인을 명시하는 것으로 원자성 문제를 완화하고, 실제 ID 분리는 보류한다 — 추후 이 작업 범위가 더 커지면 별도 작업 폴더로 분리를 고려할 것.
