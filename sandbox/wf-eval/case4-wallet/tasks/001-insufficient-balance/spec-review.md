## 요약

general-purpose 서브에이전트(동기 실행)로 `spec.md`를 검토했다. 검토자는 기존 정책 충돌 자체(VIP 후불 정산 vs 신규 차단 정책)는 spec이 이미 정확히 인용·해소했다고 확인했지만, spec이 다루지 않은 두 번째 충돌(기존 `amount<=0` `ValueError` 가드와 신규 잔액 검증의 실행 순서·경계값 상충), 정상 결제 구간(`amount < balance`)에 대한 정책 부재, 예외 상속 계층 미정, 문서 내부 자기모순(요약이 "미확정"이라 서술한 파라미터를 정책은 이미 확정값으로 사용)을 차단 결함으로 지적했다. 5건 전부를 spec.md에 반영했다: 실행 순서를 명문화하고, `InsufficientBalanceError(Exception)` 상속을 확정하고, 신규 정책 `P-001-5`(정상 결제 성공)를 추가하고, P-001-1/P-001-3에 `amount>0` 전제를 명시하고, 요약 문단의 자기모순을 제거했다. 품질 개선 지적 3건은 동작을 바꾸지 않는 것으로 단정하기 어려워 보류했다. spec은 이제 `status: approved`다.

### 반례 시나리오 3개와 판정

1. **정상 결제 구간(`amount < balance`) 미정의** — 모든 정책을 문자 그대로 만족하면서 "`amount == balance`일 때만 성공, 그 외 전부 거부"로 구현 가능. 판정: spec 무답(차단) → **P-001-5 추가로 해소**.
2. **`balance=0, amount=0` 입력에서 신규 잔액 검증과 기존 `amount<=0` 검증 동시 발동, 순서 미정** — 판정: spec 무답(차단) → **정책충돌 섹션에 "기존 가드가 항상 먼저 실행되고 신규 정책은 `amount>0`에만 적용" 명문화로 해소**.
3. **`InsufficientBalanceError`의 상속 계층 미정** (`Exception` 직접 상속 vs `ValueError` 상속에 따라 `except ValueError:` 호출자 코드의 동작이 달라짐) — 판정: spec 무답(차단) → **`Exception`을 직접 상속하고 `ValueError`는 상속하지 않는다고 확정하여 해소**.

## 반영 내역

**적용 (차단 해소, 5건)**

1. [차단] 기존 `amount<=0` 가드와 신규 잔액 검증(P-001-3 관련) 순서 미정 — 정책충돌 섹션에 "기존 가드가 항상 먼저 실행, 신규 정책은 `amount>0`에만 적용"을 명문화하고 P-001-1·P-001-3에 `amount>0` 전제를 추가.
2. [차단] `amount < balance` 정상 결제 성공에 대한 정책 부재 — `P-001-5`(잔액 충분 시 정상 결제 성공) 신규 추가, 예시 `1000-400=600` 검산 완료.
3. [차단] 신규 검증과 기존 검증의 실행 순서 미정의 — `변경 범위`에 "신규 잔액 검증은 기존 `amount<=0` 검증 통과 후에만 수행한다" 명시.
4. [차단] 요약과 정책충돌 섹션의 자기모순(파라미터를 "미확정"이라 서술하면서 실제로는 이미 확정 사용) — 요약 문단에서 해당 서술을 제거하고 확정된 파라미터명·기본값을 명시하는 문장으로 교체.
5. [차단] `InsufficientBalanceError`의 상속 계층 미정 — `Exception`을 직접 상속(비-`ValueError`)한다고 정책충돌 섹션과 변경 범위에 확정 명시.

**확정 (기본값, 0건)**

- 없음. 검토자가 "결정 대기"로 분류한 항목이 없었다 (spec 본문에 `결정 필요(미결정)`으로 남겨진 사항이 없었음). 위 5건은 모두 "차단" 해소 과정에서 함께 확정된 기본값이지만, 분류상 차단 해소에 포함해 집계했다.

**보류 (3건)**

1. P-001-1·P-001-3의 복합 단언("예외 발생 + 잔액 불변", "반환값 + 잔액 모두 0")을 원자적 정책으로 분리하는 개선 — 관련 정책: P-001-1, P-001-3. 사유: 분리 시 정책 수·ID가 늘어나 구조 변경 폭이 커지고, 검토자 스스로도 "동일 관측 대상의 다른 표현이라 심각도 낮음"이라 평가해 동작 변경 없는 명확한 개선으로 단정하기 어려움.
2. P-001-1(잔액 불변)과 P-001-2(history 불변)의 정책 세분화 기준 불일치(같은 트리거를 다른 층위로 나눔) 개선 — 관련 정책: P-001-1, P-001-2. 사유: 병합/재분리가 테스트 매핑(정책 ID ↔ 테스트) 구조에 영향을 줄 수 있어 판단 보류.
3. P-001-4가 기존 회귀 테스트와 중복될 가능성 — 관련 정책: P-001-4. 사유: `/test` 단계의 "기존충족" 표기 메커니즘으로 이미 흡수 가능하다고 판단해 spec 구조는 바꾸지 않고, 대신 `변경 범위`에 안내 문장만 추가(완전 보류는 아니고 경량 반영).
