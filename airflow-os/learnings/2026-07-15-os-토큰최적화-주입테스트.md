## 무엇을
- **주입 검증 테스트** `check-injection.sh`: transcript의 Read 로그로 "선언 context를 실제로 읽었나"를 결정적 검사. `--agent`는 메인 스폰(`subagent_type`) ↔ 서브 로그를 조인해 **그 에이전트 자기 로그만** 보고(메인 오염 제거), **필수 vs 조건부**(`- (검증 모드) …`처럼 괄호로 시작하면 조건부)를 구분. `.claude/tests/`로 이동, repo 루트는 `.claude` 찾아 거슬러 올라가 위치 무관. 이후 SubagentStop 훅(`^dag-(reviewer|builder|tester)$`)으로 자동화.
- **토큰 최적화 실험**: 같은 샘플 DAG·정답지에 A가 읽는 context만 변형(full/relevant/회사-only/압축)해 recall vs 토큰 측정. **다른 위반을 심은 DAG#2(held-out)**로 재검증.
- **다이어그램**: 조건부 주입(테두리 뱃지=검증 모드에서만) 반영 + 뱃지 오류 2개 교정(antipatterns −T, workspace +T).

## 왜 (결정과 트레이드오프)
- **주입 검증 = canary(AI 판단) 아니라 로그 grep.** lazy loading이라 "Read=주입"이 팩트로 남음. 단, rules/hook 주입은 `additionalContext`라 Read로 안 찍힘 → 그건 신호를 바꿔야(훅 발동 여부). 테스트는 "폐기"가 아니라 lazy엔 유효·rules엔 회귀가드로 역할 축소.
- **A/B는 별도 세션 아니라 격리 서브에이전트로.** 서브에이전트는 메인 대화를 못 봐 서로·메인과 격리 → 한 세션에서 결정적으로 오케스트레이션 가능. 각 변형이 지정 파일만 읽었는지도 transcript로 검증(무결성).
- **압축본은 "자(측정 도구)"지 산출물 아님.** 정답지를 알고 썼으니 과적합 의심 → held-out(새 위반)으로 걷어냄.

## 발견 / 배운 점
- **리뷰어 탐지 recall은 3540→564토큰(−84%)에서도 유지.** held-out DAG#2에서도 압축본=full(순수 3/3, 전체 8/8) — DAG#1에 없던 새 위반(HV2 run_offset 누락)까지 잡아 **과적합 아님** 확인.
- **범용 antipatterns 주입은 강한 모델엔 탐지 기여 0** — V2(antipatterns 제거)에서 ① 5/5 유지, 로그로 antipatterns 안 읽음 확증. 단 "리뷰어가 매번 같은 기준을 본다"는 일관성 용도는 남음.
- **모델은 규칙 "이름"만 있으면 잡는다.** 산문·예시가 토큰의 대부분 → 압축 여지는 내용이지 파일 개수가 아님.
- **결론을 오독 주의**: "한 파일 압축본이 통했다" ≠ "conventions/를 합쳐라". 성질별 분리는 **선택적 주입을 가능케 해** 최적화를 돕는다(합치면 못 고름).
- 7가지 주입법(day2): lazy는 비결정적 → 항상 필요한 건 rules 매칭/전역이 신뢰성 우위. RAG는 md 몇 개 규모엔 과함.

## 다음에 재사용할 것
- **컨텍스트 최적화 = 구조 유지 + 내용 다이어트 + 작업별 선택 주입.** 파일 합치기 아님.
- **주입 효과·최적화 실험은 격리 서브에이전트 + 정답지 + held-out(과적합 배제)**로. 토큰은 파일 크기로 측정, recall은 정답지 대조.
- **탐지 기여 없는 context(범용 안티패턴)는 슬림/제외 후보** — 단 일관성 용도는 별도 판단.
- **신뢰성이 필요한 항상-주입은 lazy 말고 rules 매칭**(다음 개선 레버). 검증 신호도 Read-grep→훅 발동으로 바꿔야.
- 각 셀 n=1 — 신호는 강하고 일관되나 확정하려면 반복.
