## 무엇을
- prod-airflow 재정독(서브에이전트) → 확정 컨벤션을 `.claude/context/`로 승격하고 **성질별로 재구성**: `conventions/`(naming·defaults·schedule·loading·operators·reuse·dbt·airbyte) / `airflow3-knowledge`(버전지식) / `platform`(플랫폼·계보) / `workspace`(환경) / `airflow-antipatterns`(범용). `project-conventions.md` 해체.
- 작성 규칙 신설: **컨텍스트에 실제 prod DAG 이름 금지** → `CLAUDE.md` 작성 규칙(lint가 자동 검사).
- 회사 지식(`dbt`·`airbyte`·`platform`) + `draft/` gitignore.
- 주입 검증 테스트 `tests/check-injection.sh`: transcript의 Read 로그를 grep해 "실제 주입됐나" 결정적 확인.

## 왜 (결정과 트레이드오프)
- **성질(누가 정함 + 얼마나 빨리 닳나)로 분리.** 컨벤션(회사·안정) / 버전지식(빠르게 닳음) / 플랫폼 / 환경. 성질 다른 걸 한 파일에 섞으면 유지보수 지점이 엉킴. 그래서 코드위치=환경(컨벤션 아님), import 경로=버전지식(컨벤션 아님)으로 각각 이동.
- **grab-bag 지양.** 얇을 땐 임시로 묶더라도, 두툼해지면 주제별로 쪼갠다 — **구조는 내용 양을 따라간다.** 성질이 안 드러나는 잡탕 이름("basics")은 폐기.
- **새 규칙은 memory가 아니라 `CLAUDE.md` 작성 규칙에.** 자동주입 + lint 강제. memory는 개인 기억이라 OS 규칙엔 부적합.
- **주입 검증은 canary(AI 판단)가 아니라 로그 grep.** lazy loading이라 "Read 호출 = 주입". transcript에 팩트로 남아 결정적. canary는 출력 판단이라 폐기.

## 발견 / 배운 점
- **중복이 곳곳에.** repo-legacy 안티패턴 섹션이 naming·operators·기존 antipatterns와 대부분 겹침 → 유니크한 `verify=False`만 남기고 삭제. "재나열 금지"의 실전 — 파보면 대개 이미 딴 데 있다.
- **보안.** 관찰문서·안티패턴에 특정 prod 약점 위치(vpn 평문 시크릿)가 tracked 파일로 새면 위험 → "실제 이름 금지"의 두 번째 이유.
- **transcript 위치**: `~/.claude-personal/projects/<경로인코딩>/<세션>.jsonl` (+ `subagents/`). `.claude/`가 아니다. `.claude-personal` transcript는 live로 flush돼 진행 중 세션도 조회된다.
- A/B 효과 수치·정답지 태깅 교정은 `2026-07-15-ab-컨텍스트주입-재현.md` 참고.

## 다음에 재사용할 것
- 컨텍스트는 **성질(소유·닳는 속도)로 분리**, 성질 섞지 말 것.
- 구조는 **내용 양을 따라간다** — 얇으면 합치고 두툼해지면 쪼갬. 미리 잘게 나누지 말 것.
- 컨텍스트 파일끼리 **cross-ref 금지**(`→ dbt.md` 같은 포인터 X) — 연결은 둘 다 읽는 소비자 agent가.
- **새 작성 규칙은 `CLAUDE.md` 작성 규칙에** 넣어 lint가 강제하게. memory 아님.
- **회사 지식은 gitignore, 결론만 `learnings/`로.**
- **주입 검증 = transcript Read 로그 grep** (`tests/check-injection.sh --agent NAME`), canary 아님. lazy loading은 agent가 읽기로 선택하는 거라, 실제로 다 읽었는지는 실행 후 로그로만 안다.
