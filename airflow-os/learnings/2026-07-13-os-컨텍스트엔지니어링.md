## 무엇을
- **컨텍스트 파일 3개 신규**(`airflow-antipatterns`·`dag-design-spec`·`project-conventions`) + 소비자(builder·reviewer·tester·interview)에 "먼저 Read" 참조 주입.
- **CLAUDE.md 신규** — 메인 세션 항상 로드용(코드 위치·작업 라우팅·작성 규칙).
- **설계도 파일화**: interview가 `designs/<dag_id>.md`로 떨구고 워커가 Read (프롬프트 복붙 제거).
- **스킬 트리거 갭 수정**: "리팩터해줘" → dag-audit(진단) → 승인 → airflow-pipeline(수정). interview는 신규 전용으로 좁힘.
- **description·본문 결합 정리** + **lint 스킬** 신규(작성 규칙 린터).
- **이름 정비**: os-sync→sync, retro→retrospective, retros→learnings, local-airflow-admin→lab, trim→lint.

## 왜 (결정과 트레이드오프)
- **컨텍스트 = WHAT(지식)만, 소비자 행동은 agent에.** 계약(dag-design-spec)만 예외적으로 생산자/소비자를 명명. 그래야 새 소비자가 생겨도 지식 파일 안 건드림.
- **참조는 이름으로, 번호·개수 금지.** `(2번)`·`1~7` 같은 위치 참조는 목록 바뀌면 깨짐 → 항목 이름으로.
- **description은 자기설명, 본문은 "내가 호출·사용하는 것만 이름".** 서로 가리키면 결합 발생 — 라우터가 모든 description을 조합하므로 cross-ref 불필요. 오케스트레이터만 자기 워커·단계를 명명.
- **CLAUDE.md vs OS.md 역할 분리.** CLAUDE.md=항상 로드되는 운영 컨텍스트(린해야 함), OS.md=청사진(설계 사상). 운영 팁을 청사진에 우겨넣지 않음.
- **이름은 사전에서 바로 통하는 단어, jargon·하이픈 지양.** ("drift"는 IaC 용어라 탈락 → sync.)

## 발견 / 배운 점
- **A/B 주입 실험**: 표준 안티패턴은 주입해도 recall 동일(8/8 vs 8/8) — 강한 모델은 이미 앎. **프로젝트 고유 규칙**은 3/3 vs 0/3. → 주입의 진짜 가치는 "더 똑똑하게"가 아니라 **"이 프로젝트를 알게"** 하는 것.
- **description = 라우팅 컨텍스트.** 세션 시작 시 이름+description만 로드되니, "리팩터해줘"가 세 스킬 어디에도 안 꽂히던 갭도 description 문제였음. description도 컨텍스트 파일처럼 린해야.
- **콜드리드 실패**: 심링크(`prod-airflow`) 뒤 DAG를 Glob이 기본으로 못 따라감 → 새 세션이 파일을 못 찾음. 코드 위치를 CLAUDE.md(메인)·project-conventions(워커) 양쪽에 명시(로드 맥락이 달라 불가피한 최소 중복).
- **첫 A/B가 약했던 게 수확**: n=1·프롬프트 누수·합성 DAG → "좋은 A/B가 뭘 갖춰야 하는지"를 알게 됨(도전2로 이어짐).

## 다음에 재사용할 것
- 새 컨텍스트/스킬 쓸 땐 **CLAUDE.md 작성 규칙 6개**를 따르고 `lint`로 검사.
- **콜드리드 테스트**: "메모리 없는 새 세션이 이 파일만 보고 바로 행동 가능한가?" — 막연한 명사("그 팩토리")면 실제 이름·경로로.
- **컨텍스트 파일끼리 서로 참조하지 않는다** — 연결은 둘 다 읽는 소비자(agent)가.
- **A/B로 주입 효과를 보이려면 프로젝트 고유 규칙을 심어야** 한다(표준 안티패턴은 기본 모델이 이미 잡음).
- 이름: 사전적으로 통하는 단어 / jargon·하이픈 최소 (→ [[naming-plain-over-jargon]] 성향).
