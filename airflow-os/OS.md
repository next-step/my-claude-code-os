# Airflow OS

## 목표

Apache Airflow 데이터 파이프라인 작업(추가·수정, 코드 리뷰, 테스트, 리팩터링)의 전 과정을 AI와 함께 수행한다.

- **작업을 더 쉽게**: 요청만 하면 설계 → 구현 → 검증까지 AI가 일관된 프로세스로 진행한다.
- **테스트를 빠르고 정확하고 꼼꼼하게**: 구현과 동시에 테스트 코드를 작성하고, 통과할 때까지 반복 검증한다.
- **재사용 가능하게**: 이 프로세스 자체를 스킬/문서로 만들어, 어떤 파이프라인 작업에도 같은 방식으로 적용할 수 있게 한다.

## 설계 구상

사람은 **요청**과 **승인**만 하고, 나머지는 AI가 수행하는 파이프라인이다.

```
[사람] 요청 입력
   ↓
[AI] ① 설계        — 요구사항 구체화, DAG 구조(task + 의존성) 제안
   ↓
[AI] ② 구현        — 설계 기반으로 DAG/코드 작성
   ↓
[AI] ③ 테스트      — 테스트 코드 작성 + 실행, 실패 시 ②로 돌아가 수정
   ↓
[AI] ④ 코드 리뷰   — 컨벤션 준수, 잠재적 오류, Airflow 안티패턴 점검
   ↓                 문제 발견 시 ②~③으로 돌아가 반영
[사람] ⑤ 승인      — 설계·코드·테스트·리뷰 결과를 보고 승인/반려
   ↓
[AI] ⑥ 배포        — 승인된 코드를 배포
   ↓
[AI] ⑦ 회고/기록   — 무엇을 왜 바꿨는지, 배운 점을 기록으로 남김
```

### 단계별 메모

| 단계      | 핵심                                                            | 산출물                        |
| ------- | ------------------------------------------------------------- | -------------------------- |
| ① 설계    | **신규**는 인터뷰로 구체화 후 설계 합의, **수정·리팩터**는 진단(현재 코드 리뷰)으로 개선 범위 합의 | 설계도(신규) 또는 진단 개선목록(수정·리팩터) |
| ② 구현    | 설계도에 없는 것은 만들지 않음                                             | DAG/파이프라인 코드               |
| ③ 테스트   | 테스트가 통과해야 다음 단계로 진행                                           | 테스트 코드 + 실행 결과             |
| ④ 코드 리뷰 | 컨벤션, 잠재적 오류, 성능/안티패턴                                          | 리뷰 결과 (지적사항은 코드에 반영)       |
| ⑤ 승인    | 사람이 최종 판단 — 유일한 수동 게이트                                        | 승인 or 반려(사유)               |
| ⑥ 배포    | 승인된 것만 배포                                                     | 배포 완료                      |
| ⑦ 회고/기록 | 다음 작업에서 재사용할 수 있게 남김                                          | 작업 기록 문서                   |

### 설계 결정

- **①설계는 신규/수정 두 갈래**: 신규는 백지라 질문(인터뷰)이 먼저지만, 수정·리팩터는 코드가 이미 있으니 진단(현재 코드를 읽어 개선 목록화)이 먼저다. 같은 리뷰 역량을 ①진단·④검증 앞뒤로 재사용한다.
- **코드 리뷰는 테스트 뒤, 승인 앞**: 테스트를 통과한 코드만 리뷰하면 "돌아가긴 하는 코드"를 놓고 품질을 논할 수 있고, 리뷰까지 끝난 결과를 사람이 한 번에 보고 승인하면 된다.
- **사람의 개입은 최소 2회**: 처음(요청)과 끝 직전(승인). 나머지 루프(구현↔테스트↔리뷰)는 AI가 자체적으로 돈다.
- **재사용 전략**: 각 단계를 `.claude/` 하위의 스킬·커맨드로 분리해, 단계 단독 실행(예: 리뷰만)도 가능하게 한다.
