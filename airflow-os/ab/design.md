# A/B: 컨텍스트 주입 효과 — 설계 개요

## 질문
`.claude/context/` 주입이 컨벤션 위반 탐지를 바꾸나. **가설: ① 범용 A≈B, ② 회사 A≫B.**

## 1단계 (확정) — 탐지 · 리뷰어
- **방식**: 위반 심은 DAG를 리뷰어에게 주고 "문제 찾아", context ON(A)/OFF(B) 비교.
- **왜 리뷰어**: 진단 모드라 설계도 불필요 + context 효과가 깨끗이 분리(빌더의 prod 참고 혼입 없음).
- **패키지** (`ab/`) — 방법론은 git 올림, 재료는 회사 컨벤션 노출이라 gitignore:
	- `protocol.md` — 새 세션이 그대로 돌릴 실행 절차 (올림)
	- `design.md` — 이 설계 개요 (올림)
	- `answer-key.md` — 심을 위반 목록 = 채점 기준 (gitignore)
	- `sample-dag.py` — 위반 심은 DAG, 정적 리뷰용 (gitignore)
	- `results.md` — 결과 기록 (gitignore)

## 정답지 원칙
- `.claude/context/`에 적힌 **확정 규칙만**(관찰 나열이 아님).
- **① 범용 5 + ② 회사 10**, 종류별 recall 분리. "순수 vs 일반" 난이도 태그로 순수 신호 격리 — 태그는 실측 B 탐지율(0/3=순수, 잡음=일반)로 교정.

## 이전 A/B 약점(고침)
- n=1 → 각 안 3회+. / 프롬프트 누수 → 카테고리 힌트 금지·샘플 주석에 위반명 없음. / 토이 DAG → 2단계에서 실제 DAG로 보완.

## 다음 단계 (나중)
