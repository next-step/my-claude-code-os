# A/B 실행 프로토콜 (새 세션용 · self-contained)

이 대화 맥락 없이 이 문서만 보고 실행할 수 있게 썼다. 작업 디렉토리: `airflow-os/`.

## 목적
컨텍스트 주입(`.claude/context/`)이 **리뷰어의 컨벤션 위반 탐지**를 얼마나 바꾸나 측정.
가설: **① 범용 best-practice는 A≈B**(모델이 이미 앎), **② 회사 컨벤션은 A≫B**(context 없인 모름).

## 재료 (fixture — 회사 컨벤션이 드러나 git엔 안 올림, `ab/` 안에 두되 gitignore)
- `ab/sample-dag.py` — 위반 15개 심은 DAG. **정적 리뷰만, 실행 금지**(top-level 코드가 죽음).
- `ab/answer-key.md` — 심은 위반 목록 = 채점 기준.
- `ab/results.md` — 결과 기록처.

## 두 조건 — DAG·프롬프트 동일, **context 접근만 다름**
둘 다 **일반 에이전트**(general-purpose)에 주고, **카테고리·힌트 없이** "문제를 모두 찾아라"까지만. 정적 리뷰(읽고 판단만).

**A안 (주입 O)** — 프롬프트:
> `.claude/context/`의 모든 `.md`를 먼저 읽어라. 그다음 `ab/sample-dag.py`를 읽고(실행하지 마라) 이 DAG의 문제를 **전부** 라인과 함께 나열하라.

**B안 (주입 X)** — 프롬프트:
> `ab/sample-dag.py`를 읽고(실행하지 마라) 이 DAG의 문제를 **전부** 라인과 함께 나열하라. `.claude/context/`는 읽지 마라 — 네가 이미 아는 지식만으로.


→ 유일한 차이 = context 접근 여부. 그 외(DAG·프롬프트·모델) 전부 동일.

## 반복
각 안 **최소 3회**(모델이 확률적). 매번 **새 에이전트**로.

## 채점 (`ab-answer-key.md` 대조)
- 각 실행 출력의 지적을 answer-key 항목(BP1-5, CV1-10)과 매칭 → 잡음 / 놓침.
- **매칭 규칙**: 같은 이슈를 명확히 짚었으면 인정(표현 달라도 OK). 막연·일반 언급은 불인정.
- recall = 잡은 수 / 전체. **① (/5), ② (/10), ② 순수 (/5)** 따로 계산.
- 3회 평균·범위를 `ab-results.md` 표에 기록.

## 해석
- **② 순수 recall이 A ≫ B** → 주입의 가치 = "더 똑똑"이 아니라 **"이 회사를 알게"**. 가설 지지.
- **① recall이 A ≈ B** → 범용은 주입 무관(모델이 이미 앎).

## (선택) 실제 스킬로도 확인
A안을 일반 에이전트 대신 실제 `dag-reviewer` 서브에이전트(진단 모드, 입력=이 DAG 경로)로도 돌려 비교. 단 그건 리뷰어 고유 지시가 더해져 **순수 격리는 아님**(참고용).

- **최종 발견**(수치·결론)만 sanitized 요약으로 `learnings/`에 커밋 → 미션 산출물.
