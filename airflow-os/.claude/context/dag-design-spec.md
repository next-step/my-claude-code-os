# DAG 설계도 spec

파이프라인에선 **task 이름 + 의존성 그래프가 곧 spec**이다. 이 파일은 그 설계도의 **형식과 필드**를 정의한다.

이 파일은 **빈 양식**이다. `<dag_id>` 같은 꺾쇠는 자리표시고, 실제 값이 채워진 설계도는 **`designs/<dag_id>.md`**(DAG마다 한 개)에 산다.

---

## 설계도 형식

```
## 설계 — 이대로 만들까요?

DAG: <dag_id>
스케줄: <cron>  (예: 0 2 * * * = 매일 02:00, catchup=False)
참고 패턴: <기존 DAG 경로>   ← 이거 참고하는 거 맞나요?   (조사로 찾은 발견이면 반드시 확인)

task 그래프:
  <task_a>        (<Operator>)
    >> <task_b>   (<Operator>)
    >> <task_c>   (<Operator> · <핵심 옵션 예: event_id upsert>)

적재:   <증분/풀>, <증분이면 커서 컬럼·lookback 며칠>
멱등성: <재실행 안전 방식 — 키 upsert / 파티션 delete-then-insert>
백필:   <catchup 설정 / 수동 backfill 범위>
검증:   <완료 확인 방법 — 행수 대조 등>

가정 (안 물어보고 기본값으로 정한 것):
  - ...

이대로 진행할까요? 고칠 부분 있으면 말씀해주세요.
```

## 필드

| 필드         | 의미                                            |
| ---------- | --------------------------------------------- |
| `DAG`      | dag_id                                        |
| `스케줄`      | cron + catchup                                |
| `참고 패턴`    | 따를 기존 DAG 경로 (없으면 생략)                         |
| `task 그래프` | task 이름 + Operator + 의존성(`>>`)                |
| `적재`       | 증분/풀, 커서 컬럼, lookback                         |
| `멱등성`      | 재실행 안전 방식 (키 upsert / 파티션 delete-then-insert) |
| `백필`       | catchup 설정 / 수동 backfill 범위                   |
| `검증`       | 완료 확인 방법                                      |
| `가정`       | 안 묻고 정한 기본값 (확정 아님)                           |

## 이 설계도의 성질
- **exhaustive하다.** 여기 적힌 것이 전부다 — 없는 task·옵션은 구현 대상이 아니다. 빈 곳은 `# TODO(확인 필요)`로 남긴다.
- **task 그래프가 정답지다.** 실제 DAG의 task·의존성이 이 그래프와 정확히 일치해야 한다.
