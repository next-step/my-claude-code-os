# diagram — 저장소 다이어그램 스타일

`diagrams/` 아래 모든 그림에 적용한다. **복사 시작점은 스킬 폴더의 `sample.py`**(내용 없는 제네릭 템플릿) —
새 다이어그램은 이걸 `diagrams/src/build_<이름>.py`로 복사해 `PANELS`·`CARDS`·`EDGES`만 바꾼다.
채워진 실제 예시가 필요하면 `diagrams/src/build_context_system.py`를 본다.

## 두 가지 트랙

| 트랙                    | 도구                             | 언제                                             |
| --------------------- | ------------------------------ | ---------------------------------------------- |
| **완성본** (사용자에게 보여줄 것) | 카드 스타일 HTML → Chrome 헤드리스 스크린샷 | 항상 이것이 목표                                      |
| 초안/탐색                 | Graphviz                       | 구조 파악용 스케치. 이 결과물을 완성본이라고 내밀지 말 것 (세 번 퇴짜 맞았다) |

## 완성본 레시피 (카드 스타일)

`build_context_system.py` 구조: 좌표를 직접 계산하는 파이썬 생성기 → HTML(절대배치 카드 + SVG 엣지 레이어) → Chrome 스크린샷.

```bash
python3 diagrams/src/build_xxx.py   # HTML 생성
# --window-size는 콘텐츠(시트+페이지 여백)에 맞춘다 = SHEET_W+80 × SHEET_H+80.
# 1920×1080 같은 고정값을 쓰면 시트보다 큰 창이 그대로 찍혀 오른쪽·아래 여백이 남는다.
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu \
  --screenshot=out.png --window-size=<시트W+80>,<시트H+80> --force-device-scale-factor=2 \
  --hide-scrollbars "file://$PWD/xxx.html"
```

구성 요소와 규칙:

1. **캔버스**: 연회색 페이지(#eef1f5) 위 흰 시트(radius 24, 그림자). 좌상단 큰 제목 + 부제(기준·생략 사실 명시) + 가는 구분선.
2. **레이어 = 세로 패널**: 컬럼(=계층)마다 옅은 틴트 패널(radius 16) + 헤더는 **색 점 · 자간 타이틀만** — 컬럼 부제는 달지 않는다(피드백으로 제거됨). 컬럼 제목은 그 계층이 뭔지 **한 단어**로 — `·`로 부제·수식어를 붙이지 않는다.
   수렴 화살표가 지저분해지는 **종착 컬럼은 카드만 두고 화살표 없이 섬으로 남긴다**.
   **세로 배치는 화살표 길이 최소화**: 공급원 카드는 자기 타깃들의 **세로 중앙**에 둔다(타깃-위 / 공급원-가운데 / 타깃-아래).
   타깃이 셋 이상인 팬아웃도 공급원을 전체 타깃의 세로 중앙에 둬 **위·아래 대칭 팬**으로 만든다 —
   한쪽으로 치우치면 화살표가 흩뿌려져 보인다("화살표가 구리다" 피드백). 캔버스를 가로지르는 긴 사선이 보이면 재배치한다.
3. **노드 = 흰 카드**: radius 12, 1px 테두리(#e6e8ee), 은은한 그림자, 제목 15px semibold + 부제 11.5px muted.
   **강조 틴트는 아껴서** — 대부분 흰 카드로 두고 특별한 것 한 종류만 옅게 칠한다(예: 보라 #f4f0fd). 여러 색을 쓰면 "왜 이건 색이 있냐" 피드백을 받는다.
   부제가 카드 폭을 넘으면 글자수를 줄이거나 **그 카드만 높이를 키워 2줄**로 나눈다(가장자리로 넘치게 두지 않는다).
   카드를 키우면 아래로 자란다 → 위 카드 간격뿐 아니라 **패널 바닥·하단 범례와 겹치지 않는지** 확인하고,
   모자라면 그 컬럼을 위로 당기고 패널 높이·시트 높이를 함께 키워 여백을 낸다.
4. **엣지 = 회색 단일, 거의 직선**: 1.4px #aab2be + 작은 삼각 화살촉, 제어점은 짧게
   `dx = clamp((tx-sx)*0.18, 24, 60)` — 곡률을 키우면 "흐물거린다"는 피드백을 받는다.
   **가파른 팬**(타깃 세로 폭 > 컬럼 간 가로 간격)에선 베지어가 좌우로 흐물거린다 →
   **수평 스텁 폴리라인**으로 뽑는다: `M sx sy L sx+16 sy L tx-16 ty L tx ty` + `stroke-linejoin=round`.
   카드를 수평으로 진출·진입한 뒤 그 사이만 직선이라 대칭 팬이 깔끔하게 맞물린다.
   **색 강조선은 쓰지 않는다**(회색 하나로 통일 — "화살표 왜 색깔이냐" 피드백).
   주 흐름의 카드들은 같은 높이에 놓아 선이 수평이 되게 한다.
   가까운 아래 대상으로 갈 때는 출발 앵커를 카드 **아래 변**으로 (오른쪽 변에서 시작하면 U턴),
   중간에 낀 카드 열을 넘어가야 하면 **위 변에서 출발해 호를 그려 넘긴다** (top 앵커 — 선이 카드를 뚫는 것 방지).
   **수렴 엣지가 많아 지저분해지는 카드는 화살표를 아예 생략**하고 카드만 남긴다.
   보조 프로세스(파이프라인·잡 등)는 노드로 세우지 말고 카드 부제로.
5. **반복 팬아웃은 접는다**: 같은 종류 카드 N개는 `<이름> ×N` 대표 카드 하나로.
6. **선이냐 뱃지냐의 기준은 "이쁘게 그릴 수 있는가"**: 인접 컬럼 사이처럼 깔끔하게 떨어지는 연결은 선으로 잇는다.
   다대다로 뭉쳐 선이 지저분해지는 연결(여러 소비자가 한 자원을 참조 등)은 선을 생략하고,
   연관 카드의 **제목 글자 바로 옆 인라인 원형/글자 뱃지**(하늘색 #0ea5e9)를 붙여 범례 한 줄로 설명한다.
   뱃지를 카드 테두리 위에 걸치지 말 것, 색은 노랑/주황 금지("노란색 구려" 피드백).
7. **하단**: 범례(스와치+라벨) 한 줄 + 우측 스탬프(기준 시점). **각주(※)는 달지 않는다** — 꼭 필요한 단서면 상단 부제에 넣는다.

## 사실만 그린다

그린 내용은 **실측한 사실만** — 참조·연결·구조를 기억으로 채우지 말고 실제로 확인(grep·조회)한 것만 그린다.
불완전하면 상단 부제나 스탬프에 그 사실을 밝힌다.

## Graphviz 초안 트랙 (참고)

탐색용으로 쓸 때의 최소 규칙: `theme.dot` 프리앰블(무채색, splines=line, LR) + `palette.tsv` 토큰만 사용.
계층 그래프는 `newrank=true` + 레이어별 `{rank=same}` + invis flat chain으로 컬럼 정렬
(rank=same 없이 invis chain을 걸면 세로가 아니라 가로로 밀린다). 대형 그래프에 클러스터를 걸면
세로 기둥이 된다(수백 노드에서 폭보다 높이가 몇 배). 노드 `height=0.25` 안 주면 세로 1.5배.

## 절차

1. 데이터 수집(실측만, 기억으로 채우지 말 것) → 보여줄 이야기를 정한다 (전수가 아니라 흐름).
2. `diagrams/src/`의 기존 생성기를 복사해 수정. 산출물 PNG는 `diagrams/`, 생성기는 `diagrams/src/`에 커밋.
3. **렌더링 결과를 반드시 눈으로 본다** — 전체 + 엣지가 몰리는 구간 원본 해상도 크롭.
   엣지가 카드를 뚫거나 U턴을 그리면 앵커/좌표를 조정한다.
4. 사용자 피드백으로 그림을 고쳤으면 **같은 턴에 이 스킬에도 반영**하고, 기준 생성기가 실제로 돌아가는지 확인한다.
