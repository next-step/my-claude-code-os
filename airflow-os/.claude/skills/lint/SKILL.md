# lint — OS 작성 규칙 린터

`.claude/`의 스킬·서브에이전트·컨텍스트가 **작성 규칙**을 지키는지 점검한다. 리포트만, 코드는 고치지 않는다.

## 기준
CLAUDE.md의 `## 작성 규칙`을 먼저 Read해 그걸 기준으로 삼는다 — 규칙이 바뀌면 이 스킬은 손대지 않아도 따라간다.

## 대상
- `.claude/skills/*/SKILL.md`
- `.claude/agents/*.md`
- `.claude/context/` (하위 디렉토리 포함)

## 점검 항목 (작성 규칙별)
- **description 자기설명** — 다른 스킬·에이전트 이름이나 파이프라인 step 번호(②③⑤)가 있으면 위반. 불필요하게 길면(대략 200자+) 플래그.
- **본문 이름 참조** — 자기가 호출·사용하지 않는 컴포넌트 이름(비유·caller·소비자)이면 위반. 오케스트레이터가 자기 워커·단계를 부르는 것은 예외(정당).
- **참조 방식** — 번호·개수·순서(`(2번)`, `1~7`, ①②③)로 가리키면 위반. 이름으로 가리켜야.
- **내용 재나열** — 컨텍스트 파일의 목록·내용을 참조처에 요약·복붙했으면 위반.
- **편집 사유·해설** — "여기 개수를 박지 않는다" 같은 왜-이렇게-썼는지 주석이 산출물에 있으면 위반.

## 출력
- 위반을 `[항목] 파일:라인 — 무엇이 / 어떻게 고칠지`로 항목별 정리.
- 위반 없으면 **"통과"** 명시.

## 수정
- 리포트 후 사람이 승인하면 **수정을 적용한다**(사람은 승인만, 편집은 AI).
- 자동으로 먼저 고치지 않는다 — 리포트가 먼저.

## 원칙
- 기준은 CLAUDE.md 작성 규칙 하나 — 판단이 갈리면 그걸 따른다.
