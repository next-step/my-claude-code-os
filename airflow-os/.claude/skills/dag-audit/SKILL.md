# dag-audit — 단독 DAG 감사

전체 파이프라인(설계~승인)을 돌 필요 없이 **기존 DAG의 상태만 빠르게 점검**하고 싶을 때 쓴다. 진단만 하고 코드는 고치지 않는다.

## dag-reviewer 재활용
이 스킬은 **`dag-reviewer` 서브에이전트를 호출**한다. 코드 리뷰 전문성은 한 곳(dag-reviewer)에만 두고 재활용한다 — 리뷰 기준이 갈라지지 않게.

## 흐름
1. **대상 확인**: 감사할 DAG 파일(또는 폴더) 경로를 정한다. 안 주어졌으면 사용자에게 묻는다.
2. **dag-reviewer 호출**: `dag-reviewer`를 **진단 모드**(목적 없으면 일반 건강검진)로 호출한다. "배포 전 점검" 같은 목적이 있으면 함께 전달한다.
3. **정리해 보고**: 반환된 지적을 사람이 읽기 좋게 심각도 순으로 정리한다.
   - 각 항목의 위치·이유·고칠 방향. 문제 없으면 "감사 통과"라고 명시.
4. **다음 안내**: 고칠 게 있으면 "수정까지 하려면 `airflow-pipeline` 수정·리팩터 모드로 이어가면 된다"고 안내한다(강제 아님).

## 원칙
- **읽기만.** 코드를 고치지 않는다(고치려면 파이프라인으로).
- reviewer의 판단을 그대로 전달하되, 사람이 우선순위를 잡도록 심각도 순으로 정리한다.
- 전역 스킬은 쓰지 않는다 — 로컬 `dag-reviewer`만 재활용.
