# 📈 stock-os — 파이어 투자 앱 (OS #1)

> 나의 **첫 번째** 클로드 코드 OS. **독립 실행 가능** — 이 폴더(`stock-os/`)를 열고 클로드 코드를 켜면 그대로 돌아간다.
> 상세 설계는 [OS.md](OS.md) 참고.

## 실행 방법
- **이 폴더를 프로젝트 루트로 열어야** `.claude/`(스킬·에이전트·메뉴)가 로드된다.
  ```
  cd stock-os && claude
  ```
- 세션을 켜면 `.claude/menu.md` 메뉴가 뜨고, `/study-loop`·`/rebalance`·`/fire-progress`·`/market-now`를 쓸 수 있다.
- ⚠️ 레포 루트에서 켜면 이 `.claude/`는 로드되지 않는다 (OS는 폴더 단위로 하나씩 연다).

## 구성
- 메뉴(스킬): `study-loop`(매일 공부), `rebalance`(비중 진단), `fire-progress`(진척도), `market-now`(시장 전반)
- 부품(에이전트): `market-researcher`, `study-tutor`
- 데이터: `portfolio.md`(설계값), `portfolio.private.md`(비공개 장부)
- 기록: `journal/`(날짜별 학습 노트)

## 여기서 배운 것 (다음 OS로 그대로 가져감)
- 오케스트레이터 + 서브 에이전트(병렬) 구조
- 스킬 / 에이전트 / 컨텍스트 / 하루 루프 설계
- "계산은 스크립트, 설명은 AI", 민감정보 분리, 필요할 때만 기능 추가 같은 설계 원칙
- 무엇보다 **"OS가 뭔지"를 손으로 익힘** → 덕분에 이걸 실무(Airflow)에 적용할 그림이 보이게 됨

## 왜 두 번째 OS(airflow-os)를 시작했나 (2026-07-06)
- 투자 OS는 **완성돼서 정체** — 새 개념을 배워도 "여기 더 뭘 하지?"가 잘 안 떠오름 (도메인 표면적이 좁음).
- 반대로 **회사에서 하는 Airflow 파이프라인 개발**은 요구사항→설계→구현→테스트→리뷰→배포처럼 단계가 많아, 새로 배우는 기술의 **적용처가 바로바로 보임** (학습 무대로 더 좋음).
- 마침 **로컬 Airflow 테스트 환경**이 없어 미뤄뒀는데, 그 OS를 만들며 겸사겸사 구축 = 실무 페인 해결.
- 그래서 투자 OS를 **버리지 않고** 독립 폴더로 유지한 채, 학습 무대만 `../airflow-os/`로 옮겼다.
