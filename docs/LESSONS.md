# LESSONS — 교훈 원장 / 프로세스 회고 누적

이 문서는 `/retrospect` 회고 루프가 **작업을 진행하며 실제로 겪은 마찰**(반복 실패·재작업·재질문·예상 못 한 함정)에서 뽑아낸 **프로세스 교훈**을 한 작업을 넘어 누적한다.
목적: 같은 실수를 다음 작업에서 **반복하지 않도록**(마찰 억제) OS에 **경험 기억**을 부여한다 — "겪은 걸 남긴다".

> **다른 원장과의 경계** (중복 방지)
> - `REUSE.md`(재고) = **코드 자산** — "이미 있는 부품, 갖다 써라".
> - `DECISIONS.md`(정책) = **승인된 회색지대 결정** — "이미 정한 정책, 다시 묻지 마라".
> - `LESSONS.md`(교훈) = **프로세스에서 겪은 마찰의 재발 방지책** — "지난번 여기서 넘어졌다, 이렇게 피해라".
>
> 코드로 승격 가능하면 REUSE로, 일반 정책으로 승격 가능하면 DECISIONS(게이트①)로 보낸다. **그 어느 쪽도 아닌 프로세스 교훈만** 여기에 남는다.

## 소유권 · 흐름 (계약)
- **쓰기(소유): `/retrospect` 오케스트레이터만.** 세션 끝 회고에서 마찰을 분류해 교훈을 append 한다.
- **읽기**:
  - **`os-mapper`(1단계)** — 스캔 시 활성 교훈을 읽어, 이번 작업에 해당하는 항목을 **보고에 상기**시킨다(되먹임 진입점). 그래야 2단계가 함정을 피한다.
  - **오케스트레이터(`/os`)** — 게이트① 전에 훑어, 교훈이 곧 정책이 될 만하면 게이트①에 올린다.
- **해소**: 교훈이 가드레일(스킬/에이전트/문서 수정)로 **구조에 흡수되면** 항목을 `상태: 해소(YYYY-MM-DD, 흡수처)`로 표시한다. 줄을 지우지 않는다(추적성).
- **형식**: 아래 항목 스키마를 따른다. 최신 교훈을 위에 쌓는다.

```

```

## 활성 교훈

### L-003 BigDecimal 분배·비례 로직은 음수/0 scale을 경계로 넣고, 합-불변식 외에 조각별 값을 단언하라
- **증상**: `allocate`가 최소 분배 단위를 `amount.scale()`로 잡는데 음수 scale을 가드하지 않아, `new BigDecimal("100.00").stripTrailingZeros()`(→ `1E+2`, scale −2) 입력이 `[100, 0, 0]`으로 쏠렸다. **합==원금(유실-0) 검사는 통과**해 조용히 배포될 뻔했고(리뷰 게이트 블로킹으로 포착), 음수 scale 테스트도 없었다.
- **근본 원인**: (a) 요구사항 경계조건에 *BigDecimal의 scale이 음수가 될 수 있음*(`stripTrailingZeros`·지수표기)을 안 넣음. (b) 분배 테스트가 **합-불변식만** 검증 → 쏠림을 못 잡음. 불변식 통과 ≠ 정확 분배.
- **가드레일**: ① BigDecimal 금액 로직은 경계조건 목록에 **음수·0 scale 입력**을 반드시 포함한다. ② 분배·비례 로직은 `sum==원금` 외에 **조각별 값도 엄격 단언**한다(예: `parts[0]==34,33,33`). ③ 구현은 유효 scale을 `Math.max(scale,0)`로 정규화한다(무손실 `setScale` 확장).
- **적용 위치**: 게이트①/1절 요구사항 경계조건 · os-developer 테스트 작성 · 리뷰 게이트 엣지케이스 점검.
- **출처·상태**: 확정(money/2026-07-16) — 상태: **활성**. money 모듈은 정규화로 수정했으나, 이 가드레일은 *다른 금액/비례 모듈에 재발 가능*하므로 교훈으로 유지.

### L-002 모듈 전용 예외를 요구하기 전에 "실제 도메인 실패 케이스"를 한 문장 이상 적어라
- **증상**: 요구사항이 "도메인 실패는 `MoneyException`으로 던진다"고 명시했으나, 순수 산술이라 실제 도메인 실패 케이스가 없어 전용 예외를 만들지 않았다(모든 실패가 형식·계약 위반 → `IllegalArgumentException`). 요구사항↔구현 편차가 2단계까지 미뤄져 발견됨.
- **근본 원인**: 기존 모듈(crypto/sudoku)이 전용 예외를 가지니 관성적으로 요구했으나, *그 예외가 표현할 실제 도메인 실패*가 있는지 요구사항 확정 단계에서 검증하지 않음.
- **가드레일**: 전용 예외(`XxxException`)를 요구할 땐 **그 예외가 던져질 도메인 실패 시나리오를 최소 1개** 요구사항에 적는다. 못 적으면 전용 예외를 만들지 말고 표준 예외(`IllegalArgumentException`)로 간다(REUSE §2·DECISIONS §A 지침과 일치).
- **적용 위치**: 게이트①/1절 요구사항 확정(공개 API 계약의 에러 처리 항목).
- **출처·상태**: 확정(money/2026-07-16) — 상태: **활성**.

### L-004 게이트①에서 정한 정책이 실제 코드 경로에 쓰이는지 2단계 보고에서 확인하라
- **증상**: 게이트①에서 반올림=`HALF_EVEN`을 확정하고 `ROUNDING_MODE` public 상수로 노출했으나, 4개 연산이 모두 정확 연산이라 **반올림이 실제로 개입하지 않았다**. 상수가 "적용되지 않는 계약"으로 노출돼 호출부 오해 소지(리뷰 게이트 지적, Javadoc으로 보강).
- **근본 원인**: 게이트① 결정이 코드의 어느 경로에서 실제로 소비되는지 확인하는 단계가 없어, 결정과 구현이 미묘하게 어긋남(죽은 계약).
- **가드레일**: 게이트①에서 확정한 정책(반올림·정밀도·시간대 등)은 2단계 보고에 **"어느 메서드/경로가 이 정책을 실제로 적용하는가"**를 한 줄로 명시한다. 실제 적용 경로가 없으면 public 계약으로 노출하지 말고 내부 주석/문서로 남긴다.
- **적용 위치**: os-developer 2단계 보고 · 리뷰 게이트(재사용/계약 점검).
- **출처·상태**: 확정(money/2026-07-16) — 상태: **활성**.

### L-005 한글·긴 옵션의 AskUserQuestion은 raw JSON으로 조립하지 말고 구조화 파라미터로 넘겨라
- **증상**: 결정 게이트①에서 `AskUserQuestion`을 raw JSON 문자열로 조립하다 이스케이프/제어문자로 파싱 실패 → 1회 재시도로 복구(게이트 지연).
- **근본 원인**: 한글·백슬래시·긴 설명이 섞인 질문을 손으로 JSON 직렬화하면 인코딩이 깨지기 쉽다.
- **가드레일**: `AskUserQuestion`은 도구의 구조화 `questions` 파라미터로 직접 넘긴다(수동 JSON 문자열 조립 금지). 게이트에서 자주 쓰는 도구이므로 재발 방지 가치 있음.
- **적용 위치**: `/os`·`/interview`·`/ralph` 등 게이트에서 AskUserQuestion 호출 시.
- **출처·상태**: 확정(money/2026-07-16) — 상태: **활성**.

### L-001 빌드 toolchain 불일치를 코드 짜기 전에 잡아라
- **증상**: IDE는 JDK24, 빌드도구(Gradle)는 하위 JDK만 지원 — 이 불일치를 모르고 진행하면 빌드가 뒤늦게 깨진다.
- **근본 원인**: 1단계에서 *설치 런타임 / 빌드도구 지원범위 / IDE 설정* 세 가지를 대조하는 **환경 프리플라이트가 없으면** 마찰이 3단계(테스트)까지 미뤄져 늦게 터진다.
- **가드레일**: 1단계에서 세 값을 반드시 대조하고, 어긋나면 **권장 정렬값을 게이트① 근거로** 올린다.
- **적용 위치**: `os-mapper` 환경 프리플라이트 → 게이트①(toolchain 결정).
- **출처·상태**: 확정(sudoku/2026-06-30) — 상태: **해소**(2026-06-30, `os-mapper`에 프리플라이트 단계로 흡수 + `DECISIONS.md §C`로 정책 승격). *부트스트랩 예시 — 회고 루프가 어떤 교훈을 남기는지 보여주는 실제 사례.*
