# 도메인 — auth (회원가입·로그인)

> 한 줄 정의: 아이디/비밀번호로 사용자를 **인증**하는 도메인 — 계정을 생성하고, 자격증명을 검증해 **JWT 액세스 토큰을 발급**한다.

## 정체 (무엇을 / 책임)
- 담당하는 것:
  - **계정 생성(signup)**: `username`·`password`·`name`으로 신규 사용자 등록, 중복 아이디 차단(409).
  - **자격증명 검증(login)**: 아이디/비밀번호 확인 후 액세스 토큰 발급. 아이디 없음·비밀번호 불일치는 **구분 없이 동일 실패**(401).
  - **비밀번호 보관**: 사용자별 랜덤 솔트 + SHA-512 해시(평문 미저장), 검증은 상수시간 비교.
  - **토큰 발급**: JWT HS256, payload `sub=user_id`, 만료 60분.
- 핵심 역할: "이 사용자가 본인인가"를 판정하고, 그 결과를 **다른 도메인이 신뢰할 수 있는 토큰**으로 만든다.
- **소유 엔티티**: `User`(`users` 테이블 — id·username·name·password_hash·salt·created_at). ※ 이 도메인이 User를 소유한다(인터뷰 확인: `user`는 별도 도메인 아님).

## 경계 (무엇은 아닌가)
- **발급만, 검증은 안 함**: 발급한 JWT를 받아 검증·인가하는 것은 각 소비자(보호된 리소스)의 몫이다. auth는 토큰을 *만들* 뿐이다.
- **범위 밖(현재)**: 토큰 갱신(refresh)·로그아웃·내 정보 조회·소셜 로그인·비밀번호 찾기·이메일 인증·속도 제한. (PRD가 명시적으로 제외)
- **기술 계층은 관계가 아님**: DB·시크릿·프레임워크는 의존하는 인프라일 뿐, 도메인 관계로 세지 않는다.

## 관계 (무엇과 이어지나)
- **의존(upstream)**: 다른 서비스 도메인에 의존하지 않음(자족적). — 코드 신호: `auth_service`가 외부 도메인을 import 하지 않음.
- **피의존(downstream)**: ❓미확인 — 발급한 JWT를 소비(검증)하는 도메인이 이 저장소엔 **아직 없음**. 실제 서비스에선 "인증이 필요한 보호된 리소스"들이 이 토큰을 소비할 예정. (그 도메인이 생기면 여기 `[[링크]]`로 잇는다.)
- **공유 개념**: `user_id` — 토큰 `sub`에 실려 나가는 사용자 식별자. downstream 도메인이 "누구의 요청인가"를 알 때 이 값을 공유하게 된다.

> 근거: 코드 신호(`app/controllers/auth_controller.py`·`app/services/auth_service.py`·`app/security/token.py`·`app/security/password.py`·`app/models/user.py`) + 인터뷰(User 소유·downstream 미확인은 사람 확인). ❓미확인 항목은 실제 소비자 도메인이 생길 때 갱신.
