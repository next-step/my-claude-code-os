# OS.md 재작성 — 자동 시뮬레이션 루프 설계 문서

## 목표
OS.md를 강의 학습 문서에서 **순수 시스템 설계 문서**로 완전히 다시 쓴다. 끝나면 OS.md가
"매일 도는 무인 모의 투자 루프"의 구조(A~F 단계·오케스트레이션·가드레일 층)를 담은 살아있는
설계 문서가 되어 있고, 강의·동기·4주 계획·단계별 로드맵 흔적이 남아 있지 않다.

## 범위
- 포함:
  - 기존 OS.md **전면 삭제 후 재작성**. 주제·동기·4주 계획·주차별 개념·단계별 로드맵 표 전부 제거(G1·G2).
  - 새 정체성: 제목(자동 시뮬레이션 루프 설계 문서) + 맨 위 한 줄 목적("매일 도는 무인 모의 투자 루프의 구조를 담는 살아있는 설계 문서")(G5·Q10).
  - 루프 설계 본문: 하루 흐름(아침 수집 → 위원회 소집 → 국면 분석 → 계획 작성/수정 → 09:00~15:30 모의 체결 → 토요일 회고), 단계별 독립 스킬 + 외부 헤르메스 에이전트 순차 체이닝(daily-trading-loop Q2·Q6), 산출물 토폴로지(계획서=살아있는 문서, 회의록·체결·브리핑=append 로그, 포트폴리오=상태 제자리 갱신)(Q3).
  - 정체성 재프레이밍(K): "조언가/추천"이 아니라 "분석 → 계획 → 모의 매매까지 자율 수행하는 OS".
  - 가드레일은 **층을 나눠** 유지: 모의 루프의 무인 자동 체결 vs 미래 실계좌 연동 지점의 "실주문은 사람"(단계표는 없애되 안전 원칙은 남긴다, Q2 유의).
  - OS-log.md 참조 문단 제거(G6·Q11).
- 제외:
  - 각 스킬·스크립트의 **구현 상세**는 이 문서가 아니라 해당 plans 항목(5~10)이 맡는다. OS.md는 큰 틀·이유만.
  - CLAUDE.md·컨텍스트 파일 수정은 항목 2·3·4 소관.

## 구현 단계
1. 기존 OS.md 내용을 백지화(interview 파일이 이력 보관 — 별도 아카이브 불필요).
2. 새 헤더(제목 + 한 줄 목적) 작성.
3. 루프 하루 흐름·오케스트레이션·산출물 토폴로지·가드레일 층을 이유와 함께 서술(OS.md 작성 규칙: 결정에 이유 병기, 살아있는 문서).
4. 진행 상황 체크박스(큰 틀)만 남기고, 순서 있는 실행 큐는 TODO.md에 위임(중복 금지).
5. 옛 스킬 3종·2주차 컨텍스트 서사 제거 확인.
