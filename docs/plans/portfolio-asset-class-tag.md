# 포트폴리오·시뮬엔진에 자산군 태그 반영

## 목표
계획서에 생긴 '자산군' 구분(개별주/ETF-헤지/ETF-테마/ETF-채권)이 실제 보유에도 이어지도록,
포트폴리오(진실원천)에 자산군 태그를 담고 시뮬엔진이 체결 시 이를 기록하게 한다. 주식:헤지:현금
배분을 실제 보유 기준으로 한눈에 점검할 수 있게 한다.

## 범위
- 포함:
  - `data/portfolio.md`(및 sim-engine이 참조하는 포트폴리오 스키마)에 **'자산군' 칸** 추가.
  - `sim-engine`(E) 체결 처리에서, 매수 체결 시 **계획서의 자산군 태그를 포트폴리오 보유 항목에
    함께 기록**하도록 지침/스키마 갱신(값의 출처는 계획서 — 복제가 아니라 태그 전달).
  - `record-conventions`(및 관련 컨텍스트)에 포트폴리오 자산군 표기 규칙을 한 줄 반영.
  - ETF도 6자리 종목코드라 fill_engine 체결 로직 자체는 변경 불필요함을 확인(코드 무변경 전제 검증).
- 제외:
  - 자산군별 배분 한도·인버스 가드레일 — 위원회 일임, 고정 상수 없음(Q6). 이번에 상수화하지 않는다.
  - 계획서 스키마 '자산군' 칸(항목 2에서 완료 전제).
  - 긴급위·주간 회고의 자산군 관련 로직(필요성은 표본 쌓인 뒤 회고 부활 경로로).

## 구현 단계
1. `sim-engine` SKILL과 `data/portfolio.md`(있으면) 현행 스키마를 읽어 보유 항목 컬럼 구조를 확인한다.
2. 포트폴리오 스키마에 '자산군' 칸을 추가하고, 기존 보유 항목이 있으면 `개별주`로 소급 태깅한다.
3. sim-engine 체결(매수) 처리 지침에 "계획서의 자산군 태그를 포트폴리오에 기록" 규칙을 반영한다.
4. record-conventions에 포트폴리오 자산군 표기를 한 줄 추가한다.
5. fill_engine.py가 종목/ETF를 구분 없이 처리함을 확인한다(코드 변경이 필요 없는지 점검).
6. 가능하면 모의 체결을 한 건 돌려 자산군 태그가 포트폴리오에 남는지 확인한다.

## 건드릴 파일
- `.claude/skills/sim-engine/SKILL.md` — 체결 시 자산군 태그 기록 지침 + 포트폴리오 스키마.
- `data/portfolio.md` — '자산군' 칸 추가(있으면 소급 태깅).
- `.claude/context/record-conventions.md` — 포트폴리오 자산군 표기 규칙 한 줄.
