# 문서 품질 5차원 루브릭 (doc-quality)

> **재사용 가능한 채점 기준.** 문서·스킬·에이전트·컨텍스트 md의 *서술 품질*을 5개 차원으로 1~5점 채점한다.
> `ralph-loop` 같은 반복 개선 루프가 매 반복 **자기채점 기준**으로 읽는다(fresh 컨텍스트마다 같은 잣대를 쓰도록 파일로 고정).
> 이 루브릭은 "무엇을 하는가(동작·설계)"가 아니라 "어떻게 서술됐는가(품질)"만 잰다 — 동작을 바꾸는 리팩터에는 쓰지 않는다.

## 5차원

각 파일을 아래 5개 차원마다 **1~5점**으로 채점한다. 앵커(1·3·5)를 기준으로 중간값(2·4)을 보간한다.

### 1. 명확성 (Clarity)
목적·절차·결정이 오독 없이 한 번에 읽히나.
- **5** — 처음 읽는 사람도 오독 없이 이해. 용어가 처음 쓰일 때 정의되고, 순서가 자연스럽다.
- **3** — 대체로 읽히나 일부 문장이 중의적이거나 흐름이 헷갈린다.
- **1** — 목적·절차가 모호해 여러 번 읽어야 하거나 오독 소지가 크다.

### 2. 일관성 (Consistency)
용어·구조·표기가 문서 내부 + OS 전역 규약(다른 스킬·컨텍스트·OS.md 교차참조)과 맞물리나.
- **5** — 같은 개념은 늘 같은 말·표기로 부르고, 구조가 자매 문서와 정렬되며, 교차참조가 서로 일치한다.
- **3** — 문서 내부는 일관되나 전역 용어·표기와 일부 어긋난다.
- **1** — 같은 개념을 다른 말로 부르거나 구조가 들쭉날쭉하다.

### 3. 완결성 (Completeness)
이미 있는 설계의 전제·엣지케이스·산출물·연결이 서술에 빠짐없나. *(없는 기능·규칙을 지어내라는 뜻이 아니다 — 서술 누락만 메운다.)*
- **5** — 필요한 전제·엣지케이스·산출물·연결이 모두 서술돼 빈틈이 없다.
- **3** — 핵심은 있으나 엣지케이스·전제 일부가 암묵적이다.
- **1** — 중요한 단계·전제·산출물이 서술에서 누락됐다.

### 4. 간결성 (YAGNI / Concision)
군더더기·중복·과잉 서술이 없나. *(이 프로젝트의 핵심 가치.)*
- **5** — 더 뺄 게 없다. 중복·군더더기·과잉 서술이 없다.
- **3** — 읽을 만하나 반복·불필요한 수식이 일부 있다.
- **1** — 중복·장황함이 핵심을 가린다.

### 5. 정합성 (Correctness)
링크·파일경로·상호참조·인용 수치가 실제 리포지토리 상태와 일치하나.
- **5** — 링크·경로·상호참조·인용 수치가 모두 실제 리포와 일치. 깨진 링크·틀린 경로·철 지난 참조 0.
- **3** — 대체로 맞으나 철 지난 참조·경로가 소수 있다.
- **1** — 깨진 링크·틀린 경로·오래된 참조가 다수다.

## 완료 조건 (기본값)

대상 파일 **전부**가 5개 차원 각각 **≥ 4.5**이고, 마지막 **교차정합 패스**에서 파일 간 모순·깨진 링크가 **0**일 때. 그 전까지 매 반복 "가장 점수 낮은 파일·차원"부터 한 덩어리씩 개선한다.
(임계값은 호출하는 목표에서 덮어쓸 수 있다.)

## 채점 기록 형식 (스냅샷용)

반복마다 파일별 점수를 아래 형태로 남기면 추세를 쌓을 수 있다:

```json
{"iter": 3, "ts": "2026-07-11T15:40:00", "file": ".claude/skills/sim-engine/SKILL.md",
 "scores": {"clarity": 4, "consistency": 3, "completeness": 4, "concision": 3, "correctness": 5}, "mean": 3.8}
```

## 사용법

`ralph-loop` 목표에서 이 파일을 가리키면 된다 — 매 반복 worker가 읽어 같은 잣대로 자기채점한다:

```
/ralph-loop <대상·제약 서술> 채점 기준은 docs/ralph-runs/rubric-doc-quality.md 의 5차원을 쓴다.
```
