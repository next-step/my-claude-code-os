# 자동 시뮬레이션 루프 설계 문서

> 매일 도는 무인 모의 투자 루프의 구조를 담는 살아있는 설계 문서다.
> 큰 틀·원칙·설계 이유만 담고, 각 부품의 구현 상세는 `docs/plans/`, 순서 있는 실행 큐는 [docs/TODO.md](./TODO.md)가 맡는다.

## 이 OS의 정체성

이 OS는 **조언가·추천기가 아니라, 분석 → 계획 → 모의 매매까지 스스로 수행하는 자율 시스템**이다.
사람은 매매를 요청·승인하지 않는다. 아침에 시장을 읽고, 투자 위원회가 국면을 합의해 계획을 세우고,
장중에 계획대로 모의 체결하고, 주말에 스스로 되짚는 하루 루프가 **사람 개입 없이 굴러간다.**
사람은 성향(위험 허용도)과 무결성 가드레일이라는 **통제 손잡이**만 쥐고, 시스템이 도출한 개선안을
**승인**하는 자리에 선다.

- **대상 시장**: 국내 코스피/코스닥.
- **매매 환경**: 자체 페이퍼트레이딩(모의) 시뮬레이터. 실계좌·실주문은 없다(→ [가드레일 층](#가드레일-층)).

## 하루 흐름 (A~F)

하루 루프는 **여섯 개의 독립 스킬·스크립트**로 나뉜다. 각 단계가 독립 부품인 이유: 스킬=하나의 절차라는
패턴을 유지해 단계별로 수동 재실행·디버깅할 수 있게 하고, 장중 내내 도는 시뮬(E)처럼 수명주기가
다른 단계를 자연스럽게 떼어내기 위해서다. 단계 사이 연쇄는 [오케스트레이션](#오케스트레이션-헤르메스-체이닝)이 맡는다.

```
아침 8시   A. 뉴스 수집 ── 구조화 브리핑 append
   ↓
           B. 투자 위원회 (7인, 2단계 토론)
              1단계: 시장 국면 합의  ← C. 국면 지표 스크립트(사실판)
              2단계: 투자 계획 합의  → D. 계획서 갱신 + 회의록 append
   ↓
09:00~15:30 E. 모의 시뮬레이션 엔진 (1분 폴링 체결)
              급변 감지 → 긴급 위원회 자동 소집 → 즉시 시장가 체결
   ↓
토요일     F. 주간 회고 (위원회 페르소나 자기 되짚기 → 개선안)
              └──────── 사람 승인 후 기준 반영 ↻ ────────┘
```

### A. 아침 뉴스 수집
개장 전 **판단을 바꾸는 사실**만 수집해 '오늘의 브리핑'으로 구조화 저장한다.
- 범위: 국내 헤드라인 + 미국장 마감(지수·반도체) + 거시 정량 스냅샷(원달러·전일 지수·업종 등락) + 보유/관심 종목 뉴스 + 수급(외국인/기관 전일 매매동향).
- **사실은 수집, 해석은 위원회.** 브리핑은 사실·출처 링크만 담고 매수/매도 해석은 넣지 않는다 — 위원회 토론 전에 편향을 주입하지 않기 위해서다. 원본 전문은 저장하지 않고 링크만 둔다(누적 부담 제거).
- 수집 방식: 정성(뉴스·거시 내러티브)=웹검색 서브에이전트, 정량(지수·환율·수급)=스크립트(→ [정성/정량 분리](#정성해석과-정밀-수치를-나눈다)).
- 저장은 영구 append, 위원회 주입은 오늘 + 최근 N영업일(기본 5)만 — 저장과 소비를 나눠 각자 최적화한다.

### B. 투자 위원회
공통 사실판 위에서 **7인이 2단계로 토론**해 국면을 합의하고 투자 계획서(D)를 작성/수정한다. 메인 스킬이 의장 겸 사회자다.
- **7인 = 분석 4렌즈 + 관리 3렌즈**, 각각 실존 인물 페르소나 오마주:

  | 렌즈 | 페르소나 |
  |------|----------|
  | 기술적 | 마크 미너비니 |
  | 펀더멘털 | 워런 버핏 |
  | 거시·시장전략 | 레이 달리오 |
  | 심리·뉴스 | 앙드레 코스톨라니 |
  | 회의론자(악마의 변호인) | 나심 탈레브 |
  | 수급 | 스탠리 드러켄밀러 |
  | 리스크·자금관리 | 폴 튜더 존스 |

  페르소나는 **추론 스타일·강조점만** 정하고, 사실·수치는 여전히 브리핑·스크립트 출처만 쓴다(오마주일 뿐 실인물의 실제 발언·포지션이 아님). 이 7인 정의는 정규 위원회·긴급위(부분집합)·주간 회고(축약)가 공유하므로 **컨텍스트로 분리**한다.
- **입력은 전원 동일** — 오늘 브리핑 + 투자계획서 + 시뮬 현황. 같은 사실 위에서 관점 차이로만 다툰다(서로 다른 사실 위에서 다투지 않게).
- **2단계 순차 토론**: ①국면 합의(상승/하락/횡보 + 사이클 위치) → ②그 국면 위에서 계획 합의. 각 단계 끝에 수렴 판정. 국면을 먼저 못박아야 계획이 같은 전제 위에 선다.
- 산출: **계획서(D, 살아있는 문서)** + **회의록(append 로그 — 그날 무엇을·왜 바꿨나)**.

### C. 국면 지표 스크립트 (사실판)
지수와 개별 종목의 국면을 **결정론적 정량치로** 산출해 위원회 1단계 토론이 딛고 설 사실판을 깐다.
- **하이브리드**: 스크립트는 정량 지표까지만, 서술 라벨('상승장 후반부' 등)은 위원회가 그 위에 붙인다. 라벨까지 스크립트가 정하면 위원회 1단계가 형식화되므로 선을 긋는다.
- 대상: 지수(배경 국면) + 보유·관심 종목 각각(진입/청산 타이밍의 직접 근거). 단기 스윙은 종목 단위로 결정나므로 종목별 사이클 위치가 필수다.
- 지표 3축: ①추세(이평 배열·기울기) ②사이클 위치(52주 고저 대비%·신고가/신저가) ③변동성(ATR%). 국면을 가르는 최소 축. (시장 폭 breadth는 표본이 쌓여 필요성이 확인되면 후행 추가.)

### D. 투자 계획서
위원회(B 2단계)가 작성/갱신하는 **하나의 살아있는 문서** — '현재 유효한 의도'만 담는다. 구현은 B와 한 스킬로 묶이지만, 설계상 별도 산출물이라 따로 둔다.
- **스키마**: 종목별 진입가·목표가·손절가·목표 비중·**주문 수량**·근거·상태 라벨 + 헤더(국면 전제·목표 현금 비중·총 리스크). 조건부 시나리오 규칙은 담지 않는다 — 급변 대응은 E 긴급 위원회가 실시간 판단한다(관심사 분리).
- **부분 갱신**: 바뀐 종목·필드만 제자리 수정하고, '무엇을·왜 바꿨나' 이력은 B의 회의록이 맡는다(상태=제자리 / 사건=로그 분리).
- **의도 ↔ 실제 분리**: 주문 수량은 위원회가 자본·비중·진입가로 정수주까지 확정하고(그래서 '못 사는 종목'은 계획 단계에서 배제된다), 체결 엔진(E)은 집행만 한다. 실제 보유·현금은 포트폴리오(E)가 진실원천이고, 계획서는 종목별 상태 라벨(대기/진행중/완료)로만 연결한다.

### E. 모의 시뮬레이션 엔진
장중 **09:00~15:30 라이브 1분 폴링**으로 계획서대로 체결하고 포트폴리오를 갱신한다. 이 루프의 핵심 가치인 '장중 실시간 대응'을 살리기 위해 사후 일괄 재구성이 아닌 실시간 폴링을 택했다.
- **체결 판정 = 한 틱 관통**(매수 지정가 −1틱, 매도 +1틱 관통 시 체결로 봄 — 보수적 확인), **체결가는 지정가로 기록**. 판정은 보수적으로, 체결가는 명확하게 나눠 낙관/비관 어느 쪽으로도 안 치우치게 한다. 틱은 KRX 가격대별 호가단위를 스크립트가 적용한다.
- **포트폴리오 = 상태파일 제자리 갱신(지금 상태 진실원천) + 체결 로그 append(사건 이력).** 초기 자본 100만원.
- **긴급 위원회**: 시뮬이 정량 임계(종목 급락·손절가 도달·지수 급변)를 감지하면 **자동 소집**(무인 정합). 축약 3~4인(리스크·기술·수급 — 정규 7인의 부분집합, 페르소나 재사용)이 빠르게 판단하고, 결정은 **즉시 시장가 체결**(관통 대기 없음) + 포트폴리오·계획서 즉시 반영 + 긴급 회의록 append. 긴급의 본질은 속도라 인원을 줄이되 급변에 직결되는 렌즈만 남긴다.

### F. 주간 회고
매주 토요일, **계획을 세운 위원회 페르소나(축약)가 자기 판단을 되짚어** 개선안을 도출한다. 회의론자(탈레브)가 자화자찬을 견제한다.
- 입력 = 결과(체결·수익률) + **판단 이력**(회의록·국면 판정·계획 변경). '왜 그 판단을 했고 결과가 어땠나'를 봐야 실력 vs 시장 휩쓸림을 분리할 수 있다.
- portfolio 회고에서 검증된 **결정론 status 스크립트 + 수렴 토론 + 리포트 append 패턴을 차용**하되, 주체·기록은 루프 전용으로 새로 짠다(계획한 주체가 반성해야 '판단→결과'의 연속성이 산다).
- **되먹임 = 제안까지 무인, 반영은 사람 승인.** 개선안(임계·배점·손절폭·페르소나 가중)은 무인으로 도출하되, 실제 시스템 반영(스크립트 상수·이 문서 변경)은 사람 승인 후. 표본 부족(n=0~1) 가설은 즉시 바꾸지 않고 lessons 파일에 표본 대기로 기록한다.

## 오케스트레이션 (헤르메스 체이닝)

단계별 독립 스킬을 **외부 '헤르메스 에이전트'가 시각·완료 이벤트에 맞춰 무인으로 순차 연쇄**시킨다.
클로드 코드 내부 cron이 아니라 외부 에이전트가 "8시에 수집 실행 → 끝나면 위원회 소집 → 계획 갱신 →
09:00 시뮬 기동"으로 체인을 잇고, 주간 체인은 토요일에 회고를 자동 실행한다.
헤르메스 에이전트의 실체(외부 스케줄러/오케스트레이터)와 완료→다음 트리거를 잇는 방법은 구현 시 확정한다.

## 산출물 토폴로지

기록물을 **성격에 따라** 저장 방식을 나눈다 — '지금 상태'는 한 곳에서 제자리 갱신, '일어난 사건'은 박제 append.

| 기록물 | 성격 | 저장 방식 | 진실원천 |
|--------|------|-----------|----------|
| 투자 계획서 | 현재 유효한 의도 | **하나의 살아있는 문서, 제자리 갱신**(바뀐 종목·필드만) | 계획(의도)의 진실원천 |
| 포트폴리오 상태 | 지금 보유·현금·평단·손익 | **상태파일 제자리 갱신** | 실제(체결)의 진실원천 |
| 아침 브리핑 | 그날의 사실 | 날짜별 **append 로그**(영구) | — |
| 위원회 회의록 | 그날 무엇을·왜 바꿨나 | 날짜별 **append 로그**(긴급 회의록도 '긴급' 표기로 여기 append) | 계획 변경 근거 |
| 체결 로그 | 매 체결 사건 | 날짜별 **append 로그** | 체결 이력 |
| 회고 리포트 | 주간 되짚기·개선안 | 주별 **append 로그** | 개선 이력 |

- **계획(의도) ↔ 포트폴리오(실제)는 분리한다.** 갱신 주체·주기가 다르기 때문 — 계획서는 위원회가 하루 1회 갱신하는 의도, 포트폴리오는 시뮬이 1분마다 갱신하는 실제. 한 파일에 두면 경합해 진실원천이 흐려진다. 둘은 종목별 상태 라벨(대기/진행중/완료)로만 연결한다.
- 이 저장 경로들의 스키마·규약은 컨텍스트의 기록 규약(record-conventions)이 정의한다.

## 관통 원칙

### 정성(해석)과 정밀 수치를 나눈다
'사실은 수집·산출, 해석은 토론'이 이 OS를 관통한다. **정성 정보(뉴스·거시 내러티브)는 웹검색 서브에이전트가,
정밀 수치(현재가·지지저항·변동성·재무·국면 지표)는 결정론적 스크립트가, 종합·해석은 위원회·회고가** 맡는다.
웹검색 값은 출처마다 달라 정밀 수치에 위험하므로 진입/손절/체결의 근거 숫자는 스크립트만 쓴다.

### 검증된 데이터 계층을 재사용한다
네이버 파싱 기반 데이터 스크립트 계층(현재가·지지저항·변동성·재무 계산)은 검증된 부품으로 **그대로 재사용**한다.
개편의 본질은 '언제·누가·어떻게 판단·체결하나'라는 상위 워크플로우이지 숫자 뽑는 법이 아니다. 국면 지표(C)·KRX
호가단위처럼 새로 필요한 부품만 신설한다.

### 공유 지식은 컨텍스트로 분리한다
여러 곳이 나눠 쓰는 지식(7인 페르소나·국면 정의·데이터 소스 규약·기록 규약·용어·회고 교훈)은 `.claude/context/`
아래 컨텍스트 파일로 분리한다. 한 스킬에만 쓰이는 설명은 그 스킬 안에 둔다. **혼합 주입** — 모든 작업의 공통 기준인
2종(위험 허용도·무결성 가드레일)은 CLAUDE.md로 항상 로드, 나머지는 소비자 스킬이 필요할 때만 Read. Read 지시의
누락 위험은 `scripts/check_context.py`의 정적 검증으로 보완한다. (컨텍스트 파일 집합·소비자 연결의 최종 형태는
context 재정비 항목이 확정한다.)

## 가드레일 층

무인 자율 시스템이라 안전선은 **층을 나눠** 둔다.

1. **전술 한도는 위원회에 일임한다.** 총 손실 한도·종목당 비중·투자 기간·손절 폭·자본 배분을 사람이 고정하지 않고 **위원회가 매 계획에서 결정**한다. *왜:* 전부 모의라 실패가 값싼 교훈이고, 위원회를 둔 이유 자체가 이 전술 값을 정하기 위해서다. 안 겪은 문제에 미리 방어막을 치기보다(뼈대 우선/YAGNI) 위원회에 맡기고, **문제 패턴이 주간 회고(F)에서 드러나면 사람 승인 후 경계를 되살려** 스크립트 상수·이 문서에 반영한다(부활 경로 = F의 되먹임 루프).
2. **사람이 쥔 통제 손잡이 2종은 일임 대상이 아니다.**
   - **위험 허용도(중립)** — 한도가 아니라 위원회에게 주는 방향타(페르소나들이 얼마나 공격적일지의 기준). 이게 없으면 위원회의 성향 앵커가 사라진다. `investor-profile`이 담는다.
   - **무결성 가드레일** — 출처 없는 수치 금지 · 모든 매매 판단에 근거 기록 · 정밀 수치는 스크립트 · 튜닝 반영은 사람 승인 · 표본 없는 수치 변경 금지. '누가 전술을 정하나'와 무관한 시스템 정직성 규칙이라 그대로 유지한다. `trading-principles`가 담는다.
3. **모의 자율 체결 ≠ 실주문.** 이 루프의 무인 자동 체결은 **전부 모의(페이퍼)**다. "실제 주문은 AI가 직접 실행하지 않는다"는 원칙은 **미래 실계좌 연동 지점의 안전선으로 그대로 남는다** — 모의 루프의 무인 자동화와는 다른 층이며, 서로 충돌하지 않는다.
4. **기준 변경(튜닝)은 매매와 다른 층이다.** 매매 실행은 무인이지만, 시스템 기준 변경은 사람 승인 후에만 반영한다(소표본 자동 튜닝 = 과적합의 지름길).

## 미래 확장 후보 (표본 쌓이면 / 필요 시)

> 선택 기준: **"이 데이터·기능이 판단을 바꾸는가?"** — 아니면 넣지 않는다(표본 없이 먼저 넓히지 않는다).

- **시장 폭(breadth)** — 등락종목수·신고가종목수. 지수 국면 정밀도를 올리나 지수 전용 수집이 필요해 후행.
- **공시(DART)** — 무료·구조화·공신력 1차 자료. 한 종목을 깊게 볼 때 판단을 바꾸므로 그때 도입.
- **실계좌 연동** — 모의 루프의 신뢰가 쌓이면 검토할 다음 층. 이때 [가드레일 층 3](#가드레일-층)의 '실주문은 사람'이 발동한다.
