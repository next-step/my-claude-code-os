# /suggest 스킬 평가 — 컨텍스트 주입 유무 비교

- **날짜**: 2026-09-08
- **도구**: Anthropic 공식 `skill-creator` 플러그인 (테스트 케이스 → 격리 서브에이전트 병렬 실행 → assertion 채점 → 벤치마크 집계)
- **질문**: 컨텍스트 파일(experiments/·knowledge/·metrics.md)의 자동 주입 연결이 스킬 동작을 실제로 어떻게 바꾸는가?
- **테스트 케이스**: `.claude/skills/suggest/evals/evals.json` (프롬프트 2개 × 채점 기준 5개)

## 실험 설계

같은 스킬(`/suggest`)을 두 환경에서 같은 프롬프트로 실행했다. 변인은 **컨텍스트 파일의 존재 여부** 하나다.

| 구성 | 환경 |
|---|---|
| **주입** (with) | 실제 저장소 — experiments/ 4건, knowledge/ 1건, metrics.md 존재 |
| **미주입** (without) | 격리 임시 프로젝트 — 스킬·에이전트 정의만 복사, 컨텍스트 파일 3종 전부 부재. 격리 규칙으로 원 저장소 접근 차단 |

각 구성 × 프롬프트 2개("다음 실험 뭐 하면 좋을까?" / "후보 2~3개를 근거·기대 효과·리스크와 함께") = 총 4런. 실행은 각각 독립 서브에이전트.

## 결과

| 지표 | 주입 | 미주입 | Δ |
|---|---|---|---|
| **채점 통과율** | **100% (10/10)** | **60% (6/10)** | **+0.40** |
| 소요 시간 | 162.5s ± 14.3 | 105.0s ± 2.4 | +57.5s |

### 산출물의 질적 차이

**주입 런**: 후보 3개를 제안 — 전부 실험 기록의 "다음 실험 후보" 절과 knowledge 문서를 인용했고, 채점자가 인용 수치(실측 15/27, 병합 임계 35, 게이트 마진 등)를 원문과 대조해 **전건 실존 확인** (창작 0건). 후보마다 기대 측정 변화가 측정 셋 케이스 수준으로 구체적.

**미주입 런**: 후보 0개 — 스킬의 불변 규칙 2("근거 없는 후보 금지")에 따라 **"제안 불가"를 명시적으로 보고**하고, 무엇이 없어서 불가한지(기록·지식·측정 기준)와 선행 조건(metrics 정의 → 베이스라인 기록 → 지식 시드)을 제시했다. 프롬프트가 "후보 2~3개"를 못박았는데도 창작하지 않았다.

## 결론

1. **컨텍스트 주입의 효과는 "제안 능력의 활성화"다.** 미주입 실패 4건은 전부 "후보를 낼 재료가 없어서"이지 잘못된 출력이 아니다. 주입이 없으면 스킬은 안전하게 무능해지고, 주입되면 기록에 근거한 제안이 나온다.
2. **양쪽 모두 할루시네이션 0건** — 스킬에 명문화된 "근거 없는 후보 금지" 규칙이 컨텍스트 부재 시의 방어선으로 작동했다. 컨텍스트 연결(능력)과 근거 규칙(안전)은 서로 보완하는 별개 장치다.
3. **주입 비용은 런당 약 +57초** — 기록 4건 + 지식 문서를 독립 컨텍스트에서 읽는 시간. 근거 있는 제안의 대가.

## 발견된 개선점 (통증 목록 후보)

- 스킬은 `knowledge/` 부재만 명시적으로 다루고, **experiments/·metrics.md까지 전부 없는 경우의 절차가 미정의** — 이번엔 근거 규칙이 우아한 실패를 만들었지만, 명시 경로를 추가할 가치가 있다.
- 채점 기준 중 "각 후보에 X" 형태는 후보 0개일 때 구조적 FAIL이 되어 품질 신호와 주입 효과 신호가 섞인다 — 차기 평가에서 분기 필요.

> 원시 산출물(4개 런의 proposals.md·grading.json·benchmark.json)은 세션 스크래치패드 산출물로, 커밋하지 않는다. 테스트 케이스(evals.json)만 스킬 옆에 보존해 차기 이터레이션에 재사용한다.
