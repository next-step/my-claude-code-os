1단계🤖 os-mapper

현재 코드 컨벤션·재사용 자산 확인

구조·네이밍·테스트 관행을 조사하고 재사용 가능한 기존 코드를 목록화한다.

산출 · CONVENTIONS.md · REUSE.md
2단계🤖 os-developer

재사용 우선 구현 + 단위·통합 테스트 작성

REUSE.md를 먼저 뒤져 기존 자산을 활용하고, 기능 코드와 테스트를 함께 만든다.

산출 · 기능 코드 + 단위·통합 테스트
3단계 · 🚦 초록불 게이트🤖 os-verifier⚙️ gradle · JaCoCo

테스트 검증 루프

CI가 전체 테스트를 실행하고, os-verifier가 실패 원인을 분석해 코드/테스트를 고친다.

❌ 실패 → ↺ 수정·재실행✅ 모두 green → 다음
🚦 리뷰 게이트🤖 /code-review

코드 품질·재사용 준수·놓친 엣지케이스 점검

green이 "의도대로 도는가"만 보므로, 품질·설계는 별도 리뷰가 본다. (새 에이전트 없이 기존 스킬 재사용)

⛔ 블로킹 이슈 → 2단계로✅ 경미/없음 → 다음
4단계🤖 os-documenter

문서화 — docs + HTTP/API

검증된 기능의 사용법·결정·제약을 문서화하고, API 변경이 있으면 HTTP 문서를 갱신한다.

산출 · docs/ · HTTP 문서
🚦 수용 게이트 ②🙋 사람
