색상 실험 OS — 개요

색상 추출 알고리즘 개선 작업에서 AI와 사람이 협력하는 체계. 스킬·에이전트(행동)와 문서·SSOT(지식·상태)의 두 기둥으로 구성됩니다.

이 HTML은 시각화 전용 산출물입니다. 원본 내용은 OS.md 와 기획 문서 에 있습니다. 구축 현황(2026-09-01): 배치 0~2 완료(실험 0001~0003으로 실전 검증), ⬜ 표시 항목은 배치 3 예정 — 상세는 OS.md "구축 현황" 절.

1. 스킬 · 에이전트 카탈로그

스킬은 진입점이자 절차서(지휘 악보), 서브에이전트는 스킬을 수행하는 메인 에이전트가 스폰하는 독립 일꾼입니다 (독립 컨텍스트 · 백그라운드 · 병렬).

카테고리스킬 (지휘)서브에이전트 (일꾼)협력 방식
방향 결정
외부 입력 · 의사결정		 /research 기법 조사 에이전트 ×N + 큐레이터 병렬 스폰 → 큐레이터가 취합·선별해 knowledge 문서로 정리
/suggest 기록 분석 에이전트 실험 기록을 독립 컨텍스트에서 읽고 다음 후보만 요약 반환
실험 파이프라인

+ 정답지 갱신 시 label-drafter		 순차 협력: 리서치→(승인)→적용→측정→기록 검증 루프(3회 상한), 판정은 메인 담당
공유 에이전트
스킬 전속 아님		 — label-drafter 이미지를 보고 정답지 초안 + 추출 대조 HTML 생성 → 사람 확정 → 적용 에이전트가 등록
유틸리티
반복 작업 지원		 /compare ⬜ 리포트 에이전트 기록을 읽고 전후 비교 리포트 생성 (향후 시각화 확장 지점)
/retrospect ⬜ 없음 (메인 직접) 대화 맥락 자체가 재료 — 분리하면 오히려 손해
OS 관리
메타		 /os ⬜ 없음 (메인 직접) OS 파일 수정의 유일 경로 — 사람과의 상호작용이 핵심
💡 병렬 vs 순차 — 조사처럼 대상이 독립적이면 병렬, 적용→측정처럼 선후 의존이 있으면 순차.
💡 모든 스킬에 에이전트가 필요한 건 아니다 — 대화 맥락·사람의 결정이 핵심인 작업은 위임하지 않는다.
