## Q3. 컨텍스트 파일 구성
- **결정**: 제안 6종 전부 — ① investor-profile(투자 성향·한도) ② trading-principles(매매 원칙·가드레일) ③ data-sources(데이터 소스 규약) ④ record-conventions(기록 스키마 규약) ⑤ market-glossary(용어·해석 기준) ⑥ retro-lessons(회고 교훈 누적).
- **기각**: 핵심 5종만(⑥ 제외) — 미션 최소 요건은 되지만 '누적되는 컨텍스트' 유형을 경험하지 못함.
- **이유(AI 정리·확인됨)**: 정적 규약 5종 + 살아있는 누적 파일 1종으로 성격이 다른 컨텍스트를 골고루 경험. 특히 ①은 OS.md 1단계 정의("사람이 투자 성향 제공")에 있으나 실체가 없던 파일이라 미션과 정확히 맞물리고, A/B 비교에서 효과가 가장 잘 드러난다.

## Q4. 자동 주입 방식
- **결정**: 혼합 — 모든 작업에 필요한 핵심은 CLAUDE.md로 항상 로드, 나머지는 소비자 SKILL.md·에이전트 md에 "먼저 X를 읽어라" Read 지시로 필요 시 로드.
- **기각**: 전부 본문 Read 지시(고정비 0이나 주입 누락 위험이 전 파일에 적용) / 전부 CLAUDE.md 항상 로드(누락 위험 최소지만 모든 세션이 무거워져 '컨텍스트 최적화' 취지와 역행, 서브에이전트 미적용 한계).
- **이유(AI 정리·확인됨)**: 비용(항상 로드 고정비)과 확실성(주입 누락 위험)의 균형. 점진적 공개 개념을 실제로 실습하는 구성이며, Read 지시의 누락 위험은 Q2에서 포함한 검증 테스트가 보완한다.

## Q6. A/B 비교 대상 스킬
- **결정**: `analyze-company`.
- **기각**: recommend-stocks(1회 실행이 무거워 A/B 2회는 더 비싸고, 출력 변동 요인이 많아 주입 효과 분리가 어려움) / portfolio-retrospect(토론 결과가 data 상태 의존·비결정적이라 차이의 원인 판별이 어려움).

## Q7. A/B 비교 방법
- **결정**: 수동 A/B 2회 실행 — 같은 회사로 주입 off(지시 임시 제거)/on 각 1회 실행, 출력을 나란히 대조해 판정 체크리스트(손절폭·비중·톤에 성향 반영됐나)로 판정, 결과를 파일로 남김.
- **기각**: 미션이 지목한 도구(skill-creator/ab-test) 사용 — 현 환경에 미설치(강의 제공 도구로 추정)라 도구 확보 전까지 진행이 보류됨 / 수동+도구 병행 — 작업 2번.
- **이유(AI 정리·확인됨)**: 지금 바로 가능하고 판정 기준을 스스로 설계하는 학습 효과. 단, 미션이 지목한 도구를 안 썼다고 볼 여지가 있어 리뷰어 확인이 필요할 수 있음(알려진 위험).

## Q8. 도식화 형식

- **기각**: mermaid+md(GitHub 자동 렌더·diff 추적은 좋으나 표현력 제한) / 이미지 파일(갱신에 원본 툴 필요, diff 불가).

## Q9. 정량 비교 지표 (도전2)
- **결정**: 고정 로드량 측정 — "항상/매번 로드되는 양"(CLAUDE.md+임포트, 스킬 description, 각 SKILL.md 본문, 에이전트 md)을 스크립트로 집계해 최적화 전후 비교.
- **기각**: 실제 세션 토큰 측정(/context·/cost) — 실사용 비용을 직접 보지만 실행마다 변동이 커 비교가 흐림 / 둘 다 — 작업량 증가.
- **이유(AI 정리·확인됨)**: 결정론적·재실행 가능해 OS 기존 규약("정밀 수치=스크립트")과 일치. 실제 토큰 소모는 간접 추정이라는 한계는 인지함.

## Q10. 검증 테스트 형태 (도전1)
- **결정**: 정적 검사 스크립트 — 컨텍스트 파일 6종 존재 + 각 소비자(SKILL.md·에이전트 md)가 자기 몫의 파일을 참조하는지 + CLAUDE.md 연결을 검사.
- **기각**: 정적+런타임 검증 — 진짜 동작까지 보증하지만 실행마다 비용이 들고 판정이 비결정적이라 자동화가 어려움.
- **이유(AI 정리·확인됨)**: 결정론적·공짜·언제든 재실행 가능(파일 이동·경로 오타 버그를 즉시 잡음). "모델이 지시를 실제로 따르느냐"는 런타임 검증은 A/B 비교(Q7)가 이미 겸한다.
