## Q1. 전역화 범위
- **결정**: `plan` 스킬, `retrospect` 스킬, CLAUDE.md의 인터뷰→플랜→구현→검증→회고 절차 서술 세 가지 모두 `~/.claude`로 전역화한다.
- **기각**: plan+retrospect만(CLAUDE.md 서술 제외) / plan만 우선.
- **이유(AI 정리·확인됨)**: interview처럼 워크플로우 전체를 어느 프로젝트에서든 다시 쓸 수 있게 만드는 것이 이번 작업의 원래 동기이므로, 범위를 좁히면 다음에 또 나머지를 전역화해야 하는 반복 작업이 생긴다. docs 구조 의존이라는 대가는 이후 지도 항목에서 별도로 해결한다.

## Q2. CLAUDE.md 절차의 전역화 방식
- **결정**: `~/.claude/skills/dev-workflow/`(가칭) 같은 새 전역 스킬을 만들어, 5단계 절차와 각 단계가 어느 스킬(interview/plan/verify/retrospect)을 쓰는지 설명한다.
- **기각**: `~/.claude/CLAUDE.md`에 절차를 직접 추가(모든 프로젝트에 상시 강제되는 규칙이 되어, 원치 않는 프로젝트에도 지속적으로 적용되는 대가가 큼).
- **이유(AI 정리·확인됨)**: 스킬은 명시 호출·참조가 선택적이라 다른 전역 스킬들과 일관되고, 사용자가 프로젝트별로 필요할 때만 끌어다 쓸 수 있다. CLAUDE.md에 넣으면 매 프로젝트마다 상시 적용되는 규칙이 되어 버려 선택권이 없어진다.

## Q3. 문서 구조 의존 처리
- **결정**: `docs/TODO.md`·`docs/plans/`·`docs/workflow-retros/` 등 경로명은 관례로 그대로 전제하고, 프로젝트에 아직 없으면 사용자에게 묻지 않고 새로 만들어 진행한다.
- **기각**: 경로를 설정 가능하게 일반화(사용자에게 묻거나 설정 파일 도입).
- **이유(AI 정리·확인됨)**: interview 전역화 때 Q7과 같은 패턴 — 경로를 설정 가능하게 만들면 스킬 복잡도가 올라가고, 이번 인터뷰 범위를 벗어난다. 고정 관례로 전제하는 편이 단순하고 일관적이다.

## Q4. retrospect의 완료 항목 검토·정리 포함 여부
- **결정**: "완료 항목 검토·정리" 마지막 단계도 전역 사본에 그대로 포함한다.
- **기각**: 전역 사본에서는 이 단계를 생략하고 워크플로우 회고만 남긴다.
- **이유(AI 정리·확인됨)**: Q3에서 docs/TODO.md·docs/plans/ 경로를 관례로 그대로 전제하기로 했으므로, 같은 관례를 쓰는 이 로직만 따로 빼면 프로젝트 사본과 전역 사본의 기능이 갈려 불필요한 관리 포인트가 생긴다. 하나로 유지하는 편이 단순하다.

## Q5. 설계 근거 링크·동기화 방식
- **결정**: interview 전역화 선례를 그대로 따른다 — ① 전역 사본에서만 `docs/interviews/...` 상대경로 링크를 "my-claude-code-os 원본 저장소 ... 참고" 같은 설명 텍스트로 치환(프로젝트 사본은 링크 유지), ② 심볼릭 링크가 아닌 실물 복사로 옮기고 프로젝트 사본은 원본으로 계속 유지한다.
- **기각**: 다른 방식(예: 심볼릭 링크, 링크 그대로 유지) — 별도로 검토하지 않음, 선례 재사용으로 확정.
- **이유(AI 정리·확인됨)**: interview 전역화 때 이미 "심볼릭 링크는 원격 클론 시 깨진다"는 이유로 실물 복사가 결정됐고, 링크 텍스트화도 같은 이유(전역 사본만 다른 프로젝트에서 열릴 수 있어 상대경로가 깨짐)로 결정됐다. 같은 문제이므로 같은 해법을 재사용한다.

## Q6. 대시보드 스킬 호출 방식
- **결정**: 새 전역 대시보드 스킬(5단계 절차 설명)은 명시 호출로만 쓰인다. interview/plan/retrospect처럼 사용자가 직접 부르거나 참조할 때만 동작하고, 자동으로 다른 작업에 개입하지 않는다.
- **기각**: 새 작업 시작 시 자동으로 워크플로우 단계를 안내/유도하는 방식.
- **이유(AI 정리·확인됨)**: 자동 개입은 다른 스킬의 트리거 로직과 겹치거나 불필요하게 끼어들 수 있다. 순수 참고용 설명서로 두는 편이 다른 전역 스킬들과 일관되고 단순하다.

## Q7. 프로젝트 CLAUDE.md의 워크플로우 서술 처리
- **결정**: 이 프로젝트의 CLAUDE.md에 있는 5단계 워크플로우 전문 서술은 그대로 둔다. 전역 스킬은 별도 산출물로 새로 만들 뿐, CLAUDE.md를 그 스킬을 참조하도록 축약하지 않는다.
- **기각**: CLAUDE.md 서술을 "자세한 절차는 ~/.claude/skills/dev-workflow 참고"로 축약.
- **이유(AI 정리·확인됨)**: interview 전역화 선례와 동일한 원칙(프로젝트 사본은 원본으로 계속 유지)을 CLAUDE.md에도 적용한다. 축약하면 이 프로젝트만의 규칙(CLAUDE.md 규칙 1: OS 관련 파일은 프로젝트 안에)과 전역 참조가 뒤섞여 불필요한 결합이 생긴다.
