# 자동 시뮬레이션 루프 — 1페이지 개요

> 매일 스스로 뉴스를 읽고 → 7인 위원회가 계획을 세우고 → 장중 모의 체결하고 → 주말에 자기 판단을
> 되짚어 개선하는 **무인 루프**. 체결은 전부 모의(페이퍼)다. 이 문서는 루프를 한눈에 보는 요약이고,
> 설계 이유·상세는 [OS.md](./OS.md)가 진실원천이다.

## 루프 도식

```
┌──────────────────────────── 매일 (평일) ────────────────────────────┐
│                                                                     │
│  08:00  A. 아침 뉴스 수집 ─────────────────► data/briefings/ (append)│
│            │  사실만 수집·해석 없음                                  │
│            ▼                                                         │
│         B. 투자 위원회 (7인 · 2단계 토론)                            │
│            │   1단계  시장 국면 합의  ◄── C. market_regime.py (사실판)│
│            │   2단계  투자 계획 합의  ──► D. investment-plan.md (갱신)│
│            │                         └──► data/minutes/ (append·근거)│
│            ▼                                                         │
│  09:00  E. 모의 시뮬 엔진 (1분 폴링 체결)                            │
│  ~15:30    │  급변 감지 → 긴급위 자동소집 → 즉시 시장가 체결          │
│            └──► data/fills/ (append) · data/portfolio.md (상태 갱신) │
│                                                                     │
└─────────────────────────────────┬───────────────────────────────────┘
                                   │
                     토요일 09:00  ▼
                F. 주간 회고 (위원회 페르소나가 자기 판단 되짚기)
                   │  "왜 그 판단을 했고 결과가 어땠나" → 개선안(패턴 가설)
                   ├──► data/retrospectives/ (append)
                   │
                   │   ┌─ 표본 부족(n≤1) ─► loop-lessons.md (표본 대기 축적)
                   └───┤
                       └─ 표본 충분 ─► [사람 승인] ─► 스크립트 상수 · OS.md
                                                          │
                 ↻  다음 루프가 바뀐 기준을 자동 적용  ◄────┘
```

## 단계 요약

| 단계 | 시각 | 하는 일 | 산출물 |
|------|------|---------|--------|
| **A** 아침 뉴스 수집 | 08:00 평일 | 판단을 바꾸는 사실만 구조화 수집(해석은 위원회 몫) | `briefings/` (append) |
| **B** 투자 위원회 | A 직후 | 7인 서브에이전트가 2단계 수렴 토론(국면→계획) | `minutes/` (append) |
| **C** 국면 지표 | B 안 | 지수·종목 국면을 결정론 스크립트로 산출한 **사실판** | (B에 주입) |
| **D** 투자 계획서 | B 안 | 진입가·손절·목표 비중·수량을 담은 **살아있는 의도** | `investment-plan.md` (제자리 갱신) |
| **E** 모의 시뮬 엔진 | 09:00~15:30 | 1분 폴링으로 계획대로 체결, 급변 시 긴급위 즉시 체결 | `fills/` (append) · `portfolio.md` (상태) |
| **F** 주간 회고 | 토 09:00 | 계획한 그 페르소나가 판단↔결과를 되짚어 개선안 도출 | `retrospectives/` (append) |

## 자율 개선 장치 (실행할수록 개선·축적되는 이유)

1. **자산 축적** — 매 실행이 `briefings·minutes·fills·retrospectives`에 **append로 박제**된다.
   고치지 않는 이 원본이 회고가 "그땐 왜 그렇게 판단했나"를 검증할 재료로 쌓인다.
2. **자기 개선 되먹임(F)** — 계획을 세운 **바로 그 위원회 페르소나**가 결과를 되짚어(회의론자=탈레브가
   자화자찬 견제) 개선안을 낸다. 계획한 주체가 반성해야 판단→결과의 연속성이 산다.
3. **안전 게이트(2층)** — 개선안 도출은 무인, **반영은 사람 승인 후**.
   - 표본 부족(n≤1) 가설 → `.claude/context/loop-lessons.md`에 **표본 대기**로 축적(즉시 반영 금지).
   - 표본 충분(반복 패턴) → 사람 승인 → 스크립트 상수·OS.md에 반영.
4. **폐곡선(↻)** — 승인·반영된 개선은 상수·문서에 녹아 **다음 루프가 자동 적용**한다.
   회고 리포트를 위원회 일일 입력에 상시 주입하지 않는 것도 이 때문(반영은 상수로, 미반영은 대기열로).

## 오케스트레이션 (무인 배선 — 헤르메스)

단계 사이 연쇄는 외부 스케줄러 **헤르메스**가 잇는다. 헤르메스 LLM은 루프에 개입하지 않고
`claude -p '/스킬명'`만 부른다 — 판단은 위원회(B)·시뮬(E) 안에만 둔다(재현성).

| 체인 (`scripts/hermes/`) | cron | 역할 |
|------|------|------|
| `morning-chain.sh` | `0 8 * * 1-5` | 휴장일 게이트 → A → B·D → 시뮬 직접 기동 |
| `sim-chain.sh` | `0 9 * * 1-5` (백스톱) | watchlist 조립 → `poll` 상시 → 이벤트마다 클로드 호출 |
| `weekly-chain.sh` | `0 9 * * 6` | 주간 회고(F) |

## 가드레일 (사람이 쥔 통제 손잡이)

- **방향타** — 위험 허용도(중립): 위원회가 얼마나 공격적일지의 성향 앵커. `investor-profile.md`.
- **무결성** — 출처 없는 수치 금지 · 모든 판단에 근거 기록 · 정밀 수치는 스크립트만 · 튜닝은 사람 승인 ·
  표본 없는 수치 변경 금지. `trading-principles.md`.
- **모의 ≠ 실주문** — 무인 자동 체결은 전부 모의. 미래 실계좌 연동의 실주문은 여전히 사람이 승인·실행.
