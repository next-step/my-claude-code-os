## 무엇이 어떻게 변했나

### 1단계 — 기준선 → 구축 후 (체계 도입의 비용)
**+17,330 B (+33%)** 증가. 컨텍스트 체계를 도입한 직접 비용이다.
- **항상 로드 +4,434 B**: CLAUDE.md가 @임포트하는 컨텍스트 2종(investor-profile 1,791 B + trading-principles 2,101 B = 3,892 B) + CLAUDE.md 본문 증가(컨텍스트 규칙 추가로 542 B).
- **호출 시 로드 +12,896 B**: 컨텍스트 파일 4종(9,579 B) + 각 SKILL.md·에이전트 md에 Read 지시가 추가돼 본문이 약간 팽창(3,317 B).
- *왜 기꺼이 지불하나:* ① 투자 성향·가드레일이 모든 세션에 자동으로 깔리고, ② 소비자가 필요한 규약을 Read로 가져가 "같은 맥락 위에서 일관된 출력"이 가능해진다. A/B 비교(`docs/context-ab-test.md`)가 이 효과를 정성 검증했다.

### 2단계 — 구축 후 → 최적화 후 (점진적 공개 적용)
**"호출 시 로드" −2,625 B 감소**, 그중 **7,177 B가 "특정 단계 로드"로 이동**.
- 3개 스킬의 SKILL.md 본문에서 긴 출력 템플릿·기록 스키마 상세를 `references/output-template.md`로 분리:
  - analyze-company: 10,178 → 8,734 B (−1,444 B)
  - recommend-stocks: 8,559 → 7,993 B (−566 B)
  - portfolio-retrospect: 10,445 → 9,830 B (−615 B)
- 분리된 references 합계 7,177 B는 "특정 단계 로드"로 새 범주를 만들었다.
- *왜 이것이 최적화인가:* 스킬 본문은 **스킬이 호출되면 무조건 전부 로드**된다. 반면 references는 **출력을 만드는 특정 단계(4·5단계)에서만** Read로 가져온다. 즉 "항상 로드"(스킬 호출 즉시)에서 "특정 단계 로드"(필요할 때)로 로드 시점을 뒤로 미뤄, 실제 소비를 줄인 것이다 — 점진적 공개(progressive disclosure)의 실천.
- *합계가 오히려 늘어난 이유:* references 파일 3종(7,177 B) 자체가 새로 집계에 들어왔고, 분리 과정에서 SKILL.md에 "이 단계에서 references를 읽어라"는 지시가 추가돼 본문이 일부 회복했다. 그러나 합계가 늘어난 것은 측정이 분류를 더 정밀하게 한 결과이지, 실제 로드량이 늘어난 것이 아니다 — **"호출 시 로드"의 감소가 실질 효과**다.

### 3단계 — 최적화 후 → 중복 제거 후 (역할 분담 정리)
**"항상 로드" −240 B 감소** — 매 세션마다 무조건 로드되는 분량이 줄었으므로 실질 절약 효과가 가장 큰 부분이다.
- `trading-principles.md` 2,101 → 1,861 B (−240 B): 같은 파일 안의 자기 반복(출처 없는 수치 금지·재료 없으면 산출 불가 2줄)을 1줄로 흡수하고, "정밀 수치=스크립트" 상세를 `data-sources.md` 참조 한 줄로 줄임.
- `market-glossary.md` 2,749 → 2,764 B (+15 B): "매매 가격대" 섹션에서 산출 수치(-5~8% 등)를 빼고 용어 정의만 남겼다. 손절가 줄에 "폭 산정 규칙은 trading-principles.md가 본점" 참조를 추가해 글자 수가 살짝 늘었지만, 역할 분담을 명시해 나중에 다시 중복이 생기는 걸 막는다.
- *왜 합계 변화가 작은가:* 중복 제거는 "최적화 후" 시점의 74,328 B 중 **서로 겹치는 내용**을 빼는 작업이라, 절대량보다 **의미 중복 제거**가 본질이다. 다만 "항상 로드"가 줄고 "호출 시 로드"가 거의 제자리라, 로드 빈도를 가중하면 실비용 감소 효과는 합계 감소(-225 B)보다 크다.
