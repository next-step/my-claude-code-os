# A/B 실험 — 컨텍스트 주입이 스킬 생성을 바꾸는가

skill-creator로 같은 스킬을 두 번 만들되, **OS 컨텍스트 주입 여부만** 달리해 비교했다.

## 방법

- 도구: skill-creator의 실제 절차를 따름. skill-creator 자신이 쓰는 A/B 방식(같은
  프롬프트로 서브에이전트 둘 — with/baseline)을 그대로 차용했다.
- 변수: 컨텍스트 주입 여부 하나만. 나머지(모델·과제·skill-creator 지침)는 동일.
- 공정성 장치: 서브에이전트는 CLAUDE.md가 자동 주입되지 않는다. 그래서
  - 대조군(`without_context/`) = OS 컨텍스트 전혀 없음 (진짜 baseline)
  - 주입군(`with_context/`) = 실제 `@import` 번들과 똑같은 것만 주입(CLAUDE.md +
    user·project·writing-style·work-principles). INDEX 전문은 넣지 않음 — 실제로도
    import 대상이 아니라 이름으로만 참조되므로.
- 과제(양쪽 동일): "코드의 TODO/FIXME 주석을 모아 정리하는 스킬"의 SKILL.md 작성.
- 산출물: `without_context/SKILL.md`, `with_context/SKILL.md` (각 59줄).

## 채점

| 기준 | 대조군(미주입) | 주입군(주입) | 변별력 |
|---|---|---|---|
| 한국어 | 지킴 | 지킴 | 없음 |
| 이모지 없음 | 지킴 | 지킴 | 없음 |
| description 트리거 구체·적극 | 지킴 | 지킴 | 없음 |
| 간결(분량) | 지킴 | 지킴 | 없음 |
| 읽기 전용 인식 | 있음(금지형) | 있음(선언+경계) | 약함 |
| 범위 확장 시 "묻기" | 없음 | 있음 (3곳) | 강함 |
| 변경은 확인·명시적 지시로만 | 없음(그냥 안 함) | 있음 | 강함 |

## 무엇이 갈렸나

주입의 효과는 **work-principles("가급적 묻고, 시킨 것만")** 에서 뚜렷했다.

- 대조군은 "하지 않을 것: 찾은 TODO를 수정·삭제하지 않는다"처럼 **평평한 금지**로만
  적었다. 묻는 행동은 없다.
- 주입군은 같은 읽기 전용 원칙을 **협업 행동**으로 바꿨다.
  - 절차 1: "규모가 크면 사용자에게 범위를 한 번 확인한다."
  - 경계: "정리·제거가 필요하면 사용자에게 확인받고, 실제 변경은 별도 지시로만."
  - 경계: "태그 목록을 바꿀 필요가 보이면 묻는다."
  즉 "안 한다"가 아니라 "묻고 나서 한다"로 바뀌었다. 이게 work-principles가 주입돼
  행동으로 내려온 지점이다.

## 정직한 한계 (그리고 배운 것)

writing-style 항목(이모지·한국어·간결)은 변별력이 0이었다. 과제 프롬프트가 한국어였고
skill-creator 지침도 "간결"을 요구해, **양쪽 다 주입 없이도 이미 지켰기** 때문이다.

교훈: 컨텍스트 주입의 한계효용은 **베이스라인이 이미 지키는 곳에선 안 보이고, 안
지키는 곳에서만 드러난다.** writing-style 효과를 제대로 보려면 프롬프트를 영어나
스타일 중립으로 줘서 베이스라인이 이모지·번역투를 쓰도록 조건을 바꿔야 한다. 이건
도전 2(정량 비교)에서 조건을 통제해 다시 측정할 대목이다.

## 결론

- 컨텍스트 주입은 실제로 스킬 생성 결과를 바꾼다 — 이 실험에선 work-principles가
  산출 스킬의 행동(묻고 하기)까지 전파됐다.
- 다만 효과는 조건 의존적이다. 베이스라인이 이미 만족하는 규칙은 주입해도 티가 안 난다.
- 산출물 원본은 `with_context/`, `without_context/`에 그대로 있다.
