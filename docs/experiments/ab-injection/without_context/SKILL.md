# TODO/FIXME 수집기

코드베이스를 훑어 미완성·수정필요 주석을 모으고, 파일·라인과 함께 정리한다.

## 절차

1. **범위 확인.** 사용자가 경로를 지정했으면 그 안에서만 찾는다. 지정이 없으면 프로젝트 루트 전체를 대상으로 하되, 아래 "제외 대상"은 건너뛴다.

2. **검색.** `ripgrep`(rg)으로 주석 마커를 찾는다. 라인 번호를 반드시 포함(`-n`)하고, 대소문자는 구분하지 않는다(`-i`). 기본 마커는 다음과 같다.
   ```bash
   rg -n -i --no-heading \
     -g '!**/node_modules/**' -g '!**/.git/**' -g '!**/dist/**' -g '!**/build/**' -g '!**/vendor/**' \
     '\b(TODO|FIXME|HACK|XXX)\b'
   ```
   - `rg`가 없으면 `grep -rniE`로 대체한다.
   - 사용자가 특정 마커만 원하면(예: "FIXME만") 패턴을 좁힌다.

3. **파싱.** 각 결과에서 파일 경로, 라인 번호, 마커 종류, 주석 본문을 뽑는다. 주석 기호(`//`, `#`, `/*`, `<!--` 등)와 앞뒤 공백은 제거해 본문만 남긴다.

4. **정리·출력.** 아래 형식으로 보고한다. 마커 종류별로 묶고, 각 항목은 파일 경로와 라인을 앞에 둔다.

## 출력 형식

먼저 한 줄 요약(총 개수, 종류별 개수)을 준 뒤, 표 또는 목록으로 정리한다.

```
총 12건 — FIXME 3, TODO 8, HACK 1

## FIXME (3)
- src/auth/login.ts:42 — 토큰 만료 검증이 빠져 있음
- src/api/client.ts:17 — 재시도 로직 하드코딩된 3회를 설정값으로
- ...

## TODO (8)
- src/ui/Table.tsx:88 — 페이지네이션 추가
- ...
```

- 항목이 많으면(30건 초과) 마커별 개수 요약을 먼저 주고, 우선순위 높은 FIXME/XXX/HACK을 먼저 펼친다.
- 담당자·티켓 표기(`TODO(name)`, `TODO: JIRA-123`)가 있으면 본문에 그대로 살린다.
- 결과가 0건이면 "남은 TODO/FIXME 주석 없음"이라고만 답한다.

## 제외 대상

- 의존성·산출물 디렉터리: `node_modules`, `.git`, `dist`, `build`, `vendor`, `.next`, `target`
- 이 스킬 파일 자신이나 문서 예시 속 마커는 실제 코드가 아니면 제외한다.

## 하지 않을 것

- 찾은 TODO를 임의로 수정·삭제하지 않는다. 요청은 "수집·정리"까지다.
- 추측으로 없는 항목을 만들지 않는다. 검색 결과에 있는 것만 보고한다.
