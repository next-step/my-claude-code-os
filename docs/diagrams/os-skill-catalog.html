개발 OS — 스킬 카탈로그

우리 OS의 스킬 16개가 각각 뭘 하는지 한눈에. 위 = 기능 개발 흐름(순서대로 ①→④, 게이트는 사람 검토) · 아래 = 목적별 받침 스킬(빠른·루프 트랙 포함). 색 = 종류(범례).

기능 개발 흐름 · 흐름 스킬 기능 하나가 요청 → 요구사항 → 설계 → 구현 → 마무리로 흐른다. 사람 검토 게이트를 통과해야 다음으로.
/feature — 흐름 런처 지금 어디까지 했는지 스캔해 흐름 지도를 보여주고, 상태에 맞는 다음 스킬을 실행한다. 직접 일하지 않는 안내자. 언제: "기능 만들자" · "어디까지 했지" · "/feature"
→ 아래 흐름을 상태에 맞게 실행·라우팅
① 요구사항무엇을 만들지 확정
/interview 질문으로 요구사항을 캐낸다(한 번에 하나씩·냉정하게 압박). requirements.md 채움. 언제: "요구사항 캐줘"
/prd 요구사항 → PRD 작성 후 reviewer로 검토·수정 루프를 돌려 확정. 언제: "PRD 만들자"
확정 게이트 · 사람 검토
→
② 설계어떻게 만들지 계획
/plan 확정 PRD로 구현 Plan 설계. 재활용할 기존 코드부터 조사(1차 스캔 → 갭만 병렬 탐색) 후 손댈 파일·단계·테스트 전략을 짠다. 언제: "설계하자" · "Plan 짜자"
승인 게이트 · 통과 전 구현 금지
→
③ 구현만들고 검증
/impl — 디스패처 승인된 Plan대로 구현. 변경 크기에 맞춰 방식(인라인·새 에이전트·resume)을 고르고, /verify 판정대로 루프를 돈다. 언제: "구현해줘"
/verify 구현이 기준(Plan·수용기준·테스트)을 충족하는지 검증해 판정. light(테스트만)·full(+reviewer 적대 대조). 언제: "검증해줘" · /impl이 매 라운드 호출
→
④ 마무리기록·공개 (사람이 확인)
/commit 변경사항을 의미 있는 단위로 로컬 커밋. 언제: "커밋해줘"
/push 로컬 커밋을 원격(GitHub)에 푸시. 되돌리기 어려운 일이라 확인 후. 언제: "푸시해줘"
/pr 커밋들을 분석해 PR 제목·본문을 LLM이 종합 → 템플릿 틀 확인 → gh로 PR 오픈. 언제: "PR 올려줘"
빠른 트랙
흐름(요구·PRD·Plan)을 건너뛰는 저위험 경로
/quick 작고 저위험한 변경을 종류 안 가리고 가볍게 처리 — 버그·QA·작은 스펙 변경. "빠른 이해 → 위험 감별 → 변경 → 테스트 → /verify light". 커지면 /plan·/feature로 승격. 언제: "가볍게 고쳐줘" · "간단한 수정이야"
루프 트랙 · 자기수렴 grind
지표가 값싸게 재지는 일을 반복(랄프 루프)으로 수렴
/coverage 테스트 커버리지가 목표(기본 85%)에 닿을 때까지 tests/에만 테스트를 보태며 무인 반복. 예산 상한·게이밍 방지·서킷브레이커로 방어. 프로덕션 로직은 안 건드림. 언제: "커버리지 올려줘" · "N%까지"
/perf-loop 속도 개선을 게이트 달린 랄프 루프로. 매 라운드 측정→6차원 루브릭 채점→변경 하나→재측정→/verify→≥90·정확성 통과면 채택, 아니면 되돌림. "빨라 보이지만 틀린" 변경을 게이트로 차단. 언제: "속도 개선" · "성능 최적화 루프"
지식 · 문서
흐름을 더 정확하게 만드는 컨텍스트·산출물
/domain 서비스 도메인 하나를 분석해 "정체·경계·관계"만 담은 문서(docs/domain/)를 만든다. 문서끼리 [[링크]]로 도메인 지도를 쌓음. 언제: "도메인 정리해줘"
/diagram 디자인된 HTML로 도식을 만들고 헤드리스 Chrome으로 스크린샷 → 직접 보고 검증하는 루프로 예쁜 PNG를 낸다. (이 카탈로그도 /diagram 산출물) 언제: "도식 그려줘" · "다이어그램"
메타 · 관측 (자기개선)
OS 자신을 돌아보고 측정
/retro 방금 세션을 두 렌즈로 회고 — (A) 스킬 프롬프트 개선점 (B) 손댄 도메인 문서 변경점 → 사용자에게 직접 보고(파일 안 만듦, 사람 검토 게이트). 언제: "회고" · 세션 마칠 때
/skill-stat 스킬 호출 기록(skill-usage.log)을 집계해 어떤 스킬을 많이 썼는지 통계로 보여준다. 언제: "스킬 통계"
흐름 스킬 기능 개발 ①→④ 흐름 런처 /feature 빠른 트랙 /quick 루프 트랙 /coverage·/perf-loop 지식·문서 메타·관측 게이트 사람 검토 reviewer(공유 서브에이전트)는 /prd·/verify·/retro가 함께 사용 · 자동 훅·컨텍스트 체계는 os-flow·context-system 도식 참조
