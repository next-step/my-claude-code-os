# 논문 분석: RecipeGPT — Generative Pre-training Based Cooking Recipe Generation and Evaluation System

- **원문 링크**: https://huggingface.co/papers/2003.02498 (arXiv: https://arxiv.org/abs/2003.02498)
- **저자 / 발표처 / 연도**: Helena H. Lee, Ke Shu, Palakorn Achananuparp, Philips Kokoh Prasetyo, Yue Liu, Ee-Peng Lim, Lav R. Varshney / The Web Conference (WWW) 2020, Demo track / 2020
- **분야 / 키워드**: NLP, 자연어 생성(NLG), 생성형 사전학습(GPT-2 fine-tuning), 조리 레시피 생성, 텍스트 평가 시스템

## 1. 한 줄 요약
Recipe1M 데이터로 파인튜닝한 GPT-2를 백엔드로 삼아, 재료↔조리법을 양방향으로 생성하고 그 결과 품질을 즉석에서 검증까지 해주는 웹 데모 시스템(recipegpt.org)이다.

## 2. 해결하려는 문제 (Motivation)
- 온라인에 방대한 조리 데이터가 쌓이면서 레시피 자동 생성에 대한 관심이 커졌지만, **생성(generation)과 평가(evaluation)를 하나로 묶은 통합 시스템**이 없었다.
- 사용자가 (a) 재료만 갖고 조리법을 얻거나 (b) 조리법만 갖고 필요한 재료 목록을 얻는 실용적 시나리오를 지원하고, 생성된 결과가 얼마나 그럴듯한지 사람이 바로 판단할 수 있게 돕는 것이 목표다.

## 3. 기존 접근의 한계
- 기존 레시피 생성 연구는 대체로 **단방향 생성**(재료→조리법)에 치우쳐 있었고, 재료 생성(조리법→재료)은 잘 다루지 않았다.
- 생성만 하고 **결과 품질을 사용자가 검증할 수단이 부재**했다 — 생성된 조리법이 입력 재료를 실제로 사용하는지, 유사한 실제 레시피가 있는지 확인하기 어려웠다.
- 소규모/특화 모델 대비, 대규모 사전학습 언어모델의 전이(fine-tuning) 효과를 레시피 도메인에서 체계적으로 활용·검증한 사례가 부족했다.

## 4. 제안 방법 (Method) — 핵심 아이디어와 동작 원리
- **백본**: OpenAI **GPT-2**를 대규모 조리 레시피 코퍼스(Recipe1M)로 파인튜닝. 124M·355M 두 크기를 실험하고 배포는 **124M** 사용.
- **양방향 생성 (2가지 모드)**:
  1. **조리법 생성(Instruction generation)**: 레시피 제목 + 재료 → 조리 단계 텍스트.
  2. **재료 생성(Ingredient generation)**: 레시피 제목 + 조리법 → 재료 목록.
  - 필드(title/ingredients/instructions)를 특수 구분 토큰으로 감싼 단일 시퀀스로 학습하여, 조건부로 나머지 필드를 자기회귀 생성한다. 최대 512 토큰(Recipe1M의 98.6% 커버).
- **평가 모듈(Evaluation module)**: 생성 결과의 신뢰성을 사용자에게 즉시 보여주는 것이 핵심 차별점.
  - **재료 겹침 하이라이팅**: root noun(어근 명사) 추출로 입력 재료와 생성 조리법에서 공통으로 언급된 재료를 강조 표시.
  - **최근접 이웃 검색(Nearest neighbor retrieval)**: **ElasticSearch**에 색인된 Recipe1M에서 생성 결과와 가장 유사한 실제 레시피를 찾아 비교 제시.
  - 사용자 평점/코멘트 수집 기능.

## 5. 핵심 기여 (Contributions)
- 재료↔조리법을 오가는 **양방향 레시피 생성**을 하나의 GPT-2 기반 시스템으로 통합.
- 생성과 함께 **품질 검증(재료 겹침 하이라이트 + 유사 레시피 검색)**을 결합한 최초급 통합 데모.
- Recipe1M 대규모 데이터에 대한 GPT-2 파인튜닝의 정량 성능을 여러 지표로 보고(F1·BLEU·ROUGE-L·NTED·Perplexity 등).
- 누구나 접근 가능한 **온라인 데모 플랫폼(recipegpt.org)** 및 공개 실험 코드 제공.

## 6. 실험 / 결과 — 데이터셋, 지표, 주요 수치
- **데이터셋**: Recipe1M 기반. 필터링 후 총 **904,401개** 레시피 → 학습 약 **896,401개**, 검증 **4,000개**, 테스트 **4,000개**.
- **모델/학습 설정**: GPT-2 124M(배포)·355M(비교). 최대 512 토큰, 배치 크기 **8**, 학습률 **1e-4**, 단일 NVIDIA Tesla V100에서 약 **5일(≈5 에폭)** 학습.
- **주요 보고 지표(테스트셋, 파인튜닝 GPT-2 124M)**:
  - **Ingredient F1 = 0.76** (재료 생성 정확도)
  - **평균 생성 재료 수 ≈ 7.8**
  - **BLEU = 8.34**
  - **Brevity Penalty = 0.71**
  - **ROUGE-L = 0.36**
  - **NTED(Normalized Tree Edit Distance) = 0.52** (조리법 구조 유사도)
  - **Perplexity = 3.70**
- **필드 간 재료 일관성(Jaccard, 생성 조리법 vs 입력 재료)**: 생성물 **0.53** vs 사람이 쓴 실제 조리법 **0.49** — 즉 모델 생성 조리법이 입력 재료를 사람보다 오히려 더 자주 명시적으로 언급(사람은 "combine all ingredients"처럼 뭉뚱그리는 경향).

> 참고: 위 표 수치는 배포 모델(124M) 기준으로 정리한 값이며, 논문은 124M·355M 두 크기를 비교 제시한다. 세부 표(124M vs 355M 개별 값)는 원문 Table 1 참조.

## 7. 한계 및 향후 과제
- **데모/시스템 논문**(WWW Demo track)이라 새로운 모델 구조 제안이 아니라 GPT-2 적용·시스템화가 초점 — 방법론적 신규성은 제한적.
- 평가 모듈은 재료 겹침·유사도 검색 등 **표면적 일관성** 위주로, 조리 절차의 **실제 물리적/화학적 타당성(요리로 성립하는지)**은 검증하지 못함.
- 영어 Recipe1M 도메인에 한정, 다국어·다른 요리 문화권 일반화는 원문에 명시 없음.
- 생성 안전성(알레르기·유해 조합 등)에 대한 논의는 원문에 명시 없음.
